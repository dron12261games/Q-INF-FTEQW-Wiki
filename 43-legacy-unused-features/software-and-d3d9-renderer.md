# Software-рендерер и D3D9: устаревшие пути отрисовки

> [⬅ Вернуться к оглавлению вики](../README.md)

> Раздел: [Устаревшие, экспериментальные и недоступные по умолчанию возможности](./README.md)

Коротко: отдельный программный (software, то есть отрисовка кадра силами процессора без ускорителя) рендерер, устаревший видеоинтерфейс D3D9, а также программный «аварийный» режим `d3d11 warp` не стоит считать основным путём отображения игры в обычной сборке движка или основным режимом для проверки контента.

## Что важно

- Реальные renderer backend'ы в FTEQW регистрируются только если они вообще собраны в бинарник; наличие `vid_renderer`-значения нельзя предполагать без проверки `$_vid_renderer_opts`.
- У отдельного software renderer есть собственные имена выбора (`sw`, `software`, `SoftRast`), но сам движок помечает этот путь как ограниченный и не использует его как нормальный приоритетный выбор.
- Режим `random` специально пропускает чистый software renderer.
- `d3d9` остаётся отдельным legacy backend'ом, если он вообще собран.
- `d3d11 warp` — это software-драйвер внутри D3D11-пути; полезен как аварийный/диагностический запуск без нормального GPU, но не как основной целевой режим рендера.

## Практический вывод

Для обычной документации и ожиданий от контента безопаснее считать основными путями `gl`/`egl`, а `vk`/`d3d11` — доступными только если они есть в конкретной сборке. Software/D3D9-пути лучше оставлять для отладки, диагностики и редких совместимых специальных сборок.
