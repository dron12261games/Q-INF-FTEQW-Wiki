Этот раздел собирает cvar движка FTEQW, которые не относятся напрямую к видео, освещению, звуку, сети, физике или интерфейсу, а также редкие/служебные переменные с минимальной документацией.

## Переменные

### _cl_disconnectreason
`cvar _cl_disconnectreason(string, "")`

#### Описание и логика работы
Эта квара содержит причину последнего отключения, чтобы меню мода могло знать, почему что-то не удалось.

Значение по умолчанию — `""`. Как и для большинства cvar движка, изменение вступает в силу немедленно, если явно не сказано иное в описании выше; для видео- и рендер-зависимых переменных иногда требуется [`vid_restart`](../44-cli-commands-reference/02-client-ui-commands.md#vid_restart) или [`vid_reload`](../44-cli-commands-reference/02-client-ui-commands.md#vid_reload).

#### Практическое использование
```cfg
seta _cl_disconnectreason "" // вернуть/установить значение по умолчанию
```

### allow_f_cmdline
`cvar allow_f_cmdline(int, "0")`

#### Описание и логика работы
Переменная управляет тем, отвечает ли клиент на запросы f_cmdline или q_cmdline из чата, которые обрабатываются системой validation. При ненулевом значении клиент отправляет фиксированный ответ `f_cmdline not supported`; при 0 такой запрос просто игнорируется и сведения о командной строке не раскрываются.


#### Практическое использование
```cfg
seta allow_f_cmdline "0" // вернуть/установить значение по умолчанию
```

### allow_f_modified
`cvar allow_f_modified(int, "1")`

#### Описание и логика работы

### allow_f_ruleset
`cvar allow_f_ruleset(int, "1")`

#### Описание и логика работы
Переменная зарегистрирована в группе Authentication, но в текущем коде не участвует в ветке `f_ruleset`: запрос всегда обслуживается через `Validation_AllChecks()`. По существу это зарезервированный флаг, который, вероятно, задумывался как выключатель ответа ruleset, но в данной ревизии не действует.


#### Практическое использование


### cfg_save_all
`cvar cfg_save_all(string, "")`

```cfg
seta gamecfg "0" // вернуть/установить значение по умолчанию
```

### lang
`cvar lang(string, "")`

#### Описание и логика работы
Эта переменная содержит код языка/диалекта, используемый для поиска строк локализации. Строка `prvm_language` в объявлении — это legacy-алиас имени cvar, а не значение по умолчанию. Реальное стартовое значение движок берёт из `-lang`, затем из системной локали/переменных окружения, после чего нормализует его до формы `language[_territory]`; если подходящая локаль не найдена, остаётся пустая строка.

Значение по умолчанию не является фиксированной константой и определяется при запуске движка из локали системы или ключа `-lang`.

#### Практическое использование
```cfg
seta lang "ru_RU" // пример явного выбора локали
```

Голоса будут аннулированы по истечении указанного количества минут.

Значение по умолчанию — `"10"`. Как и для большинства cvar движка, изменение вступает в силу немедленно, если явно не сказано иное в описании выше; для видео- и рендер-зависимых переменных иногда требуется `vid_restart` или `vid_reload`.

#### Практическое использование
```cfg
seta votetime "10" // вернуть/установить значение по умолчанию
```

### w_switch
`cvar w_switch(string, "")`

#### Описание и логика работы
ARCHIVE|USERINFO-переменная предпочтений автосмены оружия, почти не используемая на клиенте, но читаемая серверным builtin-кодом. В PF_CheckPlayerEXFlags_qex значение w_switch (или резервного b_switch) преобразуется в флаги поведения: пустое или 0 трактуется как режим смены только для нового оружия, а 1 — как запрет повышать оружие выше axe при подборе. Это совместимый с QuakeWorld канал передачи предпочтений игрока для gamecode.


#### Практическое использование
```cfg
seta w_switch "" // вернуть/установить значение по умолчанию
```

### watervis
`cvar watervis(string, "")`

#### Описание и логика работы
Серверное объявление того, можно ли клиенту использовать watervis — расширенную видимость или отрисовку через воду. Клиент выставляет allow_watervis в true, если поле равно ненулю; при пустом значении решение может перейти к локальному ruleset_allow_watervis, а в режиме spectating или demo разрешение даётся всегда. В NetQuake-совместимом пути server info по умолчанию подменяется на watervis=1.


#### Практическое использование
```cfg
seta watervis "" // вернуть/установить значение по умолчанию
```

### xinput_leftvibrator
`cvar xinput_leftvibrator(int, "0")`

#### Описание и логика работы
Задаёт мощность левого вибромотора XInput-контроллера. Значение напрямую умножается на 0xFFFF и передаётся в XInputSetState при каждом обновлении устройства, поэтому практически осмыслен диапазон от 0 до 1. Работает только для контроллеров, распознанных через XInput.


#### Практическое использование
```cfg
seta xinput_leftvibrator "0" // вернуть/установить значение по умолчанию
```
