# Физика и игровой процесс

> [⬅ Предыдущая страница](04-network-server-cvars.md) | [Следующая страница ➡](06-ui-console-input-cvars.md)

> [⬅ Вернуться к оглавлению вики](../README.md)
> [Индекс справочника cvar](../README.md#переменные-движка-cvar-reference)

Этот раздел собирает cvar FTEQW, которые управляют клиентским вводом, предсказанием движения, серверными movevars, совместимостью с NetQuake/QuakeWorld и набором gameplay fix-переключателей. Значения по умолчанию, режимы `auto` и строки с пустым значением сверены по реальным объявлениям `CVAR(...)`/`CVARD(...)`/`CVARF(...)`/`CVARFD(...)`/`CVARAFD(...)` в исходниках движка; там, где cvar стартует пустой строкой, движок либо работает в режиме auto, либо подставляет встроенный fallback.

## Переменные

### cl_anglespeedkey
`cvar cl_anglespeedkey(float, "1.5")`

#### Описание и логика работы
Задаёт множитель для скоростей поворота, когда активен `+speed`: он умножает базовые `cl_yawspeed`, `cl_pitchspeed` и `cl_rollspeed`. Значение `1` оставляет поворот без ускорения, `0` фактически убирает бонус от клавиши speed, а повышенные значения дают более резкий разворот; в обычных правилах движок дополнительно ограничивает экстремальные числа, чтобы темп не уходил в абсурд.

#### Практические сценарии использования
```cfg
set cl_anglespeedkey "1.5" // штатное ускорение поворота при зажатом +speed
set cl_anglespeedkey "2" // быстрее разворачиваться с клавиатуры
```

---

### cl_backspeed
`cvar cl_backspeed(float/string, "")`

#### Описание и логика работы
Определяет базовую скорость движения назад. Пустая строка означает «использовать `cl_forwardspeed`», поэтому по умолчанию задний ход симметричен движению вперёд; явный `0` почти убирает обратный ход, а повышенные значения меняют только отправляемую команду, после чего сервер всё равно вправе ограничить её через собственные movevars.

#### Практические сценарии использования
```cfg
set cl_backspeed "" // взять ту же базовую скорость, что и у cl_forwardspeed
set cl_backspeed "300" // сделать движение назад чуть медленнее вперёднего хода
```

---

### cl_fastaccel
`cvar cl_fastaccel(boolean/int, "1")`

#### Описание и логика работы
Включает мгновенный выход клиентской команды на полную заданную скорость вместо короткого «разгона» длиной примерно в кадр. `1` делает отклик ввода максимально резким, `0` оставляет более старое, мягкое ощущение старта; на серверную физику это напрямую не влияет, но меняет то, как формируется usercmd и как движение ощущается локально.

#### Практические сценарии использования
```cfg
set cl_fastaccel "1" // современный резкий отклик на старт движения
set cl_fastaccel "0" // более мягкий старт для тестов совместимости и старого ощущения
```

---

### cl_forwardspeed
`cvar cl_forwardspeed(float, "400")`

#### Описание и логика работы
Задаёт базовую величину команды движения вперёд, которую клиент отправляет серверу. `0` убирает нормальный forward-ввод с клавиатуры, умеренные числа меняют «намерение» движения, а очень большие значения не гарантируют реального ускорения, потому что итог всё равно ограничивается серверной физикой, модом и `sv_maxspeed`.

#### Практические сценарии использования
```cfg
set cl_forwardspeed "400" // стандартная клиентская база для движения вперёд
set cl_forwardspeed "320" // более консервативное значение под старые конфиги
```

---

### cl_iDrive
`cvar cl_iDrive(boolean/int, "1")`

#### Описание и логика работы
Полу-читерская (`CVAR_SEMICHEAT`) настройка, которая при нажатии противоположной кнопки движения эффективно отпускает уже зажатую. Это убирает «мёртвое время», когда вперёд/назад или влево/вправо зажаты одновременно; `0` оставляет классическое поведение, `1` делает стрейф и перекладки чище без скриптовой обвязки.

#### Практические сценарии использования
```cfg
set cl_iDrive "1" // уменьшить задержку при смене направления
set cl_iDrive "0" // вернуть полностью классическое поведение клавиш движения
```

---

### cl_instantrotate
`cvar cl_instantrotate(boolean/int, "1")`

#### Описание и логика работы
Управляет только накопленным `in_rotate`-поворотом: при `1` такой импульс применяется сразу целиком, а при `0` расходуется по времени кадра и дополнительно масштабируется через `cl_anglespeedkey`. Обычные клавиши `+left/+right`, `+lookup/+lookdown` и [`+klook`](../44-cli-commands-reference/02-client-ui-commands.md#klook) идут по своим путям через `cl_yawspeed`/`cl_pitchspeed`, поэтому этот cvar не делает их «мгновенными» и не выключает их штатное сглаживание.

#### Практические сценарии использования
```cfg
set cl_instantrotate "1" // мгновенно применять накопленный in_rotate-поворот
set cl_instantrotate "0" // растянуть такой поворот по времени кадра
```

---

### cl_lerp_driftbias
`cvar cl_lerp_driftbias(float, "0")`

#### Описание и логика работы
Добавляет смещение к точке, вокруг которой клиент удерживает интерполяцию и дрейф времени. Отрицательные значения сильнее удерживают картинку «в прошлом» и обычно повышают плавность ценой дополнительной задержки, положительные приближают интерполяцию к настоящему моменту и на нестабильной сети могут усилить дрожание.

#### Практические сценарии использования
```cfg
set cl_lerp_driftbias "-0.01" // чуть сильнее увести интерполяцию в прошлое ради плавности
set cl_lerp_driftbias "0" // оставить штатное поведение
```

---

### cl_lerp_driftfrac
`cvar cl_lerp_driftfrac(float, "0")`

#### Описание и логика работы
Определяет, насколько охотно интерполяция тянется к более свежему времени вместо более старого, стабильного. `0` оставляет максимально консервативный выбор, значения между `0` и `1` делают подстройку агрессивнее, а большие числа редко нужны и обычно лишь увеличивают риск микродёрганий на сети с потерями.

#### Практические сценарии использования
```cfg
set cl_lerp_driftfrac "0" // приоритет максимально стабильной интерполяции
set cl_lerp_driftfrac "0.25" // чуть быстрее подтягиваться к последним пакетам
```

---

### cl_lerp_smooth
`cvar cl_lerp_smooth(int, "2")`

#### Описание и логика работы
Выбирает стратегию сглаживания интерполяции. `2` — режим по умолчанию: в демо и одиночной игре ведёт себя как `1`, а в сетевом [deathmatch](04-network-server-cvars.md#deathmatch) — как `0`; `1` постоянно держит интерполяцию в прошлом на один сетевой шаг ради очень ровного движения ценой дополнительной задержки, `0` ориентируется на фактическое время прихода пакетов и потому лучше подходит для соревновательной игры, но может сильнее дёргаться при packet loss.

#### Практические сценарии использования
```cfg
set cl_lerp_smooth "2" // автоматический режим: плавно в SP/демо, жёстче в DM
set cl_lerp_smooth "1" // максимально гладкая картинка ценой лишней задержки
```

---

### cl_movement
`cvar cl_movement(boolean/int, "1")`

#### Описание и логика работы
Указывает, отправлять ли последовательность кадров движения по DPP7-совместимому пути. `1` сохраняет современное штатное поведение, а `0` заставляет клиента посылать нулевой номер последовательности; это полезно для диагностики и отдельных несовместимых случаев, но, в отличие от `cl_nopred`, может реально менять серверное поведение, а не только локальное предсказание.

#### Практические сценарии использования
```cfg
set cl_movement "1" // нормальная работа современного сетевого ввода
set cl_movement "0" // диагностический режим для проблемных DPP7-серверов/модов
```

---

### cl_nopred
`cvar cl_nopred(boolean/int, "0")`

#### Описание и логика работы
Полностью отключает клиентское предсказание собственного движения. При `1` локальный игрок ждёт подтверждённые состояния сервера, из-за чего управление становится заметно «тяжелее», зато такой режим полезен для поиска расхождений предикта, демонстрации реальной задержки или совместимости с особенно ломаными модами.

#### Практические сценарии использования
```cfg
set cl_nopred "0" // обычная игра с локальным предсказанием движения
set cl_nopred "1" // отладка десинков и проверка реальной серверной задержки
```

---

### cl_pitchspeed
`cvar cl_pitchspeed(float, "150")`

#### Описание и логика работы
Задаёт базовую скорость изменения pitch для клавиатурного обзора: [`+lookup`](../44-cli-commands-reference/02-client-ui-commands.md#lookup), [`+lookdown`](../44-cli-commands-reference/02-client-ui-commands.md#lookdown) и режима `+klook`. Ноль практически отключает такой способ смотреть вверх-вниз, а увеличение значения ускоряет набор угла; итоговая скорость также умножается на `cl_anglespeedkey` при активном `+speed` и ограничивается защитными рамками движка.

#### Практические сценарии использования
```cfg
set cl_pitchspeed "150" // стандартный темп клавиатурного look up/down
set cl_pitchspeed "220" // быстрее менять наклон взгляда с клавиатуры
```

---

### cl_predict_extrapolate
`cvar cl_predict_extrapolate(int/string, "")`

#### Описание и логика работы
Управляет тем, живёт ли локальное предсказание строго на завершённых кадрах ввода или разрешает экстраполяцию по частично собранным кадрам. Пустая строка оставляет auto-логику движка: при низком [`cl_netfps`](07-system-misc-cvars.md#cl_netfps) он сам склоняется к экстраполяции, при более высоком — к интерполяции в прошлом; `0` принудительно держит движение на завершённых кадрах, `1` форсирует более «живой», но местами плавающий и swimmy-отклик.

#### Практические сценарии использования
```cfg
set cl_predict_extrapolate "" // доверить выбор автоматике движка
set cl_predict_extrapolate "0" // предсказание только по завершённым input-кадрам
```

---

### cl_predict_timenudge
`cvar cl_predict_timenudge(float, "0")`

#### Описание и логика работы
Отладочная поправка ко времени локального предсказания в секундах. Положительные значения подталкивают симуляцию вперёд во времени и усиливают экстраполяцию, отрицательные — уводят её назад и делают картинку более «лаговой»; движок всё равно жёстко зажимает диапазон примерно в пределах `-0.5 .. 0.5`, поэтому использовать имеет смысл только маленькие дробные значения.

#### Практические сценарии использования
```cfg
set cl_predict_timenudge "0" // штатный режим без искусственного смещения времени
set cl_predict_timenudge "-0.02" // диагностически увести предсказание немного в прошлое
```

---

### cl_rollangle
`cvar cl_rollangle(float, "2.0")`

#### Описание и логика работы
Определяет максимальный визуальный наклон камеры при стрейфе. `0` полностью убирает боковой крен, штатные маленькие числа дают лёгкий классический lean-эффект, а большие значения быстро делают картинку некомфортной; на физику и точку попадания этот cvar не влияет, меняется только вид.

#### Практические сценарии использования
```cfg
set cl_rollangle "2" // классический слабый крен камеры при стрейфе
set cl_rollangle "0" // полностью убрать наклон экрана в стороны
```

---

### cl_rollspeed
`cvar cl_rollspeed(float, "200")`

#### Описание и логика работы
Задаёт скорость бокового движения, при которой камера достигает максимума из `cl_rollangle`. Чем меньше число, тем быстрее экран выходит на полный наклон даже при умеренном стрейфе; чем больше число, тем слабее и реже заметен крен. Это чисто визуальная настройка восприятия движения.

#### Практические сценарии использования
```cfg
set cl_rollspeed "200" // стандартная чувствительность крена к стрейфу
set cl_rollspeed "350" // крен будет проявляться только на более резком боковом ходе
```

---

### cl_run
`cvar cl_run(boolean/int, "0")`

#### Описание и логика работы
Включает autorun, то есть инвертирует смысл клавиши `+speed`. При `0` всё работает по классической схеме — ускорение даёт зажатый `+speed`; при `1` быстрый бег становится базовым состоянием, а `+speed` начинает выполнять обратную роль и чаще используется как «медленный ход».

#### Практические сценарии использования
```cfg
set cl_run "1" // постоянный бег по умолчанию
set cl_run "0" // классическое поведение со speed как ускорителем
```

### cl_sidespeed
`cvar cl_sidespeed(float, "400")`

#### Описание и логика работы
Определяет базовую величину бокового движения, которую клиент отправляет в usercmd при стрейфе. `0` почти убирает sidemove, умеренные изменения помогают подстроить feel под старый конфиг или контроллер, но на реальную итоговую скорость всё так же влияют серверные ограничения и текущая физика мода.

#### Практические сценарии использования
```cfg
set cl_sidespeed "400" // стандартный боковой ход
set cl_sidespeed "320" // немного менее резкий стрейф
```

---

### cl_smartjump
`cvar cl_smartjump(boolean/int, "1")`

#### Описание и логика работы
Делает кнопку прыжка контекстной: в воде она работает как [`+moveup`](../44-cli-commands-reference/02-client-ui-commands.md#moveup), а на суше остаётся обычным jump. `1` обычно удобнее, потому что упрощает плавание и делает его тише/быстрее по управлению; `0` возвращает старый подход, где всплытие и прыжок нужно разводить разными командами.

#### Практические сценарии использования
```cfg
set cl_smartjump "1" // один bind и для прыжка, и для всплытия в воде
set cl_smartjump "0" // полностью раздельное управление прыжком и +moveup
```

---

### cl_upspeed
`cvar cl_upspeed(float, "400")`

#### Описание и логика работы
Переменная объявлена и архивируется, но в текущем `CL_BaseMove` вертикальная компонента `upmove` берётся не из `cl_upspeed`, а из `cl_backspeed` либо `cl_forwardspeed` (если `cl_backspeed` пуст). Поэтому в дефолтной ветке клиентского ввода изменение `cl_upspeed` само по себе не меняет фактическую скорость `+moveup`/[`+movedown`](../44-cli-commands-reference/02-client-ui-commands.md#movedown); это скорее совместимый legacy-cvar, чем реально используемая ручка.

#### Практические сценарии использования
```cfg
set cl_upspeed "400" // оставить совместимое значение по умолчанию
set cl_backspeed "" // вместе с cl_forwardspeed сохранить текущую подстановку скорости по умолчанию
```

### cl_yawspeed
`cvar cl_yawspeed(float, "140")`

#### Описание и логика работы
Базовая скорость клавиатурного разворота по yaw для `+left` и `+right`. Она умножается на `cl_anglespeedkey`, когда активен `+speed`, затем масштабируется временем кадра; ноль почти отключает turn-keys, а большие значения ускоряют разворот, но в обычном режиме движок всё равно ограничивает чрезмерный темп ради стабильности.

#### Практические сценарии использования
```cfg
set cl_yawspeed "140" // стандартный темп поворота влево/вправо с клавиатуры
set cl_yawspeed "220" // быстрые развороты для клавиатурного управления обзором
```

### pm_airstep
`cvar pm_airstep(boolean/int/string, "")`

#### Описание и логика работы
Разрешает игроку «шагать» вверх по ступеням даже в прыжке, а не только при обычном наземном движении. Пустая строка по умолчанию эквивалентна выключенному режиму, `1` делает лестницы и мелкие уступы заметно мягче в прыжках, но одновременно может повысить достижимую высоту некоторых прыжковых траекторий; на части серверов этот параметр также виден клиенту через serverinfo.

#### Практические сценарии использования
```cfg
set pm_airstep "1" // разрешить подшагивание на ступени в прыжке
set pm_airstep "" // оставить штатное поведение без принудительного air-step
```

---

### pm_autobunny
`cvar pm_autobunny(boolean/int/string, "")`

#### Описание и логика работы
Позволяет продолжать прыгать без отпускания кнопки jump. Пустое значение оставляет автопрыжок выключенным, `1` включает непрерывный bunnyhop при удержании клавиши; это сильно меняет потолок мобильности и снижает требования к таймингу, поэтому на сервере считается именно серверной настройкой физики, а не личным клиентским вкусом.

#### Практические сценарии использования
```cfg
set pm_autobunny "1" // держать прыжок для непрерывного bunnyhop
set pm_autobunny "" // классический режим: каждый прыжок отдельным нажатием
```

---

### pm_bunnyfriction
`cvar pm_bunnyfriction(boolean/int/string, "")`

#### Описание и логика работы
Форсирует хотя бы один кадр трения при прыжке, имитируя характерную NetQuake-физику. Пустая строка оставляет дополнительное ограничение выключенным, `1` делает bunnyhop менее «скользким», сильнее режет бесплатное удержание скорости и особенно заметна на высоких tickrate, где отсутствие такого трения даёт больше выгоды.

#### Практические сценарии использования
```cfg
set pm_bunnyfriction "1" // ближе к NQ-поведению с обязательным кадром трения
set pm_bunnyfriction "" // не добавлять лишнее jump-friction поверх штатной физики
```

---

### pm_bunnyspeedcap
`cvar pm_bunnyspeedcap(float/string, "")`

#### Описание и логика работы
Добавляет верхнюю границу на горизонтальную скорость при повороте в воздухе: если игрок уже быстрее лимита, поворот аккуратно стягивает скорость к `sv_maxspeed * pm_bunnyspeedcap`. Пустая строка означает отсутствие такого капа, `1` даёт почти прямой запрет на набор и удержание лишней скорости через поворот, значения меньше `1` делают ограничение ещё строже; при этом вертикальный буст от rocket jump и подобных техник сам по себе не отключается.

#### Практические сценарии использования
```cfg
set pm_bunnyspeedcap "1" // жёстко сводить скорость обратно к maxspeed при поворотах
set pm_bunnyspeedcap "" // не ограничивать bunnyhop этим отдельным капом
```

#### Описание и логика работы

Повышение значения делает мир тяжелее и укорачивает дуги прыжков, снижение даёт более парящую физику; отдельные сущности и моды могут дополнительно масштабировать её своим множителем, но отправной точкой всё равно остаётся именно `sv_gravity`.

#### Практические сценарии использования
```cfg
set sv_gravity "800" // классическая гравитация Quake-подобной физики
set sv_gravity "600" // более высокий и «воздушный» характер прыжков
```

### sv_maxspeed
`cvar sv_maxspeed(float, "320")`

#### Описание и логика работы
Основной серверный предел желаемой скорости игрока. Он участвует в расчёте нормального наземного темпа, служит опорой для `pm_bunnyspeedcap` и ограничивает то, насколько далеко вообще можно разогнать стандартное движение без специальных техник; слишком низкие числа делают игру вязкой, слишком высокие быстро меняют весь темп карт и дуэлей.

#### Практические сценарии использования
```cfg
set sv_maxspeed "320" // классический предел базовой скорости игрока
set sv_maxspeed "400" // ускорить общий темп наземного перемещения
```

### sv_maxvelocity
`cvar sv_maxvelocity(float, "10000")`

#### Описание и логика работы
Жёсткий верхний предел на скорость сущностей, нужен как страховка от физического «взрыва», слишком больших импульсов и численной нестабильности. Стандартное значение очень высокое и почти не мешает нормальной игре, а заметное занижение может неожиданно ломать rocket jump, отскоки, телепорты и иные режимы, где кратковременно набирается большая скорость.

#### Практические сценарии использования
```cfg
set sv_maxvelocity "10000" // безопасный высокий лимит по умолчанию
set sv_maxvelocity "6000" // аккуратно подрезать экстремальные импульсы на кастомном сервере
```

### sv_nqplayerphysics
`cvar sv_nqplayerphysics(string/int, "auto")`

#### Описание и логика работы
Переключает сервер между QuakeWorld-подобной предсказуемой физикой и NetQuake-подобной логикой совместимости, причём значение `auto` заставляет callback движка выбирать режим по типу игры, моду и наличию кастомной physics-функции. `0` оставляет QW-ориентированный путь с нормальным prediction-friendly поведением, `1` отключает клиентское предсказание в пользу NQ-совместимости, `2` пытается не блокировать prediction полностью, но движок сам предупреждает, что такой компромисс может быть дёрганым. Исторический алиас `sv_nomsec` у этой настройки тоже существует, но современное имя — `sv_nqplayerphysics`.

#### Практические сценарии использования
```cfg
set sv_nqplayerphysics "auto" // доверить выбор движку по модовой совместимости
set sv_nqplayerphysics "1" // принудительно уйти в NQ-стиль ради старого мода
```

### sv_pushplayers

```

### sv_stepheight
`cvar sv_stepheight(float/string, "")`

#### Описание и логика работы

```

```

### sv_wateraccelerate
`cvar sv_wateraccelerate(float, "10")`

#### Описание и логика работы
Серверный коэффициент разгона в воде. Чем он выше, тем быстрее игрок набирает скорость при активном плавании, всплытии и манёврах под водой; низкие числа делают движение в жидкости вязким и инертным, высокие — почти сухопутным по отзывчивости.

```

### sv_waterfriction
`cvar sv_waterfriction(float, "4")`

#### Описание и логика работы
Отвечает за то, как быстро вода гасит уже набранную скорость. ```

### chase_active
`cvar chase_active(int, "0")`

#### Описание и логика работы
Включает вид от третьего лица (chase camera): при значении `1` и разрешённых читах (`cls.allow_cheats`, то есть [`sv_cheats 1`](04-network-server-cvars.md#sv_cheats) либо синглплеер/локальный сервер) камера отодвигается от игрока на расстояние, заданное `chase_back` и `chase_up`, показывая модель самого игрока со стороны, а не из глаз. Значения `2` и выше дополнительно фиксируют углы обзора камеры: `2` устанавливает вертикальный угол (pitch) в 90°, глядя сверху вниз, а `3` и выше дополнительно обнуляет горизонтальный угол (yaw), фактически превращая камеру в неподвижный вид сверху вдоль фиксированной оси. Без прав на читы cvar не действует, и игра остаётся в виде от первого лица независимо от его значения.


#### Практическое использование
```cfg
seta chase_active "0" // вернуть/установить значение по умолчанию
```
