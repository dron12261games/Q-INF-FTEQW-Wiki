# Видео, экран и общий рендеринг

> [⬅ Вернуться к оглавлению вики](../README.md)

> [Индекс справочника cvar](./README.md)

Этот раздел собирает самые важные cvar FTEQW, которые влияют на видеорежим, масштаб интерфейса, поле зрения, качество текстур, сглаживание и общий вид картинки. Список составлен по реальным объявлениям `CVAR(...)`/`CVARD(...)`/`CVARF(...)`/`CVARFD(...)` в коде движка, а описания без встроенного комментария восстановлены по контексту использования. Для параметров с `CVAR_VIDEOLATCH` безопасно считать, что изменение вступает в силу после `vid_restart`, а для `CVAR_RENDERERLATCH` — после `vid_reload` или ближайшей полной перезагрузки рендера.

## Переменные

### crosshair
`cvar crosshair(boolean/int, "1")`

#### Описание и логика работы
Включает встроенный прицел. Значение `0` полностью убирает его с экрана, а любые ненулевые значения оставляют прицел активным; в большинстве конфигураций имеет смысл использовать `0` или `1`. Переменная архивируется в конфиг (`CVAR_ARCHIVE`), поэтому подходит для постоянной пользовательской настройки и меняется на лету.

#### Практические сценарии использования
```cfg
seta crosshair "1" // обычная игра с видимым прицелом
seta crosshair "0" // скриншоты, кинематика или HUD без прицела
```

### crosshaircorrect
`cvar crosshaircorrect(boolean/int, "0")`

#### Описание и логика работы
Сдвигает прицел так, чтобы он лучше совпадал с фактической точкой попадания оружия, если модель оружия расположена ниже реальной камеры. Значение `0` оставляет классическое поведение Quake, `1` включает коррекцию; экстремально большие числа практического смысла не имеют, потому что код использует переменную как переключатель. Это semi-cheat-переменная (`CVAR_SEMICHEAT`), не архивируется автоматически и обычно применяется сразу, без рестарта.

#### Практические сценарии использования
```cfg
seta crosshaircorrect "1" // визуально честнее для оружия со смещённым muzzle point
```

### crosshairimage
`cvar crosshairimage(string, "")`

#### Описание и логика работы
Позволяет заменить стандартный прицел внешним изображением или шейдером. Пустая строка возвращает встроенный вариант, а непустое значение должно указывать на реально существующий ресурс; если путь неверный, движок обычно откатится к стандартному виду или не покажет кастомный прицел. Переменная не архивируется автоматически и меняется на лету.

#### Практические сценарии использования
```cfg
seta crosshairimage "gfx/crosshair1.tga" // использовать собственный файл прицела
```

### crosshairsize
`cvar crosshairsize(int, "8")`

#### Описание и логика работы
Задаёт виртуальный размер встроенного прицела. Малые значения делают его компактным, `0` или близкие к нулю величины фактически превращают прицел в почти незаметный, а слишком большие значения дают крупный HUD-элемент, который может мешать чтению цели. Переменная архивируется в конфиг (`CVAR_ARCHIVE`) и применяется сразу.

#### Практические сценарии использования
```cfg
seta crosshairsize "12" // увеличить прицел для высокого разрешения
seta crosshairsize "6" // сделать прицел более тонким и компактным
```

### d_lodbias
`cvar d_lodbias(float, "0")`

#### Описание и логика работы
Историческое имя cvar для смещения выбора mip-уровней текстур; в коде у неё есть алиас `gl_texture_lodbias`. Ноль оставляет штатный выбор, положительные значения заставляют рендер раньше брать более грубые mip-уровни и размывают картинку, а отрицательные делают изображение резче ценой мерцания и алиасинга на дистанции. Переменная архивируется в конфиг (`CVAR_ARCHIVE`), имеет `CVAR_RENDERERCALLBACK`, поэтому обычно применяется на лету.

#### Практические сценарии использования
```cfg
seta d_lodbias "-0.5" // сделать текстуры чуть резче
seta d_lodbias "1" // снизить shimmering на слабом железе
```

### ffov
`cvar ffov(float/string, "")`

#### Описание и логика работы
Задаёт отдельное поле зрения для нестандартных проекций, которые включаются через `r_projection`. Пустая строка означает «использовать обычный `fov`», а ненулевое число позволяет отдельно подобрать обзор для fisheye, panorama или equirectangular-режима; слишком большие величины приводят к сильным искажениям, что видно и по защитным проверкам в рендерере. Переменная не архивируется автоматически и обычно применяется сразу.

#### Практические сценарии использования
```cfg
seta ffov "180" // отдельный FOV для панорамной/рыбьеглазой проекции
```

### fov
`cvar fov(float, "90")`

#### Описание и логика работы
Основное игровое поле зрения камеры. По встроенному описанию штатный диапазон — `1-170`, стандартное значение — `90`; маленькие значения дают «зум», а слишком большие заметно искажают перспективу, особенно на узких или старых HUD-макетах. Переменная архивируется в конфиг (`CVAR_ARCHIVE`) и меняется на лету, но итоговая трактовка зависит от `scr_fov_mode`.

#### Практические сценарии использования
```cfg
seta fov "90" // классический Quake-обзор
seta fov "108" // широкий обзор в духе nQuake-конфигов
```

### gl_affinemodels
`cvar gl_affinemodels(boolean/int, "0")`

#### Описание и логика работы
Включает аффинную выборку текстур для моделей, имитируя искажения программного рендера Quake. `0` оставляет нормальную перспективно-корректную фильтрацию, `1` включает ретро-искажения; большие числа практического смысла не имеют. Переменная архивируется в конфиг (`CVAR_ARCHIVE`) и обычно применяется сразу.

#### Практические сценарии использования
```cfg
seta gl_affinemodels "1" // приблизить вид моделей к software Quake
```

### gl_compress
`cvar gl_compress(boolean/int, "0")`

#### Описание и логика работы
Разрешает автоматическое сжатие текстур драйвером даже для контента, который изначально не был сохранён в сжатом формате. `0` сохраняет максимальную предсказуемость качества, `1` экономит видеопамять и иногда ускоряет загрузку ценой возможных артефактов, особенно на UI и градиентах. Переменная архивируется в конфиг (`CVAR_ARCHIVE`); изменение лучше считать латчем уровня ресурсов и проверять после `vid_reload`.

#### Практические сценарии использования
```cfg
seta gl_compress "1" // экономить VRAM на больших HD-паках
seta gl_compress "0" // избегать артефактов компрессии на текстах и интерфейсе
```

### gl_dither
`cvar gl_dither(boolean/int, "1")`

#### Описание и логика работы
Включает или отключает аппаратный dithering там, где его поддерживает OpenGL-путь. `1` обычно помогает скрывать ступени на плавных переходах, `0` делает картинку более «чистой», но на старых путях может усилить banding; большие значения снова сводятся к логическому переключателю. Переменная не архивируется автоматически, однако код рендера отслеживает её модификацию и применяет переключение на лету.

#### Практические сценарии использования
```cfg
seta gl_dither "0" // более ровные скриншоты без зерна dithering
seta gl_dither "1" // сгладить переходы на старых путях вывода
```

### gl_finish
`cvar gl_finish(boolean/int, "0")`

#### Описание и логика работы
Принудительно вызывает `glFinish`, то есть заставляет CPU ждать полного завершения работы GPU перед продолжением кадра. `0` даёт максимальную производительность, `1` иногда помогает диагностировать микростаттер, тайминги или странности драйвера ценой ощутимого падения FPS; любые большие значения эквивалентны включению. Переменная не архивируется автоматически и действует сразу.

#### Практические сценарии использования
```cfg
seta gl_finish "1" // проверить, исчезают ли рывки из-за очереди драйвера
seta gl_finish "0" // вернуть нормальную производительность
```

### gl_lerpimages
`cvar gl_lerpimages(boolean/int, "1")`

#### Описание и логика работы
Включает более мягкий ресемплинг изображений, когда движку приходится работать с NPOT-ограничениями старых драйверов. `1` уменьшает ступенчатость и швы, `0` сохраняет более грубое классическое поведение; экстремальные значения сводятся к переключателю. Переменная архивируется в конфиг (`CVAR_ARCHIVE`) и обычно применяется без рестарта.

#### Практические сценарии использования
```cfg
seta gl_lerpimages "1" // сгладить нестандартные 2D-изображения и декали
```

### gl_max_size
`cvar gl_max_size(int, "8192")`

#### Описание и логика работы
Ограничивает максимальный размер текстуры, который движок разрешает себе использовать, даже если драйвер способен на большее. Большие значения сохраняют максимум детализации, меньшие принудительно уменьшают крупные изображения и экономят память; `0` и слишком малые числа быстро приведут к агрессивному даунскейлу и заметной потере резкости. Переменная не архивируется, имеет `CVAR_RENDERERLATCH`, поэтому безопасно менять её вместе с `vid_reload`.

#### Практические сценарии использования
```cfg
seta gl_max_size "4096" // ограничить потребление VRAM на старой видеокарте
seta gl_max_size "8192" // оставить полный размер для HD-текстур
```

### gl_motionblur
`cvar gl_motionblur(float, "0")`

#### Описание и логика работы
Управляет силой простого накопительного motion blur. В OpenGL-пути эффект выполняется только при значениях строго больше `0` и меньше `1`: `0` выключает его, числа вроде `0.2-0.6` дают заметный шлейф, а `1` и выше уже выходят за полезный диапазон и практически не дают корректного результата. Переменная архивируется в конфиг (`CVAR_ARCHIVE`) и применяется на лету.

#### Практические сценарии использования
```cfg
seta gl_motionblur "0.25" // лёгкий шлейф при движении камеры
seta gl_motionblur "0" // полностью отключить размытие движения
```

### gl_motionblurscale
`cvar gl_motionblurscale(float, "1")`

#### Описание и логика работы
Масштабирует смещение, по которому строится motion blur. Ноль почти убирает эффект даже при включённом `gl_motionblur`, `1` оставляет штатное поведение, а большие значения усиливают растягивание и быстро делают шлейф неестественным. Переменная не архивируется автоматически и применяется сразу.

#### Практические сценарии использования
```cfg
seta gl_motionblurscale "0.5" // ослабить длину шлейфа, не выключая blur полностью
```

### gl_overbright
`cvar gl_overbright(int, "1")`

#### Описание и логика работы
Управляет overbright-поведением светокарт и общей яркостью классического GL-пути. `0` даёт более тусклую и совместимую картинку, `1` — обычный компромисс, более высокие значения быстро приводят к пережогу ярких поверхностей; в старом контенте практический смысл обычно ограничен диапазоном `0-2`. Переменная архивируется в конфиг (`CVAR_ARCHIVE`), а изменение может потребовать перестройки светокарт и безопаснее проверяется после `vid_reload`.

#### Практические сценарии использования
```cfg
seta gl_overbright "0" // ближе к более тёмной классической картинке
seta gl_overbright "1" // стандартный современный режим
```

### gl_picmip
`cvar gl_picmip(int, "0")`

#### Описание и логика работы
Глобально уменьшает размер world/model-текстур по экспоненциальной схеме. `0` оставляет оригинальный размер, `1` и `2` последовательно снижают разрешение и экономят память/пропускную способность, а слишком большие числа превращают большинство материалов в очень мыльные версии. Переменная архивируется в конфиг (`CVAR_ARCHIVE`) и обычно применяется после `vid_reload` или при повторной загрузке материалов.

#### Практические сценарии использования
```cfg
seta gl_picmip "1" // умеренно снизить качество текстур ради FPS
seta gl_picmip "0" // оставить исходную детализацию
```

### gl_picmip2d
`cvar gl_picmip2d(int, "0")`

#### Описание и логика работы
Отдельно уменьшает разрешение HUD- и menu-текстур. Это полезно там, где мир хочется оставить чётким, а интерфейсный пак слишком тяжёлый; `0` ничего не режет, более высокие значения уменьшают 2D-ассеты всё сильнее. Переменная архивируется в конфиг (`CVAR_ARCHIVE`) и практичнее всего проверяется после перезагрузки графических ресурсов.

#### Практические сценарии использования
```cfg
seta gl_picmip2d "1" // облегчить тяжёлый HD-интерфейс
```

### gl_picmip_other
`cvar gl_picmip_other(int, "0")`

#### Описание и логика работы
Добавляется к `gl_picmip` именно для model-текстур. Ноль оставляет глобальное значение без надбавки, положительные числа дополнительно ухудшают только модели, что удобно для мультиплеера на слабом GPU; отрицательные значения теоретически могут компенсировать глобальный picmip, но практически обычно используют `0` и выше. Переменная архивируется в конфиг (`CVAR_ARCHIVE`).

#### Практические сценарии использования
```cfg
seta gl_picmip "1"
seta gl_picmip_other "1" // ещё сильнее упростить текстуры моделей
```

### gl_picmip_sprites
`cvar gl_picmip_sprites(int, "0")`

#### Описание и логика работы
Добавляется к `gl_picmip` только для sprite-текстур. Это позволяет отдельно делать проще дым, частицы и billboard-объекты, не ухудшая геометрию мира сильнее необходимого. Переменная архивируется в конфиг (`CVAR_ARCHIVE`); `0` значит «без дополнительного штрафа», большие значения заметно мылит спрайты.

#### Практические сценарии использования
```cfg
seta gl_picmip_sprites "1" // снизить стоимость крупных sprite-эффектов
```

### gl_picmip_world
`cvar gl_picmip_world(int, "0")`

#### Описание и логика работы
Добавляется к `gl_picmip` только для world-текстур BSP-геометрии. Ноль означает обычный глобальный режим, `1-2` дают отдельный даунскейл именно для стен, пола и архитектуры, а слишком большие значения быстро убивают читаемость окружения. Переменная архивируется в конфиг (`CVAR_ARCHIVE`).

#### Практические сценарии использования
```cfg
seta gl_picmip "0"
seta gl_picmip_world "1" // упростить только карту, оставив модели нетронутыми
```

### gl_polyblend
`cvar gl_polyblend(boolean/int, "1")`

#### Описание и логика работы
Разрешает временные полноэкранные цветовые наложения: урон, бонусы, содержимое воды и другие screen tints. `0` отключает почти все такие overlays, `1` оставляет их активными; большие числа не дают отдельного режима. Переменная архивируется в конфиг (`CVAR_ARCHIVE`) и меняется на лету; интенсивность можно дополнительно подстраивать через `gl_cshiftpercent`.

#### Практические сценарии использования
```cfg
seta gl_polyblend "0" // убрать экранные вспышки и туманы для соревновательной игры
seta gl_polyblend "1" // вернуть всю штатную визуальную обратную связь
```

### gl_smoothcrosshair
`cvar gl_smoothcrosshair(boolean/int, "1")`

#### Описание и логика работы
Сглаживает отрисовку стандартного прицела. `1` делает линии мягче и аккуратнее на высоком разрешении, `0` оставляет более жёсткий и пиксельный вид; по смыслу это обычный бинарный переключатель. Переменная не архивируется автоматически и меняется сразу.

#### Практические сценарии использования
```cfg
seta gl_smoothcrosshair "0" // подчёркнуто пиксельный олдскульный прицел
seta gl_smoothcrosshair "1" // более гладкий вид на современных мониторах
```

### gl_texture_anisotropy
`cvar gl_texture_anisotropy(int, "4")`

#### Описание и логика работы
Управляет анизотропной фильтрацией; в коде также сохранён старый алиас `gl_texture_anisotropic_filtering`. Значение `1` по сути сводит её к минимуму, `2/4/8/16` последовательно повышают качество наклонных поверхностей вроде пола и дальних стен, а слишком большие числа всё равно будут зажаты максимумом драйвера. Переменная архивируется в конфиг (`CVAR_ARCHIVE`), имеет callback и обычно подхватывается без рестарта, но работает осмысленно только вместе с линейной фильтрацией и mipmapping.

#### Практические сценарии использования
```cfg
seta gl_texture_anisotropy "16" // максимально чёткий пол и дальние плоскости
seta gl_texture_anisotropy "2" // компромисс для слабой видеокарты
```

### gl_texturemode
`cvar gl_texturemode(string, "GL_LINEAR_MIPMAP_LINEAR")`

#### Описание и логика работы
Главная переменная фильтрации world/model-текстур. Движок понимает как длинные OpenGL-имена, так и короткие трёхсимвольные схемы вроде `nll` или `lll`: первая буква управляет увеличением, вторая — выбором mipmapping, третья — уменьшением слишком крупных текстур. Переменная архивируется в конфиг (`CVAR_ARCHIVE`) и имеет callback, поэтому её можно крутить на лету; `nnn` даёт максимально «lego»-картинку, `lll` или `GL_LINEAR_MIPMAP_LINEAR` — наиболее мягкий современный вариант.

#### Практические сценарии использования
```cfg
seta gl_texturemode "nll" // пиксельное увеличение, но мягкое уменьшение вдали
seta gl_texturemode "GL_LINEAR_MIPMAP_LINEAR" // классический trilinear
```

### gl_texturemode2d
`cvar gl_texturemode2d(string, "GL_LINEAR")`

#### Описание и логика работы
То же самое, что `gl_texturemode`, но для 2D-изображений: HUD, меню, консольные панели и прочие интерфейсные текстуры. По умолчанию используется мягкая линейная фильтрация, а переход к `GL_NEAREST` или аналогичной схеме делает интерфейс жёстко пиксельным. Переменная архивируется в конфиг (`CVAR_ARCHIVE`), имеет callback и применяется на лету.


### vid_multisample
`cvar vid_multisample(int, "0")`

#### Описание и логика работы
Запрашивает MSAA при создании видеоконтекста; у переменной также есть алиас `vid_samples`. По встроенному описанию `1` явно выключает MSAA, `0` оставляет выбор движку/драйверу, а `2`, `4`, `8` и выше пытаются запросить соответствующее число сэмплов; если устройство не умеет столько, backend зажмёт значение до доступного режима. Переменная архивируется (`CVAR_ARCHIVE`) и на практике требует пересоздания swapchain/контекста, поэтому надёжнее выполнять `vid_restart`.

#### Практические сценарии использования
```cfg
seta vid_multisample "4" // 4x MSAA
seta vid_multisample "1" // явно отключить MSAA
```

### vid_renderer

### vid_srgb
`cvar vid_srgb(int, "0")`

#### Описание и логика работы
Управляет работой с sRGB/линейным цветовыми пространствами. По встроенному описанию `-1` переводит только framebuffer в sRGB-логику, `0` полностью выключает режим и может усиливать banding, `1` включает нормальную sRGB-коррекцию, `2` пытается использовать линейный floating-point framebuffer для HDR-подобного вывода; поведение драйверов здесь исторически разнится очень сильно. Переменная архивируется (`CVAR_ARCHIVE`); часть backend'ов умеет подхватывать её мягко, но надёжнее тестировать после `vid_restart`.

#### Практические сценарии использования
```cfg
seta vid_srgb "1" // корректный sRGB-пайплайн для современного освещения
seta vid_srgb "0" // максимальная совместимость со старыми путями
```

### vid_vsync
`cvar vid_vsync(int, "0")`

#### Описание и логика работы
Управляет ожиданием вертикальной синхронизации; в коде у переменной есть алиас `vid_wait`. Значение `0` отключает VSync, `1` ждёт один vblank, `2` фактически ограничивает вывод каждым вторым обновлением, а пустая строка или отрицательное число переводят поведение в режим «backend/driver decide»; в OpenGL на Windows изменение подхватывается callback'ом сразу, а в Vulkan приводит к пересозданию swapchain. Переменная архивируется в конфиг (`CVAR_ARCHIVE`).

#### Практические сценарии использования
```cfg
seta vid_vsync "1" // убрать tearing ценой дополнительной задержки
seta vid_vsync "0" // минимальная задержка ввода и максимум FPS
```

### viewsize
