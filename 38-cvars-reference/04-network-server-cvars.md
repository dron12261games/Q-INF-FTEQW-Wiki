# Сеть, сервер и мультиплеер

> [⬅ Вернуться к оглавлению вики](../README.md)

> [Индекс справочника cvar](./README.md)

Этот раздел собирает ключевые сетевые и серверные cvar движка FTEQW: публикацию сервера, лимиты клиентов, совместимость протоколов, встроенную раздачу файлов, мастер-серверы и MVD/QTV-инфраструктуру. Источником имён и значений выступают реальные объявления cvar в `sv_main.c`, `sv_master.c`, `sv_mvd.c`, `net_chan.c`, `net_wins.c` и `net_ice.c`. Там, где код не даёт готового описания, формулировка ниже опирается на контекст использования переменной в тех же файлах.

## Переменные

### allow_download_configs
`cvar allow_download_configs(булево, "0")`

#### Описание и логика работы
Управляет выдачей конфигурационных файлов с сервера: расширение `.cfg` и каталог `configs/`. Значение `1` разрешает такие загрузки, но исходное описание в коде прямо помечает режим как опасный, потому что вместе с конфигами легко утекут rcon-пароли и другие приватные настройки. Это серверная переменная для администрирования раздачи контента; на публичных серверах её почти всегда держат выключенной.

#### Практические сценарии использования
```
set allow_download_configs "0" // не отдавать конфиги игрокам
```

### allow_download_copyrighted
`cvar allow_download_copyrighted(булево, "0")`

#### Описание и логика работы
Разрешает или запрещает скачивание пакетов, которые движок считает потенциально защищёнными авторским правом — прежде всего архивов с префиксом `pak`. При `0` сервер не будет раздавать такие файлы встроенным download-механизмом; в описании кода отдельно рекомендовано также держать `allow_download_pakmaps 0` и `allow_download_pakcontents 0`. Это чисто серверная политика распространения ресурсов, важная для публичных инстансов и mirror/fastdl-схем.

#### Практические сценарии использования
```
set allow_download_copyrighted "0" // не раздавать спорные pak-файлы
```

### allow_download_demos
`cvar allow_download_demos(булево, "1")`

#### Описание и логика работы
Разрешает загрузку файлов из каталога `demos/` обычной серверной раздачей. Значение `0` полностью отрезает доступ к демкам через встроенный download, а `1` оставляет возможность скачивать записи матчей напрямую с сервера. Полезно на закрытых лигах и тренировочных серверах, где демо должны получать только через веб-архив или вручную.

#### Практические сценарии использования
```
set allow_download_demos "1" // разрешить скачивание серверных демо
```

### allow_download_logs
`cvar allow_download_logs(булево, "0")`

#### Описание и логика работы
Разрешает скачивание файлов `.log`. Встроенное описание предупреждает, что это опасно: в логах могут оказаться пароли, приватная переписка и служебная информация. Переменная серверная и в реальной эксплуатации должна оставаться `0`, кроме короткой диагностической сессии в доверенной сети.

#### Практические сценарии использования
```
set allow_download_logs "0" // не отдавать журналы сервера
```

### allow_download_maps
`cvar allow_download_maps(булево, "1")`

#### Описание и логика работы
Включает раздачу файлов из каталога `maps/`. При `0` игрок без нужной карты не сможет получить её у сервера и должен будет скачать карту другим способом; при `1` сервер может закрывать пробелы в клиентском контенте автоматически. Практически это один из основных переключателей удобства подключения на кастомные мультиплеерные карты.

#### Практические сценарии использования
```
set allow_download_maps "1" // раздавать карты новым игрокам
```

### allow_download_models
`cvar allow_download_models(булево, "1")`

#### Описание и логика работы
Управляет загрузкой содержимого `progs/` и `models/`. Ноль запрещает выдачу моделей и связанных progs-ресурсов через сервер, единица оставляет стандартную раздачу включённой. На мод-серверах отключение этой переменной обычно означает обязательный внешний fastdl или ручную установку пакета клиентом.

#### Практические сценарии использования
```
set allow_download_models "1" // разрешить скачивание моделей
```

### allow_download_pakcontents
`cvar allow_download_pakcontents(целое перечисление, "0")`

#### Описание и логика работы
Определяет, можно ли скачивать немаповые файлы, лежащие внутри серверных пакетов. `0` полностью запрещает такую выдачу, `1` разрешает только пакеты, не помеченные как copyrighted, а `2` снимает ограничение даже для спорных архивов — код отдельно предупреждает, что это режим только ради совместимости с vanilla QuakeWorld. Переменная важна для администраторов, которые хотят балансировать между совместимостью старых клиентов и юридически безопасной раздачей контента.

#### Практические сценарии использования
```
set allow_download_pakcontents "1" // разрешить безопасную выдачу содержимого пакетов
```

### allow_download_pakmaps
`cvar allow_download_pakmaps(целое перечисление, "0")`

#### Описание и логика работы
Контролирует скачивание карт, находящихся внутри пакетов сервера. `0` ничего не отдаёт, `1` разрешает выдачу только из пакетов без признаков copyrighted-контента, `2` снимает фильтр полностью, но исходный комментарий предупреждает, что использовать такой режим не следует. Это серверная переменная совместимости для старых клиентов, которые не умеют работать с пакетами так, как ожидает современный FTEQW.

#### Практические сценарии использования
```
set allow_download_pakmaps "1" // разрешить скачивание карт из безопасных пакетов
```

### allow_download_skins
`cvar allow_download_skins(булево, "1")`

#### Описание и логика работы
Разрешает выдачу файлов из каталога `skins/`. При `0` игроки не смогут автоматически скачать отсутствующие скины, что уменьшает сетевую нагрузку и риск раздачи мусорных кастомизаций, но ухудшает совместимость со старыми наборами контента. Подходит для соревновательных серверов, где важнее единый визуальный стиль и минимум лишних загрузок.

#### Практические сценарии использования
```
set allow_download_skins "0" // не раздавать пользовательские скины
```

### allow_download_sounds
`cvar allow_download_sounds(булево, "1")`

#### Описание и логика работы
Включает встроенную раздачу файлов из каталога `sound/`. Значение `0` полезно, если весь звуковой пакет уже лежит на fastdl/launcher-канале или если сервер сознательно не хочет раздавать модовые звуки. Значение `1` повышает шанс, что клиент догрузит нужные ресурсы без ручной подготовки.

#### Практические сценарии использования
```
set allow_download_sounds "1" // раздавать звуки клиентам
```

### coop
`cvar coop(булево/целое, "")`

#### Описание и логика работы
Классическая `serverinfo`-переменная режима cooperative. Пустое значение оставляет управление за конфигом или модом, а ненулевое обычно включает кооперативную логику спавна и правил. Для сетевого сервера это один из маркеров режима игры, который видят браузеры серверов и клиенты при подключении.

#### Практические сценарии использования
```
set coop "1" // запустить сервер в coop-режиме
```

### deathmatch
`cvar deathmatch(целое перечисление, "1")`

#### Описание и логика работы
Основной режим сетевой игры, экспортируемый как `serverinfo`. В dedicated/server-only сборках по умолчанию стоит `1`, а допустимые значения традиционно соответствуют режимам deathmatch, задаваемым модом или игрой. Изменение напрямую влияет на правила матча и на то, как сервер идентифицируется в листингах и при рукопожатии с клиентами.

#### Практические сценарии использования
```
set deathmatch "1" // обычный deathmatch
```

### filterban
`cvar filterban(булево, "1")`

#### Описание и логика работы
Определяет действие по умолчанию для IP-фильтрации и команды `addip`. При `1` фильтр трактуется как список запретов; при `0` логика инвертируется, и игроки по умолчанию кикаются, пока правило явно не разрешит доступ. Это серверная административная переменная: ошибочное переключение способно мгновенно отрезать игроков от сервера или, наоборот, открыть доступ тем, кого ожидали банить.

#### Практические сценарии использования
```
set filterban "1" // использовать список как бан-лист
```

### fraglimit
`cvar fraglimit(целое, "")`

#### Описание и логика работы
`serverinfo`-переменная лимита фрагов на карту или раунд. Пустое значение обычно означает отсутствие лимита, а положительное число завершает матч при достижении указанного порога. На мультиплеерном сервере это одна из базовых правиловых настроек, которую клиенты видят ещё до входа на сервер.

#### Практические сценарии использования
```
set fraglimit "30" // закончить карту на 30 фрагах
```

### hostname
`cvar hostname(строка, "unnamed")`

#### Описание и логика работы
Имя сервера, публикуемое через `serverinfo`, status-ответы и мастер-листинги. Именно эту строку игроки обычно видят в браузере серверов, поэтому сюда имеет смысл помещать короткое и читаемое название без лишнего мусора. Слишком длинные или нестандартные строки не ломают сеть сами по себе, но ухудшают сортировку, читаемость и совместимость со старыми браузерами.

#### Практические сценарии использования
```
set hostname "FTEQW Duel RU #1" // понятное имя для браузера серверов
```

### maxclients
`cvar maxclients(целое, "8")`

#### Описание и логика работы
Ограничивает число игровых слотов для активных игроков; переменная помечена как `serverinfo` и может меняться даже посреди карты. Увеличение значения напрямую влияет на сетевую нагрузку, объём снапшотов и требования к пропускной способности; слишком высокие числа также ухудшают совместимость со старым vanilla-протоколом. Если нужно жёстко нормировать и игроков, и зрителей, переменную обычно согласуют с `sv_playerslots` и `maxspectators`.

#### Практические сценарии использования
```
set maxclients "16" // разрешить до 16 игроков
```

### maxspectators
`cvar maxspectators(целое, "8")`

#### Описание и логика работы
Задаёт максимальное число зрителей на сервере и тоже объявлена как `serverinfo`. Значение можно менять на лету, но уменьшение лимита на переполненном сервере может привести к отказу новым наблюдателям или к вытеснению при смене карты/слотов. Полезна на турнирных серверах, где нужно отделить лимит играющих клиентов от лимита наблюдателей и QTV-инфраструктуры.

#### Практические сценарии использования
```
set maxspectators "4" // ограничить число зрителей
```

### net_compress
`cvar net_compress(булево, "0")`

#### Описание и логика работы
Включает Huffman-сжатие сетевых пакетов. Это уменьшает объём трафика, но добавляет вычислительные накладные расходы и меняет характер сетевого профиля сервера/клиента, поэтому включать стоит только после проверки совместимости с нужными клиентами и прокси. На узких каналах может помочь, на локальных или уже быстрых каналах — почти не дать выгоды.

#### Практические сценарии использования
```
set net_compress "1" // сжимать сетевые пакеты
```

### net_enabled
`cvar net_enabled(булево, "1")`

#### Описание и логика работы
Глобальный рубильник сетевой подсистемы. При `0` движок перестаёт создавать сокеты и выполнять сетевое разрешение имён, хотя loopback/внутренние соединения кодом всё ещё допускаются. Для обычного сервера это почти всегда аварийная или отладочная настройка, потому что она буквально отключает внешнюю сетевую жизнь процесса.

#### Практические сценарии использования
```
set net_enabled "1" // оставить сетевой стек включённым
```

### net_enable_http
`cvar net_enable_http(булево, "1")`

#### Описание и логика работы
Разрешает принимать HTTP-клиентов на TCP-портах движка. В `sv_master`-ветке код даёт этой переменной значение по умолчанию `1`, а в других HTTPSV-сборках встречается и `0`, поэтому реальный дефолт зависит от цели сборки; в любом случае смысл одинаковый — движок может обслуживать входящие HTTP-запросы и потенциально отдавать крупные файлы. Для игрового сервера это удобство, но и риск: большой HTTP-трафик способен мешать геймплейному трафику, если всё висит на одном порту и одном узком канале.

#### Практические сценарии использования
```
set net_enable_http "0" // не принимать обычные HTTP-запросы на игровом порту
```

### net_enable_qtv
`cvar net_enable_qtv(целое перечисление, "2")`

#### Описание и логика работы
Управляет тем, принимает ли сервер входящие QTV-запросы от прокси и зрителей. `0` полностью запрещает такие соединения, `1` разрешает их всем, `2` ограничивает доступ локальными адресами хоста (`127.*`, `::1`, unix sockets) и потому подходит как безопасный дефолт для машин, где внешнюю публикацию берёт на себя отдельный прокси. Эта переменная важна для инфраструктуры трансляций и записи матчей, а не для обычного игрового трафика.

#### Практические сценарии использования
```
set net_enable_qtv "1" // разрешить внешние QTV-подключения
```

### net_enable_rtcbroker
`cvar net_enable_rtcbroker(булево, "1")`

#### Описание и логика работы
Разрешает принимать websocket-подключения, используемые как брокер для прямых WebRTC/ICE-сеансов. В master-server сборке дефолт равен `1`, а в части других HTTPSV-конфигураций встречается `0`, так что при документировании нужно учитывать профиль сборки. Полезно там, где браузерные клиенты или ICE hole-punching должны находить друг друга через FTE-сервис, но лишние брокерные соединения занимают дескрипторы и создают фоновую нагрузку.

#### Практические сценарии использования
```
set net_enable_rtcbroker "0" // не принимать rtc-broker соединения на обычном матче
```

### net_enable_tls
`cvar net_enable_tls(булево, "1")`

#### Описание и логика работы
Позволяет интерпретировать бинарный поток на обычном TCP-порту как TLS-handshake, то есть поднимать `https`/`wss` поверх того же порта. Это полезно для защищённых веб-клиентов, QTV и сервисных HTTP-эндпоинтов, но только если администратор действительно поддерживает TLS в своей сборке и инфраструктуре сертификатов. Для голого dedicated-сервера без веб-обвязки функция часто просто не нужна.

#### Практические сценарии использования
```
set net_enable_tls "1" // разрешить TLS на сетевых TCP-портах
```

### net_enable_websockets
`cvar net_enable_websockets(булево, "0")`

#### Описание и логика работы
Разрешает websocket-игроков на TCP-портах движка. В `sv_master`-ветке код выставляет `0`, а в части остальных HTTPSV-сборок — `1`, поэтому фактический дефолт зависит от того, для чего собран бинарник; сама семантика не меняется. Нужна прежде всего для web-порта и браузерных клиентов, а на традиционном UDP-only сервере её можно оставить выключенной ради меньшей площади атаки.

#### Практические сценарии использования
```
set net_enable_websockets "1" // впускать websocket-клиентов
```

### net_hybriddualstack
`cvar net_hybriddualstack(булево, "1")`

#### Описание и логика работы
Включает гибридные dual-stack сокеты IPv4+IPv6 там, где платформа это поддерживает. На современном хостинге это облегчает обслуживание обоих стеков с меньшим количеством отдельных биндов, но на очень старых Windows (XP и ниже, согласно комментарию) опция не работает. Для публичного сервера обычно имеет смысл оставить `1`, если нет специальных причин жёстко разнести IPv4 и IPv6.

#### Практические сценарии использования
```
set net_hybriddualstack "1" // слушать IPv4 и IPv6 гибридно
```

### net_ice_allowmdns
`cvar net_ice_allowmdns(булево, "1")`

#### Описание и логика работы
Разрешает использовать multicast-DNS для ICE-кандидатов, чтобы не раскрывать частную адресацию напрямую, а публиковать псевдонимы. При `0` такой механизм отключается, что иногда упрощает отладку, но ухудшает приватность локальной сети. Практически это настройка для WebRTC/ICE-сценариев, а не для обычного UDP-сервера.

#### Практические сценарии использования
```
set net_ice_allowmdns "1" // не отключать mDNS-кандидаты
```

### net_ice_allowstun
`cvar net_ice_allowstun(булево, "1")`

#### Описание и логика работы
Управляет использованием STUN для определения публичного адреса этого узла. Если поставить `0`, движок перестанет получать server-reflexive адреса от внешних STUN-серверов, что может сорвать NAT-traversal, хотя подключение к уже присланным удалённым reflexive-кандидатам код не запрещает. Менять имеет смысл только в среде с жёсткими сетевыми политиками или при детальной диагностике ICE.

#### Практические сценарии использования
```
set net_ice_allowstun "1" // разрешить STUN-обнаружение публичного адреса
```

### net_ice_allowturn
`cvar net_ice_allowturn(булево, "1")`

#### Описание и логика работы
Определяет, может ли движок регистрировать TURN-соединения и использовать релейные кандидаты. Значение `0` отключает попытки получить собственный relay-маршрут, но не мешает подключаться к relay-кандидатам другой стороны. На сервере, который должен пробиваться через сложный NAT или работать с браузерными клиентами, отключение TURN обычно резко снижает шанс успешного соединения.

#### Практические сценарии использования
```
set net_ice_allowturn "1" // разрешить TURN-релей для ICE
```

### net_ice_broker
`cvar net_ice_broker(строка URL, "tls://master.frag-net.com:27950")`

#### Описание и логика работы
Адрес брокера, через который FTE пытается организовывать ICE/RTC-соединения для `sv_public /foo` и `connect /foo`. По сути это координатор hole-punching и обмена кандидатами, поэтому неправильный URL делает красивые slash-адреса недоступными, даже если сам игровой сервер жив. Переменная особенно полезна для собственных мастер/брокер-инсталляций и закрытых экосистем.

#### Практические сценарии использования
```
set net_ice_broker "tls://master.frag-net.com:27950" // использовать стандартный брокер FTE
```

`cvar sv_maxdrate(скорость/целое, "500000")`

#### Описание и логика работы
Ограничивает скорость, с которой сервер отдаёт данные одному клиенту во время скачивания файлов. `0` снимает серверный предел вообще, что вместе с пустым/нулевым клиентским `drate` может привести к очень агрессивной раздаче и фактически к DoS-подобной нагрузке на канал. На публичных серверах это один из главных балансировочных параметров между удобством fast-download и сохранением нормального пинга у играющих.

#### Практические сценарии использования
```
set sv_maxdrate "250000" // урезать скорость скачивания, чтобы не душить матч
```

### sv_maxgames
`cvar sv_maxgames(целое, "100")`

#### Описание и логика работы
Переменная master-server процесса: максимум известных игр/гейм-идентификаторов, которые он хранит. Ограничение введено именно как анти-DoS мера, чтобы злоумышленник не засыпал мастер бесконечным количеством фиктивных «игр». Для обычного игрового сервера эта cvar неактуальна; она нужна операторам собственных каталогов серверов.

#### Практические сценарии использования
```
set sv_maxgames "200" // разрешить мастеру обслуживать больше разных игр
```

### sv_maxrate
`cvar sv_maxrate(скорость/целое, "50000")`

#### Описание и логика работы
Верхний предел байт в секунду, который сервер готов отправлять одному игроку вне режима скачивания. Реальная скорость игрока дополнительно ограничивается его собственным `rate`, поэтому `sv_maxrate` — это именно серверный потолок. Слишком низкое значение вызывает дёрганый апдейт мира и потерю плавности, слишком высокое может ухудшить жизнь клиентам с плохим интернетом и быстрее забить исходящий канал сервера.

#### Практические сценарии использования
```
set sv_maxrate "75000" // слегка поднять потолок игрового трафика
```

### sv_maxservers
`cvar sv_maxservers(целое, "10000")`

#### Описание и логика работы
Переменная из `sv_master.c`: общий максимум серверов, известных мастер-серверу по всем играм сразу. Смысл тот же, что у `sv_maxgames` — защитить каталог от распухания и DoS-спама фейковыми объявлениями. Менять стоит только при эксплуатации собственного крупного master-сервиса.

#### Практические сценарии использования
```
set sv_maxservers "20000" // увеличить общий лимит серверов на мастере
```

### sv_maxtic
`cvar sv_maxtic(дробное, "0.1")`

#### Описание и логика работы
Максимальный интервал между серверными физическими тиками. Слишком маленькое значение заставляет сервер чаще догонять отставание несколькими тик-итерациями подряд, а `0` переводит поведение в фиксированный интервал, что может требоваться для ODE-сценариев. Это одна из фундаментальных настроек темпа симуляции: она влияет и на CPU, и на латентность реакции сервера на накопившееся время.

#### Практические сценарии использования
```
set sv_maxtic "0.05" // делать серверные тики чаще
```

### sv_minping
`cvar sv_minping(целое, "")`

#### Описание и логика работы
Искусственно добавляет задержку игрокам, у которых реальный ping ниже заданного порога. Значение задаётся в миллисекундах и используется как «уравнитель» на некоторых серверах, где хотят сгладить преимущество локальных игроков. Это спорный инструмент: он действительно меняет сетевое ощущение игры и ухудшает отзывчивость, поэтому применять его стоит только осознанно.

#### Практические сценарии использования
```
set sv_minping "30" // добавить минимум 30 мс самым близким игрокам
```

### sv_mintic
`cvar sv_mintic(дробное, "0.013")`

#### Описание и логика работы
Минимальный интервал между физическими тиками сервера. В dedicated/server-only варианте исходник задаёт `0.013`, а в некоторых клиентских сборках встречается `0`, чтобы локальная сторона могла думать без ограничения; для серверной документации основной ориентир — именно `0.013`. Уменьшение повышает частоту симуляции и сетевых обновлений, но напрямую увеличивает нагрузку на CPU и канал.

#### Практические сценарии использования
```
set sv_mintic "0.013" // оставить стандартную минимальную длительность тика
```

### sv_nailhack
`cvar sv_nailhack(булево, "1")`

#### Описание и логика работы
Переключает историческую сетевую оптимизацию nail-энтити. При `1`, согласно описанию, оптимизация отключается — это совместимо с привычками Qizmo, улучшает интерполяцию полёта гвоздей у клиентов и позволяет рисовать трейлы, но меняет сетевое представление этих объектов. Переменная полезна прежде всего для QuakeWorld-совместимых сценариев и старых модов, где nail-projectiles активно используются.

#### Практические сценарии использования
```
set sv_nailhack "1" // использовать совместимый режим передачи nail-снарядов
```

### sv_playerslots
`cvar sv_playerslots(целое или пусто, "")`

#### Описание и логика работы
Общий лимит слотов игроков, зрителей и ботов; в коде отмечено, что новое значение применяется со следующей карты и может привести к кикам, а alias `maxplayers` используется для совместимости. Рекомендация исходника — держать число примерно равным `maxclients + maxspectators`. С практической стороны это важный потолок протокольной ёмкости сервера: нестандартные значения и особенно числа выше 16/32 ухудшают совместимость со старыми NQ/QW-клиентами.

#### Практические сценарии использования
```
set sv_playerslots "24" // зарезервировать 24 общих слота на сервере
```

### sv_protocol
`cvar sv_protocol(строка списка, "")`

#### Описание и логика работы
Форсирует конкретные расширения сетевого протокола: исходник перечисляет `fte1`, `fte2`, `csqc`. Если клиент не поддерживает указанный набор, его выкинет ещё на входе. Переменная нужна для серверов, которые сознательно опираются на расширенные функции FTE и предпочитают жёсткую проверку совместимости вместо расплывчатых деградаций.

#### Практические сценарии использования
```
set sv_protocol "fte1 fte2" // требовать базовые расширения FTE
```

### sv_public
`cvar sv_public(целое перечисление, "0")`

#### Описание и логика работы
Главный переключатель публичности сервера. `-1` полностью блокирует входящие подключения, `0` оставляет сервер частным/LAN-only без подписки на мастер, `1` публикует адрес на публичных master-серверах; в ICE/Web-сборках есть и режим `2`, где сервер публикуется через broker для hole-punching. Ошибочная настройка здесь — одна из самых частых причин, почему сервер либо внезапно исчезает из браузера, либо наоборот светится в интернете, когда этого не хотели.

#### Практические сценарии использования
```
set sv_public "1" // опубликовать сервер на мастер-серверах
```

### sv_rconlim
`cvar sv_rconlim(целое, "4")`

#### Описание и логика работы
Ограничивает повторные невалидные попытки `rcon`. Небольшие значения уменьшают окно для перебора пароля, но могут случайно задеть администратора, который несколько раз ошибся подряд; слишком мягкие значения почти не мешают brute-force. Это одна из обязательных защит публичного dedicated-сервера, если `rcon_password` вообще используется.

#### Практические сценарии использования
```
set sv_rconlim "4" // оставить умеренный лимит на неверный rcon
```

### sv_reconnectlimit
`cvar sv_reconnectlimit(целое, "0")`

#### Описание и логика работы
Не даёт одному и тому же адресу/порту мгновенно переподключаться в течение заданного времени. Ноль отключает ограничение, положительное значение защищает от части спама переподключениями и помогает не переиспользовать ещё «зомбифицированный» слот слишком рано. Слишком большой интервал раздражает игроков с нестабильной связью, слишком маленький почти не защищает от дёрганья connect/disconnect.

#### Практические сценарии использования
```
set sv_reconnectlimit "3" // запретить мгновенные повторные входы
```

### sv_reliable_sound
`cvar sv_reliable_sound(булево, "0")`

#### Описание и логика работы
Переводит отправку звуков в надёжный канал, чтобы packet loss не съедал важные аудио-события. Цена — задержка и более «пачечная» доставка, то есть звук приходит надёжнее, но не так своевременно; кроме того, отдельные клиенты могут переопределять поведение через userinfo `rsnd`. Полезно на сервере с действительно плохими каналами или критичными звуковыми сигналами, но не всегда хорошо ощущается в динамичном дуэльном геймплее.

#### Практические сценарии использования
```
set sv_reliable_sound "1" // посылать звуки надёжно
```

### sv_reportheartbeats
`cvar sv_reportheartbeats(целое перечисление, "2")`

#### Описание и логика работы
Управляет тем, насколько многословно сервер сообщает об отправке heartbeat на мастер. При `1` уведомления идут каждый раз, при `2` сообщение показывается один раз, а `0` фактически делает процесс тихим. Это диагностическая, а не протокольная переменная: полезна, когда вы настраиваете публикацию сервера и хотите убедиться, что heartbeat действительно уходит.

#### Практические сценарии использования
```
set sv_reportheartbeats "1" // печатать heartbeat-сообщения в консоль
```

### sv_serverip
`cvar sv_serverip(строка адреса, "")`

#### Описание и логика работы
Ручной внешний адрес сервера, который движок должен объявлять, если сам не может надёжно определить публичный IP за NAT/фаерволом. Если NAT ещё и ремапит порт, его тоже нужно указать в строке. Это один из самых практичных параметров при хостинге из домашней сети: без него мастер-сервер может раздавать клиентам бесполезный внутренний адрес.

#### Практические сценарии использования
```
set sv_serverip "203.0.113.10:27500" // сообщать наружу правильный публичный адрес
```

### sv_slaverequery
`cvar sv_slaverequery(целое, "120")`

#### Описание и логика работы
Переменная master-сервера: как часто он заново опрашивает slave-master узлы. Большие значения уменьшают фоновый трафик между каталогами, но обновляют агрегированные списки медленнее; слишком маленькие добавляют лишнюю сетевую болтовню. Нужна только тем, кто эксплуатирует распределённую систему мастер-серверов на базе FTE.

#### Практические сценарии использования
```
set sv_slaverequery "120" // переопрашивать slave-master раз в 120 секунд
```

### sv_timestamplen
`cvar sv_timestamplen(целое, "60")`

#### Описание и логика работы
Хотя внутренняя переменная называется `sv_crypt_rcon_clockskew`, наружу экспортируется именно `sv_timestamplen`: она ограничивает допустимый сдвиг часов для снижения delayed replay-атак на hashed rcon. Меньшее окно усиливает защиту, но повышает шанс отказа при рассинхронизации времени у клиента-админа; большее — удобнее, но мягче к повтору захваченных пакетов. Работает в паре с `sv_crypt_rcon`.

#### Практические сценарии использования
```
set sv_timestamplen "30" // сузить окно допустимого clock skew для rcon
```

### sv_use_dns
`cvar sv_use_dns(булево/строка, "")`

#### Описание и логика работы
Включает reverse-DNS lookup, чтобы сервер мог показывать более читаемую информацию о том, откуда подключаются клиенты. Полезно для логов, администрирования и некоторых бан-политик, но добавляет стоимость DNS-разрешения и иногда задерживает диагностические выводы. На чисто производительном публичном сервере часто оставляют выключенным, а на админских/комьюнити серверах — включают ради удобства.

#### Практические сценарии использования
```
set sv_use_dns "1" // показывать хостнеймы клиентов в логах
```

### teamplay
`cvar teamplay(целое, "")`

#### Описание и логика работы
Классическая `serverinfo`-переменная командного режима. Пустое значение оставляет поведение за модом или конфигом, ненулевые значения обычно выбирают конкретный вариант teamplay-правил. Для сетевого окружения она важна не только логикой матча, но и тем, как сервер помечается в браузерах и MVD-автоименовании.

#### Практические сценарии использования
```
set teamplay "1" // включить командный режим
```

### timelimit
`cvar timelimit(целое, "")`

#### Описание и логика работы
Лимит времени на карту/раунд, экспортируемый через `serverinfo`. Пустая строка обычно означает бесконечную карту, а положительное число завершает матч по таймеру. Это одна из базовых сетевых настроек публичных ротаций и турнирных конфигов.

#### Практические сценарии использования
```
set timelimit "20" // ограничить карту двадцатью минутами
```

### timeout
`cvar timeout(целое, "65")`

#### Описание и логика работы
Глобальный сетевой таймаут: если от соединения не приходит ни одного пакета дольше указанного числа секунд, оно считается умершим. Слишком низкое значение агрессивно выбрасывает клиентов с плавающим интернетом, слишком высокое — заставляет сервер дольше держать мёртвые подключения и слоты. На практике именно с `timeout` связана грань между «терпимостью к лагам» и скоростью очистки зависших клиентов.

#### Практические сценарии использования
```
set timeout "65" // держать стандартный таймаут соединений
```

### zombietime
`cvar zombietime(целое, "2")`

#### Описание и логика работы
Сколько секунд сервер не переиспользует клиентский слот после разрыва, пока «досасывает» поздние пакеты и хвосты состояния. Малое значение ускоряет освобождение мест, но повышает риск коллизий при мгновенном переподключении; большое — делает сервер более аккуратным к сетевому мусору, но медленнее возвращает слоты в пул. Работает вместе с `sv_reconnectlimit`, хотя решает чуть другую задачу.

#### Практические сценарии использования
```
set zombietime "2" // оставить короткое зомби-окно для слота
```
