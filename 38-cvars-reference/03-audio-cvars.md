Этот раздел собирает звуковые cvar, которые реально объявлены в звуковых модулях FTEQW и управляют выводом аудио, музыкальным проигрывателем, захватом звука и связанными подсистемами. Если у переменной нет встроенной подсказки, ниже дано практическое толкование по контексту её работы.

## Переменные

### capturesound
`cvar capturesound(int, "1")`

#### Описание и логика работы
Включает запись звуковой дорожки при использовании подсистемы захвата. В исходнике отдельно отмечено, что переменная позволяет захватывать game voice, а вне [`capturedemo`](../44-cli-commands-reference/02-client-ui-commands.md#capturedemo) её можно сочетать с `cl_voip_test` для записи собственного голоса. Практически это переключатель `0/1`: при `0` аудиодорожка не создаётся, при `1` движок пытается писать звук с частотой активного микшера или с запасным значением 48000 Гц. Флаг `CVAR_ARCHIVE` не задан, поэтому значение не относится к автоматически архивируемым. [`snd_restart`](../44-cli-commands-reference/03-rendering-sound-commands.md#snd_restart) не нужен; если запись уже идёт, надёжнее остановить и заново запустить capture/capturedemo.

#### Практические сценарии использования
```cfg
seta capturesound "1" // записывать звуковую дорожку вместе с захватом
```

---

### capturesoundbits
`cvar capturesoundbits(int, "16")`

#### Описание и логика работы
Задаёт разрядность записываемого звука для подсистемы захвата. По коду значение напрямую передаётся как `sndbits`, поэтому практически имеет смысл использовать стандартные целые значения вроде `16`; экзотические числа зависят от возможностей конкретного драйвера/кодека захвата. Переменная не архивируется. `snd_restart` не нужен, но на уже идущую запись изменение обычно не влияет до её перезапуска.

#### Практические сценарии использования
```cfg
seta capturesoundbits "16" // стандартная 16-битная звуковая дорожка
```

---

### capturesoundchannels
`cvar capturesoundchannels(int, "2")`

#### Описание и логика работы
Определяет число каналов в аудиодорожке захвата. Значение читается при подготовке параметров записи и обычно используется как `1` для моно или `2` для стерео; более высокие значения теоретически возможны только если их поддержит путь захвата. Переменная не архивируется. `snd_restart` не нужен, однако для уже начатой записи изменение обычно применяется только после нового запуска capture/capturedemo.

#### Практические сценарии использования
```cfg
seta capturesoundchannels "2" // писать стерео-дорожку
```

---

### cl_voip_capturedevice
`cvar cl_voip_capturedevice(string, "")`

#### Описание и логика работы
Выбирает устройство захвата для VOIP. Строка разбирается как токены формата `driver:device`; если строка пуста или ни один вариант не подошёл, движок пробует первое доступное устройство автоматически. Переменная архивируется (`CVAR_ARCHIVE`), так что выбор микрофона можно сохранить в конфиге. `snd_restart` не требуется: параметр важен для инициализации контекста захвата, поэтому на практике достаточно выключить и снова включить передачу голоса или `cl_voip_test`, чтобы движок заново открыл устройство.

#### Практические сценарии использования
```cfg
seta cl_voip_capturedevice "wasapi:Microphone Array" // явно выбрать микрофон для голосового чата
```

---

### cl_voip_send
`cvar cl_voip_send(int, "0")`

#### Описание и логика работы
Управляет режимом отправки голосового трафика. Значения заданы прямо в строке описания: `0` — передавать голос только при [`+voip`](../44-cli-commands-reference/03-rendering-sound-commands.md#voip), `1` — voice activation, `2` — постоянная передача, `+4` — не отправлять звук в игровую часть, а только в RTP-сессии. Это именно битово-режимная переменная, поэтому встречаются комбинации вроде `6` (`2+4`). Переменная архивируется и дополнительно помечена `CVAR_NOTFROMSERVER`, то есть сервер не должен навязывать её клиенту. Изменение действует без `snd_restart`.

#### Практические сценарии использования
```cfg
seta cl_voip_send "1" // включить голосовую активацию вместо кнопки +voip
```

---

### cl_voip_test
`cvar cl_voip_test(int, "0")`

#### Описание и логика работы
Локальный тест микрофона: при `1` движок воспроизводит ваш голос напрямую, минуя сервер и сетевую задержку. Это удобно для проверки уровня сигнала и выбора устройства, но не отражает реальное сетевое качество; для эха через сервер в описании упомянут `sv_voip_echo`. Переменная не архивируется. `snd_restart` не нужен; переключение работает на лету.

#### Практические сценарии использования
```cfg
seta cl_voip_test "1" // быстро проверить, слышит ли движок микрофон
```

---

### cl_voip_vad_delay
`cvar cl_voip_vad_delay(float, "0.3")`

#### Описание и логика работы
Определяет, сколько секунд VOIP продолжает передаваться после того, как голосовая активация перестала срабатывать. По коду значение умножается на частоту кодека и превращается в запас сэмплов, поэтому разумный диапазон — небольшие положительные дробные числа. Меньшие значения быстрее обрывают хвосты фраз, большие — уменьшают риск «съедания» окончаний слов ценой лишнего трафика. Переменная не архивируется. Применяется без `snd_restart`.

#### Практические сценарии использования
```cfg
seta cl_voip_vad_delay "0.5" // чуть дольше удерживать передачу после окончания речи
```

---

### cl_voip_vad_threshhold
`cvar cl_voip_vad_threshhold(int, "15")`

#### Описание и логика работы
Порог voice-activation-detection для исходящего VOIP. В коде текущий уровень речи сравнивается с этим числом; если уровень ниже порога и вы не держите `+voip`, звук может быть отброшен. Низкие значения делают активацию чувствительнее, высокие уменьшают ложные срабатывания от шума, но могут отсекать тихую речь. Переменная архивируется (`CVAR_ARCHIVE`). `snd_restart` не нужен.

#### Практические сценарии использования
```cfg
seta cl_voip_vad_threshhold "10" // срабатывать даже на более тихую речь
```

### mastervolume
`cvar mastervolume(float, "1")`

#### Описание и логика работы
Общий дополнительный множитель для всех остальных звуков. По коду он участвует в масштабировании обычного звука и VOIP-воспроизведения, так что это именно «мастер»-уровень поверх частных регуляторов. Значение `1` оставляет уровни как есть, `0` фактически глушит звук, значения выше `1` усиливают сигнал и могут привести к перегрузке на слух. Переменная архивируется (`CVAR_ARCHIVE`) и применяется без `snd_restart`.

#### Практические сценарии использования
```cfg
seta mastervolume "0.8" // немного приглушить весь звук целиком
```

### media_hijackwinamp
`cvar media_hijackwinamp(int, "0")`

#### Описание и логика работы
Переключатель интеграции с Winamp в сборках, где эта поддержка включена. По имени и использованию в коде переменная позволяет движку «перехватывать» управление внешним Winamp-источником вместо полностью автономного воспроизведения треков. Практически это опция `0/1`; вне Winamp-enabled сборок её может не быть вовсе. Переменная не архивируется. `snd_restart` не нужен, изменение относится к медиаплееру и применяется на лету.

#### Практические сценарии использования
```cfg
seta media_hijackwinamp "1" // разрешить движку управлять воспроизведением через Winamp
```

### media_repeat
`cvar media_repeat(int, "1")`

#### Описание и логика работы
Определяет, должен ли медиаплеер продолжать воспроизведение после достижения конца списка. При `1` список зацикливается, при `0` воспроизведение может остановиться на последнем треке. В режиме случайного выбора (`media_shuffle 1`) значение остаётся вторичным: интерфейс явно показывает его в скобках, то есть смысл параметра там менее прямой, чем в последовательном режиме. Переменная не архивируется, `snd_restart` не нужен.

#### Практические сценарии использования
```cfg
seta media_repeat "0" // остановиться после последнего трека плейлиста
```

---

### media_shuffle
`cvar media_shuffle(int, "1")`

#### Описание и логика работы
Включает случайный выбор следующего трека в медиаплеере. При `1` движок выбирает следующую композицию случайно, при `0` идёт по списку последовательно. Это влияет только на логику музыкального плейлиста и не требует перезапуска звука. Переменная не архивируется и применяется сразу.

#### Практические сценарии использования
```cfg
seta media_shuffle "0" // проигрывать плейлист по порядку
```

### music_fade
`cvar music_fade(int, "1")`

#### Описание и логика работы
Управляет плавным затуханием музыки при смене трека. В коде используется целочисленная проверка, поэтому на практике это переключатель `0/1`: при ненулевом значении запускается fade-out перед подменой текущей композиции, при `0` переключение происходит жёстче. Переменная не архивируется. `snd_restart` не нужен, потому что она читается в логике переключения музыкального трека.

#### Практические сценарии использования
```cfg
seta music_fade "1" // включить мягкое затухание при смене музыки
```

### music_playlist_index
`cvar music_playlist_index(int, "-1")`

#### Описание и логика работы
Индекс совместимого cvar-плейлиста для музыкальной подсистемы. При значении `-1` этот слой логики фактически отключён; при `0` и выше движок ищет динамические переменные вида `music_playlist_listN` и `music_playlist_samplepositionN`, чтобы выбрать трек и позицию продолжения. Это нишевая, но практичная compatibility-переменная для внешних меню, модов и сценариев, которые собирают плейлист через cvar. Она не архивируется и не требует `snd_restart`.

#### Практические сценарии использования
```cfg
seta music_playlist_index "0" // использовать первый cvar-плейлист совместимого формата
```

### nosound
`cvar nosound(int, "0")`

#### Описание и логика работы
Полностью отключает звук в движке. Значение `0` оставляет подсистему активной, `1` запрещает вывод звука; кроме того, если параметр был задан через командную строку `-nosound`, исходник принудительно фиксирует cvar и не даёт конфигам вернуть звук обратно. Переменная архивируется (`CVAR_ARCHIVE`), но её поведение при запуске от аргумента командной строки важнее сохранённого значения. В обычной сессии переключение используется без `snd_restart`; если движок стартовал с жёстким `-nosound`, вернуть звук без нового запуска нельзя.

#### Практические сценарии использования
```cfg
seta nosound "1" // полностью заглушить аудиоподсистему движка
```

### s_al_debug
`cvar s_al_debug(int, "0")`

#### Описание и логика работы
Включает периодические проверки ошибок OpenAL. Это диагностическая, но вполне практичная переменная: при `1` движок начинает регулярно вызывать проверку состояния OpenAL и печатать найденные проблемы, что полезно при разборе пропавшего звука, глючных драйверов или нестабильных эффектов. Переменная не архивируется. Так как она проверяется прямо во время работы, `snd_restart` не нужен.

#### Практические сценарии использования
```cfg
seta s_al_debug "1" // включить диагностику ошибок OpenAL
```

---

### s_al_disable
`cvar s_al_disable(int, "0")`

#### Описание и логика работы
Управляет использованием OpenAL как выходного бэкенда. Значения определены в самом описании: `0` — OpenAL разрешён и обычно имеет высокий приоритет, `1` — OpenAL используется только при явном выборе устройства, `2` — полностью запретить OpenAL. Это полезно, если нужно обойти ограничения или баги сторонней OpenAL-реализации и заставить движок откатиться на платформенный вывод. В обычных сборках исходник задаёт значение по умолчанию `0`, а в web-целях — `1`. Переменная не архивируется. Для уже открытого аудиоустройства практически нужен `snd_restart`.

#### Практические сценарии использования
```cfg
seta s_al_disable "2" // принудительно не использовать OpenAL
```

### s_al_hrtf
`cvar s_al_hrtf(string, "")`

#### Описание и логика работы
Настраивает HRTF в OpenAL. Пустая строка означает авто-режим по конфигурации OpenAL, строка `0` принудительно отключает HRTF, `1` включает стандартную таблицу, а также можно указать конкретное имя HRTF-профиля, если драйвер возвращает такие варианты. Это удобно для наушников и позиционного аудио, но эффект зависит от реализации OpenAL и доступных таблиц. Переменная не архивируется. Так как HRTF выбирается при создании OpenAL-устройства, для надёжного применения нужен `snd_restart`.

#### Практические сценарии использования
```cfg
seta s_al_hrtf "1" // включить HRTF по умолчанию для OpenAL
```

### s_al_reference_distance
`cvar s_al_reference_distance(float, "120")`

#### Описание и логика работы
Опорная дистанция для моделей затухания OpenAL, при которой звук считается слышимым с «нормальной» громкостью. Меньшие значения делают близкие источники заметно громче и усиливают падение уровня с расстоянием, большие — растягивают слышимую зону. Переменная особенно важна при OpenAL-режимах с обратным или квазиреалистичным затуханием. Она не архивируется. По коду используется во время настройки источников, поэтому обычно меняется без `snd_restart`, хотя для полной предсказуемости уже играющих сцен иногда удобнее выполнить его вручную.

#### Практические сценарии использования
```cfg
seta s_al_reference_distance "90" // сделать падение громкости более заметным на ближней дистанции
```

### s_al_use_reverb
`cvar s_al_use_reverb(int, "1")`

#### Описание и логика работы
Разрешает или блокирует использование реверберации в OpenAL. Значение `0` полностью запрещает реверб-эффекты, `1` оставляет их доступными; в описании прямо сказано, что кроме подводного случая свойства реверба должны приходить из gamecode. Это полезный выключатель на случай несовместимых драйверов, лишней нагрузки или нежелательного эффекта. Переменная не архивируется. Поскольку слот эффектов создаётся на этапе инициализации OpenAL, для надёжного применения лучше делать `snd_restart`.

#### Практические сценарии использования
```cfg
seta s_al_use_reverb "0" // отключить реверберацию OpenAL
```

### s_al_velocityscale
`cvar s_al_velocityscale(float, "1")`

#### Описание и логика работы
Масштабирует значения скорости перед расчётом допплер-эффекта в OpenAL. `1` оставляет штатное поведение, меньшие значения смягчают эффект, большие — усиливают его. Параметр полезен, когда игровые единицы скорости плохо совпадают с ожидаемой шкалой OpenAL и высота тона меняется слишком слабо или слишком агрессивно. Переменная не архивируется и обычно применяется без `snd_restart`.

#### Практические сценарии использования
```cfg
seta s_al_velocityscale "0.5" // ослабить допплер при быстрых перемещениях
```

### snd_ignorecueloops
`cvar snd_ignorecueloops(int, "0")`

#### Описание и логика работы
Игнорирует cue-команды в WAV-файлах ради совместимости с Quake 3-подобным контентом. При `0` движок может учитывать встроенные cue/loop-метки, при `1` — обходить их и трактовать файл как обычный звук без таких подсказок. Это узкоспециализированная, но практичная compatibility-настройка для проблемных наборов ассетов. Переменная не архивируется. Она влияет прежде всего на интерпретацию загружаемых WAV, поэтому для уже закешированных звуков может понадобиться `snd_restart` или повторная загрузка ресурса.

#### Практические сценарии использования
```cfg
seta snd_ignorecueloops "1" // не учитывать loop/cue-метки в wav-ассетах
```

### snd_ignoregamespeed
`cvar snd_ignoregamespeed(int, "0")`

#### Описание и логика работы
Позволяет звуку не подстраиваться под игровую скорость и скорость демо. В коде именно эта cvar решает, будет ли к глобальному playback rate домножаться текущий `gamespeed` и [`cl_demospeed`](07-system-misc-cvars.md#cl_demospeed). При `0` звук синхронизируется с замедлением/ускорением игры, при `1` новые звуки могут воспроизводиться в обычном темпе и тем самым расходиться с временем игры или демо. Переменная не архивируется и действует без `snd_restart`.

#### Практические сценарии использования
```cfg
seta snd_ignoregamespeed "1" // не искажать звук при изменении скорости игры или демо
```

### snd_loadasstereo
`cvar snd_loadasstereo(int, "0")`

#### Описание и логика работы
Заставляет моно-звуки загружаться как стерео. Сам исходник прямо предупреждает, что это обычно не полезно и лишь тратит память, но настройка может пригодиться для экспериментов с контентом, тестов микшера или отладки необычных проблем с каналами. Типичный режим — `0/1`. Переменная не архивируется. Влияет на момент загрузки звука, поэтому для уже загруженных ассетов изменение само по себе не поможет; обычно нужен `snd_restart` или повторная загрузка материалов.

#### Практические сценарии использования

seta s_mixahead "0.1" // вернуть/установить значение по умолчанию

Значение по умолчанию — `"0"`. Как и для большинства cvar движка, изменение вступает в силу немедленно, если явно не сказано иное в описании выше; для видео- и рендер-зависимых переменных иногда требуется `vid_restart` или `vid_reload`.

#### Практическое использование
```cfg
seta tls_ignorecertificateerrors "0" // вернуть/установить значение по умолчанию
```
