> [⬅ Вернуться к оглавлению вики](../README.md)

Эта страница собирает строковые builtin-функции QuakeC, которые чаще всего используются для парсинга аргументов, форматирования текста, работы с цветовым markup и безопасной сборки команд. Для каждого builtin ниже указана сигнатура из `fteextensions.qc`, затем разобрано фактическое поведение с учётом комментариев и проверок по реализации движка. Там, где функция исторически устарела или дублируется в других VM-категориях, это отдельно оговорено.

## Функции

### strlen
`float(string s) strlen = #114;`

* **s** — строка, длину которой нужно получить.

#### Описание и логика работы
`strlen` возвращает длину строки в символах. В обычном 8-битном режиме это просто количество байтов до завершающего нуля, а при включённом UTF-8 движок считает именно символы, а не байты, поэтому кириллица и прочие многобайтные знаки не раздувают результат. Пустая строка даёт `0`. Цветовой markup и управляющие последовательности не скрываются: если они физически присутствуют в строке, `strlen` их тоже считает. Для визуальной длины текста без цветов нужен `strlennocol`.

#### Практические сценарии использования
```qc
void Demo_strlen()
{
	local string plain;
	local string coloured;

	plain = "quake";
	coloured = "^1Red ^7White";

	dprint(sprintf("plain=%g\n", strlen(plain)));       // 5
	dprint(sprintf("raw=%g\n", strlen(coloured)));      // считает и markup тоже
	dprint(sprintf("visible=%g\n", strlennocol(coloured)));
}
```

### strlennocol
`float(string s) strlennocol = #476;`

* **s** — строка с цветовым markup или управляющими кодами.

#### Описание и логика работы
`strlennocol` считает видимую длину текста после разбора цветовых кодов и другого текстового markup, который не занимает место на экране. Это ключевое отличие от `strlen`: `strlen("^1ABC")` считает сырые символы строки, а `strlennocol` вернёт длину того, что реально увидит игрок. Для пустой строки результат равен `0`. Функция полезна при выравнивании HUD-текста и проверке лимитов на отображаемую длину, когда цветовые префиксы не должны искажать расчёты.

#### Практические сценарии использования
```qc
void Demo_strlennocol()
{
	local string nick;

	nick = "^2Player^7_01";

	if (strlennocol(nick) > 10)
		dprint("Nickname is visually too long\n");
	else
		dprint("Nickname fits in the column\n");
}
```

### strcat
`string(string s1, optional string s2, optional string s3, optional string s4, optional string s5, optional string s6, optional string s7, optional string s8) strcat = #115;`

* **s1** — первая часть итоговой строки.
* **s2** — вторая часть, необязательная.
* **s3** — третья часть, необязательная.
* **s4** — четвёртая часть, необязательная.
* **s5** — пятая часть, необязательная.
* **s6** — шестая часть, необязательная.
* **s7** — седьмая часть, необязательная.
* **s8** — восьмая часть, необязательная.

#### Описание и логика работы
`strcat` просто склеивает до восьми строк в одну tempstring. Никакие разделители автоматически не вставляются: если нужен пробел, двоеточие или перевод строки, их надо передать отдельными аргументами. Пустые аргументы допустимы и просто ничего не добавляют. В FTEQW результат живёт как обычная временная строка движка, поэтому функцию удобно использовать для быстрых сообщений, путей и команд. В отличие от исторического `strzone`, дополнительного освобождения результат не требует.

#### Практические сценарии использования
```qc
void Demo_strcat()
{
	local string mapname;
	local string msg;

	mapname = "start";
	msg = strcat("Loading map: ", mapname, "\n");

	dprint(msg);
	localcmd(strcat("map ", mapname, "\n"));
}
```

### substring
`string(string s, float start, float length) substring = #116;`

* **s** — исходная строка.
* **start** — начальная позиция, нумерация с нуля.
* **length** — длина вырезаемого фрагмента.

#### Описание и логика работы
`substring` возвращает часть строки как tempstring. Позиция `start` отсчитывается от начала строки с нуля, а при отрицательном значении — от конца: `-1` означает последний символ, `-2` предпоследний и так далее. Если `length` отрицательная, движок трактует её как «взять до конца, но отбросить указанное число символов с хвоста»: например, `substring("abcdef", 1, -2)` даёт `"bcde"`, а `substring("abcdef", -3, -1)` даёт `"def"`. Если `start` уходит левее начала, он зажимается к `0`; если `start` уже за концом строки или итоговая длина оказывается неположительной, возвращается пустая строка. При включённом UTF-8 `start` и `length` считаются в символах, а не в байтах.

#### Практические сценарии использования
```qc
void Demo_substring()
{
	local string path;
	local string ext;
	local string basename;

	path = "maps/e1m1.bsp";
	ext = substring(path, -4, 4);          // ".bsp"
	basename = substring(path, 5, -5);    // "e1m1"

	dprint(sprintf("ext=%s name=%s\n", ext, basename));
}
```

### stov
`vector(string s) stov = #117;`

* **s** — строка с числовыми компонентами вектора.

#### Описание и логика работы
`stov` преобразует строку в `vector`, читая до трёх чисел слева направо. Перед первым числом допускаются пробелы и табы; ведущая одинарная кавычка `'` тоже игнорируется, поэтому строка в формате [`vtos`](01-math-vector-builtins.md#vtos) вида `"'1 2 3'"` разбирается корректно. Как только парсер встречает нечисловой компонент, разбор останавливается, а все не прочитанные координаты остаются равными нулю. Пустая строка и явно нечисловой ввод дают вектор `'0 0 0'`. Это простой текстовый парсер, а не полноценный валидатор формата.

#### Практические сценарии использования
```qc
void Demo_stov()
{
	local string saved_origin;
	local vector org;

	saved_origin = "'128 64 24'";
	org = stov(saved_origin);

	dprint(sprintf("origin=%v\n", org));
}
```

### strzone
`string(string s, ...) strzone = #118;`

* **s** — первая строка для копирования.
* **...** — дополнительные строки, которые тоже будут склеены в результат.

#### Описание и логика работы
`strzone` — исторический builtin из эпохи, когда модам приходилось вручную удерживать строку в памяти дольше обычной tempstring. В современных FTEQW он объявлен как устаревший и для совместимости ведёт себя так же, как `strcat`: склеивает аргументы и возвращает обычную временную строку. Поэтому различия между `strzone` и `strcat` в FTEQW практически нет, а освобождать результат через `strunzone` уже не требуется. Документировать его всё равно важно, потому что старый код QuakeC встречается часто.

#### Практические сценарии использования
```qc
void Demo_strzone()
{
	local string cached;

	// В FTEQW это фактически тот же strcat.
	cached = strzone("player/", "wizard", ".cfg");
	dprint(sprintf("path=%s\n", cached));
}
```

### strunzone
`void(string s) strunzone = #119;`

* **s** — строка, ранее полученная из `strzone` в старых движках.

#### Описание и логика работы
`strunzone` исторически должен был освобождать строку, выделенную `strzone`. В FTEQW builtin оставлен только ради совместимости со старым кодом и теперь ничего не делает. Это значит, что существующие вызовы не ломаются, но и практической пользы в современном FTEQW от них нет. Если вы пишете новый код, используйте обычные tempstring-операции и не стройте логику на ручном освобождении строк.

#### Практические сценарии использования
```qc
void Demo_strunzone()
{
	local string legacy;

	legacy = strzone("legacy value");
	dprint(legacy);

	// Для старого кода вызов безопасен, но в FTEQW он пустой.
	strunzone(legacy);
}
```

### strcasecmp
`float(string s1, string s2) strcasecmp = #229;`

* **s1** — первая сравниваемая строка.
* **s2** — вторая сравниваемая строка.

#### Описание и логика работы
`strcasecmp` сравнивает две строки без учёта регистра. Если строки эквивалентны, результат равен `0`; если нет, возвращается отрицательное или положительное число в стиле стандартных C-сравнений, но опираться имеет смысл только на факт равенства или неравенства. Пустые строки сравниваются нормально, а регистр букв игнорируется для всей строки целиком. Это наиболее удобный builtin для команд, ключей и имён, где пользователь может вводить `QUIT`, `quit` и `Quit` вперемешку.

#### Практические сценарии использования
```qc
void Demo_strcasecmp()
{
	local string cmd;

	cmd = argv(0);
	if (!strcasecmp(cmd, "reload"))
		dprint("Command recognized case-insensitively\n");
}
```

### strncasecmp
`float(string s1, string s2, float len, optional float s1ofs, optional float s2ofs) strncasecmp = #230;`

* **s1** — первая строка.
* **s2** — вторая строка.
* **len** — сколько символов сравнивать максимум.
* **s1ofs** — необязательное смещение в первой строке.
* **s2ofs** — необязательное смещение во второй строке.

#### Описание и логика работы
`strncasecmp` делает то же самое, что `strcasecmp`, но сравнивает только ограниченный фрагмент и умеет стартовать не с начала строк. Если результат равен `0`, выбранные диапазоны эквивалентны без учёта регистра. Смещения задаются в символах; при UTF-8 движок переводит их из символьных позиций в байтовые самостоятельно. Если смещение выходит за конец строки или отрицательно в не-UTF8 режиме, оно фактически зажимается к концу строки, так что сравнение быстро сведётся к пустому хвосту. Это удобно для проверки префиксов и подстрок без создания `substring`.

#### Практические сценарии использования
```qc
void Demo_strncasecmp()
{
	local string line;

	line = "Map e1m2";
	if (!strncasecmp(line, "map", 3, 0, 0))
		dprint("String starts with map\n");
}
```

### strncmp
`float(string s1, string s2, optional float len, optional float s1ofs, optional float s2ofs) strncmp = #228;`

* **s1** — первая строка.
* **s2** — вторая строка.
* **len** — необязательное ограничение по длине сравнения.
* **s1ofs** — необязательное смещение в первой строке.
* **s2ofs** — необязательное смещение во второй строке.

#### Описание и логика работы
`strncmp` выполняет регистрозависимое сравнение строк. Если `len` не передан, builtin ведёт себя как обычный `strcmp`: возвращает `0` при полном совпадении, отрицательное число если `s1` «меньше», и положительное если `s1` «больше». Если `len` указан, сравниваются только первые `len` символов, причём `s1ofs` позволяет начать сравнение с середины `s1`. В комментарии к декларации указаны оба смещения, но текущая реализация FTEQW надёжно применяет только `s1ofs`; параметр `s2ofs` в case-sensitive ветке лучше считать непереносимым и не закладывать в критичную логику. Для нечувствительного к регистру варианта используйте `strncasecmp`.

#### Практические сценарии использования
```qc
void Demo_strncmp()
{
	local string path;

	path = "maps/start.bsp";
	if (!strncmp(path, "maps/", 5, 0, 0))
		dprint("Path is inside maps directory\n");
}
```

### strstrofs
`float(string s1, string sub, optional float startidx) strstrofs = #221;`

* **s1** — строка, в которой ведётся поиск.
* **sub** — искомая подстрока.
* **startidx** — необязательное смещение, до которого совпадения игнорируются.

#### Описание и логика работы
`strstrofs` возвращает нулевое смещение первого найденного вхождения `sub` внутри `s1` или `-1`, если подстрока не найдена. Это аналог `strstr`, но без создания нового хвостового tempstring: на выходе вы получаете именно индекс. `startidx` позволяет пропустить первую часть строки и искать дальше; полезное значение здесь неотрицательное, а явный выход за пределы исходной строки даёт `-1`. При UTF-8 возвращаемый индекс считается в символах, а не в байтах. Для получения самого куска после индекса обычно комбинируют `strstrofs` и `substring`.

#### Практические сценарии использования
```qc
void Demo_strstrofs()
{
	local string line;
	local float pos;

	line = "skill=3;team=blue";
	pos = strstrofs(line, "team=");
	if (pos >= 0)
		dprint(sprintf("team starts at %g\n", pos));
}
```

### strtolower
`string(string s) strtolower = #480;`

* **s** — строка для перевода в нижний регистр.

#### Описание и логика работы
`strtolower` возвращает tempstring, где все буквы по возможности приведены к нижнему регистру. В отличие от грубого ASCII-преобразования builtin опирается на unicode-утилиты движка, поэтому при активном UTF-8 работает корректнее с неанглийскими символами. Символы, у которых нет понятия регистра, остаются как есть. Цветовой markup и иные небуквенные управляющие символы не теряются.

#### Практические сценарии использования
```qc
void Demo_strtolower()
{
	local string user_input;

	user_input = "HeLLo_Player";
	dprint(sprintf("normalized=%s\n", strtolower(user_input)));
}
```

### strtoupper
`string(string s) strtoupper = #481;`

* **s** — строка для перевода в верхний регистр.

#### Описание и логика работы
`strtoupper` делает обратное преобразование относительно `strtolower`: возвращает строку, в которой буквы переведены в верхний регистр настолько, насколько это позволяет таблица преобразований движка. Для ASCII и обычного UTF-8 текста это самый удобный способ получить uniform uppercase без ручного обхода символов. Пустая строка остаётся пустой, markup-секции сохраняются. Для сравнения без учёта регистра функция обычно не нужна — там удобнее `strcasecmp` или `strncasecmp`.

#### Практические сценарии использования
```qc
void Demo_strtoupper()
{
	local string shout;

	shout = strtoupper("warning: quad spawned");
	dprint(sprintf("%s\n", shout));
}
```

### strreplace
`string(string search, string replace, string subject) strreplace = #484;`

* **search** — искомая подстрока.
* **replace** — подстрока-замена.
* **subject** — исходный текст.

#### Описание и логика работы
`strreplace` проходит по `subject` слева направо и заменяет все неперекрывающиеся вхождения `search` на `replace`. Поиск регистрозависимый. Если `search` пустая строка, движок ничего не вставляет между символами и просто возвращает исходный `subject` без изменений. Замены выполняются на лету в одну сторону, поэтому типичный случай вроде замены `/` на `\` или подстановки ключевых слов работает предсказуемо. Практически важно помнить, что текущая реализация использует внутренний буфер около 4096 байт, так что очень длинные результирующие строки лучше не конструировать этим builtin в критичном коде.

#### Практические сценарии использования
```qc
void Demo_strreplace()
{
	local string cfg;

	cfg = "name=${PLAYER};team=${TEAM}";
	cfg = strreplace("${PLAYER}", "Ranger", cfg);
	cfg = strreplace("${TEAM}", "blue", cfg);

	dprint(sprintf("cfg=%s\n", cfg));
}
```

### strireplace
`string(string search, string replace, string subject) strireplace = #485;`

* **search** — искомая подстрока.
* **replace** — текст замены.
* **subject** — исходный текст.

#### Описание и логика работы
`strireplace` работает так же, как `strreplace`, но ищет совпадения без учёта регистра. Это удобно для нормализации пользовательского ввода и парсинга текстов, где регистр не фиксирован. Если `search` пустая, исходная строка возвращается как есть. В текущей реализации сравнение case-insensitive остаётся в основном байтовым, поэтому для сложного UTF-8 текста поведение может быть менее изящным, чем у `strtolower`/`strtoupper` плюс ручной логики. Как и `strreplace`, builtin ориентирован на умеренный размер результата.

#### Практические сценарии использования
```qc
void Demo_strireplace()
{
	local string msg;

	msg = "Map START is not start_old";
	msg = strireplace("start", "e1m1", msg);

	dprint(sprintf("%s\n", msg));
}
```

### strpad
`string(float pad, string str1, ...) strpad = #225;`

* **pad** — желаемая длина строки; знак задаёт сторону добивки.
* **str1** — первая часть строки.
* **...** — дополнительные части, которые сначала склеиваются, а потом дополняются пробелами.

#### Описание и логика работы
`strpad` сначала собирает входные строки в одну, а затем при необходимости дополняет её пробелами до заданной длины. Если `pad` положительный, пробелы добавляются справа; если отрицательный — слева. Если итоговая строка уже длиннее по символам/байтам, чем модуль `pad`, builtin ничего не обрезает и возвращает строку как есть. Функция особенно полезна для консольных таблиц и fixed-width HUD-колонок, но она выравнивает именно пробелами, поэтому лучше всего сочетается с моноширинным шрифтом.

#### Практические сценарии использования
```qc
void Demo_strpad()
{
	local string row;

	row = strcat(
		strpad(12, "Player"),
		strpad(-5, ftos(15)),
		" frags\n"
	);

	dprint(row);
}
```

### strconv
`string(float ccase, float redalpha, float redchars, string str, ...) strconv = #224;`

* **ccase** — режим преобразования регистра букв.
* **redalpha** — режим перекодирования буквенных символов между цветовыми диапазонами Quake charset.
* **redchars** — режим перекодирования цифр и спецсимволов между цветовыми диапазонами Quake charset.
* **str** — первая часть исходного текста.
* **...** — дополнительные части текста.

#### Описание и логика работы
`strconv` не занимается современными строковыми преобразованиями в стиле `tolower`; он работает с классическим Quake-charset и его «красными», «белыми» и специальными диапазонами символов. Параметр `ccase` задаёт регистр букв: `0` — оставить как есть, `1` — принудительно lower-case, `2` — upper-case. Параметры `redalpha` и `redchars` управляют перекодированием букв и цифр/символов между белым, красным, золотым и чередующимся представлениями: `0` ничего не меняет, `1` принудительно белый, `2` красный, `3`/`4` золотые диапазоны для чисел, `5` и `6` — чередование белого и красного. Из комментария и реализации прямо следует, что builtin не стоит смешивать с UTF-8: он рассчитан на старый Quake character set, а не на общий Unicode.

#### Практические сценарии использования
```qc
void Demo_strconv()
{
	local string score;

	// Сделать буквы верхним регистром и перевести символы в красный диапазон.
	score = strconv(2, 2, 2, "frag 25");
	dprint(sprintf("converted=%s\n", score));
}
```

### strftime
`string(float uselocaltime, string format, ...) strftime = #478;`

* **uselocaltime** — `1` для локального времени системы, `0` для UTC/GMT.
* **format** — форматная строка в стиле `strftime`.
* **...** — дополнительные строковые части формата, если нужно собрать его на лету.

#### Описание и логика работы
`strftime` форматирует текущее системное время движка по шаблону в стиле стандартной C-функции `strftime`. Если `uselocaltime` равен нулю, используется UTC/GMT; если ненулевой — локальное время машины. Поддерживаются обычные спецификаторы `strftime` вроде `%Y`, `%m`, `%d`, `%H`, `%M`, `%S`, а реализация отдельно подменяет короткие формы `%R` на `%H:%M` и `%F` на `%Y-%m-%d`, чтобы они работали и в средах с бедной стандартной библиотекой. Функция берёт именно текущее время, а не произвольный timestamp, поэтому для форматирования сохранённой даты нужен другой уровень логики.

#### Практические сценарии использования
```qc
void Demo_strftime()
{
	local string stamp_local;
	local string stamp_utc;

	stamp_local = strftime(1, "%Y-%m-%d %H:%M:%S");
	stamp_utc = strftime(0, "%F %R UTC");

	dprint(sprintf("local=%s\n", stamp_local));
	dprint(sprintf("utc=%s\n", stamp_utc));
}
```

### sprintf
`string(string fmt, ...) sprintf = #627;`

* **fmt** — форматная строка.
* **...** — значения, которые будут подставлены в формат.

#### Описание и логика работы
`sprintf` собирает tempstring по форматной строке примерно как одноимённая функция в C, но с поправками на типовую модель QuakeC. Поддерживается экранирование `%%`, флаги `#`, `0`, `-`, пробел и `+`, фиксированная ширина (`%5d`), выравнивание влево (`%-10s`), precision (`%.2f`), а также динамические width/precision через `*` и позиционные аргументы формата `%3$*1$.*2$ld`. Важно помнить о типах: большинство числовых спецификаторов по умолчанию считают аргумент `float`, а `%i` по умолчанию ожидает integer-представление; префикс `h` насильно трактует аргумент как float, `l` — как int32, `q` — как 64-битное целое. Из текстовых и специальных представлений доступны `%s` для строки, `%S` для строки в безопасно quoted/escaped виде, `%c` для символа по коду, `%v`/`%V` для трёхкомпонентного вектора, `%p`/`%P` для указателя/идентификатора в hex с нулевой добивкой, `%d`, `%o`, `%u`, `%x`, `%X`, `%e`, `%E`, `%f`, `%F`, `%g`, `%G` для обычных чисел. Для `%s`, `%S` и `%c` при UTF-8 ширина и точность стараются работать в символах, а не в байтах; флаг `#` переключает часть строковых путей обратно к «байтовой» трактовке. Для сущностей, полей и функций обычно печатают их числовое значение через `%i` или `%x`, а не через `%s`.

#### Практические сценарии использования
```qc
void Demo_sprintf()
{
	local string player;
	local float frags;
	local vector org;
	local string cmd;

	player = "Ranger";
	frags = 12;
	org = '128 64 24';

	dprint(sprintf("%s has %d frags\n", player, frags));          // %s, %d
	dprint(sprintf("ratio=%.2f\n", 3.14159));                     // precision
	dprint(sprintf("slot=[%5d]\n", frags));                       // width, right align
	dprint(sprintf("name=[%-10s]\n", player));                    // left align
	dprint(sprintf("hex=%#x\n", 255));                            // alternate hex form
	dprint(sprintf("char=%c\n", 65));                             // A
	dprint(sprintf("origin=%v\n", org));                          // vector
	dprint(sprintf("quoted=%S\n", "say \"hi\""));            // quoted and escaped
	dprint(sprintf("reordered=%2$s scored %1$5.1f\n", 12.0, player));

	cmd = sprintf("say %S", "Hello team");
	localcmd(strcat(cmd, "\n"));
}
```

### tokenize
`float(string s) tokenize = #441;`

* **s** — строка, которую нужно разбить на токены.

#### Описание и логика работы
`tokenize` разбирает строку на токены и возвращает их количество. Затем каждый токен считывается через `argv(0)` ... `argv(n-1)`. Исторически этот builtin менялся ради совместимости и удобного парсинга, поэтому его правила не тождественны консольному парсеру движка: кавычки и разделители обрабатываются «достаточно похоже», но не побайтно идентично консоли. Пустая строка или строка, состоящая только из пробелов, даёт `0`. Повторный вызов любого `tokenize*` перетирает предыдущий набор токенов, так что рекурсивно и вложенно пользоваться общим token-buffer нельзя.

#### Практические сценарии использования
```qc
void Demo_tokenize()
{
	local float argc;

	argc = tokenize("set name \"Player One\"");
	dprint(sprintf("argc=%g cmd=%s key=%s value=%s\n",
		argc, argv(0), argv(1), argv(2)));
}
```

### tokenize_console
`float(string str) tokenize_console = #514;`

* **str** — строка, которую нужно разобрать точно так же, как разбирает её консоль движка.

#### Описание и логика работы
`tokenize_console` использует именно консольный токенизатор FTEQW. Это важное отличие от обычного `tokenize`: если вы валидируете или фильтруете текст, который потом реально пойдёт в консольный пайплайн, безопаснее сверяться именно с `tokenize_console`, иначе можно разойтись с реальным поведением движка на кавычках, экранировании и прочих краевых случаях. Как и любой другой `tokenize*` builtin, он заполняет общий пул аргументов, доступный через `argv`, `argv_start_index` и `argv_end_index`.

#### Практические сценарии использования
```qc
void Demo_tokenize_console()
{
	local float argc;
	local string raw;

	raw = "cmd \"value with spaces\" ; echo hi";
	argc = tokenize_console(raw);

	dprint(sprintf("argc=%g first=%s second=%s\n", argc, argv(0), argv(1)));
}
```

### tokenizebyseparator
`float(string s, string separator1, ...) tokenizebyseparator = #479;`

* **s** — исходная строка.
* **separator1** — первый разделитель.
* **...** — дополнительные разделители, до семи штук суммарно.

#### Описание и логика работы
`tokenizebyseparator` режет строку только по явно заданным разделителям и больше ни по чему. Это очень удобно для CSV-подобных, path-подобных и key/value-подобных форматов, где пробелы должны сохраняться внутри токена. Разделители считаются равноправными, но если один разделитель является префиксом другого, длинные варианты лучше передавать раньше. В отличие от `tokenize`, builtin не выбрасывает пустые поля между соседними разделителями: строка `"a,,b"` при разделителе `","` даст три токена (`"a"`, `""`, `"b"`). Важный краевой случай из комментария: строка, состоящая только из разделителя, возвращает `2`; строка без разделителей — `1`; пустая строка в FTEQW всегда возвращает `0`.

#### Практические сценарии использования
```qc
void Demo_tokenizebyseparator()
{
	local float argc;

	argc = tokenizebyseparator("name=Ranger;team=blue;ready=1", ";", "=");
	dprint(sprintf("argc=%g\n", argc));
	dprint(sprintf("%s %s %s %s\n", argv(0), argv(1), argv(2), argv(3)));
}
```

### argv
`string(float n) argv = #442;`

* **n** — индекс токена, полученного последним вызовом `tokenize`, `tokenize_console` или `tokenizebyseparator`.

#### Описание и логика работы
`argv` возвращает текст токена по индексу из общего token-buffer. Нумерация начинается с нуля. В FTEQW отрицательные индексы считаются от конца массива: `argv(-1)` — последний токен, `argv(-2)` — предпоследний. Если индекс выходит за диапазон, возвращается null string, а не гарантированно пустая строка, поэтому для безопасной проверки существования полезно сочетать `argv` с `validstring`. Каждый новый вызов любого `tokenize*` перезаписывает содержимое `argv`.

#### Практические сценарии использования
```qc
void Demo_argv()
{
	tokenize("vote map e1m2");

	dprint(sprintf("cmd=%s\n", argv(0)));
	dprint(sprintf("target=%s\n", argv(-1)));   // последний токен: e1m2
}
```

### argv_start_index

```qc
void Demo_argv_start_index()

}
```

```qc
}
```

### validstring
`float(string str) validstring = #81;`

* **str** — строковая ссылка, которую нужно проверить.

#### Описание и логика работы
`validstring` возвращает истину, если переданная строка не является null string. Это не то же самое, что проверка на непустую строку: `""` — пустая, но валидная строка, а null string — отсутствие строки как таковой. Функция существует потому, что поведение `if (str)` в разных конфигурациях или старых диалектах могло трактоваться по-разному. На практике `validstring` особенно полезен после `argv` и других builtins, которые при ошибке индекса или отсутствии значения могут вернуть именно null.

#### Практические сценарии использования
```qc
void Demo_validstring()
{
	tokenize("onlyone");

	if (validstring(argv(1)))
		dprint("Second argument present\n");
	else
		dprint("No second argument\n");
}
```

### ftos

* **val** — число, которое нужно представить строкой.

#### Описание и логика работы

```qc
void Demo_ftos()

	local float speed;
	local string text;

	text = strcat("speed=", ftos(speed), "\n");

}
```

### altstr_get
`string(string str, float num) altstr_get = #84;`

* **str** — строка altstr.
* **num** — индекс элемента, начиная с нуля.

#### Описание и логика работы
`altstr_get` извлекает `num`-й quoted-элемент из altstr-строки. Парсер понимает экранирование обратным слэшем внутри quoted-частей и возвращает уже «распакованный» текст, то есть `\'` превращается обратно в обычную `'` внутри результата. void Demo_altstr_get()

### altstr_prepare
`string(string str) altstr_prepare = #83;`

* **str** — строка, которую нужно безопасно поместить внутрь altstr-поля.

#### Описание и логика работы
`altstr_prepare` экранирует в строке только одинарные кавычки, вставляя перед ними обратный слэш. Самих внешних кавычек функция не добавляет, поэтому она именно подготавливает содержимое поля, а не строит готовый altstr целиком. Это означает, что итоговую конструкцию вы собираете сами через `strcat`, добавляя `'` до и после подготовленного текста. Для обычных современных строковых форматов builtin не нужен, но при работе со старым altstr без него легко сломать структуру при наличии апострофов внутри данных.

#### Практические сценарии использования
```qc
void Demo_altstr_prepare()
{
	local string player;
	local string alt;

	player = "O'Brien";
	alt = strcat("'", altstr_prepare(player), "'");

	dprint(sprintf("alt=%s\n", alt));
}
```

### altstr_set
`string(string str, float num, string setval) altstr_set = #85;`

* **str** — исходная altstr-строка.
* **num** — индекс изменяемого элемента.
* **setval** — новое значение для выбранного поля.

#### Описание и логика работы
`altstr_set` заменяет `num`-й quoted-элемент в altstr новой строкой и возвращает результат как tempstring. Важный момент из комментария и реализации: `setval` не должен содержать неэкранированные одинарные кавычки, поэтому безопаснее почти всегда подавать сюда `altstr_prepare(raw_value)`. Функция переписывает только выбранный quoted-блок, не пересобирая формат заново через tokenize-подобную структуру. Если индекс неправильный, поведение старого altstr-формата становится бесполезным для новых задач, поэтому такие случаи лучше проверять заранее через `altstr_count`.

#### Практические сценарии использования
```qc
void Demo_altstr_set()
```

### uri_escape
`string(string in) uri_escape = #510;`

* **in** — исходная строка или байтовая последовательность.

#### Описание и логика работы
`uri_escape` кодирует строку для использования в URI/HTTP-параметрах через percent-encoding. Буквы, цифры и «безопасные» символы остаются как есть, а всё остальное превращается в `%HH`. По комментарию builtin оставляет alnum, точку, дефис и подчёркивание; фактическая реализация также не кодирует `~`, что соответствует RFC 3986. Пробел становится `%20`, а не `+`. Это низкоуровневое экранирование байтов, поэтому им удобно готовить query string, части пути и отдельные параметры POST/GET.

#### Практические сценарии использования
```qc
void Demo_uri_escape()
{
	local string query;

	query = strcat("name=", uri_escape("Player One"), "&msg=", uri_escape("hi & bye"));
	dprint(sprintf("%s\n", query));
}
```

---

### uri_unescape
`string(string in) uri_unescape = #511;`

* **in** — строка с `%HH`-последовательностями.

#### Описание и логика работы
`uri_unescape` выполняет обратное преобразование для percent-encoding и заменяет корректные `%HH` последовательности их исходными байтами. Если после `%` стоят некорректные hex-символы или последовательность обрывается, builtin не рушится и оставляет проблемный символ как есть. `+` в пробел не переводится, потому что функция занимается именно URI percent-decoding, а не специфическим `application/x-www-form-urlencoded` слоем. Это значит, что пары `uri_escape`/`uri_unescape` симметричны именно на уровне `%HH`.

#### Практические сценарии использования
```qc
void Demo_uri_unescape()
{
	local string decoded;

	decoded = uri_unescape("Player%20One%20%26%20Co");
	dprint(sprintf("decoded=%s\n", decoded));
}
```

### argescape
`string(string s) argescape = #295;`

* **s** — строка, которую нужно превратить в один безопасный консольный аргумент.

#### Описание и логика работы
`argescape` подготавливает строку так, чтобы позднее консольный токенизатор воспринимал её как один аргумент, даже если внутри есть пробелы, кавычки или иные специальные символы. Это не URI-экранирование и не общий `replace`: builtin формирует строку именно под правила движкового парсера командной строки. Он особенно полезен при сборке [`localcmd`](12-system-debug-builtins.md#localcmd), [`stuffcmd`](04-network-messages-builtins.md#stuffcmd) и любых текстовых команд, где пользовательские данные нельзя просто склеить через пробел, иначе их разорвёт на несколько токенов.

#### Практические сценарии использования
```qc
void Demo_argescape()
{
	local string playername;
	local string cmd;

	playername = "Player One";
	cmd = strcat("say ", argescape(playername), "\n");

	localcmd(cmd);
}
```

### stringwidth
`float(string text, float usecolours, optional vector fontsize) stringwidth = #327;`

* **text** — строка, чью экранную ширину нужно вычислить.
* **usecolours** — если `1`, невидимый markup не учитывается в ширине.
* **fontsize** — необязательный размер символов; если не задан, берётся `8 8 0`.

#### Описание и логика работы
`stringwidth` относится к клиентскому/UI слою, но часто используется вместе с обычными строковыми builtins, поэтому его удобно держать рядом. Функция измеряет, сколько места строка займёт на экране в виртуальных пикселях, с учётом шрифта и клиентского текстового рендера. Если `usecolours` включён, цветовой markup, не влияющий на геометрию текста, игнорируется при расчёте. Если размер не передан, используется шрифт `8x8`, причём ради совместимости с DarkPlaces поведение по умолчанию выглядит немного особенным, но на практике builtin просто даёт пригодную для UI ширину. Основной номер в `CSQC` — `#327`, а в menu-ветке тот же builtin регистрируется как legacy-форма `#468`. Для серверного QuakeC он не нужен, а вот в CSQC/MenuQC полезен постоянно.

#### Практические сценарии использования
```qc
void Demo_stringwidth()
{
	local string title;
	local float w;

	title = "^2READY";
	w = stringwidth(title, TRUE, '16 16 0');

	dprint(sprintf("title width=%g\n", w));
}
```

### stringtokeynum
`float(string keyname) stringtokeynum = #341;`

* **keyname** — текстовое имя клавиши в стиле команды `bind`.

#### Описание и логика работы
`stringtokeynum` ищет код клавиши по её имени так же, как это делает система биндов. Это клиентский builtin, но при работе с текстовыми конфигами и UI-меню он часто встречается рядом с другими строковыми функциями. В CSQC используется форма `#341`; в menu-ветке `fteextensions.qc` есть и более поздняя форма `#614` с той же общей задачей. По фактической клиентской реализации безопаснее передавать одиночное имя клавиши вроде `"SPACE"` или `"MWHEELUP"`: если строка содержит модификаторы вроде `CTRL+X`, результат может быть `-1`, а не составной код.

#### Практические сценарии использования
```qc
void Demo_stringtokeynum()
{
	local float key;

	key = stringtokeynum("SPACE");
	dprint(sprintf("space code=%g\n", key));
}
```

### str2chr
`float(string str, float index) str2chr = #222;`

* **str** — исходная строка.
* **index** — позиция символа.

#### Описание и логика работы
[`str2chr`](01-math-vector-builtins.md#str2chr) возвращает числовой код символа на позиции `index`. В не-UTF8 режиме это код байта 0..255, а при включённом UTF-8 — уже Unicode codepoint. Отрицательный индекс считается от конца строки: `-1` означает последний символ. Если индекс выходит за диапазон, builtin возвращает `0`. Это делает `str2chr` удобным для посимвольного разбора, проверок на разделители и ручных фильтров ввода.

#### Практические сценарии использования
```qc
void Demo_str2chr()
{
	local float first;
	local float last;

	first = str2chr("quake", 0);
	last = str2chr("quake", -1);

	dprint(sprintf("first=%g last=%g\n", first, last));
}
```

### chr2str
`string(float chr, ...) chr2str = #223;`

* **chr** — код первого символа.
* **...** — дополнительные коды символов, которые будут дописаны следом.

#### Описание и логика работы
[`chr2str`](01-math-vector-builtins.md#chr2str) делает обратную операцию относительно `str2chr`: принимает один или несколько числовых кодов и собирает из них строку. В обычном 8-битном режиме значения до `255` вставляются как одиночные байты; при UTF-8 или для кодов больше `255` движок кодирует символ в UTF-8-последовательность. Функция поддерживает столько аргументов, сколько вообще можно передать builtin в QuakeC, так что ею удобно строить короткие строки из символов, вставлять управляющие знаки и собирать данные посимвольно.

#### Практические сценарии использования
```qc
void Demo_chr2str()
{
	local string word;

	word = chr2str(81, 117, 97, 107, 101);   // "Quake"
	dprint(sprintf("word=%s\n", word));
}
```

### altstr_ins
`DEP string(string str, float num, string set) altstr_ins = #86;`

* **str** — исходная altstr-строка.
* **num** — `float`, позиция, перед которой предполагалась вставка.
* **set** — строка для вставки.

#### Описание и логика работы

`altstr_ins` числится в builtin-таблицах как устаревшая (`DEP`) совместимостная функция старого altstr-API, но в актуальном FTEQW она **не реализована**. И в `SSQC`, и в `MenuQC` имя привязано к `PF_Fixme`, то есть вызов заканчивается ошибкой вида `Builtin ... not implemented`, а не реальной вставкой элемента. Поэтому `altstr_ins` следует считать функцией-пустышкой для совместимости; для рабочего кода вставку приходится собирать вручную через `altstr_get`, `altstr_prepare` и `strcat`.

#### Практические сценарии использования

```qc
string(string alt, float num, string raw) altstr_insert_manual
{
    local float i;
    local float count;
    local string out;

    count = altstr_count(alt);
    for (i = 0; i < count; i = i + 1)
    {
        if (i == num)
            out = strcat(out, "'", altstr_prepare(raw), "' ");

        out = strcat(out, "'", altstr_prepare(altstr_get(alt, i)), "'");
        if (i + 1 < count)
            out = strcat(out, " ");
    }

    if (num >= count)
        out = strcat(out, " '", altstr_prepare(raw), "'");

    return out;
}
```

### base64decode
`__variant*(string base64str, __out int bytes) base64decode = #0:base64decode;`

* **base64str** — строка в формате Base64.
* **bytes** — `__out int`, сюда движок записывает фактический размер декодированного блока.

#### Описание и логика работы

`base64decode` декодирует Base64-строку и выделяет новый адресуемый блок памяти внутри QCVM. Возвращаемый указатель можно передавать в `mem*` builtin'ы; после использования его нужно освободить через [`memfree`](06-files-database-builtins.md#memfree), а аргумент `bytes` получает реальное число записанных байтов. Реализация дополнительно пишет нулевой байт в конец блока, но это не делает результат «обычной строкой» автоматически: безопаснее относиться к нему именно как к бинарному blob.

#### Практические сценарии использования

```qc
void() Demo_base64decode
{
    local __variant *blob;
    local int bytes;

    blob = base64decode("UUtDTQ==", bytes);
    if (blob && bytes == 4)
        dprint("decoded 4 bytes\n");

    memfree(blob);
}
```

### base64encode
`string(__variant *ptr, int bytes, optional int offset) base64encode = #0:base64encode;`

* **ptr** — `__variant *`, указатель на бинарный блок, который нужно закодировать.
* **bytes** — `int`, сколько байтов читать из блока.
* **offset** — `optional int`, документированный сдвиг внутри блока; в текущей реализации этот отдельный аргумент не применяется

#### Описание и логика работы

`base64encode` берёт бинарный blob из адресуемой памяти QC и возвращает его копию в виде Base64 tempstring. Официальная строка движка отдельно предупреждает, что здесь используются обычные символы `+` и `/`, поэтому при встраивании результата в другой текст его лучше явно брать в кавычки или дополнительно экранировать под нужный формат. Builtin доступен в `SSQC`, `CSQC` и `MenuQC`; сам результат освобождать не нужно, потому что это tempstring.

#### Практические сценарии использования

```qc
void() Demo_base64encode
{
    local __variant *blob;
    local string encoded;

    blob = memalloc(4);
    if (!blob)
        return;

    memsetval(blob, 0, 1337);
    encoded = base64encode(blob, 4);
    dprint(sprintf("payload=%s\n", encoded));

    memfree(blob);
}
```

### instr
`string(string input, string token) instr = #206;`

* **input** — строка, в которой выполняется поиск.
* **token** — подстрока, с первого вхождения которой нужно вернуть хвост.

#### Описание и логика работы

`instr` ищет первое вхождение `token` внутри `input` и возвращает не числовой индекс, а **хвост исходной строки, начиная с найденного места**. Если совпадения нет, builtin возвращает пустую/null string. В extension-list сервера прототип по ошибке описан как `float`, но реальная реализация в `pr_bgcmd.c` использует `strstr` и возвращает строковый срез; сама же докстрока честно советует в новом коде предпочитать [`strstrofs`](02-string-builtins.md#strstrofs), потому что она даёт индекс и лучше комбинируется с остальными строковыми builtin'ами.

#### Практические сценарии использования

```qc
void() Demo_instr
{
    local string tail;

    tail = instr("say_team hello squad", "hello");
    if (tail != "")
        dprint(sprintf("tail=%s\n", tail));
}
```

### matchpattern
`float(string s, string pattern, float matchrule) matchpattern = #538;`

* **s** — строка, которую предполагалось проверять.
* **pattern** — строка-шаблон.
* **matchrule** — `float`, зарезервированный режим сравнения.

#### Описание и логика работы

`matchpattern` присутствует в исходниках только как закомментированная запись в builtin-таблицах и не имеет рабочей реализации ни в `SSQC`, ни в `CSQC`, ни в `MenuQC`. Иными словами, это не «плохо документированная» функция, а фактически незаведённый зарезервированный builtin-номер: движок не регистрирует его для вызова. Для практики это следует считать функцией-пустышкой для совместимости/планов на будущее; реальный код должен использовать `strncmp`, `strstrofs`, `substring` или собственный разбор шаблонов.

#### Практические сценарии использования

```qc
float(string s, string prefix) starts_with
{
    return !strncmp(s, prefix, strlen(prefix), 0, 0);
}
```

### strcmp
`#define strcmp strncmp`

* **s1** — первая сравниваемая строка.
* **s2** — вторая сравниваемая строка.

#### Описание и логика работы

В официальных заголовках FTEQW `strcmp` — это не отдельный builtin, а препроцессорный alias к `strncmp`. Поэтому вызов `strcmp(a, b)` разворачивается на этапе компиляции и использует уже существующий строковый compare builtin `#228` без ограничения по длине, то есть ведёт себя как обычное полное регистрозависимое сравнение строк. Практически результат следует трактовать так же, как у `strncmp`: `0` означает равенство, а знак ненулевого значения можно использовать только как «меньше/больше», но не как стабильный конкретный код.

#### Практические сценарии использования

```qc
void() Demo_strcmp
{
    local string cmd;

    cmd = argv(0);
    if (!strcmp(cmd, "disconnect"))
        dprint("exact command match\n");
}
```
