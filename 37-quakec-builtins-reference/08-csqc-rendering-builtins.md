# Рендеринг и сцена CSQC

> [⬅ Предыдущая страница](07-precache-resources-builtins.md) | [Следующая страница ➡](09-csqc-input-ui-builtins.md)

> [⬅ Вернуться к оглавлению вики](../README.md)
> [Индекс справочника builtins](../README.md#встроенные-функции-quakec-builtins)

CSQC (Client-Side QuakeC) строит изображение кадра из двух независимых конвейеров. Первый — трёхмерная сцена: `clearscene` очищает список рентити (render entities), полигонов и временных динамических источников света, затем `addentity`/`addentities` копируют поля обычных entity (или entity движка через маску) в этот список, а `renderscene` рисует всё накопленное с учётом свойств вида, заданных через `setproperty`. Второй конвейер — плоская 2D-графика (`draw*`, `R_BeginPolygon`/`R_PolygonVertex`/`R_EndPolygon` с флагом `is2d`), работающая в экранных пикселях виртуального разрешения и предназначенная для HUD, меню и текста. Оба конвейера обычно вызываются из [`CSQC_UpdateView`](00-entry-points.md#csqc_updateview) (полноценный csqc-мод, отвечающий за всю отрисовку кадра, включая сцену) или из [`CSQC_DrawHud`](00-entry-points.md#csqc_drawhud)/[`CSQC_DrawScores`](00-entry-points.md#csqc_drawscores) в упрощённом режиме SimpleCSQC, где сцену и HUD движка рисует сам движок, а QC лишь дорисовывает поверх него 2D-элементы. Помимо этого в CSQC доступны builtin-функции для партиклов, декалей, динамического света и временных эффектов (`te_*`), повторяющих сетевые temp-entity события ssqc.

Часть перечисленных ниже функций также зарегистрирована в MenuQC — им посвящена отдельная статья [Функции MenuQC](./13-menuqc-builtins.md).

## Функции

### addentity
`void(entity ent) addentity = #302;`

* **ent** — entity, поля которой ([`model`](../39-entity-keys-reference/01-worldspawn-common-keys.md#model), [`origin`](../39-entity-keys-reference/01-worldspawn-common-keys.md#origin), [`angles`](../39-entity-keys-reference/01-worldspawn-common-keys.md#angles), `frame`, [`skin`](../39-entity-keys-reference/01-worldspawn-common-keys.md#skin), `colormap`, [`effects`](../39-entity-keys-reference/06-item-weapon-keys.md#effects), `alpha`, `scale`, `renderflags` и т.д.) нужно скопировать в список рентити для отрисовки.

#### Описание и логика работы
`addentity` копирует рендер-поля указанной entity в новый rentity, который будет нарисован при следующем вызове `renderscene`. Копия делается немедленно, поэтому дальнейшие изменения полей `ent` уже не повлияют на добавленную копию — если нужно анимировать модель, это делают до вызова `addentity` (например, в функции `predraw`, вызываемой из `addentities`). Вызывать `addentity` можно только между `clearscene` и `renderscene`; вызов вне этого окна не имеет смысла, так как список будет либо ещё не очищен, либо уже нарисован и заново обнулён. Координаты — мировые (`origin`/`angles` в единицах карты), а не экранные пиксели. Если `ent` невидима ([`model`](../39-entity-keys-reference/01-worldspawn-common-keys.md#model) не задан, `effects` содержит `EF_NODRAW` и т.п.), движок просто не нарисует rentity, ошибки не будет.

#### Практические сценарии использования
```c
void() CSQC_UpdateView =
{
	clearscene();

	// нарисовать собственную модель игрока-наблюдателя
	entity e = spawn();
	setmodel(e, "progs/player.mdl");
	e.origin = self.origin;
	e.angles = self.angles;
	e.frame = self.frame;
	addentity(e);
	remove(e);

	addentities(MASK_ENGINE | MASK_VIEWMODEL);
	renderscene();
};
```

### addentities
`void(float mask) addentities = #301;`

* **mask** — битовая маска: `MASK_ENGINE` добавляет обычные engine/server entity, `MASK_VIEWMODEL` — штатную вью-модель оружия.

#### Описание и логика работы
Builtin проходит по CSQC entity и для каждой проверяет `ent.drawmask & mask`. Если у сущности задан `predraw`, движок вызывает его перед автоматическим добавлением. В текущей реализации FTEQW ненулевой `return` из `predraw` отменяет auto-add, а нулевой — позволяет `addentities` самостоятельно вызвать `addentity(ent)`. Поэтому `predraw` обычно либо подготавливает поля сущности и возвращает `0`, либо сам вручную добавляет/рисует сущность и возвращает ненулевое значение. При установленном `MASK_ENGINE` в сцену также попадают обычные сетевые сущности и связанные с ними engine-эффекты, а `MASK_VIEWMODEL` добавляет стандартный viewmodel. Вызывается между `clearscene` и `renderscene`.

#### Практические сценарии использования
```c
void() CSQC_UpdateView =
{
	clearscene();
	addentities(MASK_ENGINE | MASK_VIEWMODEL);
	renderscene();
};
```

### clearscene
`void() clearscene = #300;`

* Аргументов нет.

#### Описание и логика работы
Забывает все rentity, полигоны и временные (добавленные за кадр) динамические источники света, а также сбрасывает все свойства вида (`setproperty`) к значениям по умолчанию (полноэкранный вьюпорт, стандартный [fov](../38-cvars-reference/01-video-rendering-cvars.md#fov) и т.д.). Должна вызываться в начале построения кадра, до первого `addentity`/`addentities`/`R_BeginPolygon`, поскольку старый список рентити иначе продолжает копиться от кадра к кадру. Повторный вызов `clearscene` без последующего `renderscene` просто ещё раз обнуляет уже пустую сцену — ошибки не будет, но предыдущий `renderscene` (если он был) уже успел нарисовать то, что было накоплено к этому моменту.

#### Практические сценарии использования
```c
void() CSQC_UpdateView =
{
	clearscene();          // всегда первым действием кадра
	setproperty(VF_ORIGIN, self.origin);
	setproperty(VF_ANGLES, self.v_angle);
	addentities(MASK_ENGINE | MASK_VIEWMODEL);
	renderscene();
};
```

### renderscene
`void() renderscene = #304;`

* Аргументов нет.

#### Описание и логика работы
Рисует все entity, полигоны и партиклы, накопленные в списке рентити через `addentity`/`addentities`/`R_BeginPolygon`, используя свойства вида, заданные `setproperty` (позиция камеры, углы, fov, вьюпорт). Порядок добавления элементов не важен — важно лишь то, что вызов должен идти после `clearscene` и всех `addentity`. Сцену нужно очищать заново перед добавлением новых entity, так как добавленные рентити переживают кадр и будут повторно нарисованы, если `clearscene` не вызван. Разрешено вызывать `renderscene` несколько раз за кадр (например, для рендера в текстуру и затем в основной вид), но builtin должен использоваться только внутри [`CSQC_UpdateView`](00-entry-points.md#csqc_updateview); в `CSQC_DrawHud`/`CSQC_DrawScores` сцену уже построил движок.

#### Практические сценарии использования
```c
void() CSQC_UpdateView =
{
	clearscene();
	addentities(MASK_ENGINE | MASK_VIEWMODEL);
	renderscene();          // после этой точки список рентити уже нарисован
};
```

### getproperty
`__variant(float property) getproperty = #309;` (алиас `getviewprop`)

* **property** — одна из констант `VF_*` (например, `VF_ORIGIN`, `VF_ANGLES`, `VF_FOV`, `VF_MINDIST`, `VF_DRAWWORLD`).

#### Описание и логика работы
Возвращает текущее значение указанного свойства вида — как правило, то, что ранее было установлено `setproperty`, либо значение по умолчанию движка. Тип результата зависит от конкретного `VF_`-свойства (`float`, `vector` и т.п.), поэтому builtin объявлен как `__variant` — приводите результат к нужному типу вручную. Из соображений защиты от читерства некоторые значения (например, связанные с видимостью карты или позициями других игроков) могут быть недоступны и возвращать нулевые/безопасные значения. Вызывать можно в любой момент кадра, обычно после `setproperty`, чтобы прочитать реально применённое значение (движок может подправить его, например, ограничить fov).

#### Практические сценарии использования
```c
void() CSQC_UpdateView =
{
	vector curorg = getproperty(VF_ORIGIN);
	if (curorg != self.origin)
		setproperty(VF_ORIGIN, self.origin);
	clearscene();
	renderscene();
};
```

### setproperty
`float(float property, ...) setproperty = #303;` (алиас `setviewprop`)

* **property** — константа `VF_*`, определяющая, что настраивается (вьюпорт, fov, ориджин камеры, отрисовку HUD движком и т.д.).
* **...** — один или несколько дополнительных аргументов (float или vector) в зависимости от конкретного `VF_`-свойства.

#### Описание и логика работы
Переопределяет параметры вида по умолчанию: вьюпорт (`VF_MIN`/`VF_SIZE`), позицию и углы камеры (`VF_ORIGIN`, `VF_ANGLES`), поле зрения (`VF_FOV`), а также включает или отключает отрисовку HUD движком (`VF_DRAWENGINESBAR`, `VF_DRAWCROSSHAIR` и др.). Разные `VF_`-значения ожидают разное количество и тип аргументов — вектор для позиций, один или два float для fov (горизонтальный/вертикальный). Должен вызываться до `renderscene`, так как именно эти свойства используются при построении кадра; после `clearscene` все свойства вида сбрасываются к значениям по умолчанию, поэтому `setproperty` обычно вызывают в начале `CSQC_UpdateView` каждый кадр. Некорректный номер свойства или неверный набор аргументов игнорируется движком без падения программы.

#### Практические сценарии использования
```c
void() CSQC_UpdateView =
{
	clearscene();
	setproperty(VF_ORIGIN, self.origin + '0 0 22');
	setproperty(VF_ANGLES, self.v_angle);
	setproperty(VF_FOV, 90, 90);
	setproperty(VF_DRAWENGINESBAR, FALSE); // спрятать штатный HUD движка
	addentities(MASK_ENGINE | MASK_VIEWMODEL);
	renderscene();
};
```

### setlistener
`void(vector origin, vector forward, vector right, vector up) setlistener = #351;`

* **origin** — позиция «слушателя» звука в мировых координатах.
* **forward**, **right**, **up** — ориентация слушателя (обычно `v_forward`/`v_right`/`v_up` текущей камеры).

#### Описание и логика работы
Задаёт положение и ориентацию точки, относительно которой движок рассчитывает панораму и затухание звука (3D-звук). Без явного вызова движок обычно использует позицию собственного игрока; builtin нужен, если CSQC рисует камеру не из головы игрока (например, свободная камера, зрительский режим) и звук должен слышаться именно оттуда. Рекомендуется обновлять каждый кадр, особенно при использовании предсказания движения, чтобы позиция слушателя не отставала от фактической камеры.

#### Практические сценарии использования
```c
void() CSQC_UpdateView =
{
	makevectors(self.v_angle);
	setlistener(self.origin, v_forward, v_right, v_up);
};
```

### getresolution
`vector(float vidmode, optional float forfullscreen) getresolution = #608;`

* **vidmode** — индекс режима; специальное значение `-1` запрашивает разрешение рабочего стола.
* **forfullscreen** *(optional)* — ненулевое значение выбирает fullscreen-список внутренних режимов движка.

#### Описание и логика работы
`getresolution` возвращает один режим из внутреннего списка FTEQW, а не делает прямой опрос видеодрайвера. При `vidmode == -1` builtin возвращает параметры текущего desktop mode. Компоненты `x` и `y` — ширина и высота, а `z` используется как вспомогательный `pixelheight`/status-hint: обычно `1` для обычного квадратного пикселя и `0`, если режим не найден. Это вспомогательная UI-функция для меню настроек видео, не связанная с 3D-сценой.

#### Практические сценарии использования
```c
void(float idx) DrawResolutionOption =
{
	vector res;

	res = getresolution(idx);
	if (!res_z)
		return;
	drawstring('8 8 0', sprintf("%g x %g", res_x, res_y), '8 8 0', '1 1 1', 1, 0);
};
```

### R_BeginPolygon
`void(string texturename, optional float flags, optional float is2d) R_BeginPolygon = #306;`

* **texturename** — имя шейдера/текстуры, который будет использован для последующих вершин.
* **flags** *(optional)* — битовые флаги полигона (наложение, отсечение и т.п.).
* **is2d** *(optional)* — если истина, полигон рисуется как экранный (2D) сразу по завершении `R_EndPolygon`, а не откладывается до `renderscene`.

#### Описание и логика работы
Открывает построение произвольного полигона: указывает шейдер и режим, в котором будут интерпретироваться последующие вызовы `R_PolygonVertex`. Обычные (не `is2d`) полигоны попадают в общий список рентити сцены и рисуются вместе с остальными объектами при `renderscene`, поэтому должны создаваться между `clearscene` и `renderscene`, используя мировые координаты вершин. При `is2d` полигон рисуется немедленно после `R_EndPolygon`, минуя сцену, и вершины задаются в экранных координатах — это позволяет делать сложные 2D-эффекты (градиенты, произвольные многоугольники) поверх HUD. Повторный вызов `R_BeginPolygon` с тем же шейдером не обязателен для рисования следующего полигона тем же материалом.

#### Практические сценарии использования
```c
void() DrawWorldQuad =
{
	R_BeginPolygon("textures/fx/glow", 0, FALSE);
	R_PolygonVertex(self.origin + '-32 -32 0', '0 0 0', '1 1 1', 1);
	R_PolygonVertex(self.origin + ' 32 -32 0', '1 0 0', '1 1 1', 1);
	R_PolygonVertex(self.origin + ' 32  32 0', '1 1 0', '1 1 1', 1);
	R_PolygonVertex(self.origin + '-32  32 0', '0 1 0', '1 1 1', 1);
	R_EndPolygon();
};
```

### R_EndPolygon
`void() R_EndPolygon = #308;`

* Аргументов нет.

#### Описание и логика работы
Завершает построение текущего примитива, начатого `R_BeginPolygon`. При `3+` вершинах через `R_PolygonVertex` получается обычный полигон/triangle-fan. При ровно `2` вершинах текущая реализация FTEQW не отбрасывает примитив, а превращает его в линию. При `0` или `1` вершине ничего не рисуется. После вызова можно сразу начинать следующий примитив.

#### Практические сценарии использования
```c
void() DrawTriangle =
{
	R_BeginPolygon("white", 0, TRUE);
	R_PolygonVertex('100 100 0', '0 0 0', '1 0 0', 1);
	R_PolygonVertex('150 100 0', '0 0 0', '0 1 0', 1);
	R_PolygonVertex('125 150 0', '0 0 0', '0 0 1', 1);
	R_EndPolygon();
};
```

### R_PolygonVertex
`void(vector org, vector texcoords, vector rgb, float alpha) R_PolygonVertex = #307;`

* **org** — позиция вершины: мировые координаты для 3D-полигона либо экранные `x y` пиксели для 2D (`z` обычно 0).
* **texcoords** — координаты текстуры (обычно используются `x` и `y` компоненты, диапазон 0..1).
* **rgb** — цвет вершины, компоненты 0..1.
* **alpha** — прозрачность вершины, 0..1.

#### Описание и логика работы
Добавляет очередную вершину к полигону, открытому `R_BeginPolygon`. Порядок добавления определяет порядок обхода (обычно по часовой стрелке или против — зависит от шейдера), вершины формируют веерную триангуляцию. Если вершин указано меньше трёх к моменту `R_EndPolygon`, полигон не рисуется. Вызывать можно только между `R_BeginPolygon` и `R_EndPolygon`.

#### Практические сценарии использования
См. пример в `R_BeginPolygon` выше — там же показано добавление всех вершин четырёхугольника.

### drawcharacter
`float(vector position, float character, vector size, vector rgb, float alpha, optional float drawflag) drawcharacter = #320;`

* **position** — экранные координаты `x y` в виртуальных пикселях, куда рисуется символ.
* **character** — код Quake-символа (0..255) либо, при `drawflag & 4`, unicode-кодпоинт.
* **size** — размер символа на экране, обычно `'8 8 0'`.
* **rgb** — цвет символа, компоненты 0..1.
* **alpha** — прозрачность, 0..1.
* **drawflag** *(optional)* — битовые флаги отрисовки/режима смешивания.

#### Описание и логика работы
Рисует один символ в экранных 2D-координатах. При `character == 0` builtin ничего не рисует и возвращает `-1`; при обычной отрисовке текущая реализация пишет статус `1`. Без `drawflag & 4` движок использует обычную Quake/UTF-8 логику шрифта, а не произвольный unicode-атлас. Для расчёта ширины строки или выравнивания лучше использовать `stringwidth`, а не пытаться выводить её из return value этой функции.

#### Практические сценарии использования
```c
void() CSQC_DrawHud =
{
	drawcharacter('4 4 0', 65, '16 16 0', '1 1 0', 1, 0);
};
```

### drawfill
`float(vector position, vector size, vector rgb, float alpha, optional float drawflag) drawfill = #323;` (алиас `drawfillrgb`)

* **position** — верхний левый угол прямоугольника в экранных пикселях.
* **size** — ширина и высота прямоугольника.
* **rgb** — цвет заливки.
* **alpha** — прозрачность.
* **drawflag** *(optional)* — младшие 2 бита задают режим смешивания: `0` — обычное альфа-смешивание, `1` — аддитивное.

#### Описание и логика работы
Рисует сплошной прямоугольник указанного цвета и прозрачности поверх экрана — базовый способ нарисовать фон под HUD-элементы или полосу здоровья. Полностью экранная 2D-функция, координаты в виртуальных пикселях, не зависящих от 3D-сцены. При `size` с нулевой или отрицательной шириной/высотой ничего не рисуется.

#### Практические сценарии использования
```c
void() CSQC_DrawHud =
{
	drawfill('0 0 0', '64 8 0', '0 0 0', 0.5, 0);
};
```

### drawfillpal
`void(vector pos, vector size, float paletteindex) drawfillpal = #314;`

* **pos** — верхний левый угол прямоугольника в экранных пикселях.
* **size** — ширина и высота прямоугольника.
* **paletteindex** — индекс цвета в палитре Quake (0-255), а не прямой RGB.

#### Описание и логика работы
Закрашивает сплошной прямоугольник цветом из стандартной палитры Quake по её индексу, а не по RGB-компонентам, как [`drawfill`](#drawfill). Историческое legacy-расширение из `ext_csqc_1.txt`, полезное для точного воспроизведения классических software-палитровых эффектов (например, экрана боли/лечения с оригинальными оттенками Quake).

#### Практические сценарии использования
```c
void() CSQC_DrawHud =
{
```

### drawline
`void(float width, vector pos1, vector pos2, vector rgb, float alpha, optional float drawflag) drawline = #315;`

* **width** — толщина линии в пикселях; в текущей FTE-реализации параметр принят для совместимости, но фактически не влияет на результат.
* **pos1**, **pos2** — начальная и конечная точки линии в экранных координатах.
* **rgb** — цвет линии.
* **alpha** — прозрачность.
* **drawflag** *(optional)* — режим смешивания.

#### Описание и логика работы
Рисует 2D-линию между двумя экранными точками. Несмотря на сигнатуру, текущая реализация FTEQW использует обычный thin-line path и игнорирует `width`, поэтому builtin подходит прежде всего для простых HUD-линий и разметки, а не для настоящих толстых полос. Для «широкой линии» лучше строить узкий прямоугольник/ленту через полигоны.

#### Практические сценарии использования
```c
void() CSQC_DrawHud =

};
```

### drawpic
`float(vector position, string pic, vector size, vector rgb, float alpha, optional float drawflag) drawpic = #322;`

* **position** — экранные координаты верхнего левого угла изображения.
* **pic** — имя шейдера/картинки (обычно предварительно загруженной через [`precache_pic`](07-precache-resources-builtins.md#precache_pic)).
* **size** — размер, до которого изображение растягивается/сжимается.
* **rgb**, **alpha** — цветовой множитель и прозрачность.
* **drawflag** *(optional)* — режим смешивания и прочие битовые флаги.

#### Описание и логика работы
Рисует изображение целиком внутри заданного 2D-прямоугольника экрана, с масштабированием под указанный `size`. Программные (software) рендереры движка могут игнорировать [`rgb`](../41-particle-directives-reference/01-particle-effect-directives.md#rgb)/`alpha`, но обязаны поддерживать масштабирование и корректно обрезать картинку по границам экрана без падений. Изображение должно быть предварительно загружено ([`precache_pic`](07-precache-resources-builtins.md#precache_pic)) — иначе движок либо покажет заглушку, либо подгрузит его с задержкой в первый кадр.

#### Практические сценарии использования
```c
void() CSQC_DrawHud =
{
	drawpic('8 8 0', "gfx/hud/icon_health", '32 32 0', '1 1 1', 1, 0);
};
```

### drawrawstring
`float(vector position, string text, vector size, vector rgb, float alpha, optional float drawflag) drawrawstring = #321;`

* **position** — позиция начала строки в экранных пикселях.
* **text** — строка для отображения без интерпретации разметки (`^`-кодов).
* **size** — размер символов, обычно `'8 8 0'`.
* **rgb**, **alpha** — цвет и прозрачность текста.
* **drawflag** *(optional)* — режим отрисовки.

#### Описание и логика работы
Рисует строку "как есть", без разбора цветовой разметки движка — если в игре глобально включён UTF-8, строка декодируется как UTF-8, иначе трактуется как обычные quake-символы. Полезно для вывода произвольного пользовательского текста (ников, чата), где символы `^` не должны интерпретироваться как escape-последовательности. Software-рендереры вправе считать размер `'8 8 0'`, цвет `'1 1 1'`, alpha 1 и `drawflag&3=0` умолчанием, но рисовать за границей экрана не является ошибкой.

#### Практические сценарии использования
```c
void() CSQC_DrawHud =
{
	drawrawstring('8 24 0', getplayerkeyvalue(player_localnum, "name"), '8 8 0', '1 1 1', 1, 0);
};
```

### drawsetcliparea
`void(float x, float y, float width, float height) drawsetcliparea = #324;`

* **x**, **y** — верхний левый угол области отсечения в экранных пикселях.
* **width**, **height** — ширина и высота области.

#### Описание и логика работы

### drawsubpic
`void(vector pos, vector sz, string pic, vector srcpos, vector srcsz, vector rgb, float alpha, optional float drawflag) drawsubpic = #328;`

* **pos**, **sz** — позиция и размер на экране, куда выводится результат.
* **pic** — имя изображения.
* **srcpos**, **srcsz** — прямоугольник внутри исходного изображения (в его собственных пиксельных/UV-координатах), который нужно вырезать.
* **rgb**, **alpha** — цвет и прозрачность.
* **drawflag** *(optional)* — режим смешивания.

#### Описание и логика работы
Вырезает прямоугольный фрагмент изображения (например, одну иконку из атласа/спрайт-листа) и рисует его растянутым в заданную область экрана. Полностью 2D-функция. ### iscachedpic
`float(string name) iscachedpic = #316;`

* **name** — имя изображения.

#### Описание и логика работы
Проверяет, загружено ли изображение в память движка в данный момент. Разные движки могут "врать" (например, всегда отвечать true) или сбрасывать кэш между картами, поэтому builtin следует использовать лишь как подсказку, а не как гарантию. Не связан с 3D-сценой — чисто вспомогательная функция для управления ресурсами перед `drawpic`.

```c
void() EnsureIconLoaded =

};
```

### stringwidth

* **text** — строка, ширину которой нужно вычислить.

### adddecal
`void(string shadername, vector origin, vector up, vector side, vector rgb, float alpha) adddecal = #375;`

* **shadername** — имя шейдера декали.
* **origin** — мировая точка центра декали (обычно точка попадания на поверхность).
* **up**, **side** — векторы ориентации декали (масштаб и поворот проекции).
* **rgb**, **alpha** — цвет и прозрачность декали.

#### Описание и логика работы
Добавляет временную декаль (проекцию текстуры на ближайшую поверхность), центрированную в мировой точке `origin` с ориентацией по `up`/`side`. Декаль будет нарисована при следующем `renderscene` и автоматически забыта при следующем `clearscene` — то есть, в отличие от декалей ssqc, она не сохраняется надолго и должна добавляться заново каждый кадр, если нужен постоянный эффект (например, для собственных пулевых отметин, управляемых списком в QC). Работает в мировых координатах, использование вне пары `clearscene`/`renderscene` не имеет смысла.

#### Практические сценарии использования
```c
void() CSQC_UpdateView =
{
	clearscene();
	adddecal("textures/decals/bullet", trace_endpos, trace_plane_normal, v_right, '1 1 1', 1);
	addentities(MASK_ENGINE);
	renderscene();
};
```

### boxparticles
`void(float effectindex, entity own, vector org_from, vector org_to, vector dir_from, vector dir_to, float countmultiplier, optional float flags) boxparticles = #502;`

* **effectindex** — номер эффекта, полученный от `particleeffectnum`.
* **own** — entity-владелец (используется для кеширования и относительных вычислений, само по себе не рисуется).
* **org_from**, **org_to** — диапазон точек появления партиклов (случайная точка внутри отрезка/бокса между ними).
* **dir_from**, **dir_to** — диапазон направлений скорости партиклов.
* **countmultiplier** — множитель количества партиклов относительно того, что задано в описании эффекта.
* **flags** *(optional)* — дополнительные битовые флаги эффекта.

#### Описание и логика работы
Расширенная версия `pointparticles`, позволяющая распределить партиклы по объёму (боксу), а не по одной точке, и задать диапазон направлений вместо единственного вектора. Полезна для эффектов вроде дождя над областью, взрыва в объёме или разлёта обломков по случайным направлениям. Мировые координаты. Некорректный `effectindex` (0 или незарегистрированный) не вызывает партиклов и не приводит к ошибке.

#### Практические сценарии использования
```c
float rainfx;
void() Init_Rain = { rainfx = particleeffectnum("envfx.rain"); };
void() CSQC_UpdateView =
{
	boxparticles(rainfx, world, '-200 -200 300', '200 200 300', '0 0 -1', '0 0 -1', 1, 0);
};
```

### particle
`void(vector pos, vector dir, float colour, float count) particle = #48;`

* **pos** — мировая точка появления партиклов.
* **dir** — направление и скорость разлёта партиклов.
* **colour** — индекс палитры Quake (используется диапазон `colour`..`colour+8` для вариации оттенка).
* **count** — количество партиклов.

#### Описание и логика работы
Базовый, самый старый способ породить классические квейковские партиклы (маленькие цветные точки-квадратики), раскрашенные по индексу палитры, а не по RGB. До сих пор используется для ретро-эффектов вроде пыли или искр, совместимых со старым software-рендерингом. Мировые координаты. При `count` равном 0 партиклы не появляются, отрицательные значения не имеют смысла и трактуются как 0 либо игнорируются.

#### Практические сценарии использования
```c
void() SpawnDust =
{
	particle(self.origin, '0 0 40', 111, 8); // серая пыль классической палитры
};
```

### particle2

Работает исключительно в мировых координатах.

#### Практические сценарии использования

```c
void() SpawnHexenSparkle =
```

```c
void() SpawnBoxBurst =
```

### particleeffectnum
`float(string effectname) particleeffectnum = #335;`

* **effectname** — имя эффекта партиклов; форма `foo.bar` заставит клиента при необходимости подгрузить `particles/foo.cfg`.

#### Описание и логика работы
Прекэширует (регистрирует) именованный эффект партиклов и возвращает его числовой индекс, который затем передаётся в `pointparticles`, `trailparticles`, `boxparticles`.
```c
float fx_muzzleflash;
```

### particleeffectquery
`string(float efnum, float body) particleeffectquery = #374;`

#### Описание и логика работы

Описание регенерируется из внутреннего состояния движка и может быть изменено и повторно применено через [`localcmd`](12-system-debug-builtins.md#localcmd) (например, командой `r_particlesdesc` или аналогичной, в зависимости от версии движка), что удобно для отладки и тонкой настройки эффектов "на лету". Не относится к рисованию сцены напрямую — это интроспекция состояния партикльной системы.

#### Практические сценарии использования
```c
void(float efnum) DumpEffectBody =
```

### pointparticles
`void(float effectnum, vector origin, optional vector dir, optional float count) pointparticles = #337;`

* **effectnum** — номер эффекта (от `particleeffectnum`).
* **origin** — мировая точка появления.
* **dir** *(optional)* — направление/ориентация; для обычных партиклов умножается на свойство [`veladd`](../41-particle-directives-reference/02-particle-spawn-behaviour-directives.md#veladd) эффекта, для декалей используется как подсказка ориентации по поверхности. При нулевой длине FTE считает направление "вниз".
* **count** *(optional)* — множитель количества партиклов относительно описания эффекта.

#### Описание и логика работы
Основной способ выпустить партиклы предварительно зарегистрированного именованного эффекта в одной точке — используется для вспышек выстрела, попаданий, взрывов и т.п. Мировые координаты. Если `effectnum` равен 0 или не зарегистрирован, партиклы просто не появляются, ошибки не возникает.

#### Практические сценарии использования
```c
void() FireWeapon =
{
	pointparticles(fx_muzzleflash, self.origin + v_forward * 16, v_forward, 1);
};
```

### trailparticles
`void(float effectnum, entity ent, vector start, vector end) trailparticles = #336;`

* **effectnum** — номер эффекта.
* **ent** — entity, к которой привязывается след (если не `world`, используется для кеширования пройденного расстояния между кадрами); сама по себе не рисуется.
* **start**, **end** — начальная и конечная точки отрезка следа за этот кадр.

#### Описание и логика работы
Рисует след партиклов (дымовой шлейф, огненную трассу и т.п.) вдоль отрезка от `start` до `end` за текущий кадр. Если передана не-world `ent`, движок кеширует накопленное расстояние в самой entity, чтобы плотность партиклов на единицу длины не зависела от FPS. Мировые координаты, вызывается каждый кадр движения снаряда/entity.

#### Практические сценарии использования
```c
void() Rocket_Think =
{
	trailparticles(fx_smoketrail, self, self.oldorigin, self.origin);
	self.oldorigin = self.origin;
};
```

Обычно используется для спрайтовых вспышек и коротких визуальных эффектов, унаследованных от старых модов DarkPlaces. Мировые координаты.

```c
void() SpawnFlashSprite =
```

### dynamiclight_add
`float(vector org, float radius, vector lightcolours, optional float style, optional string cubemapname, optional float [pflags](../39-entity-keys-reference/02-light-entity-keys.md#pflags)) dynamiclight_add = #305;`

* **org** — мировая позиция источника света.
* **radius** — радиус освещения.
* **lightcolours** — цвет света.
* **style** *(optional)* — номер lightstyle для мерцания/пульсации.
* **cubemapname** *(optional)* — имя cubemap/проекционной текстуры; ориентация читается из `v_forward`/`v_right`/`v_up`.
* **pflags** *(optional)* — дополнительные флаги. Если аргумент опущен, текущая реализация использует `PFLAGS_CORONA`.

#### Описание и логика работы
Добавляет динамический свет в список текущего кадра и возвращает его индекс. Свет должен быть создан между `clearscene` и `renderscene`; если он нужен каждый кадр, его надо добавлять заново. Возвращённый номер можно сразу использовать в `dynamiclight_get`/`dynamiclight_set` для точной настройки отдельных полей.

#### Практические сценарии использования
```c
void() Rocket_Think =
{
	float lno;

	lno = dynamiclight_add(self.origin, 200, '1.2 0.6 0.2', 0);
	dynamiclight_set(lno, LFIELD_RADIUS, 220);
	self.nextthink = time;
};
```

```c
void(float lno) DumpLightRadius =
```

### lightstyle
`void(float lightstyle, string stylestring, optional vector rgb) lightstyle = #35;`

* **lightstyle** — номер стиля освещения (0..63, как в стандартном Quake).
* **stylestring** — строка автоанимации яркости, где `'a'` — выключено, `'z'` — максимальная яркость; допустимы только строчные буквы.
* **rgb** *(optional)* — цвет, которым будут перекрашены все источники света, использующие этот lightstyle.

#### Описание и логика работы
Задаёт (переопределяет) анимационную строку яркости для указанного номера lightstyle — то же самое, что и мигающие/пульсирующие светильники в оригинальном Quake (torch flicker, strobe и т.д.). Влияет на все статические источники света карты и динамические источники, использующие этот стиль. В CSQC обычно применяется для собственных эффектов мерцания, синхронизированных с игровой логикой (например, аварийное освещение).

#### Практические сценарии использования
```c
void() FlickerEmergencyLights =
{
	lightstyle(10, "mmamammmmammamamaaamammma", '1 0.3 0.3');
};
```

```c
void() TurnOnStaticLight =
```

### CustomTempEnt

На стороне CSQC мод сам решает, как визуализировать полученное событие (обычно вызывая `pointparticles`, `dynamiclight_add`, `adddecal` и т.п. в соответствующем обработчике). // ssqc: разослать эффект попадания по щиту

```c
};
```

### te_blood
`void(vector org, vector dir, float count) te_blood = #405;`

#### Описание и логика работы

### addentity_lighting

#### Пример использования

```qc
};
```

### addtrisoup_simple
`void(string texturename, int flags, trisoup_simple_vert_t *verts, int *indexes, int numindexes) addtrisoup_simple = #0:addtrisoup_simple;`

* **texturename** — `string`, имя текстуры/шейдера.
* **flags** — `int`, флаги рендера для добавляемой геометрии.
* **verts** — указатель на массив вершин `trisoup_simple_vert_t`.
* **indexes** — указатель на массив индексов.
* **numindexes** — количество индексов; это именно triangle-list, поэтому один треугольник = 3 индекса.

#### Описание и особенности работы
`addtrisoup_simple` добавляет в сцену заранее подготовленный индексированный triangle soup. Это pointer-based builtin: он не принимает variadic-список вершин и не строит геометрию «на лету» из аргументов вызова. Практический смысл — уменьшить builtin spam, если у вас уже есть подготовленные массивы вершин и индексов в памяти QC.

#### Пример использования
```qc
void(string tex, float flags, trisoup_simple_vert_t *verts, int *indexes, float numindexes) SubmitPreparedMesh =
{
    addtrisoup_simple(tex, flags, verts, indexes, numindexes);
};
```

### drawrotpic
`void(vector pivot, vector mins, vector maxs, string pic, vector rgb, float alpha, float angle, optional float drawflag) drawrotpic = #0:drawrotpic;`

* **pivot** — экранная точка, вокруг которой выполняется поворот.
* **mins**, **maxs** — прямоугольник изображения относительно `pivot`; для вращения вокруг центра обычно используют половину размера с отрицательными `mins`.
* **pic** — имя картинки/шейдера.
* **rgb** — цветовой множитель.
* **alpha** — прозрачность.
* **angle** — угол в градусах.
* **drawflag** *(optional)* — режим смешивания.

#### Описание и особенности работы
`drawrotpic` рисует 2D-картинку, повёрнутую на заданный угол вокруг точки `pivot`. В отличие от старого DP-описания, builtin принимает не вектор `forward`, а угол в градусах и пару `mins/maxs`, задающую геометрию прямоугольника относительно pivot.

#### Пример использования
```qc
void(vector center, float angle) DrawRadarCompass =
{
    drawrotpic(center, '-16 -16 0', '16 16 0', "gfx/hud/arrow", '1 1 1', 1, angle, 0);
};
```

* **size** — полный размер прямоугольника.
* **mins** — смещение левого верхнего угла относительно `pivot`; `maxs` вычисляется как `size - mins`.
* **angle** — угол в градусах.
* **rgb**, **alpha** — цвет и прозрачность.
* **drawflag** *(optional)* — режим смешивания.

#### Описание и особенности работы
`drawrotpic_dp` — совместимый с DarkPlaces вариант вращающейся картинки. Внутренне он делает ту же 2D-отрисовку, но использует другой порядок аргументов, поэтому не является точной копией сигнатуры `drawrotpic`.

#### Пример использования
```qc
void(vector center, float angle) DrawDPAxisCrosshair =
{
    drawrotpic_dp(center, "gfx/hud/cross_rot", '64 64 0', '-32 -32 0', angle, '1 1 1', 1, 0);
};
```

### drawrotsubpic
`void(vector pivot, vector mins, vector maxs, string pic, vector txmin, vector txsize, vector rgb, vector alphaandangles) drawrotsubpic = #0:drawrotsubpic;`

* **pivot**, **mins**, **maxs** — геометрия как у `drawrotpic`.
* **pic** — имя текстуры/атласа.
* **txmin**, **txsize** — начало и размер вырезаемого участка текстуры.
* **rgb** — цветовой множитель.

`drawrotsubpic` совмещает идеи `drawrotpic` и `drawsubpic`: поворачивает не всю картинку, а выбранный прямоугольник из атласа. Важная особенность API — прозрачность, угол и drawflag упакованы в один вектор `alphaandangles`.

```qc
void(vector center, float angle) DrawSpeedometerNeedleFromAtlas =

    alpha_angle_flag_x = 1;
    alpha_angle_flag_y = angle;
    alpha_angle_flag_z = 0;

```

```qc
void(vector fireplace_org) SpawnPermanentCampfireLight =
```

* **style** — `float`, индекс стиля освещения.

```qc
void() UpdateShaderWithMapLightstyle =
```

```qc
void(float lno) SynchronizeLampWithMapStyle =
```

### getlocationname
`string(vector org) getlocationname = #0:getlocationname;`

* **org** — `vector`, 3D-координаты точки в мировом пространстве карты, для которой требуется определить название локации.
* **Возвращает**: `string` — текстовое название локации, закрепленное за данной областью на карте (например, `"Blue Base"`, `"Generator Room"`), либо пустую строку `""`, если точка находится вне именованных зон.

#### Описание и особенности работы
`getlocationname` — это полностью реализованная встроенная функция клиентской части движка (CSQC) в экосистеме FTEQW. Метод предназначен для автоматического определения строкового названия именованной зоны (Location), внутри которой находятся переданные 3D-координаты `org`. На уровне Си-кода ядра движок выполняет пространственный поиск по специальным навигационным сущностям (таким как `target_location` или встроенные триггеры именования зон), которые запекаются в BSP-файл карты или загружаются из внешних конфигурационных файлов (например, `.loc`-файлов в стиле QuakeWorld). Функция оптимизирована на уровне ядра для быстрых пространственных выборок и не создает накладных расходов. Данный builtin активно применяется разработчиками для вывода динамических подсказок в интерфейсе (HUD): отображения текущего местоположения игрока, формирования автоматических сообщений в командный чат (команды вида *«[Игрок] на [Локация]: нужна помощь!»*), а также для логирования событий в соревновательных игровых режимах.

#### Пример использования
```qc
void() CSQC_UpdateHUD_Location =
{
    local string loc_name;

    loc_name = getlocationname(pmove_org);
    if (loc_name == "")
        loc_name = "Unknown zone";
    drawstring('16 16 0', sprintf("Current position: %s", loc_name), '8 8 0', '1 1 1', 1, 0);
};
```

### pointcontentsmask
`__uint(vector org, optional float worldonly) pointcontentsmask = #0:pointcontentsmask;`

* **org** — `vector`, 3D-координаты проверяемой точки.
* **worldonly** *(optional)* — не content-mask, а переключатель области поиска: опущено/неноль = только world BSP, `0` = world BSP плюс прочие BSP-модели.
* **Возвращает**: беззнаковую битовую маску содержимого.

#### Описание и особенности работы
`pointcontentsmask` похожа на расширенную [`pointcontents`](03-entity-world-builtins.md#pointcontents), но её второй аргумент в CSQC не задаёт произвольную маску фильтра. Вместо этого он переключает режим запроса: только основной мир или все BSP-объекты, включая движущиеся brush-модели вроде дверей и лифтов. Возвращаемое значение — contents bitmask, а не старый одиночный код типа `CONTENT_WATER`.

#### Пример использования
```qc
void() CSQC_DebugContents =
{
    local float world_contents;
    local float all_bsp_contents;

    world_contents = pointcontentsmask(pmove_org);
    all_bsp_contents = pointcontentsmask(pmove_org, 0);
    dprint(sprintf("world=%g allbsp=%g\n", world_contents, all_bsp_contents));
};
```

### R_EndPolygonRibbon
`void(float radius, vector texcoordbias) R_EndPolygonRibbon = #0:R_EndPolygonRibbon;`

* **radius** — половина ширины генерируемой ленты.
* **texcoordbias** — добавка к `s/t` текстурным координатам для верхней стороны ribbon.

#### Описание и особенности работы
`R_EndPolygonRibbon` завершает не обычный полигон, а текущую полилинию, превращая уже добавленные через `R_PolygonVertex` точки в экранно-ориентированную ribbon/quad strip. Для работы нужно минимум две вершины. Builtin сам дублирует вершины, раздвигает их в стороны относительно направления линии и взгляда камеры и строит индексированный набор треугольников.

#### Пример использования
```qc
void(vector start_pos, vector end_pos) SpawnProjectileBeamTrail =
{
    R_BeginPolygon("shaders/beam_trail", 0, FALSE);
    R_PolygonVertex(start_pos, '0 0 0', '1 1 1', 1);
    R_PolygonVertex(end_pos, '1 0 0', '1 1 1', 1);
    R_EndPolygonRibbon(4, '0 0 0');
};
```

### r_readimage
`int*(string filename, __out int width, __out int height, __out int format) r_readimage = #0:r_readimage;`

* **filename** — имя файла изображения.
* **width**, **height** *(out)* — размеры декодированного изображения.
* **format** *(out)* — формат возвращённых пикселей.
* **Возвращает**: указатель на новый буфер с пиксельными данными либо `0` при ошибке.

#### Описание и особенности работы
`r_readimage` сам выделяет addressable-буфер в памяти QC, декодирует изображение и возвращает указатель на RGBA-данные. Это не API вида «передай свой буфер и maxsize». Размеры и формат передаются через out-параметры.

#### Пример использования
```qc
void(string custom_logo_path) ProcessTextureBytes =
{
    local int w, h, fmt;
    local int *pixels;

    pixels = r_readimage(custom_logo_path, w, h, fmt);
    if (pixels)
        dprint(sprintf("image %gx%g loaded\n", w, h));
};
```

### r_uploadimage
`void(string imagename, int width, int height, void *pixeldata, optional int datasize, optional int format) r_uploadimage = #0:r_uploadimage;`

* **imagename** — имя создаваемой картинки/текстуры.
* **width**, **height** — размеры изображения.
* **pixeldata** — указатель на пиксельный буфер.
* **datasize** *(optional)* — размер буфера; если аргумент опущен, движок ожидает обычный `width*height*4`.
* **format** *(optional)* — формат пиксельных данных; по умолчанию используется RGBA32.

#### Описание и особенности работы
`r_uploadimage` загружает в движок пиксели из уже существующего буфера памяти QC. В актуальном API сначала идут размеры и указатель на данные, а optional-аргументы задают размер буфера и формат кодирования. Хотя текущая реализация внутренне записывает `0/1` в return register, в QC def-файлах builtin объявлен как `void`, поэтому переносимый код не должен полагаться на return value.

#### Пример использования
```qc
void(void *raw_pixels) UploadProceduralTexture =
{
    r_uploadimage("gfx/procedural_grid", 2, 2, raw_pixels, 16);
};
```

### remapshader
`void(string oldshader, string newshader) remapshader = #0:remapshader;`

* **oldshader** — `string`, имя исходного графического материала, текстуры или шейдера, который подлежит замене.
* **newshader** — `string`, имя нового целевого шейдера, который будет подставляться графическим конвейером вместо исходного.

#### Описание и особенности работы
Метод выполняет динамическую подмену (перенаправление) графических материалов на уровне глобального менеджера текстур и шейдеров.

#### Пример использования
```qc
void() CSQC_ActivateThermalVision =
{
    // Перенаправляем стандартную текстуру кожи игрока на кастомный светящийся шейдер
    // Все игроки на карте, использующие этот материал, визуально изменятся
    remapshader("models/player/player_skin", "shaders/thermal_glow");
};

void() CSQC_DeactivateThermalVision =
{
    // Возвращаем оригинальное отображение текстуры, перенаправляя шейдер на самого себя
    remapshader("models/player/player_skin", "models/player/player_skin");
};
```

### setcolor
`setcolor(...)` — данная встроенная функция не реализована и является жесткой заглушкой (номера: CSQC=#401).

* Параметры не специфицированы, вызов не имеет функционального смысла.

#### Описание и особенности работы
`setcolor` (в некоторых версиях таблиц упоминается как [`setcolors`](10-skeletal-model-builtins.md#setcolors)) представляет собой нереализованный опкод под номером `#401` в клиентской виртуальной машине (CSQC). Как прямо указывает пометка из комментариев к исходному коду Си-ядра движка FTEQW (*«#401 void(entity cl, float colours) setcolors (DP_SV_SETCOLOR) (don't implement)»*), разработчики целенаправленно отказались от её интеграции, оставив слот пустым и перенаправив его на стандартную системную заглушку `PF_Fixme`. Первоначально эта функция планировалась для обратной совместимости с расширением серверной части движка DarkPlaces (`DP_SV_SETCOLOR`), которое позволяло принудительно менять палитру цветов одежды/кожи (shirt и pants) конкретного игрока или сетевого эдикта. В архитектуре FTEQW этот функционал на стороне CSQC заблокирован, так как управление палитрами моделей и цветами команд нативно и более гибко реализуется штатными методами модификации полей сущностей и шейдерами, а сам слот №401 оставлен исключительно для фиксации позиции в бинарной таблице встроенных методов компилятора. Попытка вызова функции вызовет ошибку выполнения в консоли.

### trailparticles_dp
`void(float effectindex, entity ent, vector start, vector end) trailparticles_dp = #336;`

* **effectindex** — `float`, глобальный индекс или тип эффекта частиц (Particle Effect ID), зарегистрированный в системе эффектов движка.
* **ent** — `entity`, сущность, к которой привязывается или от которой рассчитывается данный шлейф (может использоваться для чтения `.velocity` или исключения из расчетов).
* **start** — `vector`, 3D-координаты начальной точки отрезка, вдоль которого будут сгенерированы частицы.
* **end** — `vector`, 3D-координаты конечной точки отрезка.

#### Описание и особенности работы
`trailparticles_dp` — это полностью реализованная встроенная функция графической подсистемы частиц на стороне клиентской части (CSQC). Этот метод был добавлен исключительно для обеспечения бинарной обратной совместимости с расширениями системы частиц движка **DarkPlaces**. В экосистеме DarkPlaces генерация шлейфов частиц жёстко завязана на передачу отрезка мировых координат (`start` и `end`), что авторы FTEQW посчитали архитектурно неоптимальным решением. Тем не менее, внутри FTEQW эта функция полноценно работает: движок берёт указанный отрезок, рассчитывает шаг интерполяции и заполняет пространство между точками партиклами из нативного генератора эффектов текущей карты. Метод используется для того, чтобы старые или кросс-платформенные моды, изначально написанные под DarkPlaces, могли без изменения исходного QuakeC-кода отрисовывать шлейфы за летящими снарядами, трассеры пуль, дымовые хвосты ракет или световые лучи.

#### Пример использования
```qc
void(entity rocket) SpawnDPRocketTrail =
{
    // Генерируем стандартный шлейф частиц (индекс эффекта 1) от старой позиции ракеты к новой
    // Используем опкод #336 для совместимости с кодовой базой DarkPlaces
    trailparticles_dp(1, rocket, rocket.oldorigin, rocket.origin);
};
```

### V_CalcRefdef
`V_CalcRefdef(...)` — данная встроенная функция не реализована и является жесткой заглушкой (номера: CSQC=#640).

* Параметры не специфицированы, вызов не имеет функционального смысла.

#### Описание и особенности работы
`V_CalcRefdef` представляет собой нереализованный опкод под номером `#640` в клиентской виртуальной машине (CSQC). Как наглядно подтверждает структура си-таблицы встроенных функций в исходном коде репозитория FTEQW (где соседний слот `#641` прямо заблокирован записью `{NULL, PF_Fixme, 641}`), эта экспериментальная функция полностью лишена внутренней Си-реализации в ядре и перенаправлена на стандартный макрос прерывания `PF_Fixme`. Изначально авторы движка планировали выделить этот опкод для принудительного нативного расчета параметров отображения сцены и камеры (Refdef — Reference Definition, включая позицию, углы обзора, FOV и матрицы проекции) непосредственно из QuakeC, чтобы разгрузить скриптовую логику `CSQC_CalcRefdef`. Однако архитектурно вся математика расчетов осталась внутри стандартного графического движка и ручных манипуляций с глобальными переменными, а данный метод так и остался черновиком. Любая попытка его вызова приведет к выводу сообщения об ошибке выполнения встроенного метода в консоль.
