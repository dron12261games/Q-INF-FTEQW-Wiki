# Точки входа QuakeC: SSQC, CSQC и MenuQC

> [⬅ Вернуться к оглавлению вики](../README.md)

> [Индекс справочника builtins](./README.md)

В отличие от builtin-функций (которые скрипт QuakeC *вызывает сам*, чтобы попросить движок что-то сделать), точки входа — это функции, которые скрипт лишь *объявляет* под строго определённым именем, а вызывает их уже сам движок в нужный момент игрового цикла. Разработчику мода достаточно описать функцию с ожидаемым именем и сигнатурой — специально регистрировать её не нужно, движок находит её автоматически по имени при загрузке `.dat`-файла логики. Если конкретная точка входа не описана в коде мода, движок просто пропускает её вызов (за редкими исключениями, отмеченными отдельно ниже) — никакой ошибки не произойдёт.

Эта статья — единый, содержащий все три модуля справочник по именам точек входа, их точным сигнатурам и моменту вызова. Это дополняет (но не заменяет) более широкие обзорные статьи о самих модулях, где объясняется общая архитектура и принцип работы каждой VM:

- [Серверная игровая логика (SSQC)](../16-quakec-scripting/server-side-quakec-ssqc.md)
- [Клиентская логика и интерфейс (CSQC)](../16-quakec-scripting/client-side-quakec-csqc.md)
- [Логика игровых меню (MenuQC)](../16-quakec-scripting/menu-quakec.md)

Важное практическое замечание: три модуля — это три полностью независимых виртуальных прогс-файла (`progs.dat`, `csprogs.dat`, `menu.dat`), у каждого свой набор глобальных переменных и полей сущностей. Функция с одинаковым именем в разных модулях (например, `ClientConnect` в SSQC и любая функция MenuQC) не имеет друг к другу никакого отношения — движок ищет и вызывает их независимо в контексте соответствующей VM.

## SSQC: точки входа серверной логики

Все функции ниже объявляются в исходниках, которые компилируются в `progs.dat` (см. интерфейс настройки в статье [«Серверная игровая логика (SSQC)»](../16-quakec-scripting/server-side-quakec-ssqc.md)). Все они необязательны, кроме отдельно оговорённых случаев.

### SetNewParms
`void() SetNewParms`

#### Описание и логика работы

`SetNewParms` вызывается движком ровно один раз для каждого клиента — в момент его первого подключения к серверу, причём даже раньше, чем `ClientConnect`. На этом этапе у клиента ещё нет связанного игрового объекта (`self` не гарантированно указывает на что-то осмысленное), поэтому единственная разумная задача этой функции — выставить начальные («стартовые») значения шестнадцати глобальных переменных `parm1`…`parm16`. Это «сумка» числовых слотов на игрока, которая переживает переход между уровнями (в отличие от полей сущности, которые создаются заново на каждой карте) и позднее считывается через [`setspawnparms`](03-entity-world-builtins.md#setspawnparms). Если не описать эту функцию вообще, `parm1`…`parm16` останутся с значением `0` для новых игроков, что для большинства модов уже приемлемо (0 боеприпасов, 0 очков и т.д.), но, например, для стартового здоровья в 100 единиц эту функцию описать обязательно нужно.

#### Практические сценарии использования

```
void() SetNewParms =
{
	// Новый игрок должен начинать с полным здоровьем, дробовиком и небольшим
	// запасом патронов - как в оригинальном Quake.
	parm1 = 100;         // health
	parm2 = 0;           // armorvalue
	parm3 = IT_SHOTGUN;  // items (бит дробовика)
	parm4 = 0;           // weapon
	parm5 = 25;          // ammo_shells
	parm6 = 0;           // ammo_nails
	parm7 = 0;           // ammo_rockets
	parm8 = 0;           // ammo_cells
};
```

### SetChangeParms
`void() SetChangeParms`

#### Описание и логика работы

Вызывается для каждого клиента при переходе на следующий уровень (обычная смена карты по триггеру выхода, а не по `changelevel` с явным сбросом). В отличие от `SetNewParms`, здесь уже доступен `self` как текущий объект игрока, поэтому задача функции — скопировать актуальные на момент выхода с уровня поля игрока (здоровье, броню, оружие, боеприпасы, набранные предметы) в те же самые глобальные переменные `parm1`…`parm16`, чтобы они «пережили» смену `progs`-состояния мира. Если игрок должен терять часть прогресса между уровнями (например, аркадный режим с полным сбросом инвентаря на каждой карте), эту функцию можно намеренно упростить, не копируя часть полей.

#### Практические сценарии использования

```
void() SetChangeParms =
{
	// Переносим здоровье (но не более 50, чтобы штрафовать за смерти на уровне),
	// броню и всё найденное оружие и патроны на следующую карту.
	parm1 = bound(50, self.health, 100);
	parm2 = self.armorvalue;
	parm3 = self.items;
	parm4 = self.weapon;
	parm5 = self.ammo_shells;
	parm6 = self.ammo_nails;
	parm7 = self.ammo_rockets;
	parm8 = self.ammo_cells;
};
```

### ClientConnect
`void() ClientConnect`

#### Описание и логика работы

Вызывается один раз, когда подключающийся игрок полностью загрузился (принял все прекэши ресурсов) и готов получать активные объекты игрового мира. Это ещё не первая точка, где клиент вообще упоминается в логике (`SetNewParms` вызывается раньше), но это первый момент, когда с игроком можно работать как с полноценной сущностью через `self`. Именно здесь удобно проверить поддержку клиентом CSQC (через `infokeyf(self, INFOKEY_P_CSQCACTIVE)`) и принудительно отключить игрока ([`dropclient`](03-entity-world-builtins.md#dropclient)), если мод требует обязательного использования клиентской логики — до этого момента подобная проверка была бы бессмысленной, так как клиент ещё не сообщил о своих возможностях. Здесь же обычно рассылается приветственное сообщение и объявление о подключении нового игрока остальным.

#### Практические сценарии использования

```
void() ClientConnect =
{
	// Требуем от игроков поддержку CSQC - иначе интерфейс мода не будет работать.
	if (!infokeyf(self, INFOKEY_P_CSQCACTIVE))
	{
		sprint(self, "Этому серверу требуется поддержка CSQC для игры\n");
		dropclient(self);
		return;
	}

	bprint(PRINT_HIGH, self.netname);
	bprint(PRINT_HIGH, " подключился к игре\n");
};
```

### PutClientInServer
`void() PutClientInServer`

#### Описание и логика работы

Со стороны движка эта функция вызывается сразу после `ClientConnect` — на этом этапе разница между ними чисто условная (по историческим причинам из classic Quake). Но со стороны логики мода `PutClientInServer` вызывается заново при *каждом* возрождении игрока после смерти (респауне), а не только при первом подключении — поэтому именно сюда, а не в `ClientConnect`, обычно выносят код выставления стартового здоровья, оружия, боеприпасов и позиции точки появления (`info_player_start`/`info_player_deathmatch`). Здесь же типично сбрасывают `deadflag`, `movetype`, `solid` в игровые значения после того, как труп предыдущей смерти этого игрока убирается с арены.

#### Практические сценарии использования

```
void() PutClientInServer =
{
	self.classname = "player";
	self.health = 100;
	self.armorvalue = 0;
	self.deadflag = DEAD_NO;
	self.movetype = MOVETYPE_WALK;
	self.solid = SOLID_SLIDEBOX;
	self.takedamage = DAMAGE_AIM;
	self.items = IT_SHOTGUN;
	self.weapon = IT_SHOTGUN;
	self.ammo_shells = 25;

	// Ставим игрока в случайную точку появления, а не всегда в одну и ту же.
	self.origin = SelectRandomSpawnPoint();
	setorigin(self, self.origin);
};
```

### ClientKill
`void() ClientKill`

#### Описание и логика работы

Вызывается в ответ на игровую консольную команду `kill` (игрок сам решил покончить с собой, например застряв в геометрии карты). Это не единственный способ смерти — обычная боевая смерть от урона обрабатывается через функцию `.th_die` конкретного объекта игрока, а не через эту точку входа. `ClientKill` — это специально выделенный, отдельный путь для самоубийства «по команде», обычно с некоторым штрафом (например, `-1` к счёту фрагов) и упрощённой логикой смерти без учёта конкретного оружия убийства.

#### Практические сценарии использования

```
void() ClientKill =
{
	// Штрафуем за самоликвидацию, в отличие от обычной гибели от рук противника.
	self.frags = self.frags - 1;
	self.deadflag = DEAD_DEAD;
	self.health = 0;

	bprint(PRINT_HIGH, self.netname);
	bprint(PRINT_HIGH, " покончил с собой\n");

	// Дальше используется стандартный механизм смерти, например через th_die.
	self.think = respawn_player;
	self.nextthink = time + 1;
};
```

### PlayerPreThink
`void() PlayerPreThink`

#### Описание и логика работы

Вызывается каждый кадр физики сервера для каждого активного игрока — раньше, чем движок обработает ввод этого игрока (нажатия клавиш, движение мыши). Важный нюанс, зависящий от режима предсказания: при включённом предсказании движения (поведение по умолчанию для FTE и режим совместимости QuakeWorld) функция действительно вызывается до применения ввода. Но в режиме совместимости NetQuake без предсказания она вызывается уже *после* того, как в скорость игрока (`velocity`) внесены изменения от ввода (`input_*`), но ещё до фактического применения изменения позиции. Здесь обычно реализуют логику, которая должна успеть отреагировать до движения — например, состояние «оглушён» или «заморожен», временно обнуляющее допустимое ускорение игрока.

#### Практические сценарии использования

```
void() PlayerPreThink =
{
	// Пока активен эффект оглушения, полностью гасим управление движением
	// ещё до того, как оно будет применено к скорости игрока.
	if (self.stunned_until > time)
	{
		self.velocity = '0 0 0';
	}
};
```

### PlayerPostThink
`void() PlayerPostThink`

#### Описание и логика работы

Вызывается каждый кадр физики сервера для каждого активного игрока, уже после того как обработаны команды ввода и применено перемещение. Это самое частое место для логики, зависящей от актуальной, уже обновлённой позиции и состояния игрока в этом кадре — проверка попадания в триггерные зоны по текущей позиции, регенерация здоровья со временем, обновление таймеров текущего оружия, анимация модели игрока по посчитанной скорости движения.

#### Практические сценарии использования

```
void() PlayerPostThink =
{
	// Медленная регенерация здоровья вне боя, не выше базовых 100 единиц.
	if (self.health > 0 && self.health < 100 && time > self.pain_finished)
	{
		if (time > self.regen_next)
		{
			self.health = self.health + 1;
			self.regen_next = time + 1;
		}
	}
};
```

### StartFrame
`void() StartFrame`

#### Описание и логика работы

Вызывается один раз за кадр физики сервера — до того, как обрабатываются `think`-функции каких-либо игровых объектов. Это удобное место для глобальной, не привязанной к конкретному объекту логики уровня целиком: обратный отсчёт таймера раунда, периодический респаун предметов на карте, обновление статистики матча, отправка периодических сетевых сообщений всем игрокам. Так как объекты-игроки могут «думать» не в строго предсказуемом порядке между кадрами, не стоит полагаться на порядок вызовов относительно `PlayerPreThink`/`PlayerPostThink` конкретных игроков внутри одного и того же кадра.

#### Практические сценарии использования

```
void() StartFrame =
{
	// Общий таймер раунда, уменьшающийся раз в секунду, независимо
	// от какого-либо конкретного игрового объекта.
	if (time > round_timer_next)
	{
		round_timer_next = time + 1;
		round_time_left = round_time_left - 1;

		if (round_time_left <= 0)
			EndRoundByTimeout();
	}
};
```

### EndFrame
`void() EndFrame`

#### Описание и логика работы

Менее известная точка входа, вызываемая после того, как отработали `think`-функции всех не-игровых объектов в конце кадра физики. Важная оговорка: физика самих игроков обрабатывается движком отдельно и может всё ещё выполниться уже после вызова `EndFrame`, поэтому нельзя полагаться на то, что к этому моменту все игроки гарантированно уже подвинулись в этом кадре. Практическое применение — сбор пост-обработочной статистики или отложенных эффектов, которые должны учитывать состояние всех объектов мира (кроме игроков) уже после их обработки в текущем кадре.

#### Практические сценарии использования

```
void() EndFrame =
{
	// Обновляем счётчик активных монстров на уровне уже после того,
	// как все их think-функции в этом кадре отработали (например, кто-то умер).
	world_active_monster_count = CountEntitiesWithClassnamePrefix("monster_");
};
```

### ClientDisconnect
`void() ClientDisconnect`

#### Описание и логика работы

Вызывается, когда игрок отключается от сервера штатно (закрыл игру, набрал `disconnect`) или отвалился по таймауту связи. Важный практический нюанс: эта функция **не гарантированно** вызывается при смене уровня (`changelevel`) — при обычном переходе между картами вместо этого вызывается `SetChangeParms`, а `ClientDisconnect` относится именно к настоящему уходу игрока с сервера. Здесь типично объявляют об уходе игрока остальным, снимают его с таблицы результатов или удаляют временные объекты, которые он держал (например, поднятый флаг в захвате флага нужно бросить на месте).

#### Практические сценарии использования

```
void() ClientDisconnect =
{
	bprint(PRINT_HIGH, self.netname);
	bprint(PRINT_HIGH, " покинул игру\n");

	// Если игрок нёс флаг команды - роняем флаг на месте его последней позиции,
	// а не забираем вместе с ним.
	if (self.flag_carried)
		DropFlagAt(self.origin);
};
```

### main (устаревшая, не вызывается)
`void() main`

#### Описание и логика работы

Историческое наследие ранних версий Quake: в текущем движке FTEQW эта функция объявлена в перечне известных имён, но **фактически никогда не вызывается** — это мёртвый код. Она сохранена в списке распознаваемых имён исключительно для полноты и обратной совместимости со старыми прогс-файлами, где она могла присутствовать по инерции из ранних экспериментальных версий движка id Software. Описывать её в собственном моде не нужно и не имеет никакого практического эффекта — используйте `SetNewParms`/`ClientConnect`/`StartFrame` для соответствующей инициализационной логики.

## CSQC: точки входа клиентской логики

Компилируются в `csprogs.dat` (см. [«Клиентская логика и интерфейс (CSQC)»](../16-quakec-scripting/client-side-quakec-csqc.md) про интерфейс подключения и полный набор builtins рисования/сцены).

### CSQC_Init
`void(float apilevel, string enginename, float engineversion) CSQC_Init`

* **apilevel** — `float`, номер версии CSQC API, которую поддерживает движок — позволяет логике определить, какие расширения точно доступны.
* **enginename** — `string`, человекочитаемое имя движка (например, `"FTEQW"`), для отличия от других QuakeC-совместимых движков (DarkPlaces, QSS и т.д.).
* **engineversion** — `float`, числовая версия конкретного движка.

#### Описание и логика работы

Вызывается один раз при загрузке клиентской логики — это стартовая, самая первая точка входа CSQC, аналог конструктора всего модуля. Именно здесь принято делать любую одноразовую инициализацию: прекэш изображений и шрифтов интерфейса, создание стартовых значений глобальных переменных HUD, регистрацию собственных консольных команд через [`registercommand`](03-entity-world-builtins.md#registercommand). Аргументы функции позволяют логике определить, с каким именно движком она имеет дело, и отключить использование движок-специфичных расширений, если код должен сохранять совместимость с другими QuakeC-совместимыми клиентами (например, DarkPlaces).

#### Практические сценарии использования

```
void(float apilevel, string enginename, float engineversion) CSQC_Init =
{
	// Регистрируем собственную консольную команду интерфейса.
	registercommand("togglescoreboard");

	// Заранее прекэшируем изображения HUD, чтобы не было "лагов" на первом кадре.
	precache_pic("gfx/hud/health.tga");
	precache_pic("gfx/hud/armor.tga");

	if (enginename == "FTEQW")
		hud_uses_fte_extensions = TRUE;
};
```

### CSQC_WorldLoaded
`void() CSQC_WorldLoaded`

#### Описание и логика работы

Вызывается после того, как клиент завершил загрузку карты и обработал прекэши моделей и звуков, присланные сервером. Это специально выделенный момент для чтения содержимого entity-лампы (текстового списка объектов) карты вручную через [`getentitytoken`](03-entity-world-builtins.md#getentitytoken) — например, чтобы найти на карте собственные, чисто клиентские декоративные точки (не существующие как реальные сетевые сущности на сервере) и создать под них локальные CSQC-объекты: например, декоративные частицы у фонарей или чисто визуальные порталы.

#### Практические сценарии использования

```
void() CSQC_WorldLoaded =
{
	local string token;

	// Построчно читаем сырой список объектов карты в поисках своих меток.
	while ((token = getentitytoken()))
	{
		if (token == "csqc_ambient_glow")
			SpawnClientOnlyGlowEffect();
	}
};
```

### CSQC_UpdateView
`void(float vwidth, float vheight, float notmenu) CSQC_UpdateView`

* **vwidth** — `float`, ширина области вывода в виртуальных единицах экрана (не физических пикселях).
* **vheight** — `float`, аналогично высота области вывода.
* **notmenu** — `float`, булево значение: `0`, если поверх экрана сейчас открыто меню (в этом случае сцену/HUD всё ещё нужно нарисовать под меню), `1`, если меню не открыто.

#### Описание и логика работы

Главная и самая часто вызываемая точка входа CSQC — вызывается каждый кадр рендера и целиком отвечает за то, что окажется нарисованным на экране: 3D-мир (через [`clearscene`](08-csqc-rendering-builtins.md#clearscene)/[`addentities`](08-csqc-rendering-builtins.md#addentities)/[`renderscene`](08-csqc-rendering-builtins.md#renderscene)), HUD, таблицу результатов, элементы интерфейса. Если движок сообщил, что меню сейчас не открыто (`notmenu` истинно), скрипт обязан сам нарисовать полноценный HUD и таблицу результатов — движок не станет рисовать их автоматически поверх кастомной CSQC-сцены. Если параметр меню ложен, CSQC обычно всё равно рисует игровую сцену на фоне, но может пропустить прорисовку интерактивных элементов HUD, поверх которых будет открыто меню.

#### Практические сценарии использования

```
void(float vwidth, float vheight, float notmenu) CSQC_UpdateView =
{
	clearscene();
	setviewprop(VF_MIN, '0 0 0');
	setviewprop(VF_SIZE, [vwidth, vheight]);

	// Стандартная сцена игрока от первого лица.
	addentities(MASK_ENGINE | MASK_ENGINEVIEWMODEL);
	renderscene();

	// HUD нужно рисовать вручную, движок сам этого не сделает.
	if (notmenu)
	{
		DrawHealthAndArmor();
		DrawAmmoCounter();
		DrawCrosshair();
	}
};
```

### CSQC_InputEvent
`float(float evtype, float scanx, float chary, float devid) CSQC_InputEvent`

* **evtype** — `float`, тип события: `0` — клавиша нажата, `1` — клавиша отпущена, `2` — движение мыши (тогда `scanx`/`chary` — смещение по X/Y, а не код клавиши).
* **scanx** — `float`, код нажатой клавиши (или смещение мыши по X при `evtype == 2`).
* **chary** — `float`, ASCII-код символа с учётом раскладки (или смещение мыши по Y при `evtype == 2`).
* **devid** — `float`, идентификатор конкретного устройства ввода (полезно при нескольких геймпадах/мышах).

#### Описание и логика работы

Позволяет логике интерфейса перехватывать и переопределять управление ещё до того, как оно будет обработано штатным образом (движение игрока, открытие консоли и т.п.). Возвращаемое функцией булево значение `TRUE` говорит движку полностью проигнорировать это событие ввода дальше — то есть считать, что CSQC уже обработал нажатие целиком и стандартной обработке передавать его не нужно. Это ключевой механизм для полностью кастомных интерфейсов меню/инвентаря поверх игры: например, чтобы клавиши стрелок при открытом инвентаре листали предметы, а не двигали персонажа.

#### Практические сценарии использования

```
float(float evtype, float scanx, float chary, float devid) CSQC_InputEvent =
{
	// Пока открыт кастомный инвентарь, клавиши-стрелки листают предметы,
	// а не двигают игрока - и это событие не должно уйти дальше в движок.
	if (inventory_open && evtype == 0)
	{
		if (scanx == K_LEFTARROW) { InventorySelectPrev(); return TRUE; }
		if (scanx == K_RIGHTARROW) { InventorySelectNext(); return TRUE; }
	}

	return FALSE; // остальные события обрабатываются как обычно
};
```

### CSQC_ConsoleCommand
`float(string cmd) CSQC_ConsoleCommand`

* **cmd** — `string`, полная строка введённой пользователем консольной команды вместе с аргументами.

#### Описание и логика работы

Вызывается, когда игрок вводит в консоль команду, имя которой было заранее зарегистрировано через `registercommand`. Функция должна сама разобрать переданную строку (обычно через [`tokenize`](02-string-builtins.md#tokenize)/[`argv`](02-string-builtins.md#argv)) и вернуть `TRUE`, если команда была обработана и не должна уйти дальше по цепочке (например, на сервер как обычная команда). Это основной механизм для реализации собственных клиентских команд интерфейса — переключателей HUD, кастомных биндов, отладочных команд разработчика мода.

#### Практические сценарии использования

```
float(string cmd) CSQC_ConsoleCommand =
{
	tokenize(cmd);

	if (argv(0) == "togglescoreboard")
	{
		scoreboard_shown = !scoreboard_shown;
		return TRUE;
	}

	return FALSE; // не наша команда - пусть обрабатывается как обычно
};
```

### CSQC_Parse_StuffCmd
`void(string msg) CSQC_Parse_StuffCmd`

* **msg** — `string`, текст команды, присланной сервером на выполнение в клиентской консоли ([`stuffcmd`](04-network-messages-builtins.md#stuffcmd)).

#### Описание и логика работы

Даёт CSQC шанс перехватить команды, которые сервер обычно просто выполняет в консоли клиента напрямую (механизм `stuffcmd`). Полезно для разбора команды через `tokenize` вручную, чтобы решить, выполнять ли её как есть, изменить или полностью проигнорировать — например, из соображений безопасности лучше молча отбрасывать нераспознанные команды, а не выполнять их автоматически, как это происходит без описанной функции.

#### Практические сценарии использования

```
void(string msg) CSQC_Parse_StuffCmd =
{
	tokenize(msg);

	// Разрешаем только заведомо безопасные команды от сервера,
	// остальное отбрасываем, а не выполняем вслепую.
	if (argv(0) == "bf" || argv(0) == "changing")
		localcmd(msg);
};
```

Если функция возвращает `TRUE`, движок считает сообщение уже обработанным и не выводит его штатным способом.

```
float(string msg) CSQC_Parse_CenterPrint =

	// Показываем центральное сообщение собственным красивым виджетом
	// с анимацией затухания вместо стандартного текста движка.
	StartCustomCenterPrintFade(msg);
	return TRUE;
};
```

### CSQC_Parse_Print
`void(string printmsg, float printlvl) CSQC_Parse_Print`

* **printmsg** — `string`, текст сообщения (обычно от [`sprint`](12-system-debug-builtins.md#sprint)/[`bprint`](12-system-debug-builtins.md#bprint) на сервере).
* **printlvl** — `float`, один из уровней важности `PRINT_LOW`/`PRINT_MEDIUM`/`PRINT_HIGH`/`PRINT_CHAT`.

#### Описание и логика работы

Даёт CSQC шанс перехватить обычные текстовые сообщения (чат, системные объявления), присланные сервером. Клиентская логика должна сама отфильтровать сообщения по текущим настройкам игрока (например, скрыть чат команды противника) и вывести их своим методом — обычно всё ещё вызывая встроенную функцию `print`, чтобы попасть в стандартный буфер консоли/чата, либо полностью в собственный виджет чата.

#### Практические сценарии использования

```
void(string printmsg, float printlvl) CSQC_Parse_Print =
{
	// Полностью прячем сообщения низкого приоритета, если игрок
	// включил "минимальный чат" в настройках.
	if (printlvl == PRINT_LOW && cvar("cl_minimalchat"))
		return;

	print(printmsg);
};
```

### CSQC_Ent_Update
`void(float isnew) CSQC_Ent_Update`

* **isnew** — `float`, булево значение: `TRUE`, если этот сетевой объект только что появился в поле зрения клиента впервые (нужно создать локальный объект), `FALSE` — если это обновление уже существующего объекта.

#### Описание и логика работы

Ключевая точка входа для собственного клиентского сетевого протокола CSQC. Вызывается при получении обновления сущности, которую сервер явно пометил для отправки через CSQC-канал (см. серверную функцию `SendEntity`/поле `.SendEntity`). Внутри `self` указывает на объект, который нужно создать (если `isnew`) или обновить — обычно через `self.entnum`, отражающее номер сущности на сервере. Данные читаются строго теми же самыми builtin-функциями чтения ([`readbyte`](04-network-messages-builtins.md#readbyte), [`readcoord`](04-network-messages-builtins.md#readcoord), [`readangle`](04-network-messages-builtins.md#readangle), и т.п.) и в том же самом порядке, в каком сервер их записал в [`WriteByte`](04-network-messages-builtins.md#writebyte)/[`WriteCoord`](04-network-messages-builtins.md#writecoord) внутри своей `SendEntity` — любое рассогласование в порядке чтения/записи ломает разбор данных без явной ошибки движка.

#### Практические сценарии использования

```
void(float isnew) CSQC_Ent_Update =
{
	if (isnew)
	{
		self.classname = "cs_networked_prop";
		self.drawmask = MASK_ENGINE;
	}

	// Порядок чтения обязан точно совпадать с порядком WriteXxx на сервере.
	self.origin = readcoord() * '1 0 0' + readcoord() * '0 1 0' + readcoord() * '0 0 1';
	self.angles_y = readangle();
	self.modelindex = readshort();
};
```

### CSQC_Event_Sound
`float(float entnum, float channel, string soundname, float vol, float attenuation, vector pos, float pitchmod, float flags) CSQC_Event_Sound`

* **entnum** — `float`, номер сетевой сущности-источника звука.
* **channel** — `float`, канал воспроизведения (см. константы `CHAN_*`).
* **soundname** — `string`, путь к звуковому файлу.
* **vol** — `float`, громкость от `0` до `1`.
* **attenuation** — `float`, коэффициент затухания с расстоянием.
* **pos** — `vector`, мировая позиция источника звука.
* **pitchmod** — `float`, множитель высоты тона.
* **flags** — `float`, дополнительные битовые флаги воспроизведения.

#### Описание и логика работы

Даёт CSQC шанс перехватить событие звука, которое сервер обычно проигрывает автоматически (обычные звуки выстрелов, шагов, эффектов). Полезно, чтобы полностью заменить или дополнительно обработать конкретные звуки на клиенте — например, подставить случайную вариацию звука шага в зависимости от материала поверхности, которую клиент определяет сам через локальный трейс. Возвращаемое значение `TRUE` говорит движку, что звук уже обработан вручную и не нужно проигрывать его автоматически «как есть».

#### Практические сценарии использования

```
float(float entnum, float channel, string soundname, float vol, float attenuation, vector pos, float pitchmod, float flags) CSQC_Event_Sound =
{
	// Заменяем стандартный звук шага на вариацию по материалу поверхности,
	// который движок сам не знает.
	if (soundname == "player/step.wav")
	{
		sound(world, channel, PickFootstepSoundForSurface(pos), vol, attenuation);
		return TRUE;
	}

	return FALSE; // остальные звуки проигрываются как обычно
};
```

Вызывается для конкретного клиентского объекта (доступного через `self`), когда соответствующая ему сетевая сущность была удалена или скрыта сервером (перестала попадать в поле зрения этого клиента). void() CSQC_Ent_Remove =


### CSQC_UpdateViewLoading
`void(float vwidth, float vheight, float notmenu) CSQC_UpdateViewLoading`

* **vwidth** — `float`, ширина области отрисовки в пикселях.
* **vheight** — `float`, высота области отрисовки в пикселях.
* **notmenu** — `float`, признак того, что поверх экрана загрузки не открыто системное меню движка.

#### Описание и логика работы

Вызывается вместо обычного `CSQC_UpdateView` в те кадры, когда карта ещё не полностью загружена и мир не готов к штатной отрисовке (идёт стриминг ресурсов, распаковка BSP, прекэш моделей и звуков). Сигнатура идентична `CSQC_UpdateView`, но внутри `self`/списки сущностей ещё не гарантированно валидны, поэтому здесь принято рисовать только экран загрузки: заставку, полосу прогресса, подсказки. Если эта точка входа не объявлена в прогс-файле CSQC, движок на время загрузки просто показывает свой встроенный экран загрузки без участия CSQC.

```
void(float vwidth, float vheight, float notmenu) CSQC_UpdateViewLoading =
{
	// Рисуем собственный экран загрузки, пока карта не готова.
	drawfill('0 0 0', [vwidth, vheight], '0 0 0', 1, 0);
	drawstring([vwidth * 0.5 - 60, vheight * 0.5], "Загрузка карты...", '1 1 0', 1, 0);
```

### CSQC_DrawHud
`void(vector viewsize, float scoresshown) CSQC_DrawHud`

* **viewsize** — `vector`, размер области HUD в пикселях (`x`/`y` — ширина/высота, `z` не используется).
* **scoresshown** — `float`, признак того, что игрок сейчас удерживает клавишу таблицы результатов.

#### Описание и логика работы

Упрощённая, «облегчённая» точка входа для минималистичных CSQC-модов, которым не нужен полный контроль над отрисовкой 3D-сцены: движок сам рисует мир и вид от первого лица штатным образом, а CSQC получает возможность нарисовать только HUD поверх готовой картинки. Она вызывается вместо полноценного `CSQC_UpdateView`, если разработчик мода решил не переопределять управление сценой целиком. Такой подход проще в поддержке, но лишает мод контроля над постпроцессингом и порядком отрисовки мира.

```
void(vector viewsize, float scoresshown) CSQC_DrawHud =
{
	// Рисуем простую полосу здоровья поверх штатной картинки движка.
	drawfill([10, viewsize_y - 30], [200, 20], '0 0 0', 0.5, 0);
	drawfill([10, viewsize_y - 30], [200 * (getstatf(STAT_HEALTH) / 100), 20], '1 0 0', 1, 0);
};
```

### CSQC_Parse_Event
`void() CSQC_Parse_Event`

#### Описание и логика работы

Вызывается при получении сетевого сообщения `svc_csqcevent`/кастомного расширения событий, отправленного серверной стороной специально для CSQC, минуя стандартные `SVC_TempEntity`/`SVC_Print` и подобные. В отличие от `CSQC_Ent_Update`, здесь нет привязки к конкретной сетевой сущности — событие полностью произвольное, а параметры извлекаются вручную через `readbyte`/`readstring`/`readcoord` и так далее, аналогично `CSQC_Ent_Update`. void() CSQC_Parse_Event =

```
	// Читаем произвольное кастомное событие, отправленное расширением протокола сервера.

	if (eventtype == CUSTOM_EVENT_SHAKE_SCREEN)
```

### CSQC_Parse_Damage
`float(float save, float take, vector inflictororg) CSQC_Parse_Damage`

* **save** — `float`, сколько урона было погашено защитой (броней) до применения к здоровью.
* **take** — `float`, сколько урона реально ушло в здоровье локального игрока.
* **inflictororg** — `vector`, мировая позиция источника урона, используется для направленных экранных эффектов.

#### Описание и логика работы

Вызывается, когда сервер сообщает клиенту, что локальный игрок получил урон (аналог стандартного экранного «покраснения» и рывка камеры ванильного Quake).
```
float(float save, float take, vector inflictororg) CSQC_Parse_Damage =
{
```

### CSQC_Parse_SetAngles
`float(vector angles, float isdelta) CSQC_Parse_SetAngles`

* **angles** — `vector`, углы обзора, которые сервер принудительно устанавливает игроку.
* **isdelta** — `float`, признак того, что `angles` — это относительное приращение, а не абсолютное значение.

#### Описание и логика работы

Вызывается, когда сервер меняет угол обзора игрока принудительно (поле `.fixangle` серверной сущности игрока, например после телепорта или интро-камеры). Позволяет CSQC самостоятельно решить, как применить принудительный поворот — мгновенно, с плавной интерполяцией или вовсе проигнорировать в отдельных игровых состояниях (например, во время собственной cutscene-камеры мода). Возврат `TRUE` говорит движку, что CSQC уже применил изменение угла самостоятельно и встроенную обработку делать не нужно.

#### Практические сценарии использования

```
float(vector angles, float isdelta) CSQC_Parse_SetAngles =
{
	if (InCustomCutscene())
		return TRUE; // игнорируем принудительный поворот во время собственной катсцены

	return FALSE; // в остальных случаях — стандартное поведение движка
};
```

### CSQC_PlayerInfoChanged
`void(float playernum) CSQC_PlayerInfoChanged`

* **playernum** — `float`, номер игрока (индекс слота), у которого изменился userinfo.

#### Описание и логика работы

Вызывается при изменении userinfo конкретного игрока — смена имени, скина, модели, команды или любого другого ключа, который сервер синхронизирует через userinfo. Удобно, чтобы обновить локальный кэш подписанных табличек над головами игроков, перечитать цвет команды для HUD или заново применить кастомный скин, не дожидаясь следующего полного обновления сущности.

#### Практические сценарии использования

```
void(float playernum) CSQC_PlayerInfoChanged =
{
	// Обновляем локальный кэш отображаемого имени игрока после смены userinfo.
	RefreshPlayerNameTag(playernum, getplayerkeyvalue(playernum, "name"));

```

### CSQC_ServerInfoChanged
`void() CSQC_ServerInfoChanged`

#### Описание и логика работы

Вызывается при изменении serverinfo — например, при смене режима игры, лимита фрагов, названия карты в ротации или любого другого ключа, который сервер публикует через serverinfo. В отличие от `CSQC_PlayerInfoChanged`, здесь нет параметра, поэтому мод обязан сам перечитать нужные ключи через `serverkey`/`serverkeyfloat` целиком, чтобы понять, что именно изменилось.

#### Практические сценарии использования

```
void() CSQC_ServerInfoChanged =
{

	local string mode = serverkey("gamemode");
	UpdateHudForGameMode(mode);
};
```

### CSQC_Input_Frame
`void() CSQC_Input_Frame`

#### Описание и логика работы

Вызывается каждый раз, когда движок опрашивает устройства ввода, отдельно от кадра отрисовки `CSQC_UpdateView` — частота вызова может отличаться от частоты кадров рендера (например, если рендер и обработка ввода разделены по времени для снижения задержки ввода). Подходит для логики, которая должна реагировать на ввод с минимальной задержкой независимо от текущего FPS, в отличие от `CSQC_UpdateView`, который привязан к отрисовке.

#### Практические сценарии использования

```
void() CSQC_Input_Frame =
{
	// Обрабатываем зажатие клавиши со собственной, независимой от рендера частотой.
	if (input_buttons & 1)
		AccumulateChargeTime(frametime);
};
```

### CSQC_RendererRestarted
`void(string rendererdescription) CSQC_RendererRestarted`

* **rendererdescription** — `string`, текстовое описание активного видеорендерера после перезапуска (название бэкенда/драйвера).

#### Описание и логика работы

Вызывается после смены видеорежима или полного перезапуска рендерера (`vid_restart`, смена бэкенда рендеринга, потеря и восстановление устройства). Это сигнал для CSQC заново создать любые ресурсы, которые оно генерировало вручную и которые могли быть уничтожены рендерером при перезапуске — например, процедурные текстуры, кастомные шейдеры через `CSQC_GenerateMaterial`, буферы, созданные через `createbuffer`.

#### Практические сценарии использования

```
void(string rendererdescription) CSQC_RendererRestarted =
{
	// Пересоздаём процедурную текстуру миникарты после перезапуска рендера.
	RegenerateMinimapTexture();
};
```

### CSQC_GenerateMaterial
`string(string shadername) CSQC_GenerateMaterial`

* **shadername** — `string`, имя материала/шейдера, для которого движок не нашёл готового `.shader`-файла на диске.

#### Описание и логика работы

Позволяет CSQC программно сгенерировать текст `.shader`-материала на лету — вместо того, чтобы искать соответствующий файл в `scripts/*.shader`. Движок вызывает эту функцию как последний шанс получить описание материала перед тем, как использовать шейдер по умолчанию. Возвращаемая строка должна быть валидным телом материала в том же синтаксисе, что и обычные `.shader`-файлы (см. [«Язык описания материалов»](../08-materials-shaders/shader-script-language.md)). Пустая строка означает отказ — материал будет создан со стандартными параметрами по умолчанию.

#### Практические сценарии использования

```
string(string shadername) CSQC_GenerateMaterial =
{
	// Генерируем простой материал для процедурно создаваемых декалей крови.
	if (substring(shadername, 0, 11) == "blooddecal_")
		return sprintf("{\n{\nmap %s\nblendfunc blend\n}\n}\n", substring(shadername, 11, -1));

	return ""; // для остальных имён — стандартное поведение
};
```

### CSQC_ConsoleLink
`float(string text, string info) CSQC_ConsoleLink`

* **text** — `string`, отображаемый текст кликабельной ссылки внутри консоли.
* **info** — `string`, произвольные метаданные ссылки, заданные при её выводе.

#### Описание и логика работы

Вызывается, когда игрок кликает мышью по специальной кликабельной ссылке, ранее выведенной в текст консоли (движок поддерживает разметку кликабельных ссылок в некоторых текстовых сообщениях). Позволяет CSQC отреагировать на клик программно — например, открыть профиль игрока, скопировать текст в буфер обмена или выполнить консольную команду. Возврат `TRUE` говорит движку, что клик обработан модом.

#### Практические сценарии использования

```
float(string text, string info) CSQC_ConsoleLink =
{
	// Реагируем на клик по ссылке с информацией об игроке.
	if (substring(info, 0, 7) == "player:")
	{
		OpenPlayerProfile(stof(substring(info, 7, -1)));

```

### CSQC_Ent_Spawn
`void(float newentnum) CSQC_Ent_Spawn`

* **newentnum** — `float`, номер новой сетевой сущности, для которой ещё не было данных.

#### Описание и логика работы

Устаревшая (legacy) точка входа, добавленная изначально для совместимости с расширениями DarkPlaces. Вызывается при появлении новой сетевой сущности до того, как для неё вообще были прочитаны какие-либо данные через `CSQC_Ent_Update` — то есть здесь ещё нельзя читать сетевые поля этой сущности, только создать сам объект и выставить значения по умолчанию. В большинстве современных модов FTEQW не нужна: обычно достаточно создавать сущность лениво прямо внутри `CSQC_Ent_Update` при первом обновлении.

#### Практические сценарии использования

```
void(float newentnum) CSQC_Ent_Spawn =
{
	// Резервируем локальный объект под сущность заранее, до прихода первых данных.
	self.classname = "cs_pending_entity";
};
```

### CSQC_ServerSound
`float(float channel, string soundname, vector pos, float vol, float attenuation, float flags) CSQC_ServerSound`

* **channel** — `float`, канал воспроизведения звука.
* **soundname** — `string`, путь к звуковому файлу.
* **pos** — `vector`, мировая позиция источника звука.

Устаревший (deprecated) предшественник современной точки входа `CSQC_Event_Sound`. Выполняет ту же роль — даёт CSQC шанс перехватить звук, который сервер обычно проигрывает автоматически, — но с более старой, урезанной сигнатурой без параметров `entnum` и `pitchmod`. float(float channel, string soundname, vector pos, float vol, float attenuation, float flags) CSQC_ServerSound =

```
	return FALSE;

```

### CSQC_Parse_TempEntity
`float() CSQC_Parse_TempEntity`

#### Описание и логика работы

Вызывается при получении классического сетевого сообщения «temp entity» (`svc_temp_entity`) — искры, взрывы, кровь, молнии и другие одноразовые визуальные эффекты ванильного протокола Quake — до того, как движок обработает его штатным образом. Позволяет CSQC перехватить и заменить конкретные типы temp entity собственными эффектами. Все параметры самого сообщения читаются вручную через `readbyte`/`readcoord`, аналогично `CSQC_Ent_Update`. Возврат `TRUE` подавляет стандартную обработку этого сообщения движком.

#### Практические сценарии использования

```
float() CSQC_Parse_TempEntity =
{
	local float type = readbyte();
	if (type == TE_EXPLOSION)
	{
		SpawnCustomExplosion(readcoord());
		return TRUE; // подавляем стандартный эффект взрыва движка
	}

	return FALSE;
};
```

### CSQC_MapEntityEdited
`void(int entidx, string newentdata) CSQC_MapEntityEdited`

* **entidx** — `int`, индекс сущности карты, чьё описание было изменено.
* **newentdata** — `string`, новый текстовый блок ключей-значений этой сущности в формате `.ent`/entity-lump.

#### Описание и логика работы

Вызывается инструментами редактирования карт «на лету», встроенными в движок, когда описание конкретной сущности карты было изменено во время работы (например, через внутриигровой редактор сущностей или внешний инструмент, подключённый к движку). Позволяет CSQC синхронизировать собственное представление сущности с новыми данными без перезагрузки карты целиком — полезно исключительно при разработке уровней и инструментов, в готовом моде для игроков практического значения не имеет.

#### Практические сценарии использования

```
void(int entidx, string newentdata) CSQC_MapEntityEdited =
{
	// Перечитываем изменённые ключи сущности карты для мгновенного предпросмотра правок редактора.
```

## MenuQC: точки входа логики меню

Компилируются в отдельный прогс-файл логики меню (см. [«Логика игровых меню (MenuQC)»](../16-quakec-scripting/menu-quakec.md) про интерфейс подключения и builtins браузера серверов).

### m_init
`void() m_init`

#### Описание и логика работы

Вызывается один раз при первой загрузке логики меню — до первого показа какого-либо экрана. Аналог `CSQC_Init`, но для меню: здесь создаются структуры данных экранов, прекэшируются фоновые изображения и шрифты, инициализируются значения виджетов настроек из текущих cvar.

#### Практические сценарии использования

```
void() m_init =
{
	precache_pic("gfx/menu/background.tga");
	precache_pic("gfx/menu/logo.tga");

	current_menu_screen = MENU_SCREEN_MAIN;
};
```

### m_shutdown
`void() m_shutdown`

#### Описание и логика работы

Вызывается при выгрузке логики меню — обычно только при полном завершении работы движка. Место для финального сохранения любых пользовательских настроек интерфейса меню, если они не архивируются через обычные cvar с флагом сохранения.

#### Практические сценарии использования

```
void() m_shutdown =
{
	SaveMenuLayoutPreferences();
};
```

### m_toggle
`void(float show) m_toggle`

* **show** — `float`, булево значение: открывается меню или закрывается.

#### Описание и логика работы

Вызывается при открытии/закрытии меню — например, по нажатию клавиши Esc во время игры или по завершении отключения от сервера. Здесь удобно сбрасывать выбранный пункт текущего экрана на разумное значение по умолчанию или проигрывать звук/анимацию появления окна меню.

#### Практические сценарии использования

```
void(float show) m_toggle =
{
	if (show)
	{
		localsound("misc/menu_open.wav");
		current_menu_screen = MENU_SCREEN_MAIN;
	}
};
```

### m_draw
`void(vector screensize) m_draw`

* **screensize** — `vector`, виртуальный размер области рисования меню в формате `'<width> <height> 0'`.

#### Описание и логика работы

Вызывается каждый кадр, пока меню активно, и служит главной точкой входа отрисовки MenuQC. Это ближайший аналог `CSQC_UpdateView`, но для системных экранов. Здесь тем же самым набором функций рисования, что и в CSQC ([`drawpic`](08-csqc-rendering-builtins.md#drawpic), [`drawstring`](08-csqc-rendering-builtins.md#drawstring)/`drawcolorcodedstring`, [`drawfill`](08-csqc-rendering-builtins.md#drawfill) и т.д.), описывается вся отрисовка текущего активного экрана меню — фон, кнопки, поля ввода, ползунки настроек. Важное ограничение совместимости: старые DarkPlaces-совместимые меню могут ожидать сигнатуру без этого аргумента, но нативная FTE-сигнатура именно векторная.

#### Практические сценарии использования

```
void(vector screensize) m_draw =
{
	drawpic('0 0 0', "gfx/menu/background.tga", screensize, '1 1 1', 1);

	if (current_menu_screen == MENU_SCREEN_MAIN)
		DrawMainMenuButtons();
	else if (current_menu_screen == MENU_SCREEN_OPTIONS)
		DrawOptionsScreen();
};
```

### m_drawloading
`void(vector screensize, float opaque) m_drawloading`

* **screensize** — `vector`, виртуальный размер экрана загрузки в формате `'<width> <height> 0'`.
* **opaque** — `float`, булев флаг: если ненулевой, функция должна полностью закрасить экран сама.

#### Описание и логика работы

Отдельная точка входа, вызываемая специально во время экрана загрузки карты — причём вызывается, даже если основное меню в этот момент закрыто. Позволяет показать собственный прогресс-бар или фоновую картинку загрузки, соответствующую стилю мода, вместо стандартного экрана движка. Когда `opaque` истинно, MenuQC обязана полностью перекрыть экран своей отрисовкой, а не рассчитывать на уже существующий фон.

#### Практические сценарии использования

```
void(vector screensize, float opaque) m_drawloading =
{
	if (opaque)
		drawfill('0 0 0', screensize, '0 0 0', 1);

	drawpic('0 0 0', "gfx/menu/loading_bg.tga", screensize, '1 1 1', 1);
	drawstring('270 440 0', "Загрузка уровня...", '16 16 0', '1 1 1', 1, 0);
};
```

### m_keydown
`void(float scan, float chr) m_keydown`

* **scan** — `float`, код нажатой клавиши.
* **chr** — `float`, код символа с учётом раскладки клавиатуры.

#### Описание и логика работы

Устаревшая точка входа MenuQC для нажатия клавиши. В современных заголовках она помечена как deprecated в пользу `Menu_InputEvent`, но движок всё ещё вызывает её для старых меню, если новый обработчик не объявлен. Важный нюанс FTEQW: функция ничего не возвращает. Когда меню пользуется этим старым API, движок после вызова `m_keydown` считает событие «съеденным» автоматически, поэтому отдельного булева `return` здесь быть не должно.

#### Практические сценарии использования

```
void(float scan, float chr) m_keydown =
{
	if (scan == K_ESCAPE)
		CloseCurrentSubmenu();
};
```

### m_keyup
`void(float scan, float chr) m_keyup`

* **scan** — `float`, код отпущенной клавиши.
* **chr** — `float`, код символа с учётом раскладки клавиатуры.

#### Описание и логика работы

Парная legacy-функция к `m_keydown` — вызывается при отпускании клавиши, пока меню открыто, если `Menu_InputEvent` не используется. Возвращаемого значения у неё тоже нет; после вызова движок не читает никакой булев результат. Поэтому `m_keyup` подходит только для побочных эффектов: остановить автопрокрутку, завершить drag, снять флаг зажатой кнопки и т.п.

#### Практические сценарии использования

```
void(float scan, float chr) m_keyup =
{
	if (scan == K_MOUSE1)
		StopContinuousScroll();
};
```

### Menu_InputEvent
`float(float evtype, float scanx, float chary, float devid) Menu_InputEvent`

* **evtype** — `float`, тип события ввода (нажатие клавиши, движение мыши, ввод символа и т.д., те же коды, что и у `CSQC_InputEvent`).
* **scanx** — `float`, код клавиши или координата `x` в зависимости от `evtype`.
* **chary** — `float`, код символа или координата `y` в зависимости от `evtype`.
* **devid** — `float`, идентификатор устройства ввода (для мультидевайсовых конфигураций).

#### Описание и логика работы

Более новый, единый обработчик ввода меню — прямой аналог `CSQC_InputEvent`, объединяющий обработку клавиатуры, мыши и других устройств в одну функцию с общим форматом события, вместо нескольких раздельных функций (`m_keydown`, `m_keyup`, `m_draw` и т.п.). Там, где `Menu_InputEvent` объявлена в прогс-файле меню, движок использует именно её как основной канал ввода; отдельные `m_keydown`/`m_keyup` при этом можно не объявлять вовсе. Возвращаемое значение `TRUE` означает, что событие обработано логикой меню и не должно обрабатываться движком дальше.

#### Практические сценарии использования

```
float(float evtype, float scanx, float chary, float devid) Menu_InputEvent =
{
	if (evtype == IE_KEYDOWN && scanx == K_ESCAPE)
	{
		CloseCurrentSubmenu();
		return TRUE;
	}

	return FALSE;
};
```

### m_consolecommand
`float(string cmd) m_consolecommand`

* **cmd** — `string`, полная строка команды вместе с аргументами.

#### Описание и логика работы

Прямой аналог `CSQC_ConsoleCommand`, но для команд, зарегистрированных логикой меню через `registercommand`. Позволяет логике меню перехватывать собственные консольные команды, введённые игроком или вызванные через `stuffcmd`/`localcmd`, не полагаясь на разбор кодом самой игры. Возврат `TRUE` говорит движку, что команда обработана меню и не должна передаваться дальше по стандартной цепочке обработки.

#### Практические сценарии использования

```
float(string cmd) m_consolecommand =
{
	if (cmd == "menu_reload_serverlist")
	{
		RefreshServerBrowserList();
		return TRUE;
	}

	return FALSE;
};
```

### m_gethostcachecategory
`float(float hostcachenum) m_gethostcachecategory`

* **hostcachenum** — `float`, индекс найденного сервера во внутреннем кэше браузера серверов движка.

#### Описание и логика работы

Позволяет логике меню сгруппировать найденные сервера по произвольным категориям при построении собственного кастомного браузера серверов (см. [«Браузер серверов и мастер-сервер»](11-server-browser-builtins.md)). Движок вызывает эту функцию для каждого сервера в кэше и ожидает в ответ числовой номер категории; конкретное сопоставление номеров категорий подписям (например, «Официальные», «Модифицированные», «Пустые») логика меню определяет сама.

#### Практические сценарии использования

```
float(float hostcachenum) m_gethostcachecategory =
{
	// Относим сервера без игроков в отдельную категорию "Пустые".
	if (gethostcachenumber(SLIST_FIELD_NUMPLAYERS, hostcachenum) == 0)
		return CATEGORY_EMPTY;

	return CATEGORY_ACTIVE;
};
```

### Menu_RendererRestarted
`void(string rendererdescription) Menu_RendererRestarted`

* **rendererdescription** — `string`, текстовое описание активного видеорендерера после перезапуска.

#### Описание и логика работы

Прямой аналог `CSQC_RendererRestarted` для логики меню — вызывается после смены видеорежима или полного перезапуска рендерера. Даёт логике меню шанс заново создать любые ресурсы, которые она генерировала вручную (процедурные превью-текстуры, кастомные материалы) и которые могли быть уничтожены при перезапуске рендерера.

#### Практические сценарии использования

```
void(string rendererdescription) Menu_RendererRestarted =
{
	// Пересоздаём предпросмотр текущей карты после перезапуска видео.
	RegenerateMapPreviewTexture();
};
```

### GameCommand
`void(string cmdtext) GameCommand`

* **cmdtext** — `string`, команда, переданная встроенным меню движка (например, из нативных пунктов настроек графики/звука/управления).

#### Описание и логика работы

Разбирает команды, отправленные логике меню из встроенного (native) меню самого движка — той части интерфейса, которая реализована не на MenuQC, а на Си (стандартные диалоги настроек видео, звука, управления в некоторых сборках движка). Используется для интеграции: если билд движка одновременно предоставляет и нативные, и MenuQC-меню, `GameCommand` — точка стыковки между ними. Важный практический нюанс: движок просто передаёт строку в QC и **не читает возвращаемое значение**, поэтому сигнатура здесь именно `void`, а не `float`.

#### Практические сценарии использования

```
void(string cmdtext) GameCommand =
{
	// Обрабатываем команду, присланную нативным диалогом настроек графики движка.
	if (cmdtext == "apply_video_settings")
		ApplyCustomVideoPreset();
};
```
