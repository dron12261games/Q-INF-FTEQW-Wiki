# Редактор карт, криптография и разные редкие builtins

> [⬅ Вернуться к оглавлению вики](../README.md)

> [Индекс справочника builtins](./README.md)

Этот раздел собирает встроенные функции QuakeC движка FTEQW, которые не относятся напрямую к основным категориям (математика, строки, сущности, сеть, звук, файлы, рендер, скелетная анимация): интеграция с редактором карт (`brush_*`, `patch_*`), криптография (`crypto_*`), JSON, достижения (`stachievement_*`, `ststat_*`), геймпады (`gp_*`, `controller_*`), видео/кинематика (`cin_*`) и другие редкие служебные builtins.

## Функции

### brush_calcfacepoints
`void(entity brush, float facenum, void(__variant *ptr) callback) brush_calcfacepoints = #0:brush_calcfacepoints;`

* **brush** — `entity`, специальная CSQC-сущность, представляющая собой браш (объект геометрии).
* **facenum** — `float`, индекс конкретной грани (face) внутри указанного браша.
* **callback** — функция-колбэк, в которую движок передает указатель на массив координат вершин.

#### Описание и особенности работы
`brush_calcfacepoints` является частью встроенного в FTEQW инструментария для работы с динамической геометрией и внутриигрового редактора карт. Builtin выполняет низкоуровневый расчет мировых координат всех вершин (points), формирующих плоскость конкретной грани `facenum` выбранного браша. Поскольку количество вершин у грани может быть переменным, движок не возвращает массив напрямую, а использует асинхронный колбэк. Процедура ядра вычисляет точки пересечения плоскостей браша и передает временный указатель в `callback`. Метод незаменим для генерации кастомных коллизий на лету, программного анализа формы брашей или отрисовки осей редактора в CSQC.

#### Пример использования
```qc
void(string keyname, __variant val) on_face_points_ready =
{
    // Колбэк получает сырые координаты вершин грани для последующей отрисовки
    dprint("Face vertices calculated successfully\n");
};

void(entity brush_ent) DebugFirstFace =
{
    // Запрашиваем координаты вершин для самой первой грани (индекс 0) браша
    brush_calcfacepoints(brush_ent, 0, on_face_points_ready);
};
```

### brush_create
`entity() brush_create = #0:brush_create;`

* Параметры отсутствуют.
* Возвращает: `entity` — дескриптор созданной пустой сущности-браша.

#### Описание и особенности работы
`brush_create` аллоцирует в памяти движка новую изолированную сущность, предназначенную для хранения и компиляции полигональной геометрии (браша). Этот builtin инициализирует базовые внутренние структуры данных подсистемы игрового редактора FTEQW. Созданный объект изначально не имеет плоскостей и физических свойств; их необходимо задавать последующими вызовами смежных встроенных функций (например, добавлением плоскостей граней). Метод активнейшим образом применяется в CSQC для динамического создания разрушаемых преград, процедурной генерации комнат или написания кастомных плагинов трехмерного моделирования прямо внутри игры.

#### Пример использования
```qc
entity g_edit_brush;

void() Editor_SpawnNewCube =
{
    g_edit_brush = brush_create();
    if (!g_edit_brush)
        dprint("Failed to allocate memory for new brush entity\n");
};
```

### brush_delete
`void(entity brush) brush_delete = #0:brush_delete;`

* **brush** — `entity`, сущность-браш, которую необходимо уничтожить и деаллоцировать.

#### Описание и особенности работы
`brush_delete` выполняет полное удаление сущности-браша из памяти, освобождая все связанные с ней ресурсы: массивы вершин, плоскостей, текстурные координаты и индексы граней, выделенные в подсистеме игрового редактора. Внутренний Си-код движка принудительно исключает этот объект из физического движка (коллизий) и графического конвейера рендеринга текущей сцены. Использование базового удаления `remove(brush)` для объектов геометрии редактора может привести к утечкам памяти в куче движка, поэтому для корректной деаллокации геометрических структур VFS необходимо вызывать именно специализированный `brush_delete`. Передача нулевого или неинициализированного эдикта безопасно игнорируется ядром.

#### Пример использования
```qc
void() Editor_ClearCurrentSelection =
{
    if (g_edit_brush)
    {
        brush_delete(g_edit_brush);
        g_edit_brush = world;
        dprint("Selected brush geometry was deleted and freed\n");
    }
};
```

### brush_findinvolume
`entity(vector mins, vector maxs, entity start) brush_findinvolume = #0:brush_findinvolume;`

* **mins** — `vector`, минимальные координаты описывающего параллелепипеда (AABB) зоны поиска.
* **maxs** — `vector`, максимальные координаты описывающего параллелепипеда (AABB) зоны поиска.
* **start** — `entity`, сущность, с которой начинается сканирование; передайте `world` для поиска с самого начала.

#### Описание и особенности работы
`brush_findinvolume` выполняет пространственный поиск и выборку активных брашей встроенного внутриигрового редактора, попавших в заданную трехмерную область (Bounding Box). Builtin сканирует внутренние пространственные хэш-таблицы редактора и возвращает дескриптор первой найденной сущности-браша, чьи габариты пересекаются с указанным объемом. Метод работает по принципу классической функции `find` для эдиктов, позволяя организовывать последовательные циклы обхода, передавая в аргумент `start` результат предыдущей итерации. Это необходимо для массового выделения геометрии в рамке редактора, группового удаления или применения трансформаций к объектам в выделенной области.

#### Пример использования
```qc
void(vector box_mins, vector box_maxs) HighlightBrushesInZone =
{
    local entity br;

    br = brush_findinvolume(box_mins, box_maxs, world);
    while (br)
    {
        // Применяем визуальный эффект выделения к каждому брашу в зоне
        br.effects = br.effects | EF_BRIGHTFIELD; 
        br = brush_findinvolume(box_mins, box_maxs, br);
    }
};
```

### brush_get
`__variant(entity brush, float property) brush_get = #0:brush_get;`

* **brush** — `entity`, целевая сущность-браш, параметры которой запрашиваются.
* **property** — `float`, числовой идентификатор (константа) запрашиваемого свойства геометрии или текстуры.

#### Описание и особенности работы
`brush_get` — это универсальный метод извлечения свойств и метаданных конкретного геометрического объекта встроенного редактора карт. В зависимости от переданного флага `property` (например, констант для получения количества граней, общего объема, имени материала или флагов коллизии), builtin извлекает данные из внутренних С-структур ядра и возвращает их в виде универсального типа `__variant`. Метод обеспечивает безопасное чтение низкоуровневых параметров браша без необходимости прямого парсинга его текстового представления, возвращая корректные типы (float, vector или string) на лету. При передаче невалидного свойства функция возвращает пустую заглушку или ноль.

#### Пример использования
```qc
// Предположим, что константа BR_PROP_FACES_COUNT имеет значение 1
const float BR_PROP_FACES_COUNT = 1;

void(entity target_brush) PrintBrushFaceCount =
{
    local float faces;

    faces = brush_get(target_brush, BR_PROP_FACES_COUNT);
    bprint(sprintf("Selected brush has %s faces\n", ftos(faces)));
};
```

### brush_getfacepoints
`int(entity brush, float facenum, vector *ptr, int maxpoints) brush_getfacepoints = #0:brush_getfacepoints;`

* **brush** — `entity`, сущность-браш, содержащая целевую грань.
* **facenum** — `float`, индекс исследуемой грани внутри браша.
* **ptr** — `vector *`, указатель на заранее выделенный массив векторов, куда будут скопированы координаты.
* **maxpoints** — `int`, максимальное количество вершин, которое способен вместить буфер `ptr`.

#### Описание и особенности работы
В отличие от асинхронной `brush_calcfacepoints`, данный builtin выполняет синхронное, немедленное извлечение уже рассчитанных координат вершин конкретной плоскости (грани) во внешнюю память QC. `brush_getfacepoints` считывает геометрические данные грани `facenum`, копирует до `maxpoints` векторов координат в переданный буфер `ptr` и возвращает фактическое количество заполненных вершин. Если грань содержит больше точек, чем указано в `maxpoints`, запись безопасно отсекается по верхнему лимиту. Этот метод идеален для быстрого пошагового анализа полигонов, расчета кастомного освещения или построения физических мешей на стороне CSQC с использованием функций `memalloc` или `createbuffer`.

#### Пример использования
```qc
void(entity brush_ent) ProcessBrushVertices =
{
    local vector *vertex_array;
    local float count;

    // Выделяем временную память под потенциальный полигон (до 8 вершин)
    vertex_array = createbuffer(sizeof(vector) * 8);
    
    // Синхронно считываем координаты вершин первой грани
    count = brush_getfacepoints(brush_ent, 0, vertex_array, 8);
    if (count > 0)
    {
        bprint(sprintf("Successfully extracted %s vertices from face 0\n", ftos(count)));
        // Далее можно оперировать значениями vertex_array[0], vertex_array[1] и т.д.
    }
};
```

### brush_selected
`entity() brush_selected = #0:brush_selected;`

* Параметры отсутствуют.
* Возвращает: `entity` — дескриптор текущего выделенного браша или `world` (`__NULL__`), если ничего не выделено.

#### Описание и особенности работы
`brush_selected` является базовой функцией встроенного редактора трехмерной геометрии FTEQW на стороне CSQC. Builtin мгновенно обращается к подсистеме фокуса ввода редактора карт и возвращает прямую ссылку на эдикт браша, который пользователь выделил в данный момент (например, кликом мыши или рамкой выделения в окне проекции). Этот метод критически важен для написания кастомных скриптов автоматизации или инструментов UI: зная выделенный объект, разработчик может на лету считывать или модифицировать его свойства через `brush_get`, принудительно удалять через `brush_delete` или смещать плоскости граней.

#### Пример использования
```qc
void() Editor_DeleteSelectedBrush =
{
    local entity selected;

    selected = brush_selected();
    if (selected != world)
    {
        brush_delete(selected);
        dprint("The currently selected brush was successfully deleted\n");
    }
    else
    {
        dprint("No brush selected to delete\n");
    }
};
```

### bulleten
`bulleten(...)` — данная встроенная функция не реализована и является жесткой заглушкой (номера: CSQC=#243).

* Параметры не специфицированы, вызов не имеет функционального смысла.

#### Описание и особенности работы
`bulleten` — это глубокий исторический рудимент в таблицах опкодов под номером `#243`. В ранних экспериментальных ветках движка (около 2010 года) этот слот планировался для реализации кастомных досок объявлений (Bulletin Boards) или специфического сдвига текстур. Фича была полностью заброшена и вырезана, Си-код в ядре отсутствует, а сам слот указывает на `PF_Fixme`. Он сохранен исключительно для того, чтобы древние скомпилированные прогсы не приводили к падению движка из-за неопознанного номера функции.

### cin_close
`void(string id) cin_close = #0:cin_close;`

* **id** — `string`, уникальный строковый идентификатор активного кинематографического потока или видеоролика.

#### Описание и особенности работы
`cin_close` входит в состав нативного расширения движка для работы со встроенным медиаплеером и внутриигровыми видеороликами (кинематографикой). Этот builtin отвечает за принудительное закрытие, остановку декодирования и полную деаллокацию оперативной памяти, выделенной под конкретный видеопоток `id` (например, ролики в форматах ROQ, AVI или кастомные стримы через плагин FFMPEG). Внутренний Си-код на стороне MenuQC/CSQC уничтожает связанный графический шейдер и освобождает ресурсы аудиомикшера. Вызов этой функции обязателен после завершения воспроизведения кат-сцены, иначе текстура ролика останется висеть в видеопамяти, создавая утечки.

#### Пример использования
```qc
void() UI_SkipIntroCinematic =
{
    // Закрываем поток вступительного видео и освобождаем память шейдера
    cin_close("intro_video");
    
    // Переходим непосредственно к главному меню
    Menu_ActivateMainScreen();
};
```

### cin_getstate
`float(string id) cin_getstate = #0:cin_getstate;`

* **id** — `string`, уникальный строковый идентификатор активного кинематографического (видео) потока.
* **Возвращает**: `float` — числовой код текущего состояния плеера (например: `0` — остановлен/завершен, `1` — воспроизводится, `2` — на паузе).

#### Описание и особенности работы
`cin_getstate` опрашивает состояние медиа-декодера для конкретного запущенного видеоролика по его текстовому идентификатору `id`. Этот встроенный метод MenuQC позволяет динамически отслеживать статус проигрывания внутриигровых кат-сцен или фоновых меню-видео (в форматах ROQ, AVI, OGV). С его помощью QC-скрипт определяет момент, когда воспроизведение файла физически завершилось или поток столкнулся с ошибкой декодирования. Это критически важно для реализации логики автоматического переключения экранов интерфейса, скрытия плашек управления медиаплеером или принудительного закрытия видео-текстуры с целью очистки оперативной памяти.

#### Пример использования
```qc
void() Menu_CheckIntroVideoStatus =
{
    // Если ролик с идентификатором "intro" завершился (вернул 0)
    if (cin_getstate("intro") == 0)
    {
        cin_close("intro"); // Корректно закрываем дескриптор
        Menu_ActivateMainMenu(); // Перенаправляем пользователя в главное меню
    }
};
```

### cin_open
`void(string file, string id) cin_open = #0:cin_open;`

* **file** — `string`, относительный путь к файлу видеоролика в виртуальной файловой системе (например, `"video/logo.roq"`).
* **id** — `string`, уникальное строковое имя (алиас), присваиваемое создаваемому медиа-потоку.

#### Описание и особенности работы
`cin_open` инициализирует подсистему системного видеодекодера FTEQW, открывает указанный медиафайл и связывает его с уникальным текстовым дескриптором `id`. Доступен в контексте MenuQC. При вызове функции движок автоматически регистрирует в графической подсистеме динамический шейдер с именем, эквивалентным заданному `id`. Чтобы вывести изображение открытого видеоролика на экран, разработчику достаточно вызвать стандартную команду отрисовки интерфейса (например, `drawpic` или `drawshader`), передав строку `id` в качестве имени текстуры. Функция также автоматически настраивает микширование звуковой дорожки видеоролика в общую аудио-панораму игры.

#### Пример использования
```qc
void() Menu_StartIntroVideo =
{
    // Открываем видеофайл и регистрируем медиа-шейдер под именем "intro_bg"
    cin_open("video/intro.avi", "intro_bg");
};

void() Menu_DrawLoop =
{
    // Отрисовываем кадр видео во весь экран в цикле обновления интерфейса
    drawpic('0 0 0', "intro_bg", '640 480 0', '1 1 1', 1, 0);
};
```

### cin_restart
`void(string id) cin_restart = #0:cin_restart;`

* **id** — `string`, уникальный строковый идентификатор перезапускаемого видеопотока.

#### Описание и особенности работы
`cin_restart` мгновенно сбрасывает указатель текущего кадра активного медиа-декодера на нулевую позицию, заставляя видеоролик воспроизводиться с самого начала. Builtin функционирует в рамках MenuQC. Метод чрезвычайно полезен, когда в интерфейсе игры необходимо реализовать кнопку «Повторить просмотр» (Replay) для сюжетных роликов или зациклить проигрывание фоновой заставки меню в обход полного цикла закрытия и повторного открытия файла через файловую систему. Использование `cin_restart` работает значительно быстрее связки `cin_close` + `cin_open`, так как движок не производит повторную деаллокацию памяти и инициализацию кодеков в операционной системе.

#### Пример использования
```qc
void() Menu_OnReplayButtonClick =
{
    // Сбрасываем курсор воспроизведения кат-сцены на первый кадр
    cin_restart("intro_bg");
};
```

### cin_setstate
`void(string id, float newstate) cin_setstate = #0:cin_setstate;`

* **id** — `string`, уникальный строковый идентификатор активного медиа-потока.
* **newstate** — `float`, числовой код целевого состояния плеера (`1` — запустить воспроизведение, `2` — поставить на паузу).

#### Описание и особенности работы
`cin_setstate` напрямую переключает логическое состояние активного медиа-декодера для видеоролика `id` в контексте MenuQC. Этот встроенный метод позволяет ставить воспроизведение на паузу или возобновлять его без необходимости сбрасывать указатель кадра. На уровне Си-кода движка вызов замораживает обновление текстуры шейдера и приостанавливает декодирование аудиопотока из контейнера (AVI/OGV/ROQ). Метод незаменим при проектировании внутриигровых интерфейсов: например, если игрок вызывает оверлей настроек поверх воспроизводящейся кат-сцены, скрипт может временно приостановить видеоряд, а затем вернуть его в исходный темп.

#### Пример использования
```qc
void() Menu_ToggleVideoPause =
{
    // Ставим видеоролик "cutscene_1" на паузу (код состояния 2)
    cin_setstate("cutscene_1", 2);
    Menu_OpenPauseSubMenu();
};
```

### controller_query
`controller_query(...)` — данная встроенная функция не реализована и является жесткой заглушкой (номера: CSQC=#740, MenuQC=#740).

* Параметры не специфицированы, вызов не имеет функционального смысла.

### gettime
`float(optional float timetype) gettime = #519;`

* **timetype** — `float` (optional), тип запрашиваемого времени (константа, определяющая источник таймера; по умолчанию `0`).
* **Возвращает**: `float` — текущее время в секундах.

#### Описание и особенности работы
`gettime` — это базовый встроенный метод для получения текущего игрового или системного времени в секундах на стороне SSQC и MenuQC. В зависимости от переданного числового значения `timetype`, builtin обращается к различным внутренним счетчикам ядра движка. По умолчанию (`0`) возвращается стандартное серверное/игровое время кадра (эквивалент переменной `time`). Передача альтернативных флагов (например, констант `GTIME_UPTIME` или `GTIME_REALTIME`) позволяет запрашивать «чистое» время работы приложения с момента запуска или астрономическое время операционной системы. Метод крайне важен для расчетов таймингов меню, не зависящих от сетевых задержек сервера, и ведения логов.

#### Пример использования
```qc

void() Menu_LogCurrentSystemTime =
{
    local float sec;

    // Запрашиваем реальное системное время аптайма движка
    sec = gettime(GTIME_REALTIME);
    bprint(sprintf("Engine absolute uptime: %s seconds\n", ftos(sec)));
};
```

### gettimed
`__double(optional int timetype) gettimed = #0:gettimed;`

* **timetype** — `int` (optional), логический тип запрашиваемого временного таймера.
* **Возвращает**: `__double` — высокоточное значение времени в 64-битном формате с плавающей запятой.

#### Описание и особенности работы
`gettimed` является специализированной версией таймера повышенной точности, возвращающей данные в виде нативного 64-битного типа `__double`. Доступен во всех контекстах: CSQC, SSQC и MenuQC. Использование стандартного 32-битного `float` для замера времени на серверах с длительным аптаймом неизбежно приводит к потере точности (округлению на долях секунд), что ломает физику и интерполяцию. Данный builtin решает эту проблему на уровне компилятора FTEQCC и ядра движка, извлекая значения системных счетчиков высокого разрешения (высокоточный `double` из С-кода). Идеально подходит для замера точного FPS, профилирования тяжелых кусков QC-кода на лету и синхронизации комплексных сетевых анимаций.

#### Пример использования
```qc
void() ProfileHeavyLoop =
{
    local __double start_time, end_time;
    local float i;

    start_time = gettimed(0);
    for (i = 0; i < 10000; i = i + 1)
    {
        // Симулируем тяжелые вычисления рефлексии или физики
    }
    end_time = gettimed(0);

    bprint(sprintf("Loop execution took %s seconds\n", dtos(end_time - start_time)));
};
```

Метод позволяет на лету пересобрать таблицу встроенных функций VM, предотвращая сбои выполнения.

#### Пример использования

### patch_evaluate
`void(entity patch, float subdiv_x, float subdiv_y) patch_evaluate = #0:patch_evaluate;`

* **patch** — `entity`, целевая патч-сущность, созданная через `patch_create`.
* **subdiv_x** — `float`, количество шагов разбиения (тесселяции) поверхности по горизонтальной оси.
* **subdiv_y** — `float`, количество шагов разбиения (тесселяции) поверхности по вертикальной оси.

#### Описание и особенности работы
`patch_evaluate` принудительно запускает математический процессор движка для расчета, триангуляции и компиляции полигональной сетки на основе контрольных точек выбранного патча Безье. Этот builtin работает в CSQC. Метод берёт абстрактные математические кривые Безье, заданные внутри сущности `patch`, и математически рассчитывает конечные координаты полигональных вершин на основе параметров разбиения `subdiv_x` и `subdiv_y`. Более высокие значения параметров увеличивают детализацию и плавность изгиба геометрии, но повышают нагрузку на графический конвейер рендеринга и физический движок (коллизии). Функция вызывается каждый раз после изменения положения контрольных точек в редакторе, чтобы обновить меш в реальном времени.

#### Пример использования
```qc
void(entity current_mesh) Editor_FinalizeCurvedWall =
{
    // Запускаем расчет сетки патча с плотностью разбиения 16x16 полигонов
    patch_evaluate(current_mesh, 16, 16);

};
```

### patch_getcp
`vector(entity patch, float x, float y) patch_getcp = #0:patch_getcp;`

* **patch** — `entity`, целевая патч-сущность (криволинейная поверхность), созданная через `patch_create`.
* **x** — `float`, индекс контрольной точки по горизонтальной оси координатной сетки патча.

Поскольку геометрия патча формируется не классическими полигонами, а математической интерполяцией между контрольными точками, этот метод необходим для чтения структуры кривой. Это критически важно для написания интерактивных инструментов трехмерного редактора, реализации логики привязки (snapping) курсора к узлам геометрии или визуализации осей манипулятора (gizmo) вокруг выбранной контрольной точки.

#### Пример использования
```qc
void(entity active_patch) DebugPrintFirstControlPoint =
{
    local vector cp_org;

    // Считываем координаты самой первой контрольной точки на пересечении осей 0,0
```

### patch_getmesh
`int(entity patch, vector *vertex_ptr, vector *st_ptr, int maxverts) patch_getmesh = #0:patch_getmesh;`

* **patch** — `entity`, целевая патч-сущность для выгрузки полигональных данных.
* **vertex_ptr** — `vector *`, указатель на буфер памяти (массив векторов) для копирования координат вершин.
* **st_ptr** — `vector *`, указатель на буфер памяти для копирования текстурных координат (S/T маппинг).
* **maxverts** — `int`, максимальное количество вершин, которое способны безопасно вместить переданные буферы.
* **Возвращает**: `int` — фактическое количество полигональных вершин, скопированных в массивы.

#### Описание и особенности работы
`patch_getmesh` осуществляет прямое синхронное извлечение сгенерированного и триангулированного полигонального меша из внутренних С-структур движка во внешнюю оперативную память виртуальной машины QuakeC. Функция работает на стороне CSQC. После того как для патча был выполнен вызов `patch_evaluate`, движок строит физические полигоны. Данный builtin копирует позиции вершин в буфер `vertex_ptr`, а текстурные координаты (UV-развертку) в `st_ptr`. Возвращаемый результат позволяет QC-скрипту получить точную геометрию для построения кастомных систем физических столкновений, экспорта созданных в игре моделей во внешние файлы или генерации процедурных эффектов на основе формы криволинейной стены. Перед вызовом память под указатели должна быть гарантированно выделена через `memalloc` или `createbuffer`.

#### Пример использования
```qc
void(entity evaluated_patch) ProcessPatchTriangles =
{
    local vector *v_buffer;
    local vector *t_buffer;
    local float total_verts;

    // Выделяем временную память в кадре под меш из 64 вершин
    v_buffer = createbuffer(sizeof(vector) * 64);
    t_buffer = createbuffer(sizeof(vector) * 64);

    total_verts = patch_getmesh(evaluated_patch, v_buffer, t_buffer, 64);
    if (total_verts > 0)
    {
        bprint(sprintf("Extracted %s tri-vertices from internal engine patch cache\n", ftos(total_verts)));
    }
};
```

### removeinstant

#### Описание и особенности работы
`removeinstant` выполняет мгновенную деаллокацию и полную очистку сущности из памяти виртуальной машины в контексте CSQC и MenuQC. ```

#### Описание и особенности работы
`videoplaying` — это специализированный встроенный метод MenuQC для глобального контроля состояния встроенного полноэкранного медиаплеера движка FTEQW (отвечающего за нативный запуск файлов вроде `cin` или `roq` при старте игры или смене этапов). В отличие от функций семейства `cin_*`, которые работают с текстурными медиа-шейдерами внутри кастомных UI-элементов, этот опкод `#355` проверяет статус глобального Си-декодера видео на уровне ядра приложения. Метод критически важен для реализации логики блокировки: если функция возвращает `1`, скрипт главного меню должен приостановить рендеринг элементов интерфейса, фоновой музыки меню и перехват стандартных клавиш навигации, чтобы не мешать пользователю смотреть вступительный ролик или кат-сцену.

#### Пример использования
```qc
void() Menu_MainDrawLoop =
{
    // Если движок занят воспроизведением полноэкранного видеоролика — пропускаем отрисовку элементов меню
    if (videoplaying())
        return;

    // В противном случае рендерим интерфейс главного меню
    Menu_RenderButtons();
    Menu_RenderCursor();
};
```
