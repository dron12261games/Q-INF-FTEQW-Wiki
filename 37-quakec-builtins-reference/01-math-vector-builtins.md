# Математика и работа с векторами

> [⬅ Вернуться к оглавлению вики](../README.md)

> [Индекс справочника builtins](./README.md)

В эту категорию входят builtins для численной математики, тригонометрии, преобразования углов, работы с направляющими векторами и несколькими связанными строково-числовыми конвертерами, которые в QuakeC постоянно используются рядом с расчётами. Важно помнить, что `sin`, `cos`, `tan`, `asin`, `acos`, `atan` и `atan2` работают с радианами, а `makevectors`, `vectoyaw`, `vectoangles`, `changeyaw`, `changepitch` и `anglemod` — с углами Quake в градусах. В сигнатурах ниже указан основной builtin number из `fteextensions.qc`; если в `MenuQC` тот же builtin привязан к другому legacy-номеру, это отдельно оговаривается в описании.

## Функции

### acos
`float(float c) acos = #472;`

* **c** — `float` в диапазоне `[-1, 1]`, для которого нужно получить арккосинус.

#### Описание и логика работы

`acos` возвращает арккосинус числа в радианах. На практике это угол в диапазоне от `0` до `pi`, поэтому builtin удобен, когда нужно восстановить угол по косинусу, например после скалярного произведения нормализованных векторов. В `fteextensions.qc` builtin объявлен глобально, то есть доступен в `SSQC`, `CSQC` и `MenuQC`. Реализация в `pr_bgcmd.c` напрямую вызывает стандартную `acos` из математической библиотеки и не делает предварительного зажима значения, поэтому вход за пределами `[-1, 1]` даёт платформенно-зависимый NaN-подобный результат. Для устойчивого кода перед вызовом обычно стоит использовать `bound(-1, x, 1)`.

#### Практические сценарии использования

```
local vector dir_to_enemy;
local float dotv;
local float angle_rad;

// Строим forward-вектор из текущих углов сущности.
makevectors(self.v_angle);

// Направление на цель в нормализованном виде.
dir_to_enemy = normalize(enemy.origin - self.origin);

// Косинус угла между нашим forward и целью.
dotv = v_forward * dir_to_enemy;
dotv = bound(-1, dotv, 1); // защищаемся от ошибок округления

// Получаем угол в радианах.
angle_rad = acos(dotv);
```

### asin
`float(float s) asin = #471;`

* **s** — `float` в диапазоне `[-1, 1]`, для которого нужно получить арксинус.

#### Описание и логика работы

`asin` возвращает арксинус числа в радианах и обычно выдаёт результат в диапазоне от `-pi/2` до `pi/2`. Это полезно, когда нужно восстановить угол по синусу или получить вертикальную составляющую угла по нормализованному направлению. Как и `acos`, builtin объявлен для всех VM и в FTEQW напрямую завязан на стандартную математическую функцию без защитных проверок. Значения чуть больше `1` или чуть меньше `-1`, появившиеся из-за накопленной ошибки вычислений, лучше предварительно ограничивать вручную.

#### Практические сценарии использования

```
local vector dir;
local float pitch_rad;

// Нормализуем вектор, чтобы z-компонента стала синусом угла наклона.
dir = normalize(enemy.origin - self.origin);

// Ограничиваем диапазон и восстанавливаем угол по вертикальной компоненте.
pitch_rad = asin(bound(-1, dir_z, 1));
```

### atan
`float(float t) atan = #473;`

* **t** — `float`, обычно тангенс искомого угла.

#### Описание и логика работы

`atan` возвращает арктангенс числа в радианах. В отличие от `atan2`, эта версия видит только отношение `y/x` и потому не может сама восстановить квадрант: результат лежит в диапазоне `(-pi/2, pi/2)`. Builtin доступен глобально во всех VM и в реализации FTEQW просто пробрасывает аргумент в стандартную `atan`. Это быстрый и удобный вариант, когда знак и квадрант вам уже известны заранее; если же угол строится из двух компонент вектора, почти всегда правильнее использовать `atan2`.

#### Практические сценарии использования

```
local float rise;
local float run;
local float slope_angle;
local vector flat;

flat = enemy.origin - self.origin;
flat_z = 0;                     // оставляем только горизонтальную плоскость
rise = enemy.origin_z - self.origin_z;
run = vlen(flat);

if (run > 0)
    slope_angle = atan(rise / run); // угол подъёма в радианах
else
    slope_angle = 0; // вертикальный случай обрабатываем отдельно
```

### atan2
`float(float c, float s) atan2 = #474;`

* **c** — `float`, первый аргумент, который FTEQW напрямую передаёт в стандартную `atan2`.
* **s** — `float`, второй аргумент, который FTEQW напрямую передаёт в стандартную `atan2`.

#### Описание и логика работы

`atan2` вычисляет угол по двум компонентам и, в отличие от `atan`, сохраняет информацию о квадранте. Это основной builtin для восстановления полного угла направления, когда у вас есть горизонтальные компоненты вектора. Важный нюанс FTEQW: реализация без переупорядочивания вызывает C-функцию `atan2(first, second)`, поэтому для привычного угла вектора по плоскости следует передавать `y` первым, а `x` вторым. Возвращаемое значение задаётся в радианах, а при нулевых аргументах итог зависит от поведения платформенной math-библиотеки, поэтому для полностью нулевого вектора удобнее иметь отдельную защиту в QuakeC.

#### Практические сценарии использования

```
local vector dir;
local float yaw_rad;

// Строим горизонтальное направление до врага.
dir = enemy.origin - self.origin;
dir_z = 0;

if (dir_x == 0 && dir_y == 0)
    yaw_rad = 0;
else
    yaw_rad = atan2(dir_y, dir_x); // первый аргумент - y, второй - x
```

### tan
`float(float a) tan = #475;`

* **a** — `float` с углом в радианах.

#### Описание и логика работы

`tan` возвращает тангенс угла в радианах. Builtin объявлен глобально и реализован как прямой вызов стандартной `tan`, то есть никаких защит от особенностей функции нет: около `pi/2 + k*pi` значение резко растёт по модулю, а на некоторых платформах может уходить в бесконечность или в очень большие числа. Для обычной игровой логики builtin применяют там, где нужна производная высота по углу наклона или где тригонометрия заведомо работает далеко от сингулярностей.

#### Практические сценарии использования

```
local float pitch_rad;
local float forward_dist;
local float rise;

pitch_rad = 0.35;      // угол вверх в радианах
forward_dist = 256;    // хотим сместиться вперёд на 256 units
rise = tan(pitch_rad) * forward_dist;
```

### sin
`float(float angle) sin = #60;`

* **angle** — `float` с углом в радианах.

#### Описание и логика работы

`sin` возвращает синус угла в радианах. В `SSQC` и `CSQC` builtin описан как `#60`, а в `MenuQC` присутствует тот же функционал на legacy-номере `#38`. Дополнительной логики поверх стандартной математической функции нет, поэтому builtin ведёт себя так же, как обычный синус из C: хорошо подходит для анимации, колебаний, процедурных движений и расчётов по окружности. Если вы работаете с углами Quake из `self.angles` или `vectoyaw`, не забывайте сначала перевести градусы в радианы.

#### Практические сценарии использования

```
local float bob;

// Плавное вертикальное покачивание предмета.
bob = sin(time * 4) * 6;
self.origin_z = self.origin_z + bob;
```

### cos
`float(float angle) cos = #61;`

* **angle** — `float` с углом в радианах.

#### Описание и логика работы

`cos` возвращает косинус угла в радианах. В `MenuQC` используется legacy-номер `#39`, а в `SSQC`/`CSQC` — `#61`. Builtin нужен во всех стандартных тригонометрических сценариях: движение по кругу, построение смещений по фазе, восстановление проекций и работа с периодическими эффектами. Так как реализация просто вызывает стандартную `cos`, итоговая точность и обработка очень больших значений зависят от платформенной math-библиотеки, но для обычных игровых диапазонов это не представляет проблемы.

#### Практические сценарии использования

```
local float phase;
local vector offset;

phase = time * 2;
offset_x = cos(phase) * 64; // координата по окружности
offset_y = sin(phase) * 64; // вторая координата идёт через sin
offset_z = 0;
```

### sqrt
`float(float value) sqrt = #62;`

* **value** — `float`, для которого нужно вычислить квадратный корень.

#### Описание и логика работы

`sqrt` возвращает квадратный корень числа. В `SSQC` и `CSQC` builtin имеет номер `#62`, а в `MenuQC` тот же функционал виден как `#40`. Для неотрицательных входов это прямой и предсказуемый способ получить длину, дистанцию или масштаб из квадрата величины; для отрицательных чисел защит нет, и результат зависит от поведения стандартной `sqrt`, обычно превращаясь в NaN-подобное значение. Если вход может быть отрицательным из-за ошибок накопления, его имеет смысл ограничить через `max(value, 0)`.

#### Практические сценарии использования

```
local vector delta;
local float dist2;
local float dist;

delta = enemy.origin - self.origin;
dist2 = delta * delta;      // квадрат расстояния
dist = sqrt(max(dist2, 0)); // извлекаем длину безопасно
```

### pow
`float(float value, float exp) pow = #97;`

* **value** — `float`, основание степени.
* **exp** — `float`, показатель степени.

#### Описание и логика работы

`pow` возводит `value` в степень `exp`. Builtin доступен в `SSQC`, `CSQC` и `MenuQC`, но в `MenuQC` использует legacy-номер `#46`. В FTEQW это прямой вызов стандартной `pow`, поэтому дробные показатели, корни и отрицательные степени работают так же, как в обычной математической библиотеке. При этом отрицательное основание с недробно-представимым показателем, ноль в отрицательной степени или слишком большие значения могут давать бесконечности либо NaN-подобные результаты, так что для граничных случаев проверки нужно делать на стороне QuakeC.

#### Практические сценарии использования

```
local float falloff;
local float dist;

// Нелинейно ослабляем эффект по расстоянию.
dist = vlen(enemy.origin - self.origin);
falloff = 1 / pow(max(dist, 1), 2); // обратный квадрат дистанции
```

### log
`float(float v, optional float base) log = #532;`

* **v** — `float`, значение, логарифм которого нужно получить.
* **base** — `optional float`, основание логарифма; если аргумент не передан, вычисляется натуральный логарифм.

#### Описание и логика работы

`log` вычисляет логарифм числа. В FTEQW он реализован как `ln(v)` и, если указан `base`, дополнительно делится на `ln(base)`, то есть `log(v, base) = ln(v) / ln(base)`. Builtin объявлен глобально и является более новой формой старого `logarithm = #0:logarithm`; для совместимости это полезно помнить при чтении старого QuakeC. Проверок на корректность диапазона нет, поэтому `v <= 0`, `base <= 0` или `base == 1` приводят к платформенно-зависимому `NaN`/`Inf`. Это удобный builtin для экспоненциальных шкал, расчёта числа бинарных шагов и обратных преобразований к `pow`.

#### Практические сценарии использования

```
local float radius;
local float mip_level;

// Оцениваем, сколько раз размер можно делить на два.
radius = max(self.scale * 256, 1);
mip_level = floor(log(radius, 2));
```

### rint
`float(float value) rint = #36;`

* **value** — `float`, который нужно округлить до ближайшего целого.

#### Описание и логика работы

`rint` округляет число к ближайшему целому значению. В `MenuQC` builtin находится на `#34`, а в `SSQC`/`CSQC` — на `#36`. Важный нюанс FTEQW зафиксирован и в комментарии, и в реализации: `X.5` округляется от нуля, то есть `1.5` превращается в `2`, а `-1.5` — в `-2`. Это отличается от банковского округления в некоторых языках, зато делает поведение предсказуемым для координат, индексов и шагов сетки.

#### Практические сценарии использования

```
local vector snapped;

// Привязываем позицию к сетке 16 units.
snapped_x = rint(self.origin_x / 16) * 16;
snapped_y = rint(self.origin_y / 16) * 16;
snapped_z = rint(self.origin_z / 16) * 16;
```

### ceil
`float(float value) ceil = #38;`

* **value** — `float`, который нужно округлить вверх.

#### Описание и логика работы

`ceil` возвращает наименьшее целое, не меньшее входного значения. Для `SSQC`/`CSQC` это builtin `#38`, а в `MenuQC` — `#36`. В FTEQW используется стандартная `ceil`, поэтому отрицательные дроби тоже двигаются вверх по числовой прямой: `-1.2` становится `-1`. Builtin удобен при расчёте количества ячеек, страниц, сетевых блоков и любых случаев, где неполное значение должно занимать целую единицу ресурса.

#### Практические сценарии использования

```
local float pages;
local float items_per_page;

items_per_page = 8;
pages = ceil(total_items / items_per_page); // даже неполная страница считается
```

### floor
`float(float value) floor = #37;`

* **value** — `float`, который нужно округлить вниз.

#### Описание и логика работы

`floor` возвращает наибольшее целое, не большее входного значения. В `SSQC`/`CSQC` он расположен на `#37`, а в `MenuQC` — на `#35`. В отличие от простого приведения к `int`, builtin корректно работает и для отрицательных дробей, то есть `floor(-1.2)` даст `-2`. Это особенно важно там, где вы делите мир на ячейки, шаги или диапазоны и хотите получить математически правильный индекс.

#### Практические сценарии использования

```
local float cell_x;
local float cell_y;

// Вычисляем индекс ячейки карты размером 128x128.
cell_x = floor(self.origin_x / 128);
cell_y = floor(self.origin_y / 128);
```

### fabs
`float(float value) fabs = #43;`

* **value** — `float`, знак которого нужно отбросить.

#### Описание и логика работы

`fabs` возвращает абсолютное значение числа. В `MenuQC` ему соответствует legacy-номер `#18`, в `SSQC`/`CSQC` — `#43`. Реализация просто вызывает стандартную `fabs`, поэтому для обычных чисел builtin предельно прямолинеен: положительные значения не меняются, отрицательные становятся положительными, ноль остаётся нулём. Это один из самых частых вспомогательных builtins для сравнений с допуском, расчёта модулей отклонения и проверки, насколько далеко величина ушла от целевой.

#### Практические сценарии использования

```
local float yaw_error;

yaw_error = fabs(anglemod(self.angles_y) - anglemod(self.ideal_yaw));
if (yaw_error < 2)
    self.frame = self.frame_idle;
```

### bound
`float(float minimum, float val, float maximum) bound = #96;`

* **minimum** — `float`, нижняя граница диапазона.
* **val** — `float`, значение, которое нужно ограничить.
* **maximum** — `float`, верхняя граница диапазона.

#### Описание и логика работы

`bound` зажимает число в диапазон `[minimum, maximum]`: если `val` меньше минимума, возвращается `minimum`; если больше максимума — `maximum`; иначе возвращается само `val`. Builtin доступен во всех основных VM, а в `MenuQC` использует legacy-номер `#45`. Важный нюанс FTEQW: функция не пытается переставить границы местами, если вы случайно передали `minimum > maximum`; она просто последовательно выполняет сравнения, поэтому инвертированный диапазон даёт логически странный результат. Для нормализации данных, ограничений скорости, громкости, FOV или dot product это один из самых полезных математических builtins.

#### Практические сценарии использования

```
local float pitch;

// Не даём турели смотреть слишком высоко или низко.
pitch = bound(-45, self.angles_x + 10, 60);
self.angles_x = pitch;
```

### min
`float(float a, float b, ...) min = #94;`

* **a** — `float`, первый кандидат на минимум.
* **b** — `float`, второй кандидат на минимум.
* **...** — дополнительные `float`, которые тоже участвуют в сравнении.

#### Описание и логика работы

`min` возвращает наименьшее значение из переданных аргументов. Builtin доступен в `SSQC`, `CSQC` и `MenuQC`, но в `MenuQC` использует номер `#43`. FTEQW поддерживает как минимум два аргумента и произвольное количество последующих; если передать меньше двух, движок выбросит runtime-ошибку builtin'а. Аргументы сравниваются как обычные `float`, без особой обработки NaN-подобных состояний, поэтому в сомнительных числовых потоках лучше сначала нормализовать входные данные.

#### Практические сценарии использования

```
local float step;

// Выбираем самый жёсткий из нескольких лимитов скорости.
step = min(self.maxspeed, cvar("sv_maxspeed"), 320);
```

### max
`float(float a, float b, ...) max = #95;`

* **a** — `float`, первый кандидат на максимум.
* **b** — `float`, второй кандидат на максимум.
* **...** — дополнительные `float`, которые тоже участвуют в сравнении.

#### Описание и логика работы

`max` возвращает наибольшее из переданных значений. В `MenuQC` тот же builtin расположен на `#44`, а в `SSQC`/`CSQC` — на `#95`. Как и `min`, он требует минимум два аргумента, иначе FTEQW сгенерирует ошибку выполнения. Функция особенно удобна для защит от деления на ноль, нижних порогов, выбора сильнейшего эффекта и подготовки чисел к `sqrt`, `log` или `pow`, где отрицательные либо слишком малые значения нежелательны.

#### Практические сценарии использования

```
local float safe_dist;

// Не даём дистанции стать слишком маленькой перед делением.
safe_dist = max(vlen(enemy.origin - self.origin), 1);
```

### mod
`float(float dividend, float divisor) mod = #245;`

* **dividend** — `float`, делимое.
* **divisor** — `float`, делитель.

#### Описание и логика работы

`mod` возвращает остаток от деления. В старом menu-списке аналогичный функционал встречается и на legacy-номере `#70`, а в более позднем расширенном наборе для `SSQC`/`CSQC` используется `#245`. Реализация FTEQW считает остаток по формуле `a - n * int(a / n)`, то есть частное усечётся к нулю, а не к `floor`; из-за этого отрицательные значения ведут себя не как математический modulo в языках с floor-делением. Делитель `0` явно запрещён: движок выдаёт предупреждение `mod by zero` и возвращает `0`. Дробные аргументы допустимы, но из-за float-арифметики и усечения результат может быть неинтуитивным, поэтому для целочисленных циклов builtin полезнее всего вместе с `rint`, `floor` или явной дисциплиной входных значений.

#### Практические сценарии использования

```
local float next_frame;

// Зацикливаем номер кадра в диапазоне 0..9.
next_frame = mod(self.frame + 1, 10);
self.frame = next_frame;
```

### random

#### Описание и логика работы

`random` возвращает псевдослучайное число с плавающей точкой в интервале около `0..1`. В `SSQC`/`CSQC` функция описана как builtin `#7`, а в `MenuQC` — как `#12`. // Случайная задержка перед следующей атакой в диапазоне 0.2..0.5 секунды.

### randomvec
`vector() randomvec = #91;`

* Аргументы отсутствуют.

#### Описание и логика работы

`randomvec` возвращает случайный `vector`. Док-комментарий говорит о независимых компонентах в диапазоне `[-1, 1]`, но реальная реализация FTEQW делает чуть более сильную вещь: генерирует точки внутри единичной сферы, отбрасывая варианты, у которых длина не меньше `1`. Это значит, что каждая компонента действительно попадает примерно в диапазон `[-1, 1]`, но итоговый вектор всегда имеет длину меньше `1`, что особенно удобно для джиттера, разброса и случайных смещений без дополнительной нормализации. Builtin есть в `SSQC`, `CSQC` и `MenuQC`; в menu-реестре движка тот же код виден под именем `randomvec` даже там, где старые qc-дефы писали `randomvector`.

#### Практические сценарии использования

```
local vector spread;

// Добавляем небольшой случайный разброс к точке появления частицы.
spread = randomvec() * 12;
particle(self.origin + spread, '0 0 20', 66, 8);
```

### bitshift
`float(float number, float quantity) bitshift = #218;`

* **number** — `float`, который будет интерпретирован как целое битовое значение.
* **quantity** — `float`, количество бит для сдвига; положительное число сдвигает влево, отрицательное — вправо.

#### Описание и логика работы

`bitshift` выполняет побитовый сдвиг. Несмотря на тип `float` в сигнатуре, реализация в FTEQW сначала приводит оба аргумента к целым значениям, а затем делает обычный `<<` или `>>`. Builtin глобальный и подходит для `SSQC`, `CSQC` и `MenuQC`, но использовать его имеет смысл только на величинах, которые вы уже мыслите как целые маски, флаги или packed-значения. Дробная часть входов отбрасывается, переполнение не контролируется, а правый сдвиг знаковых значений наследует поведение платформенного C-компилятора, так что для переносимой логики лучше работать с неотрицательными битовыми масками.

#### Практические сценарии использования

```
local float mask;

// Выставляем третий бит во флаге.
mask = bitshift(1, 2); // 00000100
self.effects = self.effects | mask;
```

#### Практические сценарии использования

local float yaw;

yaw = anglemod(self.angles_y + 725); // превращаем 725 градусов в нормальный диапазон

### changepitch
`void(entity ent) changepitch = #63;`

```
// Плавно тянем взгляд монстра к игроку по вертикали.

`changeyaw` плавно поворачивает `self.angles_y` в сторону `self.ideal_yaw`, не превышая `self.yaw_speed` за один вызов. Builtin существует в `SSQC` и `CSQC`; в `fteextensions.qc` рядом с ним объявлен старый совместимый макро-синоним `ChangeYaw`. // Наводим турель на цель без мгновенного разворота.

### normalize
`vector(vector v) normalize = #9;`

* **v** — `vector`, который нужно привести к единичной длине.

#### Описание и логика работы

`normalize` возвращает копию вектора длиной `1`, сохраняющую исходное направление. Builtin есть во всех трёх основных VM; в `MenuQC` это legacy-номер `#8`, а в `SSQC`/`CSQC` — `#9`. Реализация FTEQW явно считает длину и, если она равна нулю, возвращает `'0 0 0'` вместо деления на ноль. Благодаря этому `normalize` безопасен даже на вырожденных векторах и отлично подходит для расчёта направлений движения, выстрела, трассировки и любых dot/cross-операций, где нужна единичная длина.

#### Практические сценарии использования

```
local vector dir;

// Получаем чистое направление полёта ракеты от стрелка к цели.
dir = normalize(enemy.origin - self.origin);
missile.velocity = dir * 900;
```

`float(vector v) vlen = #12;`

* **v** — `vector`, длину которого нужно получить.

#### Описание и логика работы

`vlen` возвращает длину вектора в quake units, то есть квадратный корень из скалярного произведения вектора на самого себя. В `MenuQC` этот builtin расположен на `#9`, а в `SSQC`/`CSQC` — на `#12`. В FTEQW это обычный `sqrt(dot(v, v))`, поэтому отрицательных сюрпризов здесь нет, кроме стандартных ограничений float-точности на очень больших числах. Builtin используют для измерения расстояний, скоростей, интенсивности импульса и нормализации вручную, если вместе с длиной нужно сохранить ещё и исходную величину.

```
local float dist;

dist = vlen(enemy.origin - self.origin);
if (dist < 128)
    self.attack_state = AS_MELEE;
```

// Печатаем позицию сущности в консоль для отладки.

### vectoangles
`vector(vector fwd, optional vector up) vectoangles = #51;`

* **fwd** — `vector`, направление, которое нужно превратить в углы.
* **up** — `optional vector`, дополнительный вектор "вверх", позволяющий получить осмысленный roll.

#### Описание и логика работы

`vectoangles` преобразует вектор направления в углы Quake. Док-комментарий подчёркивает, что возвращаемая система использует соглашение `+x = UP`, то есть это обратная операция к игровому взгляду, а не буквальная копия `makevectors`, где в комментарии указано `+x = DOWN`. Если второй аргумент `up` не передан, builtin восстановит только обычную monster-style ориентацию без надёжного roll; если `up` передан, можно получить полноценный угол поворота вокруг forward-оси. Функция доступна в `SSQC`, `CSQC` и `MenuQC` и особенно полезна при повороте сущностей по готовому направлению, например на цель или вдоль поверхности.

#### Практические сценарии использования

```
local vector dir;

// Поворачиваем сущность лицом к противнику.
dir = normalize(enemy.origin - self.origin);
self.angles = vectoangles(dir);
```

### vectoyaw
`float(vector v, optional entity reference) vectoyaw = #13;`

* **v** — `vector`, направление, из которого нужно получить yaw.
* **reference** — `optional entity`, сущность, относительно чьего направления гравитации надо интерпретировать yaw.

#### Описание и логика работы

`vectoyaw` возвращает yaw-угол в градусах для заданного направления. Если передан `reference`, FTEQW сначала проецирует вектор в локальную плоскость гравитации этой сущности; это важно для модов с нестандартной гравитацией и ходьбой по стенам. Без второго аргумента builtin просто смотрит на `x/y` компоненты мира. В текущей реализации итог дополнительно усечён до целого градуса через приведение к `int`, а для нулевого горизонтального вектора возвращается `0`, поэтому очень мелкие колебания и дробные доли градуса здесь намеренно теряются.

#### Практические сценарии использования

```
local vector dir;

// Строим целевой yaw до врага.
dir = enemy.origin - self.origin;
self.ideal_yaw = vectoyaw(dir);

### makevectors
`void(vector vang) makevectors = #1;`

* **vang** — `vector` с углами `pitch yaw roll`, из которых нужно построить базис.

#### Описание и логика работы

`makevectors` преобразует вектор углов в три глобальных вектора: `v_forward`, `v_right` и `v_up`. Builtin доступен в `SSQC` и `CSQC`, а его комментарий отдельно напоминает про внутреннее соглашение `(+x = DOWN)`, что важно при сопоставлении с `vectoangles`. Функция ничего не возвращает, а работает побочным эффектом, переписывая текущий глобальный базис VM, поэтому значение `v_forward` и друзей нужно использовать сразу или сохранять в локальные переменные, если дальше вы вызываете другие builtins, которые тоже их меняют. Это центральный кирпич для стрельбы, трассировок, смещений вправо/вверх от взгляда и любых локальных координат.

#### Практические сценарии использования

```
local vector muzzle;

// Строим локальный базис по углам игрока.
makevectors(self.v_angle);

// Находим точку выстрела немного впереди и правее.
muzzle = self.origin + v_forward * 16 + v_right * 8 + v_up * 12;
```

### vectorvectors
`void(vector dir) vectorvectors = #432;`

* **dir** — `vector`, который будет использован как новый `v_forward`.

#### Описание и логика работы

`vectorvectors` строит ортонормированный базис по одному направлению и записывает результат в глобальные `v_forward`, `v_right` и `v_up`. В отличие от `makevectors`, входом служит уже готовый вектор направления, а не углы. Реализация FTEQW сначала нормализует `dir`, затем достраивает к нему два перпендикулярных вектора, поэтому builtin особенно удобен, когда у вас есть нормаль поверхности, направление трассы или вектор полёта и на его основе нужно построить локальную систему координат. Builtin доступен как минимум в `SSQC` и `CSQC`; для `MenuQC` это не базовый legacy-инструмент.

#### Практические сценарии использования

```
local vector hitnormal;
local vector decal_origin;

// Строим базис по нормали поверхности.
hitnormal = trace_plane_normal;
vectorvectors(hitnormal);

// Смещаем decal немного вдоль нормали, чтобы он не утонул в стене.
decal_origin = trace_endpos + v_forward * 0.5;
```

### rotatevectorsbyangle
`void(vector angle) rotatevectorsbyangle = #235;`

* **angle** — `vector` углов, на которые нужно дополнительно повернуть текущий базис `v_forward/v_right/v_up`.

#### Описание и логика работы

`rotatevectorsbyangle` не создаёт базис с нуля, а вращает уже существующий глобальный базис на заданные углы. Поэтому перед вызовом обычно сначала вызывают `makevectors` или `vectorvectors`, чтобы было что вращать. Builtin доступен в `SSQC` и `CSQC` и меняет только глобальные `v_forward`, `v_right` и `v_up`, ничего не возвращая. Это удобно, когда базовый взгляд уже известен, а поверх него нужно навесить локальный offset: recoil, разброс, смещение крепления оружия, раскачку камеры и похожие эффекты.

#### Практические сценарии использования

```
local vector muzzle;

makevectors(self.v_angle);           // базовый взгляд игрока
rotatevectorsbyangle('0 5 0');       // добавляем 5 градусов вправо
muzzle = self.origin + v_forward * 16 + v_up * 12;
```

### rotatevectorsbyvectors
`void(vector fwd, vector right, vector up) rotatevectorsbyvectors = #236;`

* **fwd** — `vector`, forward-ось дополнительного поворота.
* **right** — `vector`, right-ось дополнительного поворота.
* **up** — `vector`, up-ось дополнительного поворота.

#### Описание и логика работы

`rotatevectorsbyvectors` умножает текущий глобальный базис на другой базис, переданный явными осями. Внутри FTEQW это обычная конкатенация матриц поворота: исходные `v_forward/v_right/v_up` читаются из VM, затем движок применяет новый набор осей и записывает результат обратно в те же глобалы. Builtin полезен, когда дополнительная ориентация уже хранится в виде трёх векторов, например была вычислена через `makevectors`, `vectorvectors` или получена из тега/кости. Как и остальные rotate-билтины, функция работает только через побочный эффект и поэтому требует аккуратно сохранять промежуточные оси, если они ещё понадобятся.

#### Практические сценарии использования

```
local vector add_fwd, add_right, add_up;

// Сначала получаем дополнительный базис из углов цели.
makevectors(enemy.angles);
add_fwd = v_forward;
add_right = v_right;
add_up = v_up;

// Возвращаемся к своему базису и домножаем его на базис цели.
makevectors(self.angles);
rotatevectorsbyvectors(add_fwd, add_right, add_up);
```

### rotatevectorsbytag
`vector(entity ent, float tagnum) rotatevectorsbytag = #244;`

* **ent** — `entity`, модель которой содержит tag или bone.
* **tagnum** — `float`, числовой индекс тега, обычно полученный через `gettagindex`.

#### Описание и логика работы

`rotatevectorsbytag` доступен только в `CSQC` и предназначен для привязки локального базиса к тегу или кости модели. Builtin возвращает мировую позицию тега, а также побочным эффектом записывает в `v_forward`, `v_right` и `v_up` ориентацию тега, домноженную на текущий локальный базис. Это очень удобно для muzzle flash, привязанных частиц, shell ejection и отрисовки вспомогательных объектов в пространстве viewmodel или world model. Если тег не найден, FTEQW возвращает просто `ent.origin`, а глобальный базис не получает новой полезной ориентации, поэтому перед использованием разумно проверять валидность `tagnum`.

#### Практические сценарии использования

```
local float muzzle_tag;
local vector muzzle_origin;

muzzle_tag = gettagindex(self, "tag_muzzle");
if (muzzle_tag > 0)
{
    makevectors(self.angles);                    // базис, относительно которого читаем tag
    muzzle_origin = rotatevectorsbytag(self, muzzle_tag);
    dprint("muzzle = ", vtos(muzzle_origin), "\n");
}
```

### project
`vector(vector v) project = #311;`

* **v** — `vector` в мировых координатах, который нужно спроецировать в экранные.

#### Описание и логика работы

`project` существует только в `CSQC` и преобразует мировую точку в экранные координаты текущего view/projection setup. Комментарий в `fteextensions.qc` прямо указывает, что builtin опирается на параметры камеры, выставленные через `setproperty`, а реализация в `pr_csqc.c` показывает, что возвращаемый `vector` содержит `x` и `y` в пикселях текущего viewport и `z` как глубину. Важный нюанс: если точка находится за камерой, FTEQW инвертирует знак `z`, так что отрицательная глубина — удобный способ понять, что рисовать маркер уже не нужно. Builtin полезен для HUD-указателей, world-space labels и любых интерфейсных элементов, которые должны следовать за 3D-объектами.

#### Практические сценарии использования

```
local vector screen;
local vector drawpos;

// Проецируем точку чуть выше головы сущности на экран.
screen = project(self.origin + '0 0 48');
if (screen_z > 0)
{
    // Точка перед камерой: можно рисовать маркер в screen_x/screen_y.
    drawpos_x = screen_x - 8;
    drawpos_y = screen_y - 8;
    drawpos_z = 0;
    drawpic(drawpos, "gfx/target", '16 16 0', '1 1 1', 1, 0);
}
```

### unproject
`vector(vector v) unproject = #310;`

* **v** — `vector`, где `x` и `y` — экранные пиксели, а `z` — нормализованная глубина.

#### Описание и логика работы

`unproject` — обратная операция к `project`, тоже доступная только в `CSQC`. Builtin берёт точку на экране и глубину, после чего восстанавливает соответствующую 3D-точку в мире относительно текущей камеры и активных свойств view. В реализации FTEQW видно, что ввод трактуется именно как координаты внутри текущего viewport, а глубина для non-DP пути дополнительно переводится из диапазона `0..1` во внутренний интервал clip-space. Это удобный строитель лучей из центра экрана, мышиного курсора или произвольной HUD-точки, но важно понимать, что без осмысленной глубины вы получаете лишь одну из точек на луче, а не весь луч целиком.

#### Практические сценарии использования

```
local vector world_near;
local vector world_far;
local vector ray_dir;

// Строим луч из центра условного экрана 640x480.
world_near = unproject('320 240 0.01');
world_far = unproject('320 240 0.99');
ray_dir = normalize(world_far - world_near);
```

### crc16
`__deprecated("Use digest_hex") float(float caseinsensitive, string s, ...) crc16 = #494;`

* **caseinsensitive** — `float`, ненулевое значение включает регистронезависимый вариант CRC.
* **s** — `string`, первая строка, участвующая в хешировании.
* **...** — дополнительные строки, которые будут склеены к первой до вычисления CRC.

#### Описание и логика работы

`crc16` вычисляет 16-битный CRC-хеш для одной строки или для конкатенации нескольких строковых аргументов. Builtin объявлен глобально и помечен как устаревший: в `fteextensions.qc` прямо советуют использовать `digest_hex`. В FTEQW первый аргумент выбирает один из двух вариантов хеширования — обычный или регистронезависимый, где вход приводится к нижнему регистру перед расчётом. Возвращаемое значение приходит как `float`, но по смыслу это целое 16-битное число; функция подходит для быстрых идентификаторов, контрольных сумм коротких строк и совместимости со старым кодом, однако для криптографической или просто более современной задачи лучше сразу брать `digest_hex`.

#### Практические сценарии использования

```
local float checksum;

// Считаем лёгкий идентификатор комбинации карты и режима.
checksum = crc16(TRUE, world.model, ":", self.classname);
```

### htos
`string(int value) htos = #262;`

* **value** — `int`, который нужно представить в шестнадцатеричном виде.

#### Описание и логика работы

`htos` превращает `int` в hex-строку фиксированной ширины. Док-комментарий и реализация совпадают: builtin всегда возвращает восемь шестнадцатеричных символов в нижнем регистре, без префикса `0x` и с ведущими нулями. Для отрицательных значений будет показано двоичное дополнение того же 32-битного представления, потому что внутри используется unsigned-форматирование. Строка временная, поэтому хранить её надолго нужно так же осторожно, как результат `itos` или `vtos`.

#### Практические сценарии использования

```
local string hexmask;

hexmask = htos(self.effects);
dprint("effects mask = 0x", hexmask, "\n");
```

### itos
`string(int value) itos = #260;`

* **value** — `int`, который нужно превратить в десятичную строку.

#### Описание и логика работы

`itos` возвращает десятичное текстовое представление целого числа. Builtin объявлен в `fteextensions.qc` для `SSQC`/`CSQC`, а в актуальном движке существует и как расширение menu-VM, но для переносимости разумно считать его прежде всего функцией расширенного FTE-набора. Реализация использует обычное `%d`, так что формат предельно прямой: знак сохраняется, лишних пробелов или префиксов нет. Функция особенно удобна там, где `ftos` нежелателен из-за поведения с float и округлением, а нужен именно настоящий `int`.

#### Практические сценарии использования

```
local string msg;

msg = strcat("score=", itos(self.frags), "\n");
sprint(self, msg);
```

### stoi
`int(string s) stoi = #259;`

* **s** — `string`, которую нужно прочитать как целое число.

#### Описание и логика работы

`stoi` преобразует строку в `int`. Док-комментарий в `fteextensions.qc` обещает автоопределение базы `8/10/16`, но текущая реализация FTEQW в `pr_bgcmd.c` использует обычный `atoi`, то есть практически надёжно парсит именно десятичное число с необязательными начальными пробелами и знаком. Чтение останавливается на первом неподходящем символе, а полностью нечисловая строка даёт `0`. Из-за этого для hex-строк в реальном коде FTEQW стоит использовать `stoh`, а `stoi` держать для обычных десятичных аргументов, cvar-значений и токенов командной строки.

#### Практические сценарии использования

```
local float argc;
local int limit;

argc = tokenize("kicklimit 12");
limit = stoi(argv(1)); // получаем целое число 12
```

### stoh
`int(string s) stoh = #261;`

* **s** — `string` с шестнадцатеричным числом, с `0x` или без него.

#### Описание и логика работы

`stoh` читает строку как base-16 и возвращает `int`. Комментарий в `fteextensions.qc` специально предупреждает, что builtin не следует использовать для строк в базе 8 или 10, и реализация это подтверждает: внутри вызывается `strtoul(..., 16)`, так что строка `"10"` будет прочитана как hex и даст значение `16`, а не `10`. Допустимы символы `0-9`, `a-f`, `A-F`, а префикс `0x` FTEQW тоже понимает. Если вход повреждён, разбор остановится на первом неподходящем символе, а полностью невалидная строка вернёт `0`.

#### Практические сценарии использования

```
local int color_mask;

// Читаем hex-маску из строки конфигурации.
color_mask = stoh("ff00aa55");
```

### str2chr
`float(string str, float index) str2chr = #222;`

* **str** — `string`, из которой нужно взять символ.
* **index** — `float`, позиция символа; в FTEQW отрицательные значения отсчитываются от конца строки.

#### Описание и логика работы

`str2chr` возвращает числовой код символа по указанному индексу. Builtin объявлен глобально и доступен во всех основных VM расширенного набора. По исходнику FTEQW видно несколько важных деталей: если VM работает в UTF-8-режиме, индекс считается в символах, а не в сырых байтах; отрицательный индекс поддерживается и означает смещение от конца строки; при выходе за диапазон возвращается нулевой символ. В не-UTF-8 режиме builtin отдаёт unsigned byte, поэтому для старых ASCII/Quake-char строк он особенно прямолинеен. Это удобная примитивная операция для парсинга префиксов, постфиксов и ручной обработки командных строк.

#### Практические сценарии использования

```
local float first;
local float last;

first = str2chr("rocket", 0);   // код буквы 'r'
last = str2chr("rocket", -1);   // код буквы 't' в FTEQW
```

### chr2str
`string(float chr, ...) chr2str = #223;`

* **chr** — `float`, код первого символа.
* **...** — дополнительные числовые коды символов, которые будут склеены в одну строку.

#### Описание и логика работы

`chr2str` выполняет обратное преобразование к `str2chr`: берёт один или несколько числовых кодов и создаёт из них строку. Builtin глобальный, а в реализации FTEQW каждый аргумент рассматривается как символ или Unicode code point; если VM поддерживает UTF-8 либо код больше `255`, движок кодирует значение в UTF-8. Практический лимит определяется максимальным числом параметров QuakeC-вызова, поэтому обычно сюда передают до восьми чисел. Строка временная, а сам builtin особенно удобен для ручной сборки управляющих символов, коротких токенов, ASCII-маркеров и форматирования, когда не хочется тащить более тяжёлые строковые операции.

#### Практические сценарии использования

```
local string tag;

// Собираем строку "[OK]" из кодов символов.
tag = chr2str(91, 79, 75, 93);
dprint(tag, "\n");
```
