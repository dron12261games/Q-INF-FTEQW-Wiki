# Звук

> [⬅ Вернуться к оглавлению вики](../README.md)

> [Индекс справочника builtins](./README.md)

Звуковые builtins FTEQW покрывают три разных сценария: воспроизведение звука от сущности, воспроизведение из произвольной точки мира и полностью локальный клиентский звук без участия обычной пространственной акустики. Для практического использования важнее всего понимать две вещи: выбор `CHAN_*`-канала и коэффициент затухания `ATTN_*`, потому что именно они определяют, будет ли новый звук смешиваться с текущим и как далеко он будет слышен.

Почти все игровые звуки, которые сервер отправляет клиентам через `sound`, `pointsound` и `ambientsound`, должны быть заранее зарегистрированы через `precache_sound` или `precache_sound2`. Локальные клиентские вызовы вроде `localsound` и служебные запросы вроде `soundlength` умеют подгружать sample сами, но для предсказуемого поведения ресурсы всё равно лучше прекэшировать заранее.

## Каналы воспроизведения (CHAN_*) и затухание (ATTN_*)

У entity-ориентированного воспроизведения ключевую роль играет канал.

- `CHAN_AUTO = 0` — авто-канал: движок не пытается вытеснить прежний звук, поэтому несколько запусков могут звучать одновременно.
- `CHAN_WEAPON = 1` — оружие.
- `CHAN_VOICE = 2` — голос, реплики, крики боли.
- `CHAN_ITEM = 3` — предметы, кнопки, pickups.
- `CHAN_BODY = 4` — шаги, удары по телу и похожие телесные звуки.

Если на одной и той же сущности одновременно стартовать второй звук на том же не-нулевом канале, предыдущий будет оборван и заменён новым. Именно поэтому для реплик обычно выбирают `CHAN_VOICE`, для выстрелов — `CHAN_WEAPON`, а для редких накладывающихся one-shot эффектов — `CHAN_AUTO`.

Громкость в API задаётся как `0..1`, где `1` — полный уровень, а `0` фактически даёт тишину. Затухание определяет, насколько быстро звук теряет громкость с расстоянием:

- `ATTN_NONE = 0` — слышно по всей карте, без нормального spatial falloff.
- `ATTN_NORM = 1` — стандартный игровой вариант.
- `ATTN_IDLE = 2` — быстрее затухает, подходит для фоновых и тихих источников.
- `ATTN_STATIC = 3` — ещё сильнее режет дальность, чтобы статические ambience-источники не забивали всё вокруг.

`sound` стартует звук от entity и использует её channel slot, поэтому он подходит для оружия, NPC, дверей и любых объектов, у которых важна логика «замени старый звук на этом канале». `pointsound` привязывает звук только к координате [`origin`](../39-entity-keys-reference/01-worldspawn-common-keys.md#origin), без отдельного управляемого ent/channel-слота, а `ambientsound` вообще добавляет статический map-ambient для клиентов при подключении и затем не предназначен для замены или остановки через QuakeC.

## Функции

### sound
`void(entity e, float chan, string samp, float vol, float atten, optional float speedpct, optional float flags, optional float timeofs) sound = #8;`

* **e** — `entity`, источник звука; канал принадлежит именно этой сущности.
* **chan** — `float`, номер канала `CHAN_*` или другой channel id.
* **samp** — `string`, путь к звуковому sample, который должен быть известен движку.
* **vol** — `float`, громкость в диапазоне `0..1`.
* **atten** — `float`, коэффициент затухания; обычно одна из констант `ATTN_*`.
* **speedpct** — `float`, необязательная скорость/высота воспроизведения в процентах; `100` — норма.
* **flags** — `float`, необязательные флаги `SOUNDFLAG_*`.
* **timeofs** — `float`, необязательное смещение старта; отрицательное значение даёт задержку перед началом.

#### Описание и логика работы
`sound` — основной builtin для игровых 3D-звуков. Он запускает sample от указанной сущности и записывает его в слот `entity + channel`. Это означает, что `CHAN_AUTO` можно использовать для свободного наслаивания one-shot эффектов, а любой другой канал становится взаимоисключающим: новый вызов на том же `e` и том же `chan` немедленно прерывает предыдущий звук. Внутри движка громкость переводится в 8-битную шкалу и зажимается, поэтому на практике стоит держаться документированного диапазона `0..1`.

Аргумент `atten` управляет падением громкости с расстоянием. `ATTN_NONE` нужен для UI-подобных или глобальных сигналов, `ATTN_NORM` подходит для большинства действий в мире, `ATTN_IDLE` и `ATTN_STATIC` полезны для более локальных и менее навязчивых источников. В отличие от `pointsound`, builtin завязан на сущность: это удобно для оружия, монстров, лифтов и дверей, где вы хотите иметь устойчивый channel slot и понятное правило замены. Перед первым серверным использованием sample нужно прекэшировать через `precache_sound` или `precache_sound2`; FTE умеет делать delayed precache, но он уходит надёжно, а сами sound-события часто нет, поэтому первый проигрыш может прийти клиенту раньше ресурса.

#### Практические сценарии использования
```
string snd_ogre_pain;
string snd_ogre_saw;

void() monster_ogre =
{
    snd_ogre_pain = precache_sound("ogre/ogpain1.wav");
    snd_ogre_saw = precache_sound("weapons/sawidle.wav");
};

void() OgrePainSound =
{
    // Реплика боли всегда занимает голосовой канал и заменяет прошлую реплику.
    sound(self, CHAN_VOICE, snd_ogre_pain, 1, ATTN_NORM);
};

void() OgreStartSaw =
{
    // На канале оружия новый запуск обрывает предыдущий звук пилы на этом ogre.
    sound(self, CHAN_WEAPON, snd_ogre_saw, 0.85, ATTN_IDLE, 100);
};
```

### ambientsound
`void (vector pos, string samp, float vol, float atten) ambientsound = #74;`

* **pos** — `vector`, точка в мире, из которой будет исходить ambient-звук.
* **samp** — `string`, путь к sample.
* **vol** — `float`, громкость `0..1`.
* **atten** — `float`, коэффициент затухания `ATTN_*`.

#### Описание и логика работы
`ambientsound` не запускает обычный «живой» канал, а добавляет статический ambient-источник, который клиенты получают при подключении к карте. По проверке движка это особый класс звуков: FTE при необходимости принудительно зацикливает sample, а затем не даёт штатного способа остановить или заменить этот источник позднее через QuakeC. Поэтому builtin подходит именно для постоянного map ambience — ветра, гула реактора, шума машин, а не для событийной логики.

Хотя аргументы громкости и затухания выглядят так же, как у `sound`, модель использования другая. Здесь нет entity-канала и нет правила «новый звук на том же слоте вытеснил старый»: каждый вызов просто регистрирует ещё один статический источник. Обычно такие вызовы делают во время инициализации карты, уже после `precache_sound`. Для дальних фоновых источников лучше выбирать `ATTN_IDLE` или `ATTN_STATIC`, чтобы ambience не заливал всю карту.

#### Практические сценарии использования
```
void() worldspawn =
{
    precache_sound("ambience/wind2.wav");
    precache_sound("ambience/drone6.wav");

    // Ветер на крыше слышен в основном рядом с верхней площадкой.
    ambientsound('512 256 192', "ambience/wind2.wav", 0.35, ATTN_STATIC);

    // Низкий гул генератора лучше пустить чуть дальше, но всё ещё локально.
    ambientsound('-128 768 64', "ambience/drone6.wav", 0.55, ATTN_IDLE);
};
```

### localsound
`void(string soundname, optional float channel, optional float volume) localsound = #177;`

* **soundname** — `string`, путь к sample.
* **channel** — `float`, необязательный локальный канал; если не указан, обычно используется `0`.
* **volume** — `float`, необязательная громкость `0..1`; по умолчанию `1`.

#### Описание и логика работы
`localsound` воспроизводит звук только на локальном клиенте. В клиентских реализациях FTE этот builtin не использует обычную пространственную модель мира: он подходит для меню, HUD-сигналов, подтверждения выбора, локальных ошибок ввода и других эффектов, которые не должны зависеть от расстояния или reverb-среды. В документации есть две записи с разными builtin-номерами: исторический MenuQC-вариант `#65` и более поздний вариант `#177`; по смыслу это один и тот же класс локального воспроизведения.

Из-за локальной природы builtin его не стоит путать с `sound(..., SOUNDFLAG_UNICAST)`. `localsound` не создаёт world-источник, не участвует в обычной сетевой репликации и не годится как основной способ серверу озвучивать игровые события для конкретного игрока. Канал здесь нужен только для локальной маршрутизации самого клиента; дистанционное затухание `ATTN_*` не используется. Прекэш формально необязателен, потому что клиент умеет подгружать sample сам, но без предварительной регистрации первый вызов может сопровождаться заметной задержкой.

#### Практические сценарии использования
```
string snd_menu_accept;
string snd_menu_back;

void() Menu_InitSounds =
{
    snd_menu_accept = precache_sound("misc/menu2.wav");
    snd_menu_back = precache_sound("misc/menu3.wav");
};

void() Menu_Accept =
{
    // Локальный UI-щелчок, который не зависит от позиции игрока в мире.
    localsound(snd_menu_accept, CHAN_ITEM, 0.8);
};

void() Menu_Back =
{
    localsound(snd_menu_back, CHAN_ITEM, 0.8);
};
```

### pointsound
`void(vector origin, string sample, float volume, float attenuation) pointsound = #483;`

* **origin** — `vector`, мировая точка воспроизведения.
* **sample** — `string`, путь к sample.
* **volume** — `float`, громкость `0..1`.
* **attenuation** — `float`, коэффициент затухания `ATTN_*`.

#### Описание и логика работы
`pointsound` воспроизводит звук из конкретной точки мира, не привязывая его к управляемому entity-каналу. Это полезно, когда источник есть как координата, но нет смысла держать полноценную сущность только ради озвучки: взрыв на trace-hit, телепорт-вспышка, обрушение в заранее вычисленной точке, удалённый скриптовый триггер. В отличие от `sound`, builtin не даёт удобного «слота замены» вроде `self + CHAN_VOICE`; это скорее точечный one-shot.

По громкости и `ATTN_*` он ведёт себя так же, как другие пространственные звуки: `ATTN_NONE` слышен везде, большие значения сильнее режут дальность. Концептуально `pointsound` ближе к `ambientsound` тем, что стартует от координаты, но по жизненному циклу это обычное событие, а не статическая ambience-регистрация на signon. Перед серверным использованием sample нужно прекэшировать так же, как для `sound`.

#### Практические сценарии использования
```
string snd_tele_burst;

void() worldspawn =
{
    snd_tele_burst = precache_sound("misc/r_tele1.wav");
};

void(vector org) SpawnTeleportBurst =
{
    // Звук идёт из точки телепорта даже если отдельной entity-эмиттера нет.
    pointsound(org, snd_tele_burst, 1, ATTN_NORM);
};
```

### soundlength
`float(string sample) soundlength = #534;`

* **sample** — `string`, путь к звуковому файлу, длительность которого нужно узнать.

#### Описание и логика работы
`soundlength` возвращает длительность sample в секундах. В клиентской реализации FTE builtin сам пытается загрузить звук и, если ресурс недоступен или ещё не удалось декодировать данные, возвращает `0`. Это делает функцию удобной для тайминга реплик, кат-сцен, UI-озвучки и цепочек «когда первый кусок закончится, запусти второй», не заставляя вручную хранить длины в константах.

Сам builtin не воспроизводит звук и не резервирует channel slot, но его часто используют вместе с `localsound`, `sound` или `pointsound`. Для надёжного пайплайна sample всё равно лучше прекэшировать заранее: тогда вызов `soundlength` не будет неожиданно платить за первую загрузку файла в критический момент. Так как функция доступна в клиентских VM, она особенно полезна для MenuQC и CSQC-сценариев.

#### Практические сценарии использования
```
string snd_intro_a;
string snd_intro_b;
float intro_next_time;
float intro_stage;

void() Intro_Init =
{
    snd_intro_a = precache_sound("voice/intro_a.wav");
    snd_intro_b = precache_sound("voice/intro_b.wav");
};

void() Intro_Start =
{
    intro_stage = 1;
    intro_next_time = time + soundlength(snd_intro_a);
    localsound(snd_intro_a, CHAN_VOICE, 1);
};

void() Intro_Think =
{
    if (intro_stage == 1 && time >= intro_next_time)
    {
        intro_stage = 2;
        localsound(snd_intro_b, CHAN_VOICE, 1);
    }
};
```

### getsoundtime
`float(entity e, float channel) getsoundtime = #533;`

* **e** — `entity`, сущность, на чьём канале нужно проверить текущее положение воспроизведения.
* **channel** — `float`, конкретный channel id.

#### Описание и логика работы
`getsoundtime` возвращает текущую позицию воспроизведения sample на заданном entity-канале. Это клиентский introspection-builtin: он не запускает звук сам, а позволяет синхронизировать с уже идущим проигрыванием субтитры, анимацию рта, вспышки индикатора, смену HUD-стадий и прочие эффекты. Ключевое ограничение прямо отмечено в документации: не стоит опираться на `CHAN_AUTO`, потому что авто-канал предназначен для смешивания и не даёт стабильного, предсказуемого слота.

Поэтому для отслеживаемых звуков нужно использовать фиксированный канал вроде `CHAN_VOICE` или `CHAN_ITEM`. Тогда схема получается прямой: вы запускаете `sound(self, CHAN_VOICE, ...)`, а затем каждый кадр читаете `getsoundtime(self, CHAN_VOICE)` и сравниваете с нужными отметками. Для `pointsound` такой модели нет, потому что у него нет отдельного QC-управляемого ent/channel-параметра.

#### Практические сценарии использования
```
string snd_radio_msg;

void() CSQC_Init =
{
    snd_radio_msg = precache_sound("radio/briefing.wav");
};

void() Speaker_PlayBriefing =
{
    sound(self, CHAN_VOICE, snd_radio_msg, 1, ATTN_NONE);
    self.frame = 0;
};

void() Speaker_Think =
{
    // Не используем CHAN_AUTO: нам нужен стабильный канал для тайминга.
    if (getsoundtime(self, CHAN_VOICE) >= 1.2)
        self.frame = 1; // например, открыть рот/лампу после вступительной фразы
};
```

### precache_sound
`string(string s) precache_sound = #19;`

* **s** — `string`, путь к звуковому ресурсу.

#### Описание и логика работы
`precache_sound` регистрирует sample в sound precache list, чтобы клиент знал о ресурсе и мог воспроизвести его без гонки с первой загрузкой. В Quake-подобном сетевом пайплайне это обязательный шаг перед первым серверным `sound`, `pointsound` или `ambientsound`: если отправить событие раньше, клиент может просто не успеть получить или открыть файл. В FTE есть расширение `DP_SV_PRECACHEANYTIME`, поэтому поздний precache технически возможен, но сам исходник отдельно предупреждает, что precache идёт надёжно, а события звука — нет, так что «сначала проиграть, потом прекэшировать» остаётся плохой идеей.

Builtin возвращает строку sample обратно, поэтому его удобно совмещать с инициализацией глобальных string-переменных. В MenuQC встречается отдельная запись `precache_sound = #29`, но по смыслу это тот же инструмент регистрации звука. Повторный precache того же пути безопасен и просто использует уже существующую запись.

#### Практические сценарии использования
```
string snd_door_start;
string snd_door_stop;

void() func_door =
{
    snd_door_start = precache_sound("doors/doormv1.wav");
    snd_door_stop = precache_sound("doors/doorstop.wav");
};

void() DoorBeginMove =
{
    sound(self, CHAN_BODY, snd_door_start, 0.9, ATTN_STATIC);
};

void() DoorHitTop =
{
    sound(self, CHAN_BODY, snd_door_stop, 0.9, ATTN_STATIC);
};
```

### precache_sound2
`string(string str) precache_sound2 = #76;`

* **str** — `string`, путь к звуковому ресурсу.

#### Описание и логика работы
`precache_sound2` по runtime-поведению эквивалентен `precache_sound`: движок обрабатывает его тем же builtin-кодом, регистрирует ресурс в precache list и делает звук доступным для последующих вызовов `sound`, `pointsound`, `ambientsound` и локальных client-side проигрываний. Исторический смысл отдельного имени связан не с воспроизведением в FTE, а с совместимостью старого toolchain: vanilla qcc различал такие вызовы при упаковке shareware/full-content сценариев.

На уровне мода разница обычно организационная. Если в проекте уже принят один стиль, лучше придерживаться его последовательно; смешивать `precache_sound` и `precache_sound2` в одном месте особого смысла нет. Требования к порядку те же самые: регистрируйте sound заранее, желательно в spawn/world-init, а не непосредственно перед первым событием.

#### Практические сценарии использования
```
string snd_secret_jingle;

void() worldspawn =
{
    // Runtime-эффект тот же, что у precache_sound; здесь builtin используется ради совместимого стиля проекта.
    snd_secret_jingle = precache_sound2("misc/secret.wav");
};

void(entity pl) AwardSecret =
{
    sound(pl, CHAN_ITEM, snd_secret_jingle, 1, ATTN_NONE);
};
```

### SetListener
`void(vector origin, vector forward, vector right, vector up, optional float reverbtype) SetListener = #351;`

* **origin** — `vector`, позиция слушателя в мире.
* **forward** — `vector`, вектор взгляда вперёд.
* **right** — `vector`, вектор вправо.
* **up** — `vector`, вектор вверх.
* **reverbtype** — `float`, необязательный индекс reverb slot; `0` обычно означает отсутствие спецэффекта.

#### Описание и логика работы
`SetListener` не запускает sample, а перенастраивает саму точку прослушивания аудио для текущего кадра CSQC. Документация и реализация сходятся: builtin нужно вызывать из [`CSQC_UpdateView`](00-entry-points.md#csqc_updateview), потому что без регулярного обновления движок откатывает listener обратно к обычной камере. Это основной инструмент для камер от третьего лица, кат-сцен, дронов-наблюдателей, управляемых снарядов и любых систем, где визуальная камера и источник прослушивания должны быть намеренно смещены.

В отличие от `sound`, `pointsound` и `ambientsound`, здесь нет вопроса о канале, замене звука или обязательном precache — builtin влияет на то, как уже существующие world-звуки будут spatialized для игрока. Параметр `reverbtype` привязывает listener к одному из настроенных reverb slot'ов; без отдельной конфигурации безопаснее использовать `0` или трактовать ненулевое значение как переключение на специальную среду вроде underwater/reverb zone.

#### Практические сценарии использования
```
void(vector cam_org, vector cam_ang) ApplyAudioCamera =
{
    makevectors(cam_ang);

    // Этот вызов нужно делать каждый кадр после расчёта камеры.
    SetListener(cam_org, v_forward, v_right, v_up, 0);
};

void(float w, float h, float vfov) CSQC_UpdateView =
{
    vector cam_org;
    vector cam_ang;

    cam_org = '1024 256 128';
    cam_ang = '0 180 0';
    ApplyAudioCamera(cam_org, cam_ang);
};
```

### getchannellevel
`float(entity e, float channel) getchannellevel = #0:getchannellevel;`

* **e** — `entity`, сущность, на которой будет производиться замер текущей громкости воспроизводимого семпла.
* **channel** — `float`, номер аудиоканала (sound channel) у этой сущности.

#### Описание и особенности работы
`getchannellevel` — это CSQC builtin для получения амплитуды громкости или уровня звука на заданном канале конкретного эдикта. На уровне ядра `S_GetChannelLevel` считывает данные микшера, берёт текущий фрейм звукового семпла и в процессе математических вычислений по пиковым значениям возвращает относительное значение громкости в диапазоне `0..1`. Если звук выключен или семпл закончил воспроизведение, функция возвращает `0`; если указанной связки сущности и канала вообще нет, возвращается `-1`. Это решение идеально для реализации липсинка (lip-sync), анимации VU-метров в интерфейсе или динамического изменения масштаба моделей эффектов под такт воспроизводимой музыки.

#### Пример использования
```qc
void() CSQC_UpdateSpeakerMouth =
{
    local float level;

    level = getchannellevel(self, CHAN_VOICE);
    if (level < 0)
        return; // на данном канале сейчас ничего не играет

    if (level > 0.20)
        self.frame = self.talk_frame_open;
    else
        self.frame = self.talk_frame_closed;
};
```

### getqueuedaudiotime
`float() getqueuedaudiotime = #0:getqueuedaudiotime;`

* Параметры отсутствуют.

#### Описание и особенности работы
`getqueuedaudiotime` возвращает общее время звучания (в секундах) аудиоданных, которые в данный момент находятся в очереди буфера `queueaudio` для потокового воспроизведения. В компиляторе FTEQW функция доступна как для CSQC, так и для MenuQC, поскольку вся работа со звуком ведется на клиентской стороне. Если очередь пуста, стриминговый источник завершил работу или звук ещё не отправлен на воспроизведение, возвращается `0`. Этот встроенный метод необходим для предотвращения опустошения буфера (underrun): если оставшееся время звучания падает ниже критической отметки, скрипт должен дописать новую порцию PCM-данных.

#### Пример использования
```qc
float() FeedPreviewStream =
{
    local filestream fh;
    local void *pcm;

    if (getqueuedaudiotime() > 0.25)
        return TRUE;

    fh = fopen("sound/ui/preview.raw", FILE_MMAP_READ);
    if (!fh)
        return FALSE;

    pcm = fgets(fh); // FILE_MMAP_READ вернет указатель на начало mmap-памяти.
    if (!pcm)
    {
        fclose(fh);
        return FALSE;
    }

    queueaudio(22050, 1, -16, pcm, 5512); // запись очередной порции данных в mono PCM.
    fclose(fh);
    return TRUE;
};
```

### getsoundindex
`float(string soundname, optional float queryonly) getsoundindex = #0:getsoundindex;`

* **soundname** — `string`, путь к звуковому ресурсу.
* **queryonly** — `float`, булев флаг; если установлен в `TRUE`, функция просто вернёт индекс без проведения принудительного precache и без выделения памяти под новый звук.

#### Описание и особенности работы
`getsoundindex` служит для получения сетевого индекса звука из глобальной таблицы предкешированных ресурсов (sound precache table). В серверной части (SSQC) этот метод используется для контроля индексов звуков, чтобы убедиться, что они укладываются в стандартный байтовый лимит `<= 255` для безопасной сетевой передачи в `writebyte`-командах. В CSQC функция обращается напрямую к массиву имен `cl.sound_name` для поиска совпадений. Если звук не найден и `queryonly == FALSE`, движок выполнит скрытый вызов `S_PrecacheSound`, создавая локальный приватный прекеш. В случае неудачи функция вернет `0`, сигнализируя, что файл поврежден или отсутствует на диске. Это один из важнейших встроенных методов, если ваш CSQC-скрипт динамически воспроизводит кастомные звуки и должен проверять валидность их индексов.

#### Пример использования
```qc
void() DebugSoundIndex =
{
    local float idx;

    idx = getsoundindex("weapons/rocket1i.wav", TRUE);
    if (idx > 0 && idx <= 255)
        print(sprintf("rocket1i.wav already has network-safe index %g\n", idx));
};
```

### queueaudio
`float(int hz, int channels, int type, void *data, unsigned int frames) queueaudio = #0:queueaudio;`

* **hz** — `int`, частота дискретизации передаваемого PCM-потока.
* **channels** — `int`, количество каналов: в движке поддерживаются значения `1` (моно) и `2` (стерео).
* **type** — `int`, формат семпла (sample type); официально задокументированы значения `-8` (`__int8`), `-16` (`__int16`) и `256|32` (`float`), а положительное число означает беззнаковый байт (unsigned 8-bit).
* **data** — `void *`, прямой указатель на буфер с сырыми данными (raw PCM).
* **frames** — `unsigned int`, количество аудио-кадров (sample-frames) в буфере, а не общий размер массива в байтах.

#### Описание и особенности работы
`queueaudio` осуществляет потоковую запись и микширование пользовательских PCM-данных в обход стандартных статических триггеров звуков `sound()` / `ambientsound()`. Этот builtin разработан для CSQC и MenuQC: он идеально подходит для генерации процедурного шума, воспроизведения внутриигрового радио, динамического аудио-стриминга или голосового чата, если в ваш мод внедрен кастомный сборщик сетевых пакетов. Встроенный метод возвращает `1` при успешном добавлении в очередь звукового движка, `-1` в случае некорректных параметров `hz/channels/frames` и `-2` при не поддерживаемом формате семпла. Для стабильного воспроизведения вся очередь на стороне клиента должна удерживать единую частоту `hz` и количество каналов `channels`, а функция `getqueuedaudiotime` поможет вовремя отследить момент опустошения буфера.

#### Пример использования
```qc
float() Menu_QueueRawClick =
{
    local filestream fh;
    local void *pcm;
    local float ret;

    fh = fopen("sound/ui/click.raw", FILE_MMAP_READ);
    if (!fh)
        return FALSE;

    pcm = fgets(fh); // Для mmap-файла это вернет указатель на начало всего буфера
    ret = queueaudio(22050, 1, -16, pcm, 2205); // ~0.1 секунды mono PCM
    fclose(fh);

    return (ret > 0);
};
```

### setup_reverb
`void(float reverbslot, reverbinfo_t *reverbinfo, int sizeofreverbinfo_t) setup_reverb = #0:setup_reverb;`

* **reverbslot** — `float`, индекс реверберационного слота, который будет сконфигурирован.
* **reverbinfo** — `reverbinfo_t *`, указатель на структуру с параметрами окружения и эффектов.
* **sizeofreverbinfo_t** — `int`, размер передаваемой структуры в байтах; обычно передается `sizeof(reverbinfo_t)`.

#### Описание и особенности работы
`setup_reverb` инициализирует настройки параметров среды или окружения (эхо, затухание, плотность звука) для последующей активации этой зоны через встроенную функцию `SetListener`. Исторически архитектура движка подразумевает, что слот `0` зарезервирован под открытое пространство (normal), а слот `1` под воду (underwater). Попытка переопределить эти два слота может потребовать полной перезагрузки звуковой подсистемы через консольную команду `snd_restart`; в остальных кастомных слотах данные можно менять динамически в процессе игры. На системном уровне действует жёсткое ограничение: builtin работает исключительно в CSQC, и при попытке вызвать его из другого контекста или передать пустой указатель движок выбросит критический сбой `PF_cs_setupreverb: invalid reverb pointer`. Реальное воспроизведение эффекта реверберации напрямую зависит от наличия поддержки расширений EFX на аудио-бекенде (например, OpenAL).

#### Пример использования
```qc
reverbinfo_t tunnel_reverb;

void() CSQC_InitTunnelReverb =
{
    tunnel_reverb.flDensity = 1;
    tunnel_reverb.flDiffusion = 0.85;
    tunnel_reverb.flGain = 0.32;
    tunnel_reverb.flDecayTime = 1.8;
    tunnel_reverb.flReflectionsGain = 0.18;
    tunnel_reverb.flLateReverbGain = 0.26;

    setup_reverb(2, &tunnel_reverb, sizeof(tunnel_reverb));
};

void(vector cam_org, vector cam_ang) ApplyTunnelListener =
{
    makevectors(cam_ang);
    SetListener(cam_org, v_forward, v_right, v_up, 2);
};
```

### soundnameforindex
`string(float sndindex) soundnameforindex = #0:soundnameforindex;`

* **sndindex** — `float`, индекс звука в глобальной precache-таблице.

#### Описание и особенности работы
`soundnameforindex` выполняет операцию, противоположную `getsoundindex`: по переданному сетевому индексу прекеша она возвращает строковый путь к файлу (sound resource). Разработчики серверных скриптов (SSQC) часто используют связку `soundnameforindex` + `getsoundindex` для оптимизации сетевого трафика в кастомных сообщениях для CSQC, передавая короткий индекс вместо тяжелой строки, зная, что на клиенте и сервере таблица соответствия (index/name mapping) идентична. В CSQC функция считывает данные напрямую из системного массива `cl.sound_name`, но есть важное ограничение: приватные клиентские звуки (private client-only sound indices) этой функцией не обрабатываются. Если передан невалидный индекс, функция вернет пустую строку `""`.

#### Пример использования
```qc
void() DebugResolveSoundName =
{
    local float idx;
    local string name;

    idx = getsoundindex("misc/talk.wav", TRUE);
    if (!idx)
        return;

    name = soundnameforindex(idx);
    if (name != "")
        print(sprintf("resolved sound name: %s\n", name));
};
```

### soundupdate
`float(entity e, float channel, string newsample, float volume, float attenuation, float pitchpct, float flags, float timeoffset) soundupdate = #0:soundupdate;`

* **e** — `entity`, сущность, параметры звука которой будут изменены.
* **channel** — `float`, звуковой канал на указанной сущности.
* **newsample** — `string`, новый путь к файлу; укажите пустую строку `""`, чтобы обновить параметры текущего звука без его перезапуска.
* **volume** — `float`, новый уровень громкости; отрицательные значения могут использоваться для скрытия или инверсии эффектов.
* **attenuation** — `float`, коэффициент затухания звука в пространстве (spatial falloff).
* **pitchpct** — `float`, изменение тональности/питча звука в процентах (`100` — стандартная скорость воспроизведения).
* **flags** — `float`, дополнительные конфигурационные аудио-флаги.
* **timeoffset** — `float`, временное смещение в секундах, позволяющее перемотать или запустить звук с определенного момента.

#### Описание и особенности работы
`soundupdate` динамически изменяет параметры уже воспроизводимого звука на конкретном канале выбранной сущности. Архитектурная особенность метода в том, что если `newsample` передана как пустая строка `""`, а `timeoffset` равен нулю, то движок просто скорректирует громкость или питч на лету без перезапуска аудио-кадра. Стоит учитывать, что позиционирование звука в пространстве завязано на координатах `entity.origin`, а для `SOLID_BSP` объектов (двери, лифты) расчет ведется от центра их bounding box, что предотвращает появление «блуждающего звука» внутри геометрии браша. Функция возвращает `1` в случае успешного обновления параметров; если указанный канал молчит или звук не найден, возвращается `0`. Это позволяет использовать конструкцию `if (soundupdate(...))` как безопасный чеккер активности звука на канале.

#### Пример использования
```qc
void() Drone_UpdateHum =
{
    if (!soundupdate(self, CHAN_BODY, "", 0.35, ATTN_IDLE, 115, 0, 0))
        soundupdate(self, CHAN_BODY, "ambience/dronehum.wav", 0.35, ATTN_IDLE, 115, 0, 0);
};
```

### stopsound
`void(entity ent, float channel) stopsound = #0:stopsound;`

* **ent** — `entity`, сущность, на которой необходимо остановить воспроизведение звука.
* **channel** — `float`, звуковой канал, который будет принудительно очищен.

#### Описание и особенности работы
`stopsound` немедленно прерывает воспроизведение текущего звукового семпла на выбранном канале конкретной сущности. Техническая реализация имеет важную деталь: канал `CHAN_AUTO` не может быть остановлен этим методом напрямую, так как он динамически распределяет звуки. Если передать значение `0` (или `entchannel == 0`), движок интерпретирует это как wildcard и принудительно заглушит вообще все активные каналы на указанном эдикте. Встроенный метод одинаково стабильно работает как в SSQC, так и в CSQC, предотвращая «залипание» циклических (looping) звуков при смерти персонажей или смене состояний объектов. Передача неверного ID сущности безопасно игнорируется микшером.

#### Пример использования
```qc
void() StopLoopingEngine =
{
    // Принудительно останавливаем циклический гул двигателя на канале CHAN_BODY
    stopsound(self, CHAN_BODY);
};
```
