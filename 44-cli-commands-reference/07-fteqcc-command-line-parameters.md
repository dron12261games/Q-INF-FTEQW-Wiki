Это исчерпывающий справочник параметров компилятора **FTEQCC**. Вводное объяснение синтаксиса и типовых примеров — в статье [«Компилятор FTEQCC»](../16-quakec-scripting/fteqcc-compiler.md#параметры-командной-строки-отдельного-компилятора).

## Файлы, пути и точки входа

### src
`-src <folder>`

Указать папку с исходниками (там ищется `progs.src`) вместо текущей рабочей папки.

---

### srcfile
`-srcfile <file>`

Добавить ещё один список исходников (`.src`) к сборке, помимо основного.

---

### o
`-o <file>` (слитно тоже работает: `-o<file>`)

Явно задать имя итогового скомпилированного файла вместо имени по умолчанию (`progs.dat` или заданного директивой `#pragma PROGS_DAT`).

---

### D
`-D<name>[=value]`

Определить именованную константу препроцессора, как `#define` в исходном коде.

---

### I
`-I<path>`

Добавить папку в список путей поиска для `#include`.

---

## Целевой формат байт-кода (-T)

Задаёт, под какой движок собирается байт-код — влияет на набор доступных типов данных и операций. Все варианты `-T<name>` (или `-T<name>_<revision>` для конкретной числовой ревизии, например `-Tfte_9999`):

| Значение | Формат |
|---|---|
| `standard`, `vanilla`, `q1`, `id`, `quakec` | классический байт-код id Software 1996 года (максимальная совместимость) |
| `qs` | синоним `standard` |
| `qss` | формат QuakeStandardStomping (расширенная ревизия standard) |
| `hexen2`, `h2` | байт-код оригинального Hexen II |
| `uhexen2` | байт-код «универсального» Hexen II |
| `kkqwsv`, `kk7`, `version7` | формат "version 7" (KKQWSV) |
| `fte` | расширенный формат FTEQW последней стабильной ревизии (то же самое, что `#pragma target fte`) |
| `ftedebug`, `debug` | формат FTE с дополнительной отладочной информацией |
| `fteh2` | формат FTE для модов на основе Hexen II |
| `quake2c` | алиас формата `fte` с ревизией, достаточной для проекта Quake2C |
| `darkplaces`, `dp` | байт-код, совместимый с движком DarkPlaces |
| `qtest` | формат для ранней тестовой версии Quake (QTest) |
| `parse` (`-Tparse`) | только разобрать код на ошибки, без записи файла результата |

## Уровни и флаги оптимизации (-O)

`-O0` … `-O3` — общий уровень: 0 отключает всё, 1 — компактность файла, 2 — скорость выполнения, 3 — небезопасные оптимизации (могут сломать код, полагающийся на мультипрогс). Отдельные оптимизации переключаются по имени: `-O<name>` включает, `-Ono-<name>` выключает.

| Имя | Кратко (abbrev) | Уровень по умолч. | Эффект |
|---|---|---|---|
| assignments | t | 1 | `c = a*b` за одну операцию вместо двух |
| shortenifs | i | 1 | компактная запись `if (!a)` |
| nonvec_parms | p | 1 | параметры-float не хранятся как вектор |
| constant_names | c | 2 | убирает имена именованных констант (не строк) |
| constant_names_strings | cs | 3 | убирает имена строковых констант (может сломать аддоны) |
| dupconstdefs | d | 1 | объединяет одинаковые константы |
| noduplicatestrings | s | 1 | схлопывает таблицу строк |
| locals | l | 1 | убирает имена локальных переменных (ломает декомпиляцию) |
| function_names | n | 1 | убирает имена невызываемых функций |
| filenames | f | 1 | убирает имена файлов исходников из прогса |
| overlaptemps | r | 1 | переиспользует временные переменные (важнейшая оптимизация размера) |
| constantarithmatic | a | 1 | вычисляет константные выражения (`5*6`) во время компиляции |
| precache_file | pf | 2 | убирает мёртвый вызов `precache_file` |
| return_only | ro | 2 | не пишет `done` после `return` в конце функции |
| compound_jumps | cj | 2 | схлопывает цепочки безусловных переходов |
| strip_functions | sf | 3 | убирает `defs` функций, вызываемых только напрямую (ломает FTE_MULTIPROGS/мутаторы) |
| locals_overlapping | lo | 2 | хранит все локальные переменные в общей области (сильно уменьшает размер, но отключает автообнуление при рекурсии) |
| vectorcalls | vc | 4 | вызов функции с вектором как тремя float, если это экономит память |
| class_fields | cf | 2 | убирает имена полей классов (только вредит отладке в FTEQW) |
| strip_unused_fields | uf | 4 | убирает никогда не используемые поля сущностей |

Дополнительно: `-Onon-vec_parms`/спец-флаг `overlap-locals` управляет тем же, что `locals_overlapping`, если имя не совпало ни с одной записью таблицы выше.

## Флаги компилятора и ключевые слова (-K / -F)

`-K<name>` / `-Kno-<name>` включает/выключает поддержку конкретного **ключевого слова** языка (например, `-Kno-switch` отключает `switch`, что бывает нужно, если в старом коде это имя переменной). `-F<name>` / `-Fno-<name>` переключает **поведенческие флаги** компилятора. Все распознаваемые имена:

**Ключевые слова (`-K`, полный список):** `asm`, `break`, `case`, `class`, `accessor`, `const`, `continue`, `default`, `entity`, `enum`, `enumflags`, `extern`, `float`, `for`, `goto`, `int`, `integer`, `double`, `long`, `short`, `char`, `signed`, `unsigned`, `register`, `volatile`, `noref`, `unused`, `used`, `local`, `static`, `nonstatic`, `ignore`, `auto`, `nosave`, `inline`, `strip`, `shared`, `state`, `optional`, `inout`, `string`, `struct`, `switch`, `thinktime`, `until`, `loop`, `typedef`, `union`, `var`, `vector`, `wrap`, `weak`, `accumulate`, `using`. Также `-Kkce` (`Keywords Coexist`) — не отключать ключевое слово автоматически, если в коде объявлена переменная с таким же именем.

**Поведенческие флаги (`-F`, полный список):** `acc` (эмуляция диалекта Reacc), `qccx` (синтаксис QCCX — делает мод engine-specific, не рекомендуется), `parms` (определять `PARM0`/`PARM1`/…), `autoproto` (двухпроходная компиляция с авто-прототипированием функций), `wasm` (выгрузить дамп ассемблера в `qc.asm`), `annotate` (аннотировать исходники ассемблером, только с GUI), `nullemptystr`, `ifstring`, `iffloat`, `ifvector`, `vectorlogic`, `brokenarray`, `rootconstructor`, `caseinsens`, `lax` (смягчённая проверка типов для совместимости с FrikQCC/Reacc), `hashonly`, `macroinstrings`, `lo` (`logic ops` — короткое замыкание `&&`/`||`), `msvcstyle` (сообщения об ошибках в формате MSVC), `debugmacros`, `filetimes`, `fastarrays`, `assumeint`, `subscope`, `verbose`, `typeexplicit`, `boundchecks` (проверка выхода за границы массива, включена по умолчанию), `attributes` (синтаксис `[[attributes]]`, конфликтует с конструкторами векторов), `assumevar`, `ssp` (`**` как оператор возведения в степень), `cpriority` (приоритет операторов как в C), `assumedouble`, `qcfuncs` (разбор `void()` как типа функции, включено по умолчанию), `allowuninit`, `nofileline`, `utf8` (строки в UTF-8 вместо кодировки Quake), `reciprocal-math`, `ILP32`, `undefwordsize`, `pointerrelocs`, `omitinternals` (скрыть отладочные символы — уменьшает размер, но ломает декомпиляцию и совместимость с FTE_MULTIPROGS), `embedsrc` (встроить исходный код в `.dat`, полезно для соответствия GPL), `dumpfilenames`, `dumpfields`, `dumpsymbols`, `dumpautocvars`, `dumplocalisation` (`.pot`-шаблон для перевода строк `_("")`), `dumptags` (алиас `tags`), `dumpopcodes`.

Также распознаются флаги совместимости без отдельной записи в таблице (только через `-F`/`-Fno-`): `short-logic`, `correct-logic`, `false-empty-strings`, `true-empty-strings`, `emulate-state`, `arithmetic-exceptions`, `lno`, `return-assignments`, `relaxed-switch`, `bail-on-werror`.

`-std=<name>` включает пресет флагов, ассоциированных с конкретным диалектом (например `-std=gmqcc`).

## Предупреждения (-W)

| Параметр | Назначение |
|---|---|
| `-Wall` | включить большинство полезных предупреждений (кроме отмеченных как «слишком шумные для -Wall») |
| `-Wextra` | включить вообще все предупреждения, включая самые придирчивые |
| `-Wnone` | отключить все предупреждения |
| `-Werror` | считать все включённые предупреждения ошибками, останавливающими сборку |
| `-Wno-mundane` | отключить мелкие стилистические предупреждения (неиспользуемые переменные, повторные объявления, сравнение констант и т.п.) |
| `-W<code>` / `-Wno-<code>` | включить/выключить конкретное предупреждение по его коду (например, `-Wno-F302`) |

---

## Лимиты и информационные параметры

| Параметр | Назначение |
|---|---|
| `-max_regs`, `-max_strings`, `-max_globals`, `-max_fields`, `-max_statements`, `-max_functions`, `-max_types`, `-max_temps`, `-max_macros` `<N>` | вручную задать верхнюю границу для внутренних таблиц компилятора (нужно только при сборке экстремально больших модов) |
| `-v` | подробный (verbose) вывод хода компиляции, можно указывать несколько раз |
| `--version` | вывести версию компилятора и завершить работу |
| `--help` / `-help` | вывести полный список поддерживаемых параметров, оптимизаций и флагов с описанием и завершить работу |

---

## Неактивные и неподдерживаемые параметры

Распознаются компилятором, но не выполняют полезной работы — унаследованы от других диалектов qcc ради совместимости синтаксиса командной строки:

| Параметр | Статус |
|---|---|
| `-qc`, `-E` | помечены как экспериментальные, выводят предупреждение о нестабильности |
| `-progdefs` | принят, но игнорируется — выгрузка файла описания progdefs не реализована |
| `-copy` | принят, но игнорируется — копирование файлов/запись `.pak` не реализована |
| `-bspmodels <folder>` | выводит предупреждение «не поддерживается» — функция отключена, код полностью мёртв |
| `-pak`, `-pak2` | выводят предупреждение «не поддерживается» |
| `-stdout`, `-log`, `-nolog` | приняты для совместимости с другими компиляторами qcc, не влияют на поведение FTEQCC |
| `-h2`, `-fteh2`, `-fte`, `-dp` (без `-T`) | приняты как алиасы для указания цели без явного `-T`, само по себе ничего не печатают |

---

## Примеры

```
fteqcc -src ./src -Tfte -O2 -Wall
```
Собрать `progs.src` из папки `./src` под движок FTEQW с оптимизацией по скорости и включёнными основными предупреждениями.

```
fteqcc -srcfile csprogs.src -o csprogs.dat -Tftedebug
```
Собрать клиентскую логику (CSQC) в отдельный файл с отладочным форматом байт-кода.
