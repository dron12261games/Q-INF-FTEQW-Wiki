# Помощь в прямом соединении между игроками (ICE/STUN/TURN)

> [⬅ Вернуться к оглавлению вики](../README.md)

> Раздел: [Прямые соединения и обход NAT](./README.md)

## Что это даёт геймдизайнеру

Домашние роутеры и файрволы обычно не позволяют посторонним компьютерам подключаться напрямую к машине игрока — это создаёт проблему для игр, где кто-то из игроков хочет напрямую разместить у себя матч без выделенного сервера в интернете и без ручной настройки переадресации портов на роутере (что для большинства обычных игроков попросту слишком сложно). Движок умеет автоматически «пробивать» такие препятствия при помощи технологии, применяемой в интернет-звонках и видеосвязи (той же, что используется в веб-браузерах для голосовых/видеозвонков) — она находит рабочий способ соединить два компьютера напрямую, даже если оба находятся за разными домашними роутерами.

## Интерфейс настройки

Этот механизм работает по большей части автоматически, «под капотом», при обычной попытке подключения к игре, но администратор может дополнительно настроить его несколькими переменными:

| Переменная | Назначение |
|---|---|
| `net_ice_broker` | адрес вспомогательного сервера-посредника, который помогает двум игрокам обменяться техническими данными для установления прямого соединения (по умолчанию используется официальный сервер-посредник движка; сменить можно, например, если основной окажется недоступен) |
| `net_ice_relayonly` | если включено, дополнительно скрывает собственный публичный сетевой адрес игрока от собеседника, направляя весь трафик через промежуточный ретранслирующий сервер, а не напрямую |
| `net_ice_servers` | адрес вспомогательного ретранслирующего сервера (в формате `turn:адрес:порт?user=имя?auth=пароль`, либо простого сервера подсказки собственного публичного адреса `stun:адрес:порт`), используемого как запасной вариант, если полностью прямое соединение установить не удалось; можно указать сразу несколько адресов через пробел |

Кроме того, движок поддерживает подключение по протоколам `ws://`/`wss://` (веб-сокеты, включая защищённый вариант) и защищённое соединение по `dtls://` с проверкой сервера не через обычный центр сертификации, а через прямое сравнение технического «отпечатка» сертификата сервера (который можно один раз получить и затем использовать в адресе подключения вида `dtls://адрес:порт/?fp=ОТПЕЧАТОК`) — это удобно для серверов, у которых нет собственного доменного имени, но всё равно нужно защищённое соединение.

## Примеры

- Два игрока, оба находящиеся за обычными домашними роутерами без настроенной переадресации портов, успешно играют друг с другом без выделенного сервера благодаря автоматическому «пробитию» соединения через сервер-посредник.
- Администратор турнирного сервера, заботящийся о приватности игроков, включает `net_ice_relayonly "1"` и указывает собственный ретранслирующий сервер через `net_ice_servers`, чтобы IP-адреса участников не были видны друг другу напрямую.
