# Директивы уровня стадии

> [⬅ Вернуться к оглавлению вики](../README.md)

> [Индекс справочника директив .shader](./README.md)

Стадия материала — это внутренний блок `{ ... }` внутри `.shader`, который описывает один проход отрисовки: какую текстуру брать, как смешивать её с уже нарисованным кадром, как генерировать цвет, прозрачность и UV-координаты. В отличие от внешнего блока материала, стадия работает на уровне отдельного слоя и почти всегда отвечает за конкретный визуальный вклад: базовую диффузную карту, свечение, блик, грязь, маску, отражение или служебный буфер. FTEQW понимает как классический Quake III-синтаксис, так и ряд совместимых расширений из Doom 3, RTCW, Alien Arena и QFusion/Warsow. Ниже собраны именно директивы, которые парсер принимает внутри блока стадии, без директив верхнего уровня материала.

## Директивы

### map
`map <textureOrSpecial>`

* **textureOrSpecial** — путь к обычной 2D-текстуре либо специальное имя-источник вида `$lightmap`, `$diffuse`, `$currentrender` и т. п.

#### Описание и логика работы
`map` задаёт основной источник изображения для стадии. Если `tcGen` ещё не указан, обычная картинка автоматически использует базовые UV-координаты модели (`base`). Для первой «обычной» диффузной карты это же имя часто становится и «главной» текстурой материала по умолчанию. Директива также умеет ссылаться не только на файлы, но и на встроенные буферы движка и специальные каналы рендера. Дополнительно парсер молча принимает legacy-вставки `map clamp ...`, `map clampx ...` и `map clampy ...`, но для гарантированного clamp-поведения в FTEQW надёжнее использовать именно `clampmap` или префикс `$clamp:`.

#### Особые встроенные источники

| Значение | Что подставляется |
| :--- | :--- |
| `$lightmap` | запечённая lightmap-координатная карта освещения; стадия автоматически считается lightmap-проходом |
| `$deluxmap` | deluxemap с направлением освещения |
| `$diffuse` | диффузная карта из PBR/programmable-пайплайна |
| `$paletted` | палеттизированная версия базовой текстуры |
| `$normalmap` | normal map |
| `$specular` | specular/gloss map |
| `$fullbright` | fullbright/emissive map |
| `$upperoverlay` | верхний overlay-слой player-skin окраски |
| `$loweroverlay` | нижний overlay-слой player-skin окраски |
| `$reflectcube` | cubemap отражений материала |
| `$reflectmask` | маска силы отражения |
| `$displacement` | displacement/height-карта |
| `$shadowmap` | shadow map; стадия помечается как depth-compare |
| `$lightcubemap` | light cubemap |
| `$currentrender` | текущий уже отрендеренный кадр/буфер |
| `$sourcecolour` | исходный цветовой буфер источника эффекта |
| `$sourcecube` | исходный кубический буфер |
| `$sourcedepth` | исходный буфер глубины |
| `$gbuffer0`, `$gbuffer1`, ... | конкретный G-buffer-слот по номеру |
| `$reflection` | экранное отражение/буфер отражений |
| `$refraction` | экранное преломление |
| `$refractiondepth` | глубина буфера преломления |
| `$ripplemap` | карта ряби/искажения |
| `$null` | заведомо пустая служебная карта; стадия считается detail/no-mipmap |

#### Префиксы имени текстуры
Обычное имя текстуры можно предварять служебными префиксами; они записываются прямо перед путём и могут комбинироваться цепочкой.

| Префикс | Эффект |
| :--- | :--- |
| `$rt:` | трактует ресурс как render target; одновременно включает clamp, linear и no-mipmap |
| `$clamp:` | принудительный clamp по краям |
| `$premul:` | просит движок премультиплицировать альфа-канал при загрузке |
| `$2d:` | явно 2D-текстура |
| `$2darray:` | 2D texture array |
| `$3d:` | 3D-текстура |
| `$cube:` | cubemap |
| `$cubearray:` | cubemap array |
| `$srgb:` | грузить как sRGB |
| `$nosrgb:` | грузить без sRGB-коррекции |
| `$nearest:` | nearest-фильтрация |
| `$linear:` | linear-фильтрация |
| `$palettize:` | палеттизация при загрузке |

Отдельной stage-директивы `nomipmap` парсер не имеет: для похожего результата используются `$rt:`, флаги верхнего уровня материала вроде [`nomipmaps`](01-shader-toplevel-directives.md#nomipmaps) либо специальные встроенные карты, которые сами помечаются как no-mipmap.

#### Практические сценарии использования
```
{
	map textures/mymod/water_d.tga
	rgbGen identity
}
```

### animmap
`animmap <fps> <frame1> <frame2> ...`

* **fps** — скорость покадрового переключения кадров.
* **frame1, frame2, ...** — список текстур, между которыми стадия циклически переключается.

#### Описание и логика работы
`animmap` создаёт кадровую анимацию за счёт последовательной подмены всей текстуры стадии. Если `tcGen` не задан, используется `base`. Для первого базового слоя список кадров также может стать набором «основных» текстур материала по умолчанию. Каждое имя кадра проходит через ту же систему загрузки и тех же префиксов, что и `map`.

#### Практические сценарии использования
```
{
	animmap 8 textures/signs/warn_1.tga textures/signs/warn_2.tga textures/signs/warn_3.tga
	blendfunc blend
}
```

### clampmap
`clampmap <textureOrSpecial>`

* **textureOrSpecial** — путь к текстуре или специальный `$...`-источник, как у `map`.

#### Описание и логика работы
`clampmap` делает то же, что и `map`, но принудительно запрещает повторение текстуры за пределами диапазона 0..1. Это основной выбор для декалей, масок, спрайтовых оверлеев, интерфейсных вставок и всего, где по краям не должно быть тайлинга. Префиксы загрузки и специальные `$...`-источники тоже поддерживаются.

#### Практические сценарии использования
```
{
	clampmap textures/decals/bulletmark.tga
	blendfunc blend
	alphafunc gt0
}
```

### videoMap
`videoMap <videoFile>`

* **videoFile** — путь к видеофайлу, который движок должен декодировать в текстуру.

#### Описание и логика работы
`videoMap` подставляет вместо обычной картинки видеопоток и обновляет его по мере проигрывания. Это удобно для экранов, мониторов, камер наблюдения и FMV-вставок на поверхности. Если декодер недоступен или файл не загрузился, стадия фактически превращается в чёрный слой. Сама по себе директива не задаёт смешивание, цвет или UV-анимацию — их по-прежнему настраивают отдельные команды стадии.

#### Практические сценарии использования
```
{
	videoMap video/monitor_intro.ogv
	rgbGen identity
}
```

### cubemap
`cubemap <cubeTexture>`

* **cubeTexture** — cubemap-ресурс, который нужно привязать к стадии.

#### Описание и логика работы
`cubemap` привязывает кубическую текстуру. Если до этого не было явного `tcGen`/`texgen`, движок автоматически переключает генерацию координат в режим `skybox`, то есть ожидает, что выборка будет происходить как из окружающего куба. На практике чаще всего директиву сочетают с `texgen reflect` или `tcGen environment`, если cubemap нужен не как небо, а как отражение.

#### Практические сценарии использования
```
{
	cubemap env/city_night
	texgen reflect
	blendfunc add
}
```

### cameracubemap
`cameracubemap <cubeTexture>`

* **cubeTexture** — cubemap-ресурс.

#### Описание и логика работы
`cameracubemap` — Doom 3-совместимый алиас `cubemap`. Поведение то же самое: стадия получает cubemap, а при отсутствии явной генерации координат включается `skybox`. Используйте эту форму только если поддерживаете уже существующий материал в Doom 3-стиле; для новой FTEQW-документации удобнее писать `cubemap`.

#### Практические сценарии использования
```
{
	cameracubemap env/lab_reflection
	texgen reflect
}
```

### surroundmap
`surroundmap <cubeTexture>`

* **cubeTexture** — cubemap-ресурс.

#### Описание и логика работы
`surroundmap` — QFusion/Warsow-совместимый алиас `cubemap`. Семантика идентична: stage получает cube texture и, если вы сами не задали генерацию координат, использует `skybox`-тип выборки. В новых скриптах удобнее опираться на `cubemap`, но для чтения старых материалов знать этот алиас полезно.

#### Практические сценарии использования
```
{
	surroundmap env/arena_chrome
	texgen reflect
	blendfunc add
}
```

### blendfunc
`blendfunc <preset>`
`blendfunc <srcFactor> <dstFactor>`

* **preset** — именованный готовый режим смешивания.
* **srcFactor** — множитель цвета текущей стадии.
* **dstFactor** — множитель уже нарисованного кадра.

#### Описание и логика работы
`blendfunc` определяет, как цвет стадии объединяется с тем, что уже находится в framebuffer. Это ключевая директива для стекла, огня, свечения, грязи, decals, hologram-эффектов и любых многослойных материалов. Парсер понимает как удобные короткие имена, так и прямую пару OpenGL-факторов; префикс `gl_` необязателен. Между факторами допускается и форма с запятой.

#### blend
`blendfunc blend`

Классическая альфа-прозрачность: эквивалент `gl_src_alpha gl_one_minus_src_alpha`. Используйте для стекла, дыма, тонких плёнок, интерфейсных оверлеев и любых материалов, где альфа-канал должен буквально управлять видимостью слоя.

#### premul
`blendfunc premul`

Режим для уже премультиплицированной текстуры: эквивалент `gl_one gl_one_minus_src_alpha`. Он устраняет тёмную кайму на полупрозрачных краях при линейной фильтрации и подходит для VFX-спрайтов, HUD-элементов и частиц, сохранённых в premultiplied-alpha виде.

#### filter
`blendfunc filter`

Модуляция нижележащего изображения: эквивалент `gl_dst_color gl_zero`. Текстура стадии здесь не «ложится сверху» как прозрачная плёнка, а умножает уже нарисованный кадр, поэтому хорошо подходит для теней, копоти, цветовых фильтров, разводов и затемняющих слоёв.

#### add
`blendfunc add`

Аддитивное сложение: эквивалент `gl_one gl_one`. Стадия только добавляет яркость и никогда не затемняет фон, поэтому это базовый режим для пламени, магии, светящихся ламп, неона, электроискр и энергетических ореолов.

#### replace
`blendfunc replace`

Режим полной замены без смешивания. Слой перезаписывает цвет кадра как обычная непрозрачная текстура и часто автоматически ведёт к записи глубины, если не включены отдельные нестандартные состояния.

#### bumpmap
`blendfunc bumpmap`

Doom 3-совместимый служебный режим, помечающий стадию как normal/bump-проход. В FTEQW такой проход используется прежде всего для разборки Doom 3-материалов и не ведёт себя как обычный цветовой слой Quake III-сценария.

#### specularmap
`blendfunc specularmap`

Doom 3-совместимый служебный режим, объявляющий стадию спекулярным проходом. Нужен главным образом для импорта Doom 3-подобных материалов и обычно не применяется как самостоятельная «ручная» blend-схема в классическом `.shader`.

#### diffusemap
`blendfunc diffusemap`

Doom 3-совместимый служебный режим, объявляющий стадию диффузным проходом. Используется там, где материал описывается как набор `diffuse/specular/bump`-карт, а не как традиционный набор Quake III-проходов.

#### Явная пара факторов
`blendfunc <srcFactor> <dstFactor>`

Низкоуровневая форма даёт полный контроль над формулой:
`результат = (цвет стадии × srcFactor) + (уже нарисованный кадр × dstFactor)`.

**Допустимые src-факторы:**

| Фактор | Значение |
| :--- | :--- |
| `gl_zero` / `zero` | вклад стадии равен нулю |
| `gl_one` / `one` | вклад стадии берётся целиком |
| `gl_dst_color` / `dst_color` | стадия умножается на уже нарисованный цвет |
| `gl_one_minus_dst_color` / `one_minus_dst_color` | стадия умножается на инверсию уже нарисованного цвета |
| `gl_src_alpha` / `src_alpha` | стадия умножается на собственную альфу |
| `gl_one_minus_src_alpha` / `one_minus_src_alpha` | стадия умножается на инверсию собственной альфы |
| `gl_dst_alpha` / `dst_alpha` | стадия умножается на альфу буфера кадра |
| `gl_one_minus_dst_alpha` / `one_minus_dst_alpha` | стадия умножается на инверсию альфы буфера кадра |

**Допустимые dst-факторы:**

| Фактор | Значение |
| :--- | :--- |
| `gl_zero` / `zero` | фон не участвует |
| `gl_one` / `one` | фон участвует целиком |
| `gl_src_color` / `src_color` | фон умножается на цвет текущей стадии |
| `gl_one_minus_src_color` / `one_minus_src_color` | фон умножается на инверсию цвета стадии |
| `gl_src_alpha` / `src_alpha` | фон умножается на альфу стадии |
| `gl_one_minus_src_alpha` / `one_minus_src_alpha` | фон умножается на инверсию альфы стадии |
| `gl_dst_alpha` / `dst_alpha` | фон умножается на текущую альфу буфера |
| `gl_one_minus_dst_alpha` / `one_minus_dst_alpha` | фон умножается на инверсию текущей альфы буфера |

`gl_src_color` и `gl_one_minus_src_color` невалидны как `srcFactor`, а `gl_dst_color` и `gl_one_minus_dst_color` невалидны как `dstFactor`: парсер принимает такие слова, но движок заменяет неверный фактор безопасным поведением. Поэтому лучше придерживаться допустимых позиций из таблиц выше.

#### Практические сценарии использования
```
{
	map textures/mymod/water_glow.tga
	blendfunc add
	rgbGen wave sin 0.5 0.5 0 0.3
}
```

### blend
`blend <presetOrFactors>`

* **presetOrFactors** — те же аргументы, что у `blendfunc`.

#### Описание и логика работы
`blend` — Doom 3-совместимый синоним `blendfunc`. Он понимает те же пресеты (`blend`, `premul`, `filter`, `add`, `replace`) и ту же явную пару факторов, а также служебные слова `bumpmap`, [`specularmap`](01-shader-toplevel-directives.md#specularmap), [`diffusemap`](01-shader-toplevel-directives.md#diffusemap). Для новой документации и новых `.shader` удобнее считать основной формой `blendfunc`.

#### Практические сценарии использования
```
{
	map textures/fx/spark.tga
	blend add
}
```

### rgbGen
`rgbGen <mode> [args...]`

* **mode** — способ вычисления RGB-множителя стадии.
* **args** — дополнительные параметры выбранного режима.

#### Описание и логика работы
`rgbGen` управляет тем, как стадия модифицирует цвет своей текстуры перед смешиванием. В одних режимах цвет берётся напрямую из вершин или из игрового объекта, в других — вычисляется по волновой функции, а в третьих фиксируется константой. Если `rgbGen` вообще не указан, движок подставляет значение сам: для обычных непрозрачных/слабо смешиваемых слоёв это чаще `identityLighting`, для остальных — `identity`.

#### identityLighting
`rgbGen identityLighting`

Белый цвет с учётом общей схемы освещённости/overbright, подходящий для стандартных освещаемых слоёв. Это наиболее «естественное» значение по умолчанию для типичной диффузной стадии.

#### identity
`rgbGen identity`

Чистый белый множитель без дополнительных колебаний: текстура идёт «как есть». Удобно для UI-элементов, fullbright-масок и ситуаций, где вы не хотите ни вершинного цвета, ни пульсации, ни поправок от сущности.

#### wave
`rgbGen wave <func> <base> <amplitude> <phase> <frequency>`

Периодически меняет яркость стадии по волновой функции. Поддерживаются [`sin`](../37-quakec-builtins-reference/01-math-vector-builtins.md#sin), `triangle`, `square`, `sawtooth`, `inversesawtooth`, [`noise`](../39-entity-keys-reference/01-worldspawn-common-keys.md#noise). Это главный режим для мерцания ламп, дыхания энергетических щитов, пульсации магии и любых циклических изменений яркости.

#### entity
`rgbGen entity`

Берёт RGB из цвета объекта, который задаёт игровая логика. Подходит для окраски предметов, командных моделей, временных эффектов и всего, что должно реагировать на состояние сущности, а не быть жёстко зашито в текстуру.

#### oneMinusEntity
`rgbGen oneMinusEntity`

Использует инверсию `entity`-цвета: `1 - color`. Полезно для контрподсветок, обратных масок и редких stylized-эффектов, где при осветлении объекта сам слой, наоборот, должен темнеть.

#### vertex
`rgbGen vertex`

Берёт цвет из вершинной раскраски геометрии. Важная тонкость FTEQW: если `alphaGen` ещё не задан, движок автоматически делает и `alphaGen vertex`, чтобы цвет и альфа шли из одного и того же vertex array.

#### oneMinusVertex
`rgbGen oneMinusVertex`

Инверсия вершинного цвета. Полезно для специальных карт масок, где сама геометрия задаёт «обратную» интенсивность эффекта.

#### lightingDiffuse
`rgbGen lightingDiffuse`

Заставляет стадию рассчитывать цвет от настоящего диффузного освещения сцены. Это режим для слоёв, которые должны вести себя как нормально освещаемая поверхность, а не как self-illuminated overlay.

#### entityLighting
`rgbGen entityLighting`

Комбинирует освещение сцены с цветом сущности. Хороший вариант для окрашиваемых моделей или объектов, которые одновременно должны подчиняться и командному цвету, и свету окружения.

#### exactVertex
`rgbGen exactVertex`

Берёт вершинный цвет без дополнительной коррекции/overbright-подгонки. Если нужны буквально те значения, которые записаны в вершинах, а не «улучшенная» освещённая интерпретация, используйте именно этот режим.

#### const
`rgbGen const <r> <g> <b>`

Жёстко задаёт постоянный RGB-множитель. Синонимы `constant` и `constLighting` парсер тоже принимает. Это хороший инструмент для тонирования одной и той же маски разными цветами без подготовки отдельных файлов.

#### srgb
`rgbGen srgb <r> <g> <b>`

То же, что `const`, но числа трактуются как sRGB-значения и сразу переводятся движком в линейное пространство. Синоним `srgbconst` полезен, когда цвет взят прямо из графического редактора и вы не хотите вручную пересчитывать его в линейный RGB.

#### topcolor
`rgbGen topcolor`

Использует «верхний» пользовательский цвет classic Quake player customization. Чаще всего встречается в старых player-skin/overlay-материалах.

#### bottomcolor
`rgbGen bottomcolor`

Использует «нижний» пользовательский цвет classic Quake player customization. Обычно применяется вместе с `topcolor`, чтобы раздельно перекрашивать разные области скина.

#### Практические сценарии использования
```
{
	map textures/fx/neon_glow.tga
	blendfunc add
	rgbGen wave sin 0.6 0.4 0 1.2
}
```

### alphaGen
`alphaGen <mode> [args...]`

* **mode** — способ вычисления альфа-канала стадии.
* **args** — дополнительные параметры режима.

#### Описание и логика работы
`alphaGen` задаёт, насколько прозрачной должна быть стадия до применения `blendfunc` или `alphafunc`. Если директива отсутствует, FTEQW завершает стадию значением `identity`, то есть альфа считается полной. Как и `rgbGen`, эта команда может брать данные из волновой функции, сущности, вершин или из специализированных источников вроде портала и specular-компоненты.

#### portal
`alphaGen portal <distance>`

Делает прозрачность зависимой от портальной дистанции. `distance` — характерная дальность эффекта; если передать `0`, движок всё равно использует `256`. Типичный случай — зеркала, порталы и водные поверхности, у которых глубина/видимость должна зависеть от расстояния.

#### vertex
`alphaGen vertex`

Берёт альфу из вершинных данных. Часто применяется вместе с `rgbGen vertex`, но может использоваться и отдельно, если цвет текстуры должен остаться неизменным, а вот прозрачность должна идти из mesh vertex alpha.

#### entity
`alphaGen entity`

Подчиняет прозрачность параметру сущности из игрового кода. Нужен для fade-in/fade-out, призрачных объектов, интерфейсных world-space подсказок и других управляемых эффектов.

#### wave
`alphaGen wave <func> <base> <amplitude> <phase> <frequency>`

Пульсирующая прозрачность. Поддерживаются те же волновые функции, что и у `rgbGen wave`: `sin`, `triangle`, `square`, `sawtooth`, `inversesawtooth`, `noise`.

#### lightingSpecular
`alphaGen lightingSpecular`

Строит альфу из бликовой/specular-составляющей освещения. Обычно этот режим используют не для «настоящей прозрачности», а как динамическую маску блика, которую потом смешивают подходящим `blendfunc`.

#### const
`alphaGen const <value>`

Постоянная альфа от `0.0` до `1.0`. Синоним `constant` тоже поддерживается. Это самый прямой способ сделать стадию всегда наполовину прозрачной, не трогая сам alpha-channel текстуры.

#### Практические сценарии использования
```
{
	map textures/ghost/silhouette.tga
	blendfunc blend
	alphaGen wave sin 0.5 0.25 0 0.7
}
```

### alphaShift
`alphaShift <speed> <min> <max>`

* **speed** — параметр скорости/периода совместимого Alien Arena-режима.
* **min** — нижняя граница альфы.
* **max** — верхняя граница альфы.

#### Описание и логика работы
`alphaShift` — совместимый shorthand из Alien Arena. Вместо самостоятельного отдельного алгоритма движок переводит его во внутренний синусоидальный `alphaGen wave`, который колеблет прозрачность между `min` и `max`. Для нового контента почти всегда понятнее сразу писать `alphaGen wave`, но при чтении чужих старых шейдеров важно знать, что визуально это именно периодическая пульсация альфы.

#### Практические сценарии использования
```
{
	map textures/arena/shield.tga
	blendfunc blend
	alphaShift 2 0.2 0.8
}
```

### depthfunc
`depthfunc <mode>`

* **mode** — способ проверки глубины: `equal`, `lequal`, `less` или `greater`.

#### Описание и логика работы
`depthfunc` меняет правило, по которому стадия сравнивает свою глубину с уже существующим z-buffer. Это директива для сложных многопроходных материалов, decals, спецэффектов поверх уже записанной геометрии и некоторых post-style трюков. Неправильное значение делает слой полностью невидимым или, наоборот, заставляет его проступать сквозь геометрию.

#### Практические сценарии использования
```
{
	map textures/decals/crack.tga
	blendfunc blend
	depthfunc equal
}
```

### depthwrite
`depthwrite`

#### Описание и логика работы
`depthwrite` принудительно включает запись глубины для этой стадии. Обычно прозрачные и аддитивные слои глубину не пишут, чтобы не «резать» последующие прозрачные проходы, но иногда запись нужна специально — например, у альфа-маскированной листвы, сетки или некоторых хитрых экранных эффектов. На непрозрачном `blendfunc replace` слое запись глубины и так обычно включается автоматически; `depthwrite` особенно полезен именно на нестандартных blend-схемах.

#### Практические сценарии использования
```
{
	map textures/foliage/leafmask.tga
	alphafunc ge128
	depthwrite
}
```

### nodepthtest
`nodepthtest`

#### Описание и логика работы
`nodepthtest` отключает проверку глубины для стадии. Слой рисуется независимо от того, что уже находится перед ним в z-buffer, поэтому его обычно применяют только для специальных экранных/служебных эффектов, которые должны быть видны поверх всего. В обычных world-материалах директива опасна: она легко приводит к «просвечиванию» сквозь стены и другие объекты.

#### Практические сценарии использования
```
{
	map textures/fx/hud_ring.tga
	blendfunc add
	nodepthtest
}
```

### nodepth
`nodepth`

#### Описание и логика работы
Парсер FTEQW принимает `nodepth` как совместимую stage-команду, но в текущей реализации она не выставляет отдельный собственный per-pass режим сравнения глубины, как это делает `nodepthtest`. На практике это скорее совместимый маркер, который участвует во внутреннем учёте depthwrite-состояния шейдера. Для нового контента, где вам действительно нужно игнорировать z-buffer, используйте `nodepthtest`; если же нужен контроль записи глубины, используйте `depthwrite`.

#### Практические сценарии использования
```
{
	map $diffuse
	blendfunc add
	nodepth
}
```

### alphafunc
`alphafunc <mode>`

* **mode** — пороговый режим: `gt0`, `lt128` или `ge128`.

#### Описание и логика работы
`alphafunc` включает бинарное отсечение пикселей по alpha-каналу до обычного полупрозрачного смешивания. Это основной инструмент для листвы, решёток, цепных заборов, бумажных флагов, дырчатых масок и прочих материалов, где пиксель должен быть либо полностью видим, либо полностью отброшен. В отличие от `blendfunc blend`, этот подход сохраняет жёсткий силуэт и хорошо дружит с `depthwrite`.

#### Практические сценарии использования
```
{
	map textures/foliage/leaves.tga
	alphafunc ge128
	depthwrite
}
```

### alphaMask
`alphaMask`

#### Описание и логика работы
`alphaMask` — Alien Arena-совместимый shorthand, который принудительно устанавливает тот же пороговый режим, что и `alphafunc ge128`. Никаких дополнительных аргументов не принимает. Удобно рассматривать его просто как компактный алиас для классического «покажи пиксели с альфой 128 и выше».

#### Практические сценарии использования
```
{
	clampmap textures/props/grate.tga
	alphaMask
	depthwrite
}
```

### alphaTest
`alphaTest 0.5`

* **0.5** — единственное практически поддерживаемое значение; оно переводится в порог `ge128`.

#### Описание и логика работы
`alphaTest` — Doom 3-совместимая форма порогового альфа-теста. В текущем парсере FTEQW полезным считается только значение `0.5`; любое другое число распознаётся как неподдерживаемое. По результату этот вариант эквивалентен `alphafunc ge128`.

#### Практические сценарии использования
```
{
	map textures/props/wiremesh.tga
	alphaTest 0.5
	depthwrite
}
```

### tcMod
`tcMod <mode> [args...]`

* **mode** — тип модификации UV-координат.
* **args** — параметры выбранного модификатора.

#### Описание и логика работы
`tcMod` последовательно модифицирует текстурные координаты стадии. В одном и том же блоке можно указать несколько `tcMod` подряд, и они будут применяться по очереди в порядке записи. Это главный механизм для текущей воды, вращающихся порталов, пульсирующих голограмм, анимированных атласов и любых процедурных UV-эффектов без смены самой текстуры.

#### rotate
`tcMod rotate <degreesPerSecond>`

Равномерно вращает текстуру вокруг её центра. Положительные и отрицательные значения дают противоположное направление вращения; нулевое значение не имеет практического эффекта.

#### scale
`tcMod scale <scaleS> <scaleT>`

Масштабирует UV по двум осям. Значения больше `1` меняют плотность повторения рисунка одним образом, значения меньше `1` — обратным; practically это основной способ сделать узор мельче или крупнее без изменения исходного изображения.

#### scroll
`tcMod scroll <speedS> <speedT>`

Постоянно сдвигает текстуру по U и V со скоростями `speedS` и `speedT`. Это классический режим для конвейерных лент, бегущих строк, воды, лавы, дыма и всех материалов, у которых рисунок должен непрерывно «плыть» по поверхности.

#### stretch
`tcMod stretch <func> <base> <amplitude> <phase> <frequency>`

Периодически растягивает и сжимает UV-координаты по волновой функции. Поддерживаются `sin`, `triangle`, `square`, `sawtooth`, `inversesawtooth`, `noise`. Визуально это похоже на дыхание или пульсацию самой текстуры целиком.

#### transform
`tcMod transform <m00> <m01> <m10> <m11> <t0> <t1>`

Полное аффинное преобразование UV: 2×2-матрица плюс перенос. Это самый универсальный режим `tcMod`, позволяющий за одну директиву задать произвольную комбинацию наклона, масштаба, зеркалирования, поворота и смещения.

#### turb
`tcMod turb <base> <amplitude> <phase> <frequency>`

Классическая «турбулентность» Quake: волнообразное покачивание координат. Обычно используется для воды, лавы, плазмы, тепловой ряби и других organic/shimmer-эффектов.

#### page
`tcMod page <frameCount> <columns> <rows>`

Переключает кадры внутри одного атласа, где анимация разложена плиткой `columns × rows`. Это покадровая анимация без набора отдельных файлов, удобная для терминалов, индикаторов, rune-cycles и sprite-sheet-подобных эффектов на поверхностях.

#### Практические сценарии использования
```
{
	map textures/mymod/water.tga
	blendfunc blend
	tcMod scroll 0.1 0.05
	tcMod turb 0 0.2 0 1.5
}
```

### scale
`scale <x> <y>`
`scale static <x>, static <y>`

* **x** — масштаб по первой оси.
* **y** — масштаб по второй оси.

#### Описание и логика работы
`scale` — Alien Arena/RScript-совместимый shorthand, который добавляет такой же UV-модификатор, как `tcMod scale`. Парсер допускает как простые числа, так и форму с ключевым словом `static`; между осями возможна запятая. Для нового контента чаще удобнее единообразно использовать `tcMod scale`, но при чтении старых материалов это полностью рабочий stage-синоним.

#### Практические сценарии использования
```
{
	map textures/arena/panel.tga
	scale 2 1
}
```

### scroll
`scroll static <x> static <y>`

* **x** — скорость скролла по первой оси.
* **y** — скорость скролла по второй оси.

#### Описание и логика работы
`scroll` — Alien Arena/RScript-совместимый shorthand для `tcMod scroll`. В отличие от `tcMod`, текущий парсер ожидает ключевое слово `static` перед каждым числом; это историческая особенность совместимого синтаксиса. По визуальному результату директива идентична обычному UV-скроллу.

#### Практические сценарии использования
```
{
	map textures/arena/conveyor.tga
	scroll static 0.2 static 0
}
```

### tcGen
`tcGen <mode> [args...]`

* **mode** — способ генерации текстурных координат.
* **args** — дополнительные аргументы режима, если они нужны.

#### Описание и логика работы
`tcGen` заменяет обычные UV-координаты автоматически вычисляемыми координатами другого типа. Это не анимирует уже существующую развёртку, а полностью выбирает источник координат: лайтмапу, окружение, нормали, касательные или пользовательские векторы. Если `map`/`clampmap` не задали специальный источник и вы не пишете `tcGen`, в конце разбора стадия получает обычный `base` автоматически.

#### base
`tcGen base`

Стандартные UV самой модели/поверхности. Это нормальный режим по умолчанию для почти всех обычных текстурных слоёв.

#### lightmap
`tcGen lightmap`

Использует координаты lightmap-развёртки. Обычно нужен для стадий, которые напрямую читают `$lightmap` или другие baked-lighting ресурсы.

#### environment
`tcGen environment`

Генерирует координаты из ориентации камеры относительно поверхности. Это классический дешёвый environment-mapping для хрома, полированного металла и fake-reflection материалов.

#### fireriseenv
`tcGen fireriseenv`

RTCW-совместимое слово, которое парсер FTEQW сводит к тому же режиму `environment`. Специальной уникальной логики «fire rise» здесь нет, поэтому визуально ориентируйтесь просто на стандартный environment map.

#### vector
`tcGen vector (<sX> <sY> <sZ>) (<tX> <tY> <tZ>)`

Проецирует координаты на два явно заданных вектора. Это продвинутый режим для planar/projection-эффектов, нестандартных procedural-наложений и случаев, когда UV должны определяться направлением в world/model space, а не готовой развёрткой mesh.

#### normal
`tcGen normal`

Использует нормаль поверхности как источник координат. Нишевый режим для специальных shader-приёмов, где выборка должна зависеть от направления нормали, а не от UV.

#### svector
`tcGen svector`

Использует tangent/S-вектор поверхности. Подходит для эффектов, которым важно направление первой касательной оси UV-развёртки.

#### tvector
`tcGen tvector`

Использует bitangent/T-вектор поверхности. Применяется в тех же продвинутых случаях, что и `svector`, но относительно второй оси касательного базиса.

#### skybox
`tcGen skybox`

Генерирует координаты для выборки из cubemap/skybox-окружения. Это логичный режим для `cubemap`, `surroundmap` и других стадий, которые рисуют окружающий куб, а не плоскую 2D-карту.

#### Практические сценарии использования
```
{
	cubemap env/metal_lab
	tcGen environment
	blendfunc add
}
```

### texgen
`texgen <mode> [args...]`

* **mode** — режим совместимого `texgen`.
* **args** — дополнительные параметры выбранного режима.

#### Описание и логика работы
Имя `texgen` в FTEQW встречается в двух совместимых традициях. В Quake III-подобных скриптах оно может выступать просто алиасом `tcGen`; в Doom 3-совместимых stage-блоках парсер принимает отдельный набор режимов, перечисленный ниже. Для новых материалов, которые должны быть понятны сразу, предпочтительнее явно писать `tcGen` или использовать `texgen` только тогда, когда вы сознательно документируете Doom 3-совместимый синтаксис.

#### normal
`texgen normal`

Doom 3-совместимая форма генерации координат из нормали поверхности.

#### skybox
`texgen skybox`

Doom 3-совместимая форма cubemap/skybox-генерации координат.

#### wobblesky
`texgen wobblesky <arg1> <arg2> <arg3>`

Специальный skybox-режим с дополнительными тремя числовыми параметрами. Парсер их считывает и сохраняет сам факт режима, поэтому материал распознаётся корректно, но использовать эту форму стоит только при переносе уже существующих Doom 3-стадий неба.

#### reflect
`texgen reflect`

Генерирует отражённое направление взгляда для выборки из cubemap. Это более «зеркальный» вариант по сравнению с обычным environment mapping и естественный выбор для хрома, зеркал и глянцевых энергетических сфер.

#### Практические сценарии использования
```
{
	cubemap env/chrome_room
	texgen reflect
	blendfunc add
}
```

### envmap
`envmap`

#### Описание и логика работы
`envmap` — старый совместимый shorthand, который просто выставляет тот же режим координат, что и `tcGen environment`. Сам по себе он не привязывает текстуру; нужен либо `map`/`cubemap`, либо другой источник изображения стадии. Удобно помнить о нём при чтении legacy-материалов из Alien Arena и родственных проектов.

#### Практические сценарии использования
```
{
	map textures/fx/chrome.tga
	envmap
	blendfunc add
}
```

### detail
`detail`

#### Описание и логика работы
`detail` помечает стадию как detail-проход. Такие слои обычно рассматриваются движком как мелкомасштабные добавочные текстуры — шум, микроцарапины, зерно, мелкий рельефный паттерн — которые логически отделены от «основной» поверхности. На практике директива чаще всего встречается на тонких оверлеях поверх базовой текстуры и полезна именно как семантическая пометка detail-слоя.

#### Практические сценарии использования
```
{
	map textures/stone/detail_noise.tga
	blendfunc filter
	detail
	tcMod scale 8 8
}
```

### nolightmap
`nolightmap`

#### Описание и логика работы
`nolightmap` — Alien Arena-совместимая stage-команда, которая просто переключает `rgbGen` в `identity`. То есть слой перестаёт рассматриваться как освещаемый lightmap/overbright-цветом и использует собственную текстуру без дополнительного светового умножения. Это не удаляет лайтмап-стадию из материала целиком; директива влияет именно на текущий проход.

#### Практические сценарии использования
```
{
	map textures/arena/glowstripe.tga
	nolightmap
	blendfunc add
}
```

### program
`program <programName>`

* **programName** — имя/путь generic shader program, который нужно привязать к стадии.

#### Описание и логика работы
[`program`](01-shader-toplevel-directives.md#program) назначает стадии программный GPU-проход по имени. В FTEQW это уже не «обычный» текстурный слой Quake III, а стадия, которую затем обслуживает именованный generic program. Важный практический нюанс: после `program` несколько директив `map` внутри той же стадии не перетирают друг друга, а трактуются как набор связанных texture inputs для этого же программного прохода.

#### Практические сценарии использования
```
{
	program defaultwall
	map textures/tech/panel_d.tga
	map textures/tech/panel_nm.tga
	map textures/tech/panel_s.tga
}
```

### maskcolor
`maskcolor`

#### Описание и логика работы
`maskcolor` включает запись только в цветовые каналы RGB. Альфа-канал стадией при этом не обновляется. Это полезно в узких технических сценариях, когда материал должен менять видимый цвет поверхности, но не трогать уже накопленную альфу буфера.

#### Практические сценарии использования
```
{
	map textures/fx/colorize.tga
	blendfunc add
	maskcolor
}
```

### maskred
`maskred`

#### Описание и логика работы
`maskred` разрешает стадии писать только в красный канал. Обычно это специализированный инструмент для буферных, postprocess- или packing-сценариев, а не для повседневного world-texturing.

#### Практические сценарии использования
```
{
	map textures/debug/channel_mask.tga
	maskred
}
```

### maskgreen
`maskgreen`

#### Описание и логика работы
`maskgreen` разрешает запись только в зелёный канал. Используется там, где цветовые каналы framebuffer интерпретируются не как обычный final color, а как отдельные технические слоты.

#### Практические сценарии использования
```
{
	map textures/debug/channel_mask.tga
	maskgreen
}
```

### maskblue
`maskblue`

#### Описание и логика работы
`maskblue` разрешает запись только в синий канал. Как и остальные channel-mask-команды, это в первую очередь технический, а не художественный инструмент.

#### Практические сценарии использования
```
{
	map textures/debug/channel_mask.tga
	maskblue
}
```

### maskalpha
`maskalpha`

#### Описание и логика работы
`maskalpha` разрешает стадии записывать только альфа-канал framebuffer. Наиболее полезен в системах, где альфа буфера используется как отдельная маска для последующих проходов.

#### Практические сценарии использования
```
{
	map textures/fx/fade_mask.tga
	maskalpha
}
```

### red
`red <value>`

* **value** — постоянное значение красного компонента.

#### Описание и логика работы
`red` — Doom 3-совместимый shorthand, который переводит стадию в постоянный `rgbGen const` и задаёт красную компоненту. Обычно его комбинируют с `green` и `blue`, чтобы собрать полный постоянный цвет по компонентам. Для нового контента чаще нагляднее сразу использовать `rgbGen const r g b`.

#### Практические сценарии использования
```
{
	map textures/fx/tintmask.tga
	red 1
	green 0.2
	blue 0.2
}
```

### green
`green <value>`

* **value** — постоянное значение зелёного компонента.

#### Описание и логика работы
`green` задаёт зелёную компоненту постоянного цвета стадии в Doom 3-совместимом стиле. Как и `red`, обычно применяется в связке с остальными компонентными директивами, а не в одиночку.

#### Практические сценарии использования
```
{
	map textures/fx/tintmask.tga
	red 0.1
	green 0.8
	blue 0.1
}
```

### blue
`blue <value>`

* **value** — постоянное значение синего компонента.

#### Описание и логика работы
`blue` задаёт синюю компоненту постоянного цвета стадии. Это ещё один Doom 3-совместимый shorthand поверх `rgbGen const`.

#### Практические сценарии использования
```
{
	map textures/fx/tintmask.tga
	red 0.2
	green 0.4
	blue 1
}
```

### alpha
`alpha <value>`

* **value** — постоянное значение альфы.

#### Описание и логика работы
`alpha` — Doom 3-совместимый shorthand для `alphaGen const`. Он задаёт постоянную прозрачность одним числом и чаще всего используется рядом с компонентными `red/green/blue`, когда материал описывается в Doom 3-стиле.

#### Практические сценарии использования
```
{
	map textures/fx/tintmask.tga
	blendfunc blend
	alpha 0.5
}
```

### map16
`map16 <textureOrSpecial>`

* **textureOrSpecial** — те же аргументы, что у `map`.

#### Описание и логика работы
`map16` — RTCW-совместимая условная форма `map`. Стадия реально использует указанный ресурс только тогда, когда в текущей конфигурации движок работает без 24-битной загрузки текстур; иначе строка фактически пропускается. Это инструмент совместимости со старыми материалами, у которых были разные варианты изображения для low/high-quality режима.

#### Практические сценарии использования
```
{
	map16 textures/legacy/panel_16bit.tga
}
```

### map32
`map32 <textureOrSpecial>`

* **textureOrSpecial** — те же аргументы, что у `map`.

#### Описание и логика работы
`map32` — противоположная RTCW-ветка по сравнению с `map16`. Эта карта активируется только тогда, когда движок использует 24/32-битную загрузку текстур. На практике директива встречается парами с `map16` в одном и том же stage-блоке.

#### Практические сценарии использования
```
{
	map32 textures/legacy/panel_32bit.tga
}
```

### mapcomp
`mapcomp <textureOrSpecial>`

* **textureOrSpecial** — те же аргументы, что у `map`.

#### Описание и логика работы
`mapcomp` — RTCW-совместимая условная карта для случая, когда S3TC/BC3-компрессия поддерживается и включена. Если сжатые форматы недоступны, директива не активируется. Полезна только при переносе старых материалов, которые выбирали разные assets в зависимости от поддержки texture compression.

#### Практические сценарии использования
```
{
	mapcomp textures/legacy/wall_comp.dds
}
```

### mapnocomp
`mapnocomp <textureOrSpecial>`

* **textureOrSpecial** — те же аргументы, что у `map`.

#### Описание и логика работы
`mapnocomp` — RTCW-совместимая альтернатива `mapcomp`: она активна только когда компрессия текстур не используется. Обычно идёт парой к `mapcomp` как fallback-вариант.

#### Практические сценарии использования
```
{
	mapnocomp textures/legacy/wall_uncomp.tga
}
```

### animcompmap
`animcompmap <fps> <frame1> <frame2> ...`

* **fps** — скорость анимации.
* **frame1, frame2, ...** — кадры анимированной карты.

#### Описание и логика работы
`animcompmap` — RTCW-совместимая условная версия `animmap`. Она работает только при доступной и включённой компрессии S3TC/BC3; в остальных случаях строка пропускается. Нужна почти исключительно для совместимости со старыми shader script-ами RTCW.

#### Практические сценарии использования
```
{
	animcompmap 6 textures/legacy/lamp_comp1.dds textures/legacy/lamp_comp2.dds
}
```

### animnocompmap
`animnocompmap <fps> <frame1> <frame2> ...`

* **fps** — скорость анимации.
* **frame1, frame2, ...** — кадры анимации без компрессионной ветки.

#### Описание и логика работы
`animnocompmap` — fallback-пара к `animcompmap`. Стадия использует эти кадры только тогда, когда сжатые форматы не активны.

#### Практические сценарии использования
```
{
	animnocompmap 6 textures/legacy/lamp1.tga textures/legacy/lamp2.tga
}
```

### animclampmap
`animclampmap <fps> <frame1> <frame2> ...`

* **fps** — скорость анимации.
* **frame1, frame2, ...** — список кадров.

#### Описание и логика работы
`animclampmap` — QFusion/Warsow-совместимая комбинация `animmap` + clamp. Она покадрово переключает текстуры, но одновременно принудительно запрещает их тайлинг по краям. Полезна для анимированных decals, экранов, HUD-like world-panels и любых спрайтовых оверлеев, где повторение по UV недопустимо.

#### Практические сценарии использования
```
{
	animclampmap 10 textures/screens/diag_1.tga textures/screens/diag_2.tga textures/screens/diag_3.tga
	blendfunc blend
}
```

### material
`material <baseTexture> <normalMap> <specularMap>`

* **baseTexture** — базовая диффузная карта; `-` пропускает слот.
* **normalMap** — normal map; `-` пропускает слот.
* **specularMap** — specular map; `-` пропускает слот.

#### Описание и логика работы
`material` — QFusion/Warsow-совместимая компактная форма объявления «набора PBR-подобных карт» одной строкой. Парсер связывает стадию с generic program `defaultwall`, затем по очереди читает базовую, нормальную и спекулярную карту. Это не просто декоративный алиас `map`: директива сразу настраивает программный проход и три стандартных texture input-а для него.

#### Практические сценарии использования
```
{
	material textures/metal/panel_d.tga textures/metal/panel_local.tga textures/metal/panel_s.tga
}
```
