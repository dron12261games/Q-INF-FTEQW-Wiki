# Директивы эффекта

> [⬅ Вернуться к оглавлению вики](../README.md)

> [Индекс справочника директив .particles](./README.md)

Файл описания частиц в FTEQW состоит из отдельных описаний эффектов: каждая запись начинает новый слой строкой `effect имя` или нативной формой `r_part имя`, после чего идёт набор директив, меняющих визуальный результат. Один и тот же итоговый эффект часто собирается из нескольких слоёв: вспышка, дым, искры, декаль, временный свет. На этой странице собраны только директивы, влияющие на внешний вид, срок жизни и сопутствующую визуальную часть эффекта. Параметры области спавна, скоростей, гравитации и другой кинематики вынесены в отдельную статью.

## Директивы

### shader
`shader [shaderName]`

* **shaderName** — имя материала/шейдера; если не указано, движок использует имя самого эффекта.

#### Описание и логика работы
Директива назначает частице полноценный материал вместо простой текстуры. Сразу после строки `shader` парсер может принять встроенное тело шейдера в фигурных скобках и зарегистрировать его на лету. Это полезно, когда частица должна использовать сложное смешивание, анимацию или особые стадии рендера. Если материал сам задаёт blend-состояния, директива `blend` в слое уже не является главным источником правил смешивания.

#### Практические сценарии использования
```
effect demo_shader
{
    shader particles/heat_haze   // вместо обычной текстуры используется готовый материал
    count 1
    die 0.2
    scale 48
    alpha 0.8
    type normal
}
```

### texture
`texture path`

* **path** — путь к изображению или имя встроенного ресурса частицы.

#### Описание и логика работы
Это базовый способ выбрать картинку частицы. В `p_script.c` рядом с `texture` разбираются и варианты `linear_texture`, `nearest_texture` и `nearesttexture`: они делают то же самое, но дополнительно управляют фильтрацией, особенно заметной на пиксельных или атласных текстурах. Если текстура не задана вовсе, движок может попытаться угадать тип частицы по остальным параметрам, поэтому для предсказуемого результата обычно задают и `texture`, и `type`. В effectinfo-совместимом синтаксисе близкую роль выполняет директива `tex`.

#### Практические сценарии использования
```
effect demo_texture
{
    texture particles/smoke_puff.tga   // картинка облака дыма
    count 6
    die 1.5
    scale 24
    alpha 0.35
    type normal
}
```

### tcoords
`tcoords s1 t1 s2 t2 [tscale] [rsmax] [rsstep]`

* **s1** — левая S-координата подизображения.
* **t1** — верхняя T-координата подизображения.
* **s2** — правая S-координата подизображения.
* **t2** — нижняя T-координата подизображения.
* **tscale** — масштаб координат; обычно размер атласа в пикселях.
* **rsmax** — число случайно выбираемых кадров по горизонтали.
* **rsstep** — шаг между соседними кадрами по оси S.

#### Описание и логика работы
Директива выбирает прямоугольник внутри уже назначенной текстуры. Если указан `tscale`, координаты делятся на него, поэтому удобно вводить значения в пикселях для атласа `256x256` или `512x512`. Пара `rsmax` и `rsstep` включает случайный выбор соседних ячеек по горизонтали: так один слой может брать немного разные спрайты копоти, искр или осколков без дублирования отдельных эффектов. Если `rsmax < 1` или `rsstep = 0`, рандомизация кадров фактически отключается.

#### Практические сценарии использования
```
effect demo_tcoords
{
    texture particles/fteparticlefont.tga
    tcoords 1 65 31 95 256 8 32   // берём 8 кадров из одной строки атласа
    count 8
    die 0.4
    scale 6
    alpha 0.6
    type texturedspark
}
```

### atlas
`atlas dims firstIndex [lastIndex]`

* **dims** — число ячеек по одной стороне квадратного атласа.
* **firstIndex** — первый индекс кадра в сетке.
* **lastIndex** — последний индекс диапазона; если не указан, берётся один кадр.

#### Описание и логика работы
`atlas` — упрощённая альтернатива `tcoords`, когда текстура уже равномерно разбита на сетку. Движок сам вычисляет UV-координаты нужной ячейки и может случайно выбирать кадр из диапазона. Важная деталь из парсера: диапазон не должен перескакивать на другую строку атласа; если `lastIndex` выходит за пределы той же строки, движок зажимает его и пишет предупреждение. Это удобно для простых flipbook-спрайтов, разложенных ровной таблицей.

#### Практические сценарии использования
```
effect demo_atlas
{
    texture particles/explosion_atlas.tga
    atlas 4 4 7   // берём кадры 4..7 в сетке 4x4
    count 4
    die 0.25
    scale 40
    alpha 0.8
    type normal
}
```

### rotation
`rotation startMin [startMax] speedMin [speedMax]`

* **startMin** — начальный угол в градусах.
* **startMax** — верхняя граница случайного начального угла.
* **speedMin** — начальная скорость вращения в градусах в секунду.
* **speedMax** — верхняя граница случайной скорости вращения.

#### Описание и логика работы
`rotation` задаёт и стартовый поворот спрайта, и скорость его дальнейшего вращения. Если заданы диапазоны, движок случайно выбирает угол и скорость внутри них для каждой частицы. Для раздельной записи используются родственные директивы `rotationstart` и `rotationspeed`, которые заполняют те же поля по отдельности. Для обычных billboards это хороший способ избежать одинаково ориентированных дымовых облаков; для beam-слоёв польза обычно минимальна.

#### Практические сценарии использования
```
effect demo_rotation
{
    texture particles/smoke_puff.tga
    rotation 0 360 -30 30   // случайный стартовый угол и медленное вращение
    count 10
    die 2.0
    scale 22
    alpha 0.4
    type normal
}
```

### beamtexstep
`beamtexstep unitsPerRepeat`

* **unitsPerRepeat** — сколько игровых единиц луча занимает один повтор текстуры.

#### Описание и логика работы
Директива используется для `type beam` и задаёт плотность укладки текстуры вдоль луча. Внутри парсера значение хранится как обратная величина, поэтому по смыслу это именно «длина одного тайла вдоль beam». Чем меньше значение, тем чаще повторяется рисунок; чем больше — тем спокойнее и длиннее выглядит узор. Если `beamtexstep` не задан, для beam-частиц движок подставляет значение по умолчанию, эквивалентное примерно `128` единицам на повтор.

#### Практические сценарии использования
```
effect demo_beam_step
{
    texture particles/lightning_strip.tga
    beamtexstep 64      // один повтор текстуры на 64 юнита длины луча
    count 1
    die 0.15
    scale 10
    alpha 1
    type beam
}
```

### beamtexspeed
`beamtexspeed scrollSpeed`

* **scrollSpeed** — скорость прокрутки текстуры вдоль луча.

#### Описание и логика работы
Эта директива тоже относится к `type beam`. Она не меняет геометрию луча, а сдвигает рисунок по его длине, создавая впечатление текущей энергии, бегущих полос или плазменного потока. Ноль даёт статичный beam, положительные и отрицательные значения крутят текстуру в противоположных направлениях. Наиболее заметна в сочетании с контрастными полосатыми текстурами и `blend add`.

#### Практические сценарии использования
```
effect demo_beam_scroll
{
    texture particles/lightning_strip.tga
    beamtexstep 48
    beamtexspeed 6      // узор течёт по лучу
    count 1
    die 0.15
    scale 12
    alpha 1
    type beam
}
```

### scale
`scale minSize [maxSize]`

* **minSize** — базовый размер частицы в игровых единицах.
* **maxSize** — верхняя граница случайного стартового размера.

#### Описание и логика работы
Это основной размер спрайта, искры, декали или звена луча. При одном аргументе все частицы слоя стартуют одинаковыми; при двух движок выбирает случайный размер в диапазоне. Очень маленькие значения подходят для пыли и дождя, крупные — для вспышек, дыма и пятен. С `type spark` размер также влияет на видимую толщину/площадь следа.

#### Практические сценарии использования
```
effect demo_scale
{
    texture particles/smoke_puff.tga
    scale 12 28         // каждая частица немного разного размера
    count 10
    die 1.8
    alpha 0.35
    rgb 70 70 70
    type normal
}
```

### scalefactor
`scalefactor factor`

* **factor** — коэффициент зависимости видимого размера от дистанции до камеры.

#### Описание и логика работы
`scalefactor 1` ведёт себя как обычный world-space размер. `0` полезен для экранных вспышек и корон, которые не должны заметно «съёживаться» вдали. Значения между `0` и `1` смягчают перспективное уменьшение. В `FinishParticleType` значения больше `1` движок фактически запекает в исходный размер и затем нормализует коэффициент, поэтому для предсказуемой настройки лучше держаться диапазона `0..1`.

#### Практические сценарии использования
```
effect demo_scalefactor
{
    texture particles/explosion_flash.tga
    count 1
    die 0.2
    scale 64
    scalefactor 0       // вспышка выглядит одинаково крупной на разной дистанции
    alpha 0.9
    blend add
    type normal
}
```

### scaledelta
`scaledelta unitsPerSecond`

* **unitsPerSecond** — изменение размера в игровых единицах в секунду.

#### Описание и логика работы
Положительное значение раздувает частицу со временем, отрицательное — сжимает. Это один из самых важных параметров для дыма, вспышек, следов выстрела и умирающих искр. Если значение велико по модулю, частица может очень быстро исчезнуть или, наоборот, раздуться в крупное облако. В effectinfo-совместимом синтаксисе ту же роль выполняет `sizeincrease`.

#### Практические сценарии использования
```
effect demo_scaledelta
{
    texture particles/explosion_flash.tga
    count 1
    die 0.3
    scale 32
    scaledelta 120      // вспышка быстро расширяется
    alpha 0.8
    blend add
    type normal
}
```

### stretchfactor
`stretchfactor factor [minFactor]`

* **factor** — основной коэффициент вытягивания.
* **minFactor** — минимальная длина/доля вытягивания.

#### Описание и логика работы
Параметр влияет прежде всего на искровые режимы (`spark`, `sparkfan`, `texturedspark`) и управляет тем, насколько частица вытягивается по направлению движения. Малые положительные значения дают аккуратные короткие streak-следы, большие — длинные агрессивные искры. В shipped-конфигах это часто используется для рикошетов и дождя. Отрицательные значения применяют реже, но они подходят для более «жёстких» следов фиксированного характера.

#### Практические сценарии использования
```
effect demo_stretch
{
    texture particles/spark.tga
    stretchfactor 0.08 0.02   // короткая и длинная фазы искры
    count 12
    die 0.5
    scale 3
    alpha 0.8
    type spark
}
```

### count
`count baseCount [randCount] [absoluteExtra]`

* **baseCount** — базовое число частиц в слое.
* **randCount** — случайная добавка к количеству.
* **absoluteExtra** — дополнительный абсолютный хвост количества.

#### Описание и логика работы
Хотя `count` относится к спавну, визуально он определяет плотность слоя: редкие искры, густой дым, массивная взрывная шапка. При одном числе слой всегда порождает одинаковое количество частиц. Дополнительные аргументы используются для вариативности и более «живого» результата. Для trail/beam-эффектов часто вместо `count` используют `step`, но для точечных вспышек и облаков именно `count` — главный параметр насыщенности.

#### Практические сценарии использования
```
effect demo_count
{
    texture particles/smoke_puff.tga
    count 8 4            // от 8 до 12 частиц
    die 1.2
    scale 18
    alpha 0.3
    rgb 80 80 80
    type normal
}
```

### alpha
`alpha baseAlpha [maxAlpha] [delta]`

* **baseAlpha** — начальная альфа слоя.
* **maxAlpha** — верхняя граница случайной стартовой альфы.
* **delta** — скорость изменения альфы; эквивалент встроенной записи `alphadelta`.

#### Описание и логика работы
Это основной уровень непрозрачности частицы. В нативных конфигах FTEQW обычно используют значения около `0..1`, но движок не запрещает и больше единицы для очень ярких аддитивных эффектов. Если второй аргумент задан прямо в `alpha`, движок трактует его как верхнюю границу диапазона и сам вычисляет разброс. Третий аргумент позволяет одной строкой задать и начальную альфу, и её изменение во времени.

#### Практические сценарии использования
```
effect demo_alpha
{
    texture particles/explosion_flash.tga
    count 1
    die 0.25
    scale 48
    alpha 0.7 1.0        // стартовая яркость немного плавает
    blend add
    type normal
}
```

### alpharand
`alpharand range`

* **range** — добавка случайной альфы к каждой частице.

#### Описание и логика работы
`alpharand` не задаёт максимум напрямую, а именно добавляет случайный диапазон к уже вычисленной базовой альфе. Поэтому практический итог — `alpha + random(0..range)`. Это удобно, когда нужно оставить базовую читаемость эффекта, но избежать слишком ровного вида у дыма, пыли или магических искр. Большие значения легко выбивают часть частиц в почти невидимые или, наоборот, слишком яркие состояния.

#### Практические сценарии использования
```
effect demo_alpharand
{
    texture particles/smoke_puff.tga
    count 10
    die 1.6
    scale 20
    alpha 0.15
    alpharand 0.2        // часть клубов будет плотнее остальных
    type normal
}
```

### alphadelta
`alphadelta unitsPerSecond`

* **unitsPerSecond** — скорость изменения альфы в секунду.

#### Описание и логика работы
Парсер пишет это значение напрямую в скорость изменения прозрачности. Отрицательные значения делают затухание, положительные — постепенное усиление видимости. Если `alphadelta` вообще не задан, движок использует совместимый «старый» режим пересчёта на основе `alpha` и `die`, поэтому явное указание обычно даёт более понятный и предсказуемый результат. Для коротких вспышек и дыма это один из ключевых параметров формы исчезновения.

#### Практические сценарии использования
```
effect demo_alphadelta
{
    texture particles/explosion_flash.tga
    count 1
    die 0.3
    scale 42
    alpha 1
    alphadelta -3.5      // быстрый fade-out
    blend add
    type normal
}
```

### die
`die maxTime [minTime]`

* **maxTime** — один из пределов времени жизни в секундах.
* **minTime** — второй предел времени жизни в секундах.

#### Описание и логика работы
Директива задаёт срок жизни частицы. Важная мелочь из кода: если аргументы переданы в обратном порядке, движок всё равно их переставит и возьмёт корректный диапазон, так что `die 0.8 0.4` и `die 0.4 0.8` эквивалентны по смыслу. Ноль подходит для мгновенных одношаговых визуалов вроде некоторых beam/glow-слоёв, а большие значения — для дыма, снежной взвеси и linger-эффектов. `die` также служит базой по умолчанию для времени действия `rgbdelta`, если `rgbdeltatime` отдельно не указан.

#### Практические сценарии использования
```
effect demo_die
{
    texture particles/smoke_puff.tga
    count 7
    die 0.8 1.6          // срок жизни случайно плавает
    scale 18
    alpha 0.3
    rgb 90 90 90
    type normal
}
```

### assoc
`assoc effectName`

* **effectName** — имя дочернего/связанного эффекта.

#### Описание и логика работы
`assoc` связывает текущий слой с другим эффектом, который должен запускаться одновременно. Это основной способ собрать сложный результат из независимых компонентов: вспышка плюс дым, луч плюс ореол, удар плюс декаль и мелкие искры. Важно, что `assoc` не заменяет текущий слой, а добавляет ещё один вызов, поэтому родитель продолжает отрисовываться сам. В shipped-конфигах таким образом строятся молнии, взрывы и составные hit-эффекты.

#### Практические сценарии использования
```
effect demo_assoc_flash
{
    texture particles/explosion_flash.tga
    count 1
    die 0.2
    scale 56
    alpha 0.9
    blend add
    assoc demo_assoc_smoke   // одновременно запустится второй слой
}
```

### colorindex
`colorindex paletteIndex [range]`

* **paletteIndex** — стартовый индекс в палитре Quake.
* **range** — число соседних палитровых индексов для случайного выбора.

#### Описание и логика работы
Вместо прямого RGB можно использовать индекс классической палитры Quake/Hexen II. Это удобно, когда нужно точно попасть в исторические цвета трассеров, магических вспышек или faithful-эффектов. Если задан `range`, движок добавляет случайное смещение от `0` до `range - 1`. Особый случай из кода: если итоговый индекс превышает `255`, альфа частицы дополнительно уменьшается вдвое — это совместимость с палитровыми эффектами Hexen II.

#### Практические сценарии использования
```
effect demo_colorindex
{
    texture particles/quake
    count 20
    die 0.7
    scale 3
    alpha 0.8
    colorindex 96 8       // берём один из 8 соседних палитровых цветов
    type sparkfan
}
```

### rgb
`rgb r [g b]`

* **r** — красный канал в диапазоне 0–255; если аргумент один, он применяется ко всем каналам.
* **g** — зелёный канал 0–255.
* **b** — синий канал 0–255.

#### Описание и логика работы
Это основная директива прямой окраски частицы. При одном числе получается оттенок серого, при трёх — обычный RGB. В том же парсере есть родственные формы `red`, [`green`](../40-shader-directives-reference/02-shader-stage-directives.md#green), `blue` для поштучной записи каналов и `rgbf` для записи в долях от `0` до `1`. Значения выше `255` в байтовой форме лучше не использовать: с точки зрения читаемости конфига они не дают ясного выигрыша и лишь усложняют предсказание результата.

#### Практические сценарии использования
```
effect demo_rgb
{
    texture particles/spark.tga
    count 16
    die 0.35
    scale 3
    alpha 0.9
    rgb 255 180 64       // тёплая оранжевая искра
    type texturedspark
}
```

### rgbdelta
`rgbdelta rDelta [gDelta bDelta]`

* **rDelta** — изменение красного канала в единицах 0–255 за секунду.
* **gDelta** — изменение зелёного канала в единицах 0–255 за секунду.
* **bDelta** — изменение синего канала в единицах 0–255 за секунду.

#### Описание и логика работы
Директива анимирует цвет частицы во времени. Отрицательные значения тушат канал, положительные — усиливают. Если указан только один аргумент, изменение одинаково для всех каналов; для более точной настройки есть родственные формы `reddelta`, `greendelta`, `bluedelta`, а также `rgbdeltaf` в долях от `0` до `1`. Если `rgbdeltatime` не задан отдельно, движок использует время жизни `die` как продолжительность цветового перехода.

#### Практические сценарии использования
```
effect demo_rgbdelta
{
    texture particles/spark.tga
    count 10
    die 0.6
    scale 4
    alpha 0.8
    rgb 255 160 40
    rgbdelta -255 -120 -40   // искра постепенно остывает и темнеет
    type spark
}
```

### rgbrand
`rgbrand rRange [gRange bRange]`

* **rRange** — независимый случайный разброс красного канала в шкале 0–255.
* **gRange** — независимый разброс зелёного канала.
* **bRange** — независимый разброс синего канала.

#### Описание и логика работы
`rgbrand` добавляет каждому каналу собственное случайное отклонение и делает группу частиц менее однородной. Это особенно хорошо работает на дыме, копоти, пламени и волшебных клубах, где одинаковый цвет у каждой частицы выглядит неестественно. Родственные формы `redrand`, `greenrand`, `bluerand` задают разброс по одному каналу, а `rgbrandf` делает то же в шкале `0..1`. Если диапазоны слишком велики, часть частиц может «уехать» в чужой цветовой тон.

#### Практические сценарии использования
```
effect demo_rgbrand
{
    texture particles/smoke_puff.tga
    count 12
    die 1.8
    scale 22
    alpha 0.35
    rgb 70 70 70
    rgbrand 20 20 20      // серые клубы слегка отличаются друг от друга
    type normal
}
```

### rgbrandsync
`rgbrandsync rSync [gSync bSync]`

* **rSync** — доля общего случайного множителя для красного канала.
* **gSync** — доля общего случайного множителя для зелёного канала.
* **bSync** — доля общего случайного множителя для синего канала.

#### Описание и логика работы
Эта директива управляет тем, насколько случайность цвета должна быть общей между каналами, а не полностью независимой. Значение `1` заставляет каналы брать один и тот же случайный фактор, что даёт ровное осветление/затемнение без смены оттенка. Значение `0` оставляет каждый канал независимым. Промежуточные значения смешивают оба подхода; родственные формы `redrandsync`, `greenrandsync`, `bluerandsync` позволяют настроить каналы раздельно.

#### Практические сценарии использования
```
effect demo_rgbrandsync
{
    texture particles/smoke_puff.tga
    count 12
    die 1.4
    scale 20
    alpha 0.35
    rgb 90 110 140
    rgbrand 30 30 30
    rgbrandsync 1 1 1     // частицы светлеют и темнеют, но не меняют общий тон
    type normal
}
```

### stains
`stains amount`

* **amount** — интенсивность/масштаб пятна при столкновении.

#### Описание и логика работы
Директива включает оставление следа на поверхности при ударе частицы. `0` отключает пятно. По коду видно два режима: положительные значения используют старую формулу пятна, сильно зависящую от текущей альфы частицы; отрицательные переключают альтернативный режим, где размер пятна больше связан с масштабом самой частицы и цвет читается ближе к её RGB. На практике это применяют для крови, подпалин, следов рикошета и грязи; подробности по общей системе ограничиваются ещё пользовательскими cvar из отдельной статьи о stain-следах.

#### Практические сценарии использования
```
effect demo_stains
{
    texture particles/blood_drop.tga
    count 14
    die 0.9
    scale 5
    alpha 0.7
    rgb 160 24 24
    stains -0.5           // при ударе остаётся кровавый след
    type normal
}
```

### blend
`blend mode`

* **mode** — режим смешивания: `add`/`adda`, `addc`, `subtract`, `invmod`/`invmoda`, `invmodc`, `blendcolour`/`blendcolor`, `blendalpha`, `premul_subtract`, `premul_add`, `premul_blend`, `rtsmoke`.

#### Описание и логика работы
`blend` определяет, как пиксели частицы объединяются с уже нарисованной сценой. Аддитивные режимы подходят для огня, энергии, молний и магических вспышек. `subtract` и семейство `invmod*` лучше смотрятся на копоти, крови, теневых следах и грязи. Премультиплицированные варианты обычно дают более чистые края на атласах и мягких спрайтах. Неизвестное значение не вызывает падение: движок пишет предупреждение и откатывается к `blendalpha`.

#### Практические сценарии использования
```
effect demo_blend
{
    texture particles/explosion_flash.tga
    count 1
    die 0.2
    scale 52
    alpha 1
    rgb 255 200 120
    blend premul_add      // яркая вспышка без грязного ореола на краях
    type normal
}
```

### type
`type renderType`

* **renderType** — один из режимов рендера: `normal`, `beam` (токен `vbeam` тоже принимается, но в native particle-скриптах парсится так же, как `beam`), `spark`/`linespark`, `sparkfan`/`trianglefan`, `texturedspark`, `decal`/`cdecal`, `udecal`.

#### Описание и логика работы
Это главная директива выбора способа отрисовки. `normal` — обычный billboard-спрайт. `spark` и `sparkfan` делают линейные/веерные искры, `texturedspark` добавляет им полноценную текстуру, `beam` строит цельный луч вдоль трассы, а `decal`/`cdecal` и `udecal` переключают слой в режим наклейки на поверхность. Если `type` не указан, движок действительно пытается вывести тип из остальных полей: отсутствие текстуры ведёт к `spark` или `sparkfan` в зависимости от `scale`, а уже выбранный искровой тип с текстурой может автоматически стать `texturedspark`. Но для стабильного результата явный `type` почти всегда лучше.

#### Практические сценарии использования
```
effect demo_type
{
    texture particles/spark.tga
    count 8
    die 0.4
    scale 4
    alpha 0.8
    rgb 255 180 64
    type texturedspark    // искра тянется по скорости, но сохраняет форму текстуры
}
```

### clippeddecal
`clippeddecal mask [match]`

* **mask** — маска surface flags, которую надо проверить.
* **match** — точное значение совпадения после применения маски; если не задано, равно `mask`.

#### Описание и логика работы
Директива включает clipped decal и одновременно задаёт фильтр по surface flags карты. Проверка в коде выглядит как `(surfflags & mask) == match`, то есть можно разрешить появление декали только на конкретных типах поверхностей. При использовании `clippeddecal` тип автоматически становится `cdecal`, поэтому отдельный `type decal` уже не обязателен. Это полезно для крови, следов выстрела, слизистых пятен и иных эффектов, которые должны липнуть не ко всему подряд.

#### Практические сценарии использования
```
effect demo_clippeddecal
{
    texture particles/bullet_mark.tga
    clippeddecal 0x20 0x20   // декаль появится только на подходящих поверхностях
    count 1
    die 8
    scale 14
    alpha 0.8
    blend invmodc
}
```

### cliptype
`cliptype effectName`

* **effectName** — имя эффекта, который запускается при столкновении частицы с поверхностью.

#### Описание и логика работы
`cliptype` относится к collision-логике, но используется именно ради визуального результата при ударе: вспышки рикошета, мелкого пылящего облака, брызг и вторичных искр. Само по себе имя ничего не делает, если слой не сталкивается с миром; обычно его сочетают с bounce-параметрами и количеством clip-спавна в статье о поведении. Хороший практический шаблон — длинный следящий снаряд плюс отдельный короткоживущий impact-эффект. Если нужен лишь дочерний визуал без столкновения, вместо `cliptype` лучше использовать `assoc`.

#### Практические сценарии использования
```
effect demo_cliptype
{
    texture particles/spark.tga
    count 6
    die 0.5
    scale 3
    alpha 0.9
    rgb 255 180 64
    cliptype demo_impact_spark   // при ударе сработает отдельный hit-эффект
    type spark
}
```

### rampmode
`rampmode mode`

* **mode** — режим рампы: `none`, `nearest`, `lerp`, `delta`.

#### Описание и логика работы
Рампа — это последовательность ключевых состояний цвета/альфы/размера. `none` отключает её и оставляет обычные `rgb`, `rgbdelta`, `alpha`, `scaledelta`. `nearest` переключает частицу между дискретными шагами, `lerp` плавно интерполирует соседние ключи, `delta` трактует значения рампы как скорости изменения. В legacy-конфигах встречается `absolute`; в коде это просто устаревший синоним `nearest`. Неизвестное имя режима парсер не отвергает, а молча сводит к `delta` с предупреждением.

#### Практические сценарии использования
```
effect demo_rampmode
{
    texture particles/quake
    count 64
    die 0.8
    scale 4
    alpha 0.8
    rampmode nearest      // палитровые ступени будут меняться дискретно
    type normal
}
```

### rampindex
`rampindex paletteIndex [alpha] [scale]`

* **paletteIndex** — индекс цвета в палитре Quake.
* **alpha** — альфа ключевого кадра рампы.
* **scale** — размер ключевого кадра рампы.

#### Описание и логика работы
`rampindex` добавляет один шаг рампы на основе палитрового индекса. Это удобно для faithful-взрывов и классических эффектов, где нужно буквально воспроизвести последовательность цветов из Quake. Если `alpha` не задана, шаг получает альфу `1.0`, а для legacy-индексов выше `255` — `0.5`; если `scale` не задан, берётся текущий `scale` слоя. Для быстрой записи нескольких палитровых шагов подряд существует родственная директива `rampindexlist`.

#### Практические сценарии использования
```
effect demo_rampindex
{
    texture particles/quake
    count 96
    die 0.7
    scale 4
    rampmode nearest
    rampindex 109 1.0 4   // первый палитровый шаг вспышки
    rampindex 6 0.5 3     // поздний, более тусклый шаг
}
```

### ramp
`ramp r [g b [alpha [scale]]]`

* **r** — красный канал ключевого шага; при одном аргументе задаёт серый тон.
* **g** — зелёный канал ключевого шага.
* **b** — синий канал ключевого шага.
* **alpha** — альфа этого шага рампы.
* **scale** — значение масштаба/scale-компоненты этого шага; если аргумент не указан, парсер подставляет текущее `scaledelta`, а не стартовый `scale`.

#### Описание и логика работы
`ramp` строит рампу напрямую в RGB, без палитровых индексов. Если дать один аргумент, получится серый ключ; если три — полный цвет. Если `alpha` не указана, используется текущая `alpha` слоя. Если `scale` не указана, в рампу попадает текущее значение `scaledelta`, а не стартовый размер частицы. Это особенно полезно в `rampmode delta`, где последовательность задаёт не абсолютные цвета, а то, как частица меняется по времени.

#### Практические сценарии использования
```
effect demo_ramp
{
    texture particles/quake
    count 1
    die 1
    scale 3
    alpha 0
    rampmode delta
    ramp -255 -255 0 -2.5 0   // начало: быстрый уход жёлто-красного свечения
    ramp 0 0 -128 0.65 10     // позже: холодный синий хвост и рост размера
    type beam
}
```

### lightradius
`lightradius minRadius [maxRadius]`

* **minRadius** — базовый радиус динамического света в игровых единицах.
* **maxRadius** — верхняя граница вариативного радиуса.

#### Описание и логика работы
Эта директива заставляет слой порождать временный динамический источник света. Если указан один аргумент, радиус постоянен; если два — движок выбирает значение между ними, используя внутренний flicker/random путь. Такой свет обычно сопровождает взрывы, энергетические разряды, сильные попадания и магические снаряды. Важно помнить, что это уже не просто частица, а дополнительная подсистема освещения, поэтому большие радиусы и частые срабатывания стоят дороже по производительности.

#### Практические сценарии использования
```
effect demo_lightradius
{
    texture particles/explosion_flash.tga
    count 1
    die 0.2
    scale 56
    alpha 1
    blend add
    lightradius 240 320    // каждая вспышка освещает сцену чуть по-разному
    type normal
}
```

### lightradiusfade
`lightradiusfade unitsPerSecond`

* **unitsPerSecond** — скорость уменьшения радиуса света в единицах в секунду.

#### Описание и логика работы
Параметр задаёт, как быстро сжимается динамический свет после появления. Если `lighttime` отдельно не указан, в `FinishParticleType` движок автоматически вычисляет время жизни света как `lightradius / lightradiusfade`, что полезно для коротких вспышек. Небольшое значение даёт долгий мягкий спад, большое — резкий «ударный» импульс. На практике эту директиву почти всегда настраивают вместе с `lightradius`.

#### Практические сценарии использования
```
effect demo_lightradiusfade
{
    texture particles/explosion_flash.tga
    count 1
    die 0.2
    scale 56
    alpha 1
    blend add
    lightradius 300
    lightradiusfade 900    // свет быстро схлопывается после вспышки
    type normal
}
```

### lightrgb
`lightrgb r g b`

* **r** — красный вклад света.
* **g** — зелёный вклад света.
* **b** — синий вклад света.

#### Описание и логика работы
`lightrgb` окрашивает именно динамический свет, а не сам спрайт частицы. Поэтому часто полезно задавать этот цвет отдельно: например, белая электрическая текстура может давать синеватое освещение, а оранжевая вспышка — более жёлто-белый свет. В движке значения трактуются как float-компоненты и могут быть больше `1`, если нужен пересвеченный импульс. Для анимации цвета света существует дополнительная директива `lightrgbfade`.

#### Практические сценарии использования
```
effect demo_lightrgb
{
    texture particles/explosion_flash.tga
    count 1
    die 0.25
    scale 60
    alpha 1
    blend add
    lightradius 280
    lightrgb 1.6 1.1 0.5   // тёплая жёлто-оранжевая вспышка света
    type normal
}
```

### lightcorona
`lightcorona intensity scale`

* **intensity** — сила короны/блика.
* **scale** — масштаб короны.

#### Описание и логика работы
Помимо обычного динамического света, слой может добавить видимую «корону» — яркий экранный ореол вокруг источника. Это полезно для энергетических шаров, телепортов, ламповых вспышек и плазменных зарядов. Слишком высокая интенсивность быстро начинает выглядеть как HDR-перебор и может скрывать основную текстуру эффекта, поэтому корону обычно держат умеренной и короткоживущей.

#### Практические сценарии использования
```
effect demo_lightcorona
{
    texture particles/plasma_ball.tga
    count 1
    die 0.4
    scale 24
    alpha 0.9
    blend add
    lightradius 180
    lightcorona 0.8 1.5    // у шара появляется видимый ореол
    type normal
}
```

### lighttime
`lighttime seconds`

* **seconds** — максимальное время жизни динамического света в секундах.

#### Описание и логика работы
`lighttime` ограничивает срок существования временного источника света. Если свет должен жить ровно столько же, сколько и вспышка, значения `die` и `lighttime` часто делают близкими. Если `lightradiusfade` уже задан, `lighttime` можно опустить и доверить расчёт движку. Для более тонкой настройки той же подсистемы существуют отдельные визуальные спутники: `lightshadows`, `lightcubemap`, [`lightstyle`](../37-quakec-builtins-reference/08-csqc-rendering-builtins.md#lightstyle) и `lightscales`.

#### Практические сценарии использования
```
effect demo_lighttime
{
    texture particles/explosion_flash.tga
    count 1
    die 0.2
    scale 54
    alpha 1
    blend add
    lightradius 260
    lighttime 0.3          // свет живёт ещё чуть дольше самой вспышки
    type normal
}
```

### spawnstain
`spawnstain radius r g b`

* **radius** — радиус пятна в игровых единицах.
* **r** — красный канал цвета пятна.
* **g** — зелёный канал цвета пятна.
* **b** — синий канал цвета пятна.

#### Описание и логика работы
В отличие от `stains`, эта директива создаёт stain сразу в точке появления эффекта, не дожидаясь удара частицы о поверхность. Цвет задаётся явно и не зависит от текущего `rgb` самой частицы. Это удобно для мгновенных отпечатков крови, копоти от взрыва, следов телепорта или магических сигилов, которые должны возникать синхронно с основным визуалом. Пятно создаётся один раз на спавне слоя, а не на каждом кадре его жизни.

#### Практические сценарии использования
```
effect demo_spawnstain
{
    texture particles/blood_burst.tga
    count 1
    die 0.2
    scale 20
    alpha 0.8
    rgb 160 24 24
    spawnstain 28 160 24 24   // пятно появляется сразу в точке попадания
    type normal
}
```
