# Совместимость с протоколами классических игр

## Что это даёт геймдизайнеру

Движок умеет разговаривать по сети сразу на нескольких «языках» — протоколах классических игр: одиночный/кооперативный Quake (NetQuake), сетевой QuakeWorld, а также (в зависимости от режима сборки) протоколы Quake II и Quake III. Это значит, что сервер на этом движке способен принимать подключения от игроков с самыми разными клиентами, а клиент — заходить на самые разные классические сервера, включая серверы, работающие на оригинальных играх, а не только на этом движке. Геймдизайнеру не нужно придумывать собственный сетевой протокол с нуля — можно опираться на уже готовую, проверенную десятилетиями базу.

---

## Интерфейс настройки

Выбор протокола, как правило, происходит автоматически в момент подключения — клиент и сервер по очереди предлагают друг другу тот протокол, который оба поддерживают, начиная с самого «богатого» и заканчивая самым базовым. Из полезных серверных переменных:

- **[`sv_protocol`](../38-cvars-reference/04-network-server-cvars.md#sv_protocol)** — жёстко ограничивает список протоколов, которые разрешено использовать при подключении (например, значения `fte1`, `fte2`, `csqc`); клиенты, не поддерживающие ни один из указанных, получат отказ в подключении.
- **[`sv_protocol_nq`](../38-cvars-reference/04-network-server-cvars.md#sv_protocol_nq)** — задаёт протокол по умолчанию для «немых» NetQuake-клиентов, которые сами не сообщают о своих возможностях (0 — автоопределение, 15 — классический Quake, 666 — FitzQuake, 999 — RMQ).
- **[`sv_bigcoords`](../38-cvars-reference/04-network-server-cvars.md#sv_bigcoords)** — включает более точную передачу координат и углов (числа с плавающей точкой вместо урезанных 16-битных значений), что попутно заставляет клиентов переходить на более продвинутые версии протокола (для QuakeWorld это обязательное расширение, для DarkPlaces — протокол DPP7, для классического Quake — протокол RMQ). Полезно даже на небольших картах ради более плавного прицеливания. По умолчанию включена (`1`).
- **[`sv_listen_qw`](../38-cvars-reference/04-network-server-cvars.md#sv_listen_qw)** (по умолчанию `1`) — разрешает ли сервер вообще принимать подключения от обычных клиентов по протоколу QuakeWorld.
- **[`sv_listen_nq`](../38-cvars-reference/04-network-server-cvars.md#sv_listen_nq)** (по умолчанию `0`, то есть выключено) — разрешает ли сервер принимать подключения от клиентов классического (net)Quake: значение `0` полностью запрещает такие подключения, `1` разрешает их напрямую, а `2` включает подключение NetQuake-клиентов через эмуляцию проверочного «челленджа» (так же безопасно, как QuakeWorld/Quake II, хотя формально не полностью соответствует классическому протоколу NetQuake). Исторические оговорки по безопасности и шифрованию для таких режимов лучше смотреть отдельно на странице [«Ненадёжные и legacy-сетевые возможности»](../43-legacy-unused-features/unreliable-networking-features.md).

---

## Примеры

- Сервер классического режима специально ограничивает [`sv_protocol_nq`](../38-cvars-reference/04-network-server-cvars.md#sv_protocol_nq) значением `15`, чтобы гарантированно работать со старыми клиентами без каких-либо современных расширений.
- Сервер турнирного мода включает [`sv_bigcoords 1`](../38-cvars-reference/04-network-server-cvars.md#sv_bigcoords), чтобы избавиться от «дрожания» позиций игроков на больших открытых картах.
