## Что это даёт геймдизайнеру

Помимо консоли и конфигурационных файлов, движку можно передать команды и переменные прямо в момент запуска — через параметры командной строки (то, что указывается в ярлыке игры или при запуске из терминала). Это удобно для автоматизации: например, чтобы сразу запустить конкретный мод, карту и режим игры одним щелчком по ярлыку, без захода в меню и ручной настройки.

---

## Интерфейс настройки

Параметры добавляются после имени исполняемого файла движка. Есть два вида «управляющих» параметров:

- **`+command`** — выполнить консольную команду или установить переменную сразу при запуске;
- **`-param`** — специальный параметр самого движка (выбор игровых папок, режима окна и т.д.), не являющийся консольной командой.

```
fteqw +set sv_port 26000 +map dm4
```

Справочник по аналогичным параметрам компилятора — в статье [«Компилятор FTEQCC»](../16-quakec-scripting/fteqcc-compiler.md#параметры-командной-строки-отдельного-компилятора).

### Игровые данные и пути

| Параметр | Назначение |
|---|---|
| `-basedir <path>` | указать корневую папку, где искать все игровые данные |
| `-basegame <folder>` | указать папку с данными основной игры |
| `-game <folder>` | указать папку мода, подключаемого поверх основной игры |
| `-basepack <file>` | подключить конкретный `.pak`/архив как базовый набор данных вместо папки |
| `-manifest <file.fmf>` | загрузить [файл-манифест мода/игры](../23-mods-manifests/mod-manifest-file.md) вместо ручного набора параметров |
| `-homedir <path>` / `-usehome` | задать собственную «домашнюю» папку для конфигов и сохранений вместо стандартной папки пользователя ОС |
| `-nohome` | не использовать домашнюю папку пользователя для конфигов/сохранений, писать рядом с движком |

Также существуют «игровые» флаги-подсказки, которые помогают движку точнее определить нужную игру в «людном» общем каталоге данных: `-quake`, `-quake2`, `-quake3`, `-hexen2`, `-halflife`, `-halflife2`.

### Видео и окно

| Параметр | Назначение |
|---|---|
| `-window` | запустить в оконном, а не полноэкранном режиме |
| `-width <N>` / `-height <N>` | задать стартовое разрешение экрана в пикселях (указание только `-width` подбирает высоту автоматически по стандартному соотношению сторон) |
| `-conwidth <N>` / `-conheight <N>` | задать отдельное разрешение для консоли и 2D-интерфейса, независимо от разрешения самого 3D-рендера |
| `-bpp <N>` | задать глубину цвета экрана в битах — актуально только для [программного и старых аппаратных рендереров](../43-legacy-unused-features/software-and-d3d9-renderer.md), современные видеорежимы это игнорируют |
| `-current` | использовать текущее разрешение экрана рабочего стола вместо значения по умолчанию |

### Звук

| Параметр | Назначение |
|---|---|
| `-[nosound](../38-cvars-reference/03-audio-cvars.md#nosound)` | полностью отключить звуковую подсистему при запуске |
| `-particles <N>` | задать максимальное число одновременных классических частиц — актуально для [программного рендерера/классической системы частиц](../43-legacy-unused-features/software-and-d3d9-renderer.md) |

### Сеть и сервер

| Параметр | Назначение |
|---|---|
| `-dedicated` | запустить движок только в роли сервера, без графики (для постоянно работающих серверов) |
| `-svport <N>` (или `-port <N>`) | задать номер сетевого порта, который будет слушать сервер |
| `-clport <N>` | задать номер локального порта, с которого клиент устанавливает исходящие соединения |
| `-ip <address>` | привязать сеть к конкретному сетевому адаптеру/IP вместо всех интерфейсов |
| `-clusterslave` / `-clusterhost` | роли для распределённого сервера-кластера (один процесс раздаёт карты между несколькими рабочими процессами) |
| `-notls` | отключить поддержку зашифрованных (TLS) соединений сервера |

### Файлы и безопасность

| Параметр | Назначение |
|---|---|
| `-readonly` | запретить движку любую запись на диск (конфиги, демозаписи, кэш) — полезно для запуска с носителя, доступного только для чтения |
| `-unsafefopen` | отключить файловую песочницу для [`fopen`](../37-quakec-builtins-reference/06-files-database-builtins.md#fopen), разрешая читать/писать за пределами папки мода (см. [«Чтение и запись файлов из игровой логики»](../18-data-access-from-scripts/file-read-write-from-scripts.md)) — использовать только на полностью доверенных серверах |
| `-allowfileuri` | разрешить схему `file:///` в файловых операциях игровой логики для доступа к произвольным путям диска |
| `-cheats` | разрешить чит-команды ([`noclip`](../44-cli-commands-reference/02-client-ui-commands.md#noclip), `god`, [`give`](../44-cli-commands-reference/02-client-ui-commands.md#give) и т.п.) даже вне одиночной игры — обычно требуется явно для тестовых/приватных серверов |
| `-chroot <path>` (только Linux) | ограничить процесс движка указанным корнем файловой системы после запуска, для дополнительной изоляции выделенного сервера |
| `-uid <N>` (только Linux) | сбросить права процесса до указанного непривилегированного пользователя после привязки к сетевому порту |

### Отладка, логи и обновления

| Параметр | Назначение |
|---|---|
| `-condebug` | вести подробный лог консоли в текстовый файл `qconsole.log` рядом с игрой, помимо вывода на экран |
| `-qcdebug` | включить поддержку подключения внешнего отладчика QuakeC (см. [«Отладка и „горячая“ пересборка логики»](../16-quakec-scripting/fteqcc-compiler.md#отладка-и-горячая-пересборка-логики)) |
| `-nostdin` / `-nostdout` | не читать команды из стандартного ввода терминала / не дублировать консоль в стандартный вывод — полезно при запуске выделенного сервера как управляемой службы |
| `-nocolor` (`-nocolour`) | не использовать цветной вывод в терминале (например, при перенаправлении лога в файл) |
| `-noplugins` | не загружать при старте ни встроенные, ни внешние [плагины движка](../README.md#плагины-и-физические-движки) |
| `-nomouse` | отключить обработку мыши движком (например, при отладке через удалённый рабочий стол) |
| `-safe` / `-noenumerate` | запустить в «безопасном» режиме с упрощённым перебором звуковых/видеоустройств — помогает обойти проблемы с нестабильными драйверами при первом запуске |
| `-zone <KB>` | увеличить размер стартового блока памяти движка (`Zone`) для очень требовательных модов — на современных системах почти не требуется, память выделяется динамически |
| `-noupdate` / `-noautoupdate` | отключить проверку и автоматическую загрузку обновлений самого движка при старте |
| `-lang <code>` | принудительно задать язык интерфейса вместо автоопределения по системной локали |

### Устаревшие и редко используемые параметры

Эти параметры признаются движком, но относятся либо к давно устаревшим подсистемам (см. [«Программный и D3D9-рендерер»](../43-legacy-unused-features/software-and-d3d9-renderer.md)), либо к узкоспециализированным сценариям установки под Windows:

| Параметр | Назначение |
|---|---|
| `-dinput` (только Windows, устаревшее) | принудительно использовать DirectInput вместо более новых способов опроса устройств ввода |
| `-register` / `-unregister` (только Windows) | зарегистрировать/удалить ассоциации файлов и записи в реестре при установке движка |
| `-makeinstaller` (только Windows, служебное) | использовалось внутренними сборочными скриптами для генерации инсталлятора, не предназначено для конечных пользователей |
| `-watchdog` (только Windows) | запустить вспомогательный процесс-наблюдатель, перезапускающий движок при аварийном завершении (в основном для выделенных серверов) |

## Примеры

- Ярлык для запуска сервера конкретного мода сразу на нужной карте с ограничением на 8 игроков и автоматическим анонсом в интернете:
  ```
  fteqw +set sv_public 2 +set sv_playerslots 8 +map dm4
  ```
- Запуск определённого мода поверх базовой игры:
  ```
  fteqw -game fortress
  ```
- Запуск полностью самостоятельной игры, никак не связанной с данными Quake:
  ```
  fteqw -basegame openquartz
  ```
