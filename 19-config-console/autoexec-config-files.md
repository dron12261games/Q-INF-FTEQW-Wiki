# Автозагружаемые конфигурационные файлы

> [⬅ Вернуться к оглавлению вики](../README.md)

> Раздел: [Конфигурационные файлы и консоль](./README.md)

## Что это даёт геймдизайнеру

Конфигурационный файл (`.cfg`) — это обычный текстовый файл, построчно содержащий консольные команды движка. Вместо того чтобы каждый раз при запуске игры вручную вводить в консоли одни и те же настройки, их можно один раз записать в файл и просто «выполнить» этот файл — сразу все команды подряд, в указанном порядке. Это даёт возможность:

- задать настройки мода/игры **по умолчанию**, которые сразу применяются всем новым игрокам;
- сохранить **личные предпочтения игрока** (управление, громкость, графика) между запусками игры;
- собрать **пресеты** настроек (например, «облегчённая графика», «максимальное качество») в виде отдельных файлов, между которыми игрок может переключаться одной командой.

## Интерфейс настройки

Конфиг — это просто текстовый файл, где каждая строка выглядит как команда, введённая в консоль вручную:

```
// это комментарий
seta sensitivity "5"
seta vid_width "1920"
bind "w" "+forward"
exec "другой_конфиг.cfg"
```

Выполнить файл можно двумя способами:
- вручную — командой `exec имяфайла.cfg` в консоли;
- автоматически — если файл называется **`autoexec.cfg`** и лежит в активной игровой папке (`gamedir`/`basegame`), движок выполнит его сам при каждом запуске, ещё до входа в меню.

### Порядок автоматической загрузки при старте игры

При запуске движок сам, без участия пользователя, выполняет строго определённую последовательность конфигов, причём для разных семейств игр (Quake / Quake II и III / Hexen II) порядок и имена файлов немного различаются:

1. Сначала движок сбрасывает все переменные к «заводским» значениям самого движка (`cvar_purgedefaults`, `cvarreset *`) — это гарантирует, что повторный запуск игры не унаследует случайно застрявшие значения от предыдущей сессии до применения конфигов.
2. Затем ищется классический загрузочный сценарий: **`quake.rc`** (для игр на движке Quake), либо **`hexen.rc`** (для Hexen II) — если такой файл найден, именно он определяет дальнейшую последовательность `exec`. Если ни один из них не найден (типично для модов в стиле Quake II/III), вместо них движок сам выполняет **`default.cfg`**, а затем (если найден) **`q3config.cfg`**.
3. Файл **`default.cfg`** предназначен для настроек «по умолчанию», которые задаёт сам мод (сложность, лимиты, стартовое снаряжение и т.п.) — он поставляется вместе с игрой/модом и не должен редактироваться игроком, так как переиздание мода перезапишет его.
4. Файл **`config.cfg`** (или, для модов на технологии id Tech 3, **`q3config.cfg`** — конкретное имя определяется файлом манифеста мода, см. [«Файл манифеста мода»](../23-mods-manifests/mod-manifest-file.md)) — это файл, куда сам движок **автоматически сохраняет** текущие настройки игрока (графика, звук, привязки клавиш) при выходе из игры или по команде `cfg_save`. Его не нужно писать руками — движок создаёт и обновляет его сам.
5. Последним, уже после всех вышеперечисленных, выполняется **`autoexec.cfg`**, если он существует — это единственный файл из всей цепочки, который движок никогда не перезаписывает сам, поэтому именно в него принято вручную дописывать личные постоянные настройки и алиасы, которые должны сохраняться, даже если файл `config.cfg` будет перезаписан или сброшен.

Само сохранение текущих настроек в файл регулируется набором переменных:

- `cfg_save_all` — если 1, при сохранении конфига записываются вообще все переменные; если 0 — только те, что помечены как «архивные» (`seta`); если оставить пустым — движок сам решает, сохранять всё или нет, в зависимости от того, как было вызвано сохранение (например, через пункты меню выхода из игры);
- `cfg_save_auto` — если 1, конфигурация сохраняется автоматически при выходе, без всплывающих вопросов;
- `cfg_save_infos` — сохранять ли информацию об игроке (`userinfo`/`serverinfo`, см. [«Ник, скин и командная принадлежность игрока»](../20-player-userinfo/player-userinfo-name-skin-team.md));
- `cfg_save_aliases` — сохранять ли пользовательские алиасы (учтите: алиасы, присланные сервером, никогда не сохраняются и забываются при смене карты);
- `cfg_save_binds` — сохранять ли привязки клавиш;
- `cfg_save_buttons` — сохранять ли текущее состояние удерживаемых кнопок (например, зажатый `+mlook`).

Команда `cfg_save` в любой момент принудительно сохраняет текущую конфигурацию на диск.

## Примеры

- Мод поставляется с файлом `default.cfg`, задающим стартовые настройки геймплея (сложность, лимит фрагов и т.п.), и отдельным `autoexec.cfg`, куда игрок может дописывать собственные персональные настройки, не боясь, что они будут перезаписаны при обновлении мода.
- Игрок хранит два конфига — `cfg_lowend.cfg` и `cfg_highend.cfg` — с разными настройками графики, и переключается между ними командой `exec` в зависимости от того, за каким компьютером он сейчас играет.
