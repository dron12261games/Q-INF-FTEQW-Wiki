# Проверка целостности и «чистые» серверные архивы

## Что это даёт геймдизайнеру

В сетевой игре недобросовестный игрок теоретически может подменить у себя локально файлы контента — например, сделать текстуры стен полупрозрачными, чтобы видеть противников сквозь них, или увеличить размер моделей игроков, чтобы было легче попадать. Механизм «чистых» (pure) архивов позволяет серверу заявить: «играть можно только с теми файлами ресурсов, которые есть у меня» — и таким образом закрыть эту лазейку для читерства.

Дополнительно эта же система решает более безобидную задачу: гарантирует, что **все игроки на сервере буквально видят одну и ту же игру** — одинаковые модели, текстуры, звуки — что важно для честной соревновательной игры и для предсказуемости происходящего на экране.

---

## Базовая логика проверки

Технически проверка строится на контрольных суммах (CRC) содержимого архивов: сервер заранее вычисляет контрольную сумму каждого подключённого у себя архива ресурсов (`.pak`, `.pk3`, `.dz` и другие поддерживаемые типы — см. таблицу форматов в разделе [«Архивы и упаковка»](../README.md#архивы-и-упаковка-игрового-контента)) и по запросу клиента отправляет ему этот список. Важная деталь, отличающая эту проверку от банального «побайтового» сравнения файлов: контрольная сумма считается только для источников, у которых предусмотрен соответствующий механизм подсчёта — это все стандартные типы архивов, но не «голые» файлы, физически лежащие прямо в базовой папке движка на диске. Это осознанное архитектурное решение: оно не позволяет считать «чистым» источником произвольную несжатую папку, гарантируя, что при строгом режиме сверяются именно официально упакованные и распространяемые версии контента, а не что попало на диске игрока.

## Интерфейс настройки

Управляют этим поведением две связанные переменные движка:

- **[`sv_pure`](../38-cvars-reference/04-network-server-cvars.md#sv_pure)** (настраивается на сервере; переменная относится к категории [`serverinfo`](../44-cli-commands-reference/02-client-ui-commands.md#serverinfo) — то есть её текущее значение автоматически публикуется всем подключённым и потенциальным клиентам без дополнительных действий):
  - `0` — обычные правила без ограничений (файлы клиента не проверяются), значение по умолчанию;
  - `1` — клиентам рекомендуется отдавать приоритет файлам из архивов, присутствующих на сервере;
  - `2` — клиентам разрешается использовать **только** файлы из архивов, присутствующих на сервере (самый строгий режим; надёжно работает только на полностью самостоятельных играх/тотальных конверсиях, а не поверх оригинальных данных Quake, из-за исторических различий в контрольных суммах между версиями игры 1.01 и 1.06 — движок сам иронично документирует эту переменную как «самую злую переменную на свете», подчёркивая, как много клиентских реализаций попросту игнорируют строгий режим).
- **[`cl_pure`](../38-cvars-reference/07-system-misc-cvars.md#cl_pure)** (настраивается на стороне клиента, добровольное самоограничение) — работает по тем же значениям (0/1/2) и по тому же смыслу, что и [`sv_pure`](../38-cvars-reference/04-network-server-cvars.md#sv_pure), но применяется даже при игре в одиночку или на сервере без собственных ограничений; если сервер и клиент указали разные значения, движок клиента автоматически применяет более строгое (большее числовое) из двух значений.

Практический совет для авторов серверов: значение [`sv_pure 2`](../38-cvars-reference/04-network-server-cvars.md#sv_pure) стоит включать только на сервере с полностью собственным, самодостаточным набором контента (весь нужный контент упакован и присутствует на сервере), иначе игроки с легитимными, но отсутствующими на сервере дополнительными файлами (например, косметическими скинами) могут столкнуться с неожиданными ограничениями.

## Практический пример 1: строгий турнирный сервер

Администратор турнирного сервера кладёт в конфигурацию запуска строку [`sv_pure "2"`](../38-cvars-reference/04-network-server-cvars.md#sv_pure). При подключении каждого игрока сервер сверяет присланный клиентом список контрольных сумм архивов с собственным — если у клиента обнаруживается архив с текстурами, отличающийся контрольной суммой от эталонного (например, из-за изменённой текстуры стены), клиенту не позволяется использовать файлы из такого архива, и он обязан взять соответствующий ресурс из архива сервера (или будет отключён, если сама игра не может продолжаться без него).

---

## Практический пример 2: дружеский сервер с косметическими модами

Обычный «дружеский» сервер для игры с друзьями оставляет [`sv_pure "0"`](../38-cvars-reference/04-network-server-cvars.md#sv_pure), позволяя каждому играть со своими любимыми косметическими скинами и текстурами без ограничений — сервер вообще не запрашивает и не проверяет контрольные суммы клиентских архивов.

---

## Практический пример 3: клиент с собственной защитой от читерских серверов

Осторожный игрок, подключающийся к незнакомым серверам, самостоятельно выставляет [`cl_pure "1"`](../38-cvars-reference/07-system-misc-cvars.md#cl_pure) в своём личном конфиге — это заставляет его собственный клиент отдавать предпочтение файлам сервера даже тогда, когда сам сервер не настаивает на строгой проверке, снижая риск того, что вредоносный сервер попытается подсунуть клиенту вредоносный файл под видом обычного игрового ресурса.

## Инженерный справочник

| Переменная | Тип данных | Допустимые значения | Где применяется | Значение по умолчанию |
| :--- | :--- | :--- | :--- | :--- |
| [`sv_pure`](../38-cvars-reference/04-network-server-cvars.md#sv_pure) | целое число (категория [`serverinfo`](../44-cli-commands-reference/02-client-ui-commands.md#serverinfo), видна всем клиентам) | `0` — без ограничений; `1` — рекомендательный режим; `2` — строгий режим (только файлы сервера) | сервер | `0` (пусто, что эквивалентно 0) |
| [`cl_pure`](../38-cvars-reference/07-system-misc-cvars.md#cl_pure) | целое число | `0` — без ограничений; `1` — рекомендательный режим; `2` — строгий режим | клиент | `0` |
