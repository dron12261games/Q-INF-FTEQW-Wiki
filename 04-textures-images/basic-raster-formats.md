## Что это даёт геймдизайнеру

Движок принимает текстуры в широком наборе привычных, общеупотребимых форматов изображений, поэтому художникам не нужно осваивать какой-то особый инструментарий или конвертировать готовые изображения в специальный формат — можно сохранять текстуру прямо из любого графического редактора и класть файл в игровую папку.

---

## Интерфейс настройки

Текстура кладётся в подпапку `textures/` (или иную, ожидаемую конкретной картой/материалом) с одним из поддерживаемых расширений:

- **`.tga`** (Targa) — классический формат, исторически основной для контента Quake, поддерживает прозрачность, быстро загружается;
- **`.png`** — современный формат без потерь, с прозрачностью, обычно предпочтительный выбор для нового контента (загружается несколько медленнее TGA);
- **`.jpg`** — формат со сжатием с потерями, подходит для больших фоновых текстур, где не критична пиксельная точность;
- **`.pcx`** — исходный формат текстур Quake II, поддерживается в первую очередь для совместимости со старым контентом;
- **`.bmp`** — базовый формат Windows, загрузчик его поддерживает, но по умолчанию не входит в автоматический список расширений для перебора (то есть указывать его нужно явно, полным именем файла с расширением);
- **`.dds`** и **`.ktx`** — GPU-сжатые форматы (см. [«GPU-сжатые форматы»](./gpu-compressed-formats.md)), которые при автоматическом переборе расширений проверяются в первую очередь, ещё до TGA/PNG/JPG — если для текстуры заранее подготовлен сжатый вариант, он будет использован, экономя видеопамять.

Движок сам находит подходящий файл по имени, перебирая известные расширения в определённом внутреннем порядке приоритета (по умолчанию: сначала `.dds`, затем `.ktx`, затем `.tga`, затем `.png`, затем `.jpg`, и в последнюю очередь `.pcx`) — если в описании материала или у карты указано просто имя текстуры без расширения, достаточно любого из перечисленных форматов. Порядок предпочтения форматов при поиске можно донастроить переменной [`r_imageextensions`](../38-cvars-reference/01-video-rendering-cvars.md#r_imageextensions), если художник хочет, чтобы движок в первую очередь проверял конкретный формат (например, чтобы приоритетно искать несжатый PNG раньше сжатого DDS во время отладки материалов).

## Инженерный справочник

| Элемент | Тип данных | Описание | Значение по умолчанию |
| :--- | :--- | :--- | :--- |
| [`r_imageextensions`](../38-cvars-reference/01-video-rendering-cvars.md#r_imageextensions) | строка cvar, список расширений через пробел | Переопределяет порядок и набор расширений, автоматически перебираемых движком при поиске текстуры по имени без расширения | пусто (используется встроенный порядок: `dds ktx tga png jpg pcx`) |
| [`r_dodgymiptex`](../38-cvars-reference/01-video-rendering-cvars.md#r_dodgymiptex) | булево (0/1) | При включении принудительно пересчитывает мип-уровни текстуры, отбрасывая встроенные в файл готовые мипы (поведение, повторяющее историческое поведение GLQuake) — может решить проблемы с полностью яркими (fullbright) текстурами на некоторых старых картах, ценой чуть менее качественной детализации на расстоянии | `1` |
| [`r_keepimages`](../38-cvars-reference/01-video-rendering-cvars.md#r_keepimages) | булево (0/1) | Управляет тем, остаются ли неиспользуемые текстуры в памяти после смены карты: `0` — лишние текстуры выгружаются при каждой смене уровня, `1` — сохраняются в памяти до полной перезагрузки видеосистемы ([`vid_reload`](../44-cli-commands-reference/02-client-ui-commands.md#vid_reload)), что ускоряет повторную загрузку той же карты ценой расхода оперативной/видеопамяти | `0` |
| [`r_dodgypcxfiles`](../38-cvars-reference/01-video-rendering-cvars.md#r_dodgypcxfiles) | булево (0/1) | При включении игнорирует палитру, встроенную в PCX-файл, ради совместимости с текстурами формата Quake II | `0` |
| [`r_ignoremapprefixes`](../38-cvars-reference/01-video-rendering-cvars.md#r_ignoremapprefixes) | булево (0/1) | Управляет тем, считаются ли текстуры, загруженные из специфичных для конкретной карты путей, отдельными от одноимённых текстур из других путей: `0` — не путать одинаковые по имени текстуры разных карт, `1` — разрешить одной и той же текстуре грузиться повторно из разных мест | `0` |

## Примеры

- Художник экспортирует новую текстуру стены прямо в PNG из любого графического редактора и кладёт файл в `textures/` — движок подхватывает её без какой-либо конвертации.
- Текстуры пользовательской карты частично представлены в старом формате TGA (унаследованном от исходного контента), частично — в PNG (для нового контента), и обе версии одинаково успешно загружаются.
- Для финальной сборки мода художник заранее готовит сжатые `.dds`-версии самых крупных текстур окружения — движок находит их раньше исходных `.tga`/`.png` благодаря встроенному порядку приоритета расширений, экономя видеопамять на конечных машинах игроков.
