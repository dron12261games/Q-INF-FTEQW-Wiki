# Чтение и запись файлов из игровой логики

> [⬅ Вернуться к оглавлению вики](../README.md)

> Раздел: [Работа с данными из игровой логики](./README.md)

## Что это даёт геймдизайнеру

Игровая логика может напрямую читать и создавать произвольные текстовые (а при необходимости и двоичные) файлы прямо на диске — например, вести собственный лог событий, сохранять простую конфигурацию мода в понятном текстовом виде, экспортировать статистику матча по его окончании или даже обмениваться данными по сети напрямую. Это более простой, «ручной» способ хранения данных по сравнению с полноценной базой данных (см. [«Встроенная база данных (SQLite/MySQL)»](./embedded-database-sql.md)) — подходит для небольших объёмов данных, которые удобно посмотреть и отредактировать в обычном текстовом редакторе.

## Интерфейс настройки

Игровая логика получает набор команд, работающих так же, как классические функции работы с файлами в большинстве языков программирования, но выраженных предельно просто.

### Основные функции

- **`fopen(filename, mode, необязательно minsize)`** — открывает файл и возвращает числовой дескриптор (отрицательное число означает ошибку открытия). Режим (`mode`) задаётся одной из констант: **`FILE_READ`** — построчное чтение ([`fgets`](../37-quakec-builtins-reference/06-files-database-builtins.md#fgets) читает по одной строке за раз), **`FILE_READNL`** — чтение без учёта переносов строк (весь файл целиком одной строкой), **`FILE_WRITE`** — запись ([`fputs`](../37-quakec-builtins-reference/06-files-database-builtins.md#fputs) пишет в файл), **`FILE_APPEND`** — запись в конец существующего файла, не стирая уже накопленное содержимое, **`FILE_STREAM`** — открытие сетевого потока по адресу `tcp://`/`tls://` вместо обычного файла.
- **`fgets(fhandle)`** — читает из файла одну строку текста (без символа переноса строки в конце). Если достигнут конец файла, возвращается пустая (null) строка, что отличимо от обычной пустой строки на пустой строке файла.
- **`fputs(fhandle, s, ...)`** — записывает в файл одну или несколько строк текста подряд. Автор мода должен сам добавлять символ переноса строки в конце, если хочет, чтобы `fgets` впоследствии читал построчно.
- **`fclose(fhandle)`** — закрывает файл; необходимо вызывать для каждого успешно открытого файла, иначе движок предупредит о незакрытых файлах.
- **`fremove(fname)`** — удаляет указанный файл, возвращает 0 при успехе.
- **`whichpack(filename, необязательные флаги)`** — узнаёт, в каком именно архиве (pak-файле или ином контейнере, см. [«Форматы игровых архивов»](../01-archives-packaging/README.md)) находится указанный игровой файл — полезно для диагностики или автоматической загрузки нужных архивов на клиентах.

### Правила безопасности («песочница»)

Все файловые операции по умолчанию выполняются в пределах папки мода — логика не может обращаться к произвольным местам на диске пользователя, что предотвращает случайное или намеренное повреждение чужих файлов. Для максимальной надёжности имена файлов рекомендуется всегда указывать с префиксом **`data/`** — иначе запись может быть перенаправлена в другое место, а чтение — не сработать. Строгую песочницу можно отключить параметром командной строки движка **`-unsafefopen`** (не рекомендуется для публичных серверов, принимающих сторонние моды), а доступ к произвольным путям диска через схему **`file:///`** дополнительно требует ещё одного параметра запуска — **`-allowfileuri`** (это отдельный, ещё более редкий случай, обычно достаточно вместо этого создать символическую ссылку внутри папки мода). Открытые файловые дескрипторы не сохраняются в файл сохранения игры — их не стоит держать открытыми между кадрами дольше необходимого.

### Сетевой доступ через тот же интерфейс

Тем же самым набором функций можно работать и с сетевыми соединениями: если в качестве имени файла указать адрес со схемой **`tcp://`** или **`tls://`** в сочетании с режимом **`FILE_STREAM`**, движок откроет не файл, а прямое сетевое соединение. Читать такой поток можно и `fgets`, и `fread`, но для надёжного различения пустой строки, конца соединения и ситуации «данные ещё не пришли» предпочтительнее `fread`. Сама логика должна периодически проверять, не появились ли новые данные, помня, что ответ сервера может прийти даже по одному байту за раз. Это открывает возможность подключаться к произвольным внешним сетевым сервисам прямо из игровой логики, не создавая полноценный HTTP-запрос (см. также [«Обращение к внешним веб-сервисам»](../32-third-party-services/README.md)).

## Примеры

- По завершении каждого матча серверная логика дописывает итоговую статистику (список игроков, счёт, длительность) отдельной строкой в текстовый файл-журнал в режиме `FILE_APPEND`, который администратор сервера позже может открыть и просмотреть.
- Мод сохраняет пользовательские текстовые настройки (например, список любимых карт игрока) в собственном простом файле в папке `data/`, не полагаясь на обычные переменные конфигурации движка.
- Экспериментальный серверный скрипт открывает прямое сетевое соединение к внешнему сервису через `tcp://адрес:порт` с флагом `FILE_STREAM`, обмениваясь с ним данными через собственный простой протокол поверх строк или байтовых блоков.
