# Встроенная база данных (SQLite/MySQL)

> [⬅ Вернуться к оглавлению вики](../README.md)

> Раздел: [Работа с данными из игровой логики](./README.md)

## Что это даёт геймдизайнеру

Многим серверным модам требуется хранить данные, переживающие перезапуск сервера, — статистику игроков, рейтинги, внутриигровую экономику, историю матчей. Вместо изобретения собственного формата хранения данных «с нуля» серверная логика может напрямую обращаться к настоящей базе данных: к локальному файлу SQLite или, если движок специально собран с такой поддержкой, к внешнему MySQL.

## Интерфейс настройки

Эти builtin-функции доступны **серверной логике (SSQC)**. В стандартной конфигурации FTEQW обычно доступен SQLite. Поддержка MySQL относится к опциональным путям: она требует отдельной сборки с MySQL и дополнительного запуска движка с параметром `-mysql`, а также не считается песочницей.

### Полный список функций работы с базой

- **`sqlconnect(host, user, pass, defaultdb, driver)`** — подключается к базе данных и возвращает числовой идентификатор соединения (используется во всех последующих вызовах). Все параметры необязательны: конкретные значения зависят от того, какой драйвер базы данных выбран (например, для локального файла SQLite в качестве «сервера» указывается путь к файлу, а для MySQL — сетевой адрес, логин и пароль).
- **`sqldisconnect(serveridx)`** — закрывает ранее открытое соединение с базой.
- **`sqlopenquery(serveridx, callback, querytype, query)`** — отправляет в базу текстовый SQL-запрос. Когда результат готов, движок сам вызывает указанную функцию-колбэк вида `callback(serveridx, queryidx, rows, columns, eof, firstrow)`, сообщая ей количество полученных строк и столбцов результата, дошли ли уже все данные (`eof`), и с какой строки начинается очередная порция данных — это позволяет обрабатывать даже очень большие результаты порциями, не блокируя сервер на время ожидания ответа базы.
- **`sqlclosequery(serveridx, queryidx)`** — освобождает результат запроса после того, как данные из него больше не нужны.
- **`sqlreadfield(serveridx, queryidx, row, column)`** — читает значение конкретной ячейки результата запроса как текстовую строку.
- **`sqlreadfloat(serveridx, queryidx, row, column)`** — то же самое, но сразу как число, без необходимости самостоятельно преобразовывать текст в число.
- **`sqlerror(serveridx, queryidx)`** — возвращает текст последней ошибки базы данных (например, если запрос содержал синтаксическую ошибку) — параметр номера запроса необязателен.
- **`sqlescape(serveridx, data)`** — экранирует текстовую строку так, чтобы её можно было безопасно подставить прямо в текст SQL-запроса (защита от «SQL-инъекций» — случая, когда пользовательский текст, например имя игрока, случайно ломает структуру запроса или используется для атаки на базу).
- **`sqlversion(serveridx)`** — возвращает строку с версией используемого сервера базы данных.

### Особенности хранения

Для файловой базы SQLite никакой отдельной установки не требуется — вся база хранится в одном обычном файле в writable-части игровой папки, движок сам создаёт такой файл при первом обращении, если его ещё не существует. SQLite-путь дополнительно ограничен песочницей движка. Для MySQL требуется доступ к уже существующему серверу базы данных (например, поднятому отдельно администратором сервера или предоставленному хостингом), плюс отдельная сборка движка с поддержкой MySQL и запуск с `-mysql`; этот путь заметно менее безопасен и потому не считается вариантом «из коробки».

## Примеры

- Одиночный мод хранит таблицу рекордов прохождения в локальном файле SQLite, который создаётся автоматически при первом запуске и продолжает накапливать статистику между сессиями игры.
- Сеть из нескольких игровых серверов одного проекта использует общий MySQL-сервер, чтобы рейтинг и валюта игроков были одинаковыми независимо от того, к какому конкретно серверу они подключились.
- Мод обрабатывает результат запроса на большую таблицу рекордов постранично через колбэк-функцию, показывая игроку таблицу лидеров без задержки при загрузке.
