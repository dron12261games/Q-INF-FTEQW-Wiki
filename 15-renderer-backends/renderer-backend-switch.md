# Переключение графического бэкенда

> [⬅ Вернуться к оглавлению вики](../README.md)

> Раздел: [Выбор движка рендеринга](./README.md)

## Что это даёт геймдизайнеру

Движок умеет выводить изображение не одним-единственным способом, а через несколько принципиально разных технологий рендеринга — это даёт возможность подобрать наиболее подходящий и стабильно работающий вариант под конкретное железо игрока, включая очень старые компьютеры или, наоборот, современные видеокарты с поддержкой Vulkan. Для разработчика это означает, что игра/мод получает широкую совместимость «бесплатно» — не нужно самому переписывать графику под разные технологии, достаточно того, что материалы и модели описаны обычным для движка образом (см. [«Язык описания материалов»](../08-materials-shaders/shader-script-language.md)).

## Интерфейс настройки

Выбирается переменной **[`vid_renderer`](../38-cvars-reference/01-video-rendering-cvars.md#vid_renderer)** — среди поддерживаемых значений:

| Значение | Технология |
|---|---|
| `gl` | классический OpenGL (наиболее широко совместимый вариант) |
| `egl` | OpenGL ES (часто используется на мобильных и встраиваемых платформах) |
| `vk` | современный Vulkan |
| `d3d8` | Direct3D 8 (для максимально старого «ретро»-железа/драйверов) |
| `d3d9` | Direct3D 9 |
| `d3d11` | Direct3D 11 с обычным аппаратным рендерингом |
| `d3d11 warp` | Direct3D 11 с программным (не использующим видеокарту, драйвер `D3D_DRIVER_TYPE_WARP`) рендерингом — крайний случай для машин без работающей видеокарты |
| `headless` | без вывода изображения вообще (полезно для автоматизированных серверных или тестовых сценариев) |
| `sv` | выделенный сервер без клиентского рендеринга вовсе |
| [`random`](../37-quakec-builtins-reference/01-math-vector-builtins.md#random) | движок сам случайным образом выбирает один из доступных полноценных рендереров (исключая `sv`, `headless` и программный рендер) — используется преимущественно для отладки совместимости движка на множестве бэкендов сразу |
| *(пусто, значение не задано)* | Движок автоматически выбирает наиболее приоритетный доступный на этой платформе рендерер |

Переменная требует перезапуска видеоподсистемы, чтобы новый выбор вступил в силу — выполняется командой **`vid_restart`**. Также доступна консольная команда **`setrenderer <строка>`**, которая мгновенно переключает рендерер без необходимости отдельно вызывать `vid_restart` (и, в отличие от прямой записи в `vid_renderer`, не сохраняет в cvar значение `headless`, чтобы случайно не остаться без изображения при следующем запуске). Если значение не задано явно, движок сам выбирает подходящий доступный вариант при первом запуске.

## Примеры

- На старом компьютере без поддержки современных технологий рендеринга пользователь явно выставляет `vid_renderer "gl"` и выполняет `vid_restart`, обеспечивая максимальную совместимость.
- Автоматизированный сервер, которому не требуется показывать изображение, запускается с `vid_renderer "headless"`, экономя ресурсы, которые иначе ушли бы на ненужный вывод графики.
- Энтузиаст с новой видеокартой переключается на `vid_renderer "vk"`, чтобы воспользоваться более современной технологией рендеринга Vulkan.
- На виртуальной машине без аппаратного 3D-ускорения используется программный рендеринг Direct3D 11 командой `setrenderer "d3d11 warp"`, что позволяет запустить игру даже там, где нет полноценного графического драйвера.
- QA-инженер, тестирующий совместимость мода со всеми доступными бэкендами сразу, при каждом запуске указывает `vid_renderer "random"`, чтобы движок каждый раз выбирал случайный рендерер и быстрее выявлял специфичные для конкретного API визуальные баги.
