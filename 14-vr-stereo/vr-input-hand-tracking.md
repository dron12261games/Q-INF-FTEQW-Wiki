# VR-ввод (контроллеры, отслеживание рук)

> [⬅ Вернуться к оглавлению вики](../README.md)

> Раздел: [VR и стереоскопия](./README.md)

## Что это даёт геймдизайнеру

Помимо простого отслеживания положения головы, VR-режим через WebXR (см. [«Поддержка VR-гарнитур»](./vr-headset-support.md)) передаёт движку данные от VR-контроллеров игрока — их положение в пространстве и нажатые кнопки — точно так же, как обычный игровой контроллер или джойстик передаёт свои оси и кнопки. Это позволяет игровой логике распознавать жесты и действия руками (прицеливание, хватание предметов, взмахи) как полноценный источник ввода, наравне с клавиатурой и мышью.

## Интерфейс настройки

С точки зрения игровой логики VR-ввод представлен двумя параллельными механизмами. Во-первых, кнопки и стики VR-контроллеров транслируются в те же самые игровые коды клавиш, что и у обычного геймпада (`K_GP_A`, `K_GP_LEFT_TRIGGER`, `K_GP_RIGHT_TRIGGER`, `K_GP_LEFT_SHOULDER` и т. д.) — их положение и кнопки доступны как оси и события ввода, которые можно как угодно связать с игровыми действиями через обычный механизм привязки клавиш/кнопок движка (см. [«Привязка клавиш и устройств ввода»](../19-config-console/key-bindings-input-devices.md)). Во-вторых, само трёхмерное положение и поворот головы и обеих рук в пространстве передаются в игровую логику напрямую через специальный набор глобальных переменных QuakeC, обновляемых движком каждый серверный кадр:

| Глобальная переменная QuakeC | Тип | Описание |
| :--- | :--- | :--- |
| `input_head_status` | float (битовая маска) | Отражает, доступны ли данные о положении (бит `VRSTATUS_ORG`) и повороте (бит `VRSTATUS_ANG`) головы в данный момент |
| `input_head_origin` | vector | Позиция головы игрока в VR-пространстве относительно точки отсчёта VR-комнаты |
| `input_head_angles` | vector | Углы поворота головы (pitch/yaw/roll) |
| `input_head_velocity` | vector | Линейная скорость движения головы |
| `input_head_avelocity` | vector | Угловая скорость вращения головы |
| `input_head_weapon` | float | Дополнительный код «оружия»/режима, ассоциированный с устройством головы (используется отдельными профилями ввода) |
| `input_left_status` / `input_right_status` | float (битовая маска) | То же самое, но для левого и правого VR-контроллера соответственно |
| `input_left_origin` / `input_right_origin` | vector | Позиция левого/правого контроллера в пространстве |
| `input_left_angles` / `input_right_angles` | vector | Углы поворота левого/правого контроллера |
| `input_left_velocity` / `input_right_velocity` | vector | Линейная скорость левого/правого контроллера |
| `input_left_avelocity` / `input_right_avelocity` | vector | Угловая скорость левого/правого контроллера |
| `input_left_weapon` / `input_right_weapon` | float | Дополнительный код «оружия»/режима для соответствующего контроллера |
| `VF_VRBASEORIENTATION` (поле камеры CSQC) | vector + vector (позиция и углы) | Задаёт положение и ориентацию точки отсчёта («базы») VR-комнаты в мировых координатах уровня — позволяет программно двигать точку, от которой отсчитываются все VR-координаты головы и рук |

Отдельной специфической настройки конкретно под VR-контроллеры в файлах мода не требуется — разработчик игровой логики читает состояние контроллеров тем же способом, что и состояние любого другого игрового устройства ввода, а положение рук и головы — через перечисленные глобальные переменные, что делает написание VR-специфичного взаимодействия делом обычной игровой логики, а не отдельной подсистемы.

## Примеры

- Мод, поддерживающий VR, назначает действие «взять предмет» на кнопку захвата VR-контроллера (`K_GP_RIGHT_TRIGGER`), определяя игровую логику подбора предметов исходя из значения `input_right_origin` в 3D-пространстве, а не курсора мыши.
- Оружие в VR-моде наводится не движением мыши, а непосредственно направлением, в котором игрок держит VR-контроллер, читая `input_right_angles` при каждом обновлении кадра.
- Игровая логика проверяет бит `VRSTATUS_ANG` в `input_left_status`, прежде чем использовать `input_left_angles`, чтобы корректно обрабатывать ситуацию, когда левый контроллер временно потерял отслеживание (например, вышел из поля зрения камер гарнитуры).
- При телепортационном перемещении игрока по уровню игровая логика обновляет `VF_VRBASEORIENTATION`, сдвигая точку отсчёта VR-комнаты вместе с игроком, чтобы виртуальные руки и голова корректно оставались в новой точке мира.
