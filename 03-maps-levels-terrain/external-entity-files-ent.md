## Что это даёт геймдизайнеру

Внутри BSP-карты хранится не только геометрия, но и список расставленных на ней игровых объектов («сущностей») — точек появления игроков, монстров, предметов, триггеров и переключателей. Обычно, чтобы поменять расстановку объектов, пришлось бы заново компилировать всю геометрию карты целиком. Файл **`.ent`** решает эту проблему: он позволяет **переопределить список сущностей карты отдельным текстовым файлом, не трогая и не пересобирая саму геометрию**. Это крайне полезно для быстрой донастройки чужих или уже давно скомпилированных карт под правила конкретного мода — например, добавить точки появления для новой команды или поменять типы предметов — без доступа к исходникам самой карты и без долгой повторной компиляции геометрии.

---

## Интерфейс настройки

Файл сущностей — это простой текстовый файл в том же формате описания объектов, что используется внутри самой BSP-карты, с тем же именем, что и файл карты, но расширением **`.ent`**, положенный в ту же подпапку `maps/`. Если движок находит рядом с картой `mapname.ent`, список сущностей из этого текстового файла используется **вместо** списка, встроенного в саму `.bsp`-геометрию. Технически это делается той же самой универсальной системой «поглощения» (injest) сопутствующих файлов карты, что подключает и файлы освещения `.lit`/`.lux` (см. [«Внешние патчи освещения и видимости»](./external-lighting-visibility-patches.md)) — при загрузке карты движок сам ищет рядом файл с таким именем и, если находит, заменяет соответствующий внутренний блок данных карты его содержимым, полностью прозрачно для игровой логики.

---

## Практический пример: полный `.ent`-файл с добавленными точками появления команды

Допустим, есть карта `maps/dm3.bsp` из классического набора одиночных карт, и требуется адаптировать её под командный режим, добавив точки появления для второй команды, не трогая геометрию. Рядом кладётся файл `maps/dm3.ent` со следующим содержимым:

```
{
"classname" "worldspawn"
"wad" "gfx/base.wad"
}
{
"classname" "info_player_start"
"origin" "480 -352 88"
"angle" "90"
}
{
"classname" "info_player_team2"
"origin" "-480 352 88"
"angle" "270"
}
{
"classname" "info_player_team2"
"origin" "-448 352 88"
"angle" "270"
}
```

Разбор: первая фигурная скобка — обязательная сущность `worldspawn`, представляющая саму геометрию уровня; поле [`wad`](../39-entity-keys-reference/01-worldspawn-common-keys.md#wad) должно совпадать с тем, что использовалось при исходной компиляции карты, чтобы текстуры продолжали корректно находиться. Далее следует классическая точка старта для одиночной игры `info_player_start` (сохраняется для совместимости с обычным режимом). Затем добавляются две новые точки старта `info_player_team2` в другой части карты — с их помощью появляется возможность запускать эту же классическую карту в командном режиме, где игроки второй команды будут появляться в отдельной точке, физически удалённой от точки старта первой команды, что критически важно для честного командного геймплея.

---

## Примеры

- Классическая одиночная карта адаптируется под командный режим игры: рядом с оригинальным `.bsp`-файлом кладётся `.ent`-файл с добавленными точками появления для двух команд, без изменения самой геометрии карты.
- Автор мода донастраивает расстановку предметов на давно скомпилированной карте стороннего автора, не имея доступа к исходным файлам её геометрии.
- Разработчик временно тестирует изменённую расстановку монстров на большой карте, редактируя только текстовый `.ent`-файл в обычном текстовом редакторе, вместо запуска долгой повторной компиляции геометрии в специализированном редакторе уровней.
