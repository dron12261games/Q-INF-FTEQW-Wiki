# Совместное редактирование ландшафта в реальном времени

> [⬅ Вернуться к оглавлению вики](../README.md)

## Что это даёт геймдизайнеру

Ландшафт на основе карты высот (см. [«Ландшафт на основе карт высот»](./heightmap-terrain.md)) можно править **в сервер-авторитетном режиме**: сервер помечает изменённые секции, клиенты получают уведомление и догружают нужные куски по требованию. Это годится для совместного прототипирования и живых редакторских сессий, но важно понимать, что сеть здесь синхронизирует именно серверные правки секций terrain.

---

## Интерфейс настройки

Режим включается переменной **[`mod_terrain_networked`](../38-cvars-reference/02-lighting-materials-cvars.md#mod_terrain_networked)**. Когда она активна, клиент обычно больше не читает секции terrain с локального диска, а получает их у сервера по мере необходимости; сервер же рассылает уведомления о смене секций. Обратная сторона этой схемы: локальная правка на клиенте сама по себе **не** реплицируется обратно на сервер и может быть перезаписана серверным состоянием, поэтому для настоящего совместного редактирования правки нужно пропускать через SSQC/сервер с собственными проверками прав.

## Инженерный справочник: связанные переменные ландшафта

| Cvar | Тип данных | Описание | Значение по умолчанию |
| :--- | :--- | :--- | :--- |
| [`mod_terrain_networked`](../38-cvars-reference/02-lighting-materials-cvars.md#mod_terrain_networked) | булево (0/1) | Включает server→client синхронизацию секций terrain: клиенты докачивают секции по требованию, а сервер уведомляет об изменениях | `0` |
| [`mod_terrain_defaulttexture`](../38-cvars-reference/02-lighting-materials-cvars.md#mod_terrain_defaulttexture) | строка, имя текстуры | Текстура, назначаемая заново создаваемым тайлам ландшафта; как правило, обновляется самим редактором ландшафта, а не вручную | пусто |
| [`mod_terrain_savever`](../38-cvars-reference/02-lighting-materials-cvars.md#mod_terrain_savever) | строка | Версия внутреннего формата секции ландшафта, используемая при сохранении отредактированных данных на диск | пусто (текущая версия) |
| [`mod_terrain_sundir`](../38-cvars-reference/02-lighting-materials-cvars.md#mod_terrain_sundir) | вектор `x y z` | Направление условного «солнца», используемое при просчёте статичного освещения ландшафта (вектор автоматически нормализуется) | `0.4 0.7 2` |
| [`mod_terrain_ambient`](../38-cvars-reference/02-lighting-materials-cvars.md#mod_terrain_ambient) | число с плавающей точкой | Доля рассеянного (ambient) света в общей формуле освещения ландшафта | `0.5` |
| [`mod_terrain_shadows`](../38-cvars-reference/02-lighting-materials-cvars.md#mod_terrain_shadows) | булево (0/1) | Включает трассировку лучей для определения затенённых участков ландшафта | `0` |
| [`mod_terrain_shadow_dist`](../38-cvars-reference/02-lighting-materials-cvars.md#mod_terrain_shadow_dist) | число, игровые единицы | Максимальная дальность трассировки лучей при поиске перекрывающей свет геометрии для теней | `2048` |
| [`mod_map_lights`](../38-cvars-reference/02-lighting-materials-cvars.md#mod_map_lights) | булево (0/1) | Просчитывает освещение на обычных геометрических кистях/патчах ландшафтной карты | `0` |
| [`mod_map_texscale`](../38-cvars-reference/02-lighting-materials-cvars.md#mod_map_texscale) | число с плавающей точкой | Масштаб текселей текстуры на геометрии карты: `1` для карт Quake/Quake II, `0.5` для карт формата Quake III | `1` |

---

## Примеры

- На сервере с включённым [`mod_terrain_networked`](../38-cvars-reference/02-lighting-materials-cvars.md#mod_terrain_networked) несколько администраторов одновременно правят форму ландшафта, и изменения сразу видны всем подключённым игрокам.
- Экспериментальный мультиплеерный «песочница»-режим позволяет игрокам совместно перестраивать ландшафт прямо во время матча.
- Автор карты включает [`mod_terrain_shadows 1`](../38-cvars-reference/02-lighting-materials-cvars.md#mod_terrain_shadows) и подбирает направление [`mod_terrain_sundir`](../38-cvars-reference/02-lighting-materials-cvars.md#mod_terrain_sundir), чтобы статичные тени от рельефа ложились в нужную сторону перед финальным сохранением ландшафта.
