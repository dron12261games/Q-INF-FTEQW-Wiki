# Внешние патчи освещения (.lit/.lux)

> [⬅ Вернуться к оглавлению вики](../README.md)

> Раздел: [Уровни, карты и ландшафт](./README.md)

## Что это даёт геймдизайнеру

Расчёт освещения для карты — это долгий процесс, обычно встроенный прямо в геометрию `.bsp`-файла. Движок поддерживает вынесение результатов этого расчёта в отдельные файлы-патчи, которые можно пересчитать и заменить, не трогая геометрию самой карты. Это удобно, когда нужно улучшить освещение старой карты (например, добавить цветной свет или более качественный расчёт) — без необходимости заново компилировать саму геометрию с нуля.

## Интерфейс настройки

- **`.lit`** — файл с цветными картами освещения повышенного качества (в отличие от базового чёрно-белого освещения, встроенного прямо в `.bsp`). Кладётся рядом с картой, с тем же именем, в ту же подпапку `maps/`. Дополнительно поддерживается вариант **`.hdr`** — тот же принцип, но с расширенным динамическим диапазоном яркости, без выгорания самых ярких участков.
- **`.lux`** — сопутствующий файл направленного освещения (см. также [«Направленное освещение по нормали (deluxemap)»](../09-lighting-shadows/deluxemap-directional-lighting.md)), уточняющий, с какой стороны падает свет — это нужно для более реалистичного объёмного освещения рельефных поверхностей.

Движок автоматически подхватывает такие файлы, если находит их рядом с картой при загрузке — никаких дополнительных команд для игрока не требуется, но подключается это поведение через управляющий cvar **`r_loadlits`** (см. таблицу ниже): при его нулевом значении внешние файлы освещения игнорируются и используется только освещение, встроенное непосредственно в `.bsp`. Сами файлы создаются утилитами компиляции освещения для карт, точно так же, как компилируется сама геометрия, только с указанием сохранить результат в отдельный файл, а не встраивать его в `.bsp`. Помимо отдельного файла-спутника, то же самое содержимое цветного и направленного освещения может быть встроено прямо внутрь `.bsp`-файла через технологию BSPX (см. [«Расширенные лимиты карт»](./extended-bsp-limits-bsp2.md)) — движок ищет данные в обоих местах и приоритетно использует встроенный BSPX-блок, если он присутствует.

**Важное уточнение**: несмотря на то, что в некоторых старых обсуждениях упоминается отдельный файл видимости `.vis`, в текущем коде движка автоматическая подгрузка такого отдельного файла при обычной загрузке карты не реализована (соответствующий код существует лишь в виде отключённой заготовки внутри вспомогательной консольной команды `mod_bspx_injest`, предназначенной для встраивания сопутствующих файлов прямо в сам `.bsp`). Поэтому полагаться на отдельный работающий файл `.vis` не стоит — для пересчёта видимости актуальный путь — это повторная компиляция геометрии карты специализированной утилитой видимости.

## Инженерный справочник

| Элемент | Тип данных | Описание | Значение по умолчанию |
| :--- | :--- | :--- | :--- |
| `r_loadlits` | целочисленный cvar | Управляет подгрузкой внешних файлов `.lit`/`.hdr`/`.lux`: `0` — отключить полностью и использовать только встроенное в `.bsp` освещение; `1` — загружать, если найден подходящий файл; значения `2` и выше включают дополнительные диагностические и принудительные режимы догрузки | `1` |
| `.lit` | Формат файла, сигнатура `QLIT` | Цветная карта освещения стандартного динамического диапазона, по одному байту RGB на каждый люксель, что и в базовой карте освещения | — |
| `.hdr` | Формат файла, сигнатура `QLIT` (HDR-вариант) | Цветная карта освещения расширенного динамического диапазона (не выгорающая на ярких участках) | — |
| `.lux` | Формат файла, сигнатура `QLIT` | Направление падения света для каждого люкселя карты освещения, используется при расчёте бамп-подобного затенения рельефных поверхностей | — |

## Примеры

- Старая карта получает современный качественный цветной пересчёт освещения через `.lit`-файл, не требуя повторной компиляции самой геометрии.
- Карта с сильными контрастами яркого света и тёмных теней использует `.hdr`-вариант вместо обычного `.lit`, избегая заметного «выгорания» самых ярких участков.
- Художник карты повышает cvar `r_loadlits` до `2` во время отладки, чтобы принудительно проверить и перезагрузить внешние файлы освещения без перезапуска движка.
