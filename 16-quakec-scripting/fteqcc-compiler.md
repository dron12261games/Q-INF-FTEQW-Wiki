## Что это даёт геймдизайнеру

Исходный код на QuakeC (файлы `.qc`) — это просто текст, который сам по себе игру не запустит. Чтобы движок мог его выполнить, текст нужно превратить в компактный бинарный файл со специальным байт-кодом — эту работу выполняет компилятор **FTEQCC** (сокращение от «FTE QuakeC Compiler»). Понимание того, как устроена эта сборка, нужно любому автору мода, ведь без неё ни одно изменение в коде логики не попадёт в игру.

С этим компилятором связаны ещё три вещи, о которых стоит знать заранее. Во-первых, чтобы вызвать встроенную функцию движка (builtin) из своего кода, её сначала нужно **объявить** — указать компилятору её имя, типы аргументов и номер `#NN`, под которым она зашита в движке (см. [«Функции»](./quakec-language-basics.md#функции-два-способа-объявления)); переписывать эти объявления вручную в каждом новом проекте долго и чревато ошибками, поэтому вместе с движком распространяются готовые **заголовочные файлы** с такими объявлениями. Во-вторых, у FTEQCC есть отдельная программа для сборки вне игры, со своими **параметрами командной строки** — она нужна при автоматизации сборки мода (скрипты, CI, сторонние редакторы кода). В-третьих, движок содержит встроенные инструменты **отладки** уже скомпилированного мода прямо во время игры — точки останова, пошаговое выполнение и аварийные дампы состояния при падении.

## Список исходников: файл `progs.src`

Компилятору нужно знать, какие именно файлы `.qc` и в каком порядке собирать. Для этого используется текстовый файл, который по договорённости называется **`progs.src`** для серверной логики (SSQC), **`csprogs.src`** для клиентской логики (CSQC) и **`menu.src`** для логики меню (MenuQC). Пример типичного содержимого:

```c
// Первый непустой/некомментарийный символ файла — # означает "новый стиль" progs.src
#pragma PROGS_DAT "qwprogs.dat"

#include "defs.qc"
#include "subs.qc"
#include "weapons.qc"
#include "world.qc"
#include "player.qc"
```

Директива `#pragma PROGS_DAT "filename.dat"` задаёт имя итогового скомпилированного файла (по умолчанию — `progs.dat`). Директива `#include "file.qc"` подключает содержимое другого файла с исходным кодом ровно на этом месте — то есть весь проект мода на самом деле собирается как **один большой файл**, просто разбитый на удобные для чтения части, объединяемые в порядке перечисления в `progs.src`. Из-за этого важно подключать файлы в правильном порядке: если один файл использует функцию или поле, объявленное в другом файле, тот файл должен быть подключён раньше (либо соответствующее объявление нужно вынести в общий заголовочный файл — см. [«Стандартные заголовочные файлы»](#стандартные-заголовочные-файлы-для-quakec) ниже).

Дополнительно можно объявлять собственные условные флаги компиляции прямо в `progs.src` (директивами `#define`/`#ifdef`/`#else`/`#endif`, точно как в языке C), чтобы собирать разные варианты мода из одного набора исходников:

```c
#define MONSTERS

#ifdef MONSTERS
#include "monsters.qc"
#else
#include "nomonst.qc"
#endif
```

Ещё одна полезная директива — `#pragma target fte` — явно указывает компилятору собирать код в «расширенном» формате байт-кода FTE (с поддержкой более широких типов данных и возможностей движка), а не в исходном, ограниченном формате байт-кода id Software 1996 года. Директив препроцессора и `#pragma` у FTEQCC заметно больше, чем эта пара примеров — полный перечень с описанием каждой приведён в справочнике в конце страницы.

## Как запустить компиляцию

Есть два равноценных способа собрать мод:

1. **Прямо внутри самого движка**, без выхода из игры — консольной командой [`compile`](../44-cli-commands-reference/04-server-multiplayer-commands.md#compile) (по умолчанию собирает `progs.src` из текущей игровой папки в `progs.dat`; можно явно указать другой файл списка исходников, например [`compile csprogs.src`](../44-cli-commands-reference/04-server-multiplayer-commands.md#compile)). Это удобно тем, что не нужно возиться с отдельной программой — движок содержит в себе версию FTEQCC.
2. **Отдельной программой-компилятором** FTEQCC, запускаемой вне игры (например, из командной строки или через сторонний редактор кода с поддержкой QuakeC) — так собирают более крупные проекты, а также в тех случаях, когда результат сборки нужно куда-то распространять отдельно от исходников. Параметры, с которыми запускается эта отдельная программа, разобраны в отдельном разделе ниже.

После правки кода командой **[`applycompile`](../44-cli-commands-reference/04-server-multiplayer-commands.md#applycompile)** можно применить только что собранный код «на лету», без перезапуска карты и без отключения игроков — по сути, это быстрое сохранение и мгновенная загрузка игры с новым кодом. Это не проверяет и не переносит новые поля объектов автоматически — подходит для быстрой проверки одной подправленной функции, а не для полной переработки структуры данных мода. Подробнее о живой правке кода без остановки игры — в разделе [«Отладка и „горячая“ пересборка логики»](#отладка-и-горячая-пересборка-логики) ниже.

## Типичные ошибки компиляции и что они значат

Компилятор останавливает сборку и сообщает об ошибке, если находит нарушение синтаксиса или явную нестыковку типов данных. Разбираться в сообщениях об ошибках — обычный навык, который нарабатывается с практикой, но несколько самых частых причин стоит знать заранее:

- **Пропущенная точка с запятой** — компилятор обычно указывает на строку, которая идёт *после* настоящего места ошибки (потому что до самой точки с запятой он ещё «ждал продолжения» предыдущей инструкции).
- **Несовпадение типов** — например, попытка присвоить `entity`-значение переменной типа `float`, или передать строку туда, где функция ожидает число.
- **Использование неизвестного имени** — обращение к функции, полю или переменной, которая нигде не была объявлена (либо опечатка в имени, либо забыли подключить нужный `#include`, либо файл с объявлением подключён в `progs.src` *после* места использования).
- **Незакрытая фигурная скобка или комментарий** — если где-то в файле не хватает закрывающей `}` или `*/`, ошибка компиляции может показаться в совершенно неожиданном, отдалённом месте файла — стоит перепроверить именно баланс скобок и комментариев.

## Параметры командной строки отдельного компилятора

Отдельная программа-компилятор FTEQCC, запускаемая вне игры, принимает параметры командной строки: какие файлы собирать, в какой формат байт-кода, с каким уровнем оптимизации и строгости предупреждений. Общий синтаксис: `fteqcc [params] [files.qc]`. Если не передать явный список исходников, компилятор ищет `progs.src` в текущей папке. Полный постатейный справочник по каждому параметру — в статье [«Параметры командной строки FTEQCC (полный справочник)»](../44-cli-commands-reference/07-fteqcc-command-line-parameters.md); здесь — обзор по группам с примерами.

### Файлы, пути и точки входа

```
fteqcc -src ./src -I ./include -DDEBUG=1
```
Собрать исходники из папки `./src` (там же ищется `progs.src`), добавив `./include` в пути поиска для `#include` и определив константу препроцессора `DEBUG`.

| Параметр | Назначение |
|---|---|
| [`-src <folder>`](../44-cli-commands-reference/07-fteqcc-command-line-parameters.md#src) | указать папку с исходниками (там же ищется `progs.src`), вместо текущей рабочей папки |
| [`-srcfile <file>`](../44-cli-commands-reference/07-fteqcc-command-line-parameters.md#srcfile) | добавить ещё один список исходников (`.src`) к сборке, помимо основного |
| [`-o <file>`](../44-cli-commands-reference/07-fteqcc-command-line-parameters.md#o) / [`-o<file>`](../44-cli-commands-reference/07-fteqcc-command-line-parameters.md#o) | явно задать имя итогового скомпилированного файла вместо имени по умолчанию (`progs.dat` или заданного директивой `#pragma PROGS_DAT`) |
| [`-D<name>[=value]`](../44-cli-commands-reference/07-fteqcc-command-line-parameters.md#d) | определить именованную константу препроцессора, как `#define` в исходном коде |
| [`-I<path>`](../44-cli-commands-reference/07-fteqcc-command-line-parameters.md#i) | добавить папку в список путей поиска для `#include` |

### Целевой формат байт-кода (`-T`)

Задаёт, под какой движок собирается байт-код — влияет на набор доступных типов данных и операций. Например, `-Tstandard` соберёт мод так, чтобы он запускался даже на движках 1996 года, а `-Tfte` откроет доступ ко всем расширениям FTEQW ценой совместимости со старыми движками:

| Параметр | Назначение |
|---|---|
| `-Tstandard` (`-Tvanilla`, `-Tq1`, `-Tid`, `-Tquakec`) | классический байт-код id Software 1996 года (максимальная совместимость со старыми движками) |
| `-Tfte` | расширенный байт-код [FTEQW](../README.md#устаревшие-экспериментальные-и-недоступные-по-умолчанию-возможности) последней стабильной ревизии (то же самое, что `#pragma target fte`) |
| `-Tftedebug` (`-Tdebug`) | формат FTE с дополнительной отладочной информацией |
| `-Tfteh2` | формат FTE для модов на основе Hexen II |
| `-Thexen2` / `-Th2`, `-Tuhexen2` | байт-код оригинального Hexen II / его «универсальной» вариации |
| `-Tdarkplaces` (`-Tdp`) | байт-код, совместимый с движком DarkPlaces |
| `-Tkkqwsv` (`-Tkk7`, `-Tversion7`) | формат "version 7" (KKQWSV) |
| `-Tqss` | формат QuakeStandardStomping (QSS) |
| `-Tparse` | только разобрать код на ошибки, без записи файла результата (проверка синтаксиса) |
| `-T<target>_<N>` | указать конкретную числовую ревизию формата, например `-Tfte_9999` |

### Уровни и флаги оптимизации (`-O`)

```
fteqcc -O2
```
Оптимизировать байт-код по скорости выполнения — обычный выбор для финальной сборки мода.

| Параметр | Назначение |
|---|---|
| `-O0` … `-O3` | общий уровень оптимизации: 0 — отключить, 1 — компактность файла, 2 — скорость выполнения, 3 — небезопасные оптимизации (могут сломать код, полагающийся на мультипрогс) |
| `-O<name>` / `-Ono-<name>` | включить/выключить конкретную оптимизацию по имени (например, `-Ooverlaptemps`, `-Ono-locals`) — полный список имён выводится через `--help` |
| `-Ostrip_functions`, `-Olocals`, `-Ofilenames` и т.п. | точечные оптимизации размера файла, обычно ценой ухудшения читаемости декомпилированного/отладочного вывода |

### Флаги компилятора и ключевые слова (`-F` / `-K`)

Многие расширения языка (см. [«Полный справочник ключевых слов»](./quakec-language-basics.md#справочник-синтаксиса) в статье про синтаксис) можно включать и выключать по отдельности. Механизм `-K<name>` включает/выключает поддержку конкретного **ключевого слова** языка — например, `-Kno-switch` отключает `switch`, что бывает нужно для совместимости со старым кодом, где `switch` использовалось как имя переменной. `-F<name>` / `-Fno-<name>` переключает **поведенческие флаги** компилятора — например, `-Flax` смягчает проверку типов для совместимости с FrikQCC/Reacc-кодом, а `-Fifstring` исправляет трактовку `if(string)`. Пресет `-std=<name>` (например, `-std=gmqcc` или `-std=reacc`) включает сразу целую группу таких флагов, ассоциированную с конкретным диалектом QuakeC. Обе группы флагов многочисленны (около 90 идентификаторов) и рассчитаны на редкие случаи совместимости со старым/сторонним кодом — полный список с описанием каждого выводится опцией `--help` и приведён в [полном справочнике параметров](../44-cli-commands-reference/07-fteqcc-command-line-parameters.md#флаги-компилятора-и-ключевые-слова--k---f).

### Предупреждения (`-W`)

| Параметр | Назначение |
|---|---|
| `-Wall` | включить большинство полезных предупреждений (кроме отмеченных как «слишком шумные») |
| `-Wextra` | включить вообще все предупреждения, включая самые придирчивые |
| `-Wnone` | отключить все предупреждения |
| `-Werror` | считать все включённые предупреждения ошибками, останавливающими сборку |
| `-Wno-mundane` | отключить мелкие стилистические предупреждения (неиспользуемые переменные, повторные объявления и т.п.) |
| `-W<code>` / `-Wno-<code>` | включить/выключить конкретное предупреждение по его коду (например, `-Wno-F302`) |

### Лимиты и информационные параметры

| Параметр | Назначение |
|---|---|
| `-max_regs`, `-max_strings`, `-max_globals`, `-max_fields`, `-max_statements`, `-max_functions`, `-max_types`, `-max_temps`, `-max_macros` `<N>` | вручную задать верхнюю границу для внутренних таблиц компилятора (актуально только при сборке экстремально больших модов, упирающихся в лимиты по умолчанию) |
| `-v` | подробный (verbose) вывод хода компиляции, можно указывать несколько раз |
| `--version` | вывести версию компилятора и завершить работу |
| `--help` / `-help` | вывести полный список поддерживаемых параметров, оптимизаций и флагов с описанием и завершить работу |

Следующие параметры распознаются компилятором, но либо ничего не делают, либо только выводят предупреждение о том, что функциональность не реализована — это унаследованные заглушки от других диалектов qcc, оставленные для совместимости синтаксиса командной строки: `-qc`/`-E` (помечены как экспериментальные), `-progdefs`/`-copy` (приняты, но игнорируются), `-bspmodels`/`-pak`/`-pak2` (предупреждают о неподдержанности), `-stdout`/`-log`/`-nolog` (приняты для совместимости, не влияют на поведение).

**Примеры:**

```
fteqcc -src ./src -Tfte -O2 -Wall
```
Собрать `progs.src` из папки `./src` под движок FTEQW с оптимизацией по скорости и включёнными основными предупреждениями.

```
fteqcc -srcfile csprogs.src -o csprogs.dat -Tftedebug
```
Собрать клиентскую логику (CSQC) в отдельный файл с отладочным форматом байт-кода.

## Стандартные заголовочные файлы для QuakeC

Переписывать объявления builtin-функций вручную в каждом новом проекте мода — долго и чревато ошибками в номерах `#NN`. Поэтому вместе с движком и его инструментами распространяется набор готовых текстовых файлов с такими объявлениями — их достаточно один раз подключить директивой `#include` в начале своего проекта, и сразу становится доступен весь соответствующий набор функций и полей. Готовые заголовочные файлы делятся на две смысловые группы, которые обычно лежат рядом друг с другом в наборе инструментов для разработки мода:

**«Общие» заголовки** (совместимость с разными движками) объявляют функции и поля так, чтобы код мода мог без переделок запускаться не только на FTEQW, но и на других движках семейства Quake, поддерживающих те же самые расширения (например, DarkPlaces). Отдельные файлы под разные контексты выполнения кода: заголовок для серверной логики (SSQC); заголовок для клиентской логики (CSQC) в варианте, ориентированном на широкую межигровую совместимость; отдельный, более полный заголовок для клиентской логики специально под возможности FTEQW; заголовок под клиентскую логику в стиле другого популярного движка (для мода, портируемого между движками); заголовок для логики меню (MenuQC). Такие заголовки стоит выбирать, если мод изначально задумывается как переносимый между несколькими совместимыми движками, а не только для FTEQW.

**Заголовки расширений, специфичных для FTEQW**, напротив, объявляют функции и поля, которые распознаёт **только сам FTEQW** (а также, возможно, движки, прицельно копирующие его расширения) — то есть все те дополнительные возможности, которых нет в оригинальном Quake и которые перечислены в статье [«QuakeC: синтаксис, расширения и модульные прогс-файлы»](./quakec-language-basics.md) и в справочнике [встроенных функций](../README.md#встроенные-функции-quakec-builtins). Сюда входят: общий заголовок расширений FTE для серверной/общей логики (в нём собраны десятки именованных расширений вида `FTE_STRINGS`, `FTE_MULTITHREADED`, `FTE_QC_CHECKPVS` и т.п. — каждое оформлено как отдельный, самодокументированный блок с объявлением нужных функций и коротким описанием, что оно делает и зачем); заголовок системных объявлений для клиентской логики (CSQC) — специфичные для FTE поля и функции интерфейса рендеринга; заголовок системных объявлений для логики меню (MenuQC) — аналогично, но для экранов меню. Такие заголовки стоит подключать, если мод целенаправленно ориентирован на FTEQW и использует его продвинутые возможности, не заботясь о запуске на других движках.

Достаточно добавить строку `#include` в самое начало общего исходного файла (обычно — того же `defs.qc`, что объявляет и стандартные, «ванильные» поля Quake), например:

```c
#include "fteextensions.qc"
```

Дальше все объявленные в этом файле функции и поля доступны в любом месте проекта, куда этот `defs.qc` (или другой общий файл) подключается раньше по списку в `progs.src` — см. [«Список исходников: файл `progs.src`»](#список-исходников-файл-progssrc) выше.

Важная деталь: сам факт наличия объявления функции в заголовочном файле расширений означает лишь, что *компилятор знает, как её вызвать* — то, будет ли конкретная функция реально работать во время игры, зависит от того, включена ли соответствующая возможность в той сборке движка, на которой запущена игра (см. раздел [«Устаревшие, экспериментальные и недоступные по умолчанию возможности»](../README.md#устаревшие-экспериментальные-и-недоступные-по-умолчанию-возможности) — там же перечислены самые заметные подобные ограничения). Перед тем как полагаться на редкую возможность в важной части своего мода, стоит на практике проверить, что она действительно работает на той версии движка, с которой будет распространяться игра.

## Отладка и «горячая» пересборка логики

Движок содержит встроенные инструменты для разработки и отладки игровой логики прямо во время игры, без необходимости в отдельной внешней среде разработки:

- **Встроенный компилятор.** Команда [`compile [filename.src]`](../44-cli-commands-reference/04-server-multiplayer-commands.md#compile) собирает исходный код мода (по умолчанию `progs.src`, либо `csprogs.src` для клиентской логики) прямо внутри запущенного движка; движок сам ищет исходники в подпапках `qc`, `progs` или прямо в папке мода, если явный путь не найден. Обратная операция — команда **[`decompile [name.dat]`](../44-cli-commands-reference/04-server-multiplayer-commands.md#decompile)** — превращает уже скомпилированный `.dat`-файл обратно в примерный QuakeC-исходник, что полезно для изучения устройства чужих модов, если их исходный код недоступен.
- **Применение изменений без перезапуска.** Команда [`applycompile`](../44-cli-commands-reference/04-server-multiplayer-commands.md#applycompile) подхватывает только что пересобранный код «на лету» — по сути, быстрое сохранение и мгновенная загрузка игры, — позволяя проверить исправление одной функции, не отключая игроков от сервера и не перезапуская карту. Этот способ не может сам по себе изменить структуру данных (добавить новые игровые поля) — только логику существующего кода.
- **Точки останова.** Команда [`breakpoint`](../37-quakec-builtins-reference/12-system-debug-builtins.md#breakpoint) ставит или снимает точку останова для серверной логики (SSQC); для клиентской и MenuQC логики существуют отдельные команды **[`breakpoint_csqc`](../44-cli-commands-reference/02-client-ui-commands.md#breakpoint_csqc)** и **[`breakpoint_menuqc`](../44-cli-commands-reference/02-client-ui-commands.md#breakpoint_menuqc)**. Аналогично, у watchpoint'ов есть варианты **[`watchpoint`](../44-cli-commands-reference/04-server-multiplayer-commands.md#watchpoint)** / **[`watchpoint_ssqc`](../44-cli-commands-reference/04-server-multiplayer-commands.md#watchpoint_ssqc)** для SSQC, **[`watchpoint_csqc`](../44-cli-commands-reference/02-client-ui-commands.md#watchpoint_csqc)** для CSQC и **[`watchpoint_menuqc`](../44-cli-commands-reference/02-client-ui-commands.md#watchpoint_menuqc)** для MenuQC. Условие для включения полноценной пошаговой отладки — включённая переменная [`developer`](../38-cvars-reference/07-system-misc-cvars.md#developer) `1` и наличие рядом с прогс-файлом отладочного файла соответствий (`.lno`, создаётся современным QuakeC-компилятором вместе с самим прогс-файлом).
- **Программная точка останова прямо из кода мода.** Встроенная функция QuakeC [`breakpoint()`](../37-quakec-builtins-reference/12-system-debug-builtins.md#breakpoint) (без аргументов) может быть вызвана прямо в исходном коде — при её достижении движок немедленно останавливает выполнение точно так же, как если бы здесь стояла точка останова, поставленная командой из консоли; на движках, не реализующих отладчик, аналогичный вызов может вместо этого привести к аварийному завершению с отладочным исключением.
- **Управление в момент остановки** (когда доступен графический интерфейс — то есть не на выделенном сервере без экрана): `F11` — выполнить следующую строку кода (шаг внутрь вызовов); `F9` — включить/выключить точку останова; `F5` — продолжить выполнение до следующей точки останова; строка ввода для проверки значений переменных прямо в момент остановки (можно даже присвоить переменной новое значение для проверки, но нельзя вызывать функции); `Escape` — закрыть отладчик и продолжить выполнение как обычно. На выделенном сервере без графического интерфейса вместо интерактивного отладчика движок просто построчно печатает в консоль код исполняемых строк.
- **Принудительное включение трассировки из самого кода мода** — builtin-функция [`traceon()`](../37-quakec-builtins-reference/03-entity-world-builtins.md#traceon) включает пошаговый режим программно; при необходимости его можно потом выключить [`traceoff()`](../37-quakec-builtins-reference/03-entity-world-builtins.md#traceoff).
- **Аварийные дампы состояния.** По умолчанию движок умеет автоматически писать отдельные core-файлы для SSQC/CSQC/MenuQC при ошибках в соответствующей VM (`ssqccore.txt`, `csqccore.txt`, `menucore.txt`). Такой дамп можно запросить и вручную командами [`coredump_ssqc`](../44-cli-commands-reference/04-server-multiplayer-commands.md#coredump_ssqc), [`coredump_csqc`](../44-cli-commands-reference/02-client-ui-commands.md#coredump_csqc), [`coredump_menuqc`](../44-cli-commands-reference/02-client-ui-commands.md#coredump_menuqc).

## Справочник

Ниже — компактные таблицы для быстрого поиска: директивы препроцессора и `#pragma`, упомянутые выше в общих чертах, здесь перечислены полностью.

### Директивы препроцессора

| Директива | Что делает | Пример |
|---|---|---|
| `#define` | Определяет макрос или именованную константу, в т.ч. с параметрами | `#define MAX_CLIENTS 16` |
| `#append` | Дописывает дополнительный текст к уже существующему макросу | `#append MAX_CLIENTS extra` |
| `#undef` | Удаляет ранее определённый макрос | `#undef DEBUG` |
| `#if` / `#elif` | Условная компиляция по значению выражения | `#if VERSION >= 2` |
| `#ifdef` / `#ifndef` | Условная компиляция по наличию/отсутствию макроса | `#ifdef FOO` |
| `#else` / `#endif` | Завершают условный блок | `#endif` |
| `#include` | Подключает содержимое другого файла (`"..."` или `<...>`) | `#include "defs.qc"` |
| `#includelist` / `#endlist` | Построчный список включаемых файлов | `#includelist`<br>`foo.qc`<br>`#endlist` |
| `#error` | Останавливает сборку с сообщением об ошибке | `#error unsupported target` |
| `#warning` | Выводит предупреждение, не останавливая сборку | `#warning deprecated path` |
| `#message` | Выводит информационное сообщение | `#message building server qc` |
| `#eof` | Принудительно завершает чтение текущего файла | `#eof` |
| `#output` | Задаёт имя итогового файла, если оно не зафиксировано в командной строке | `#output "progs.dat"` |
| `#datafile` | Добавляет внешний файл (например, звук) в упаковку результата | `#datafile "sound/misc/hit.wav"` |
| `#merge` | Подключает уже скомпилированный `.dat`-файл для совместного использования символов | `#merge "other.dat"` |
| `#forcecrc` | Задаёт принудительное значение CRC для итогового файла | `#forcecrc 12345` |
| `#copyright` | Задаёт строку авторских прав, добавляемую в результат | `#copyright My Mod` |
| `#packid`, `#pack1`…`#pack5` | Служебные директивы для упаковки нескольких pk3/pak в один результат | `#packid 12` |
| `#pragma` | Вызывает одну из директив компилятора (см. ниже) | `#pragma once` |

### Директивы `#pragma`

| `#pragma` | Что делает | Пример |
|---|---|---|
| `PROGS_DAT` | Меняет имя итогового файла, если оно не задано в командной строке | `#pragma PROGS_DAT "progs.dat"` |
| `target` (`TARGET`) | Меняет целевой формат байт-кода (см. [«Целевой формат байт-кода»](#целевой-формат-байт-кода--t) выше) | `#pragma target fte` |
| `once` | Подключает файл через `#include` не более одного раза | `#pragma once` |
| `noref` | Меняет поведение по умолчанию для предупреждения «переменная не используется» для следующих объявлений | `#pragma noref 1` |
| `nosave` | Меняет поведение по умолчанию для ключевого слова `nosave` для следующих объявлений | `#pragma nosave 1` |
| `defaultstatic` | Меняет, становятся ли глобальные переменные/функции файловыми (`static`) по умолчанию | `#pragma defaultstatic 1` |
| `autoproto` | Включает автоматическое прототипирование функций (двухпроходная компиляция) | `#pragma autoproto 1` |
| `optimise` / `optimize` | Меняет уровень или конкретную оптимизацию прямо из кода | `#pragma optimise 2` |
| `opcode` | Включает/выключает конкретные машинные инструкции байт-кода | `#pragma opcode enable MUL_F` |
| `keyword` | Включает/выключает конкретное ключевое слово языка прямо в процессе компиляции | `#pragma keyword enable inout` |
| `flag` | Включает/выключает конкретный поведенческий флаг компилятора прямо в процессе компиляции | `#pragma flag enable cpriority` |
| `warning` | Меняет статус конкретного предупреждения (`on`/`off`/[`error`](../37-quakec-builtins-reference/12-system-debug-builtins.md#error)) | `#pragma warning error deprecated` |
| `includedir` | Добавляет папку поиска для `#include`, относительно текущего файла | `#pragma includedir("../include")` |
| `compress` | Включает/выключает сжатие итогового файла | `#pragma compress 1` |
| `forcecrc` | То же, что директива `#forcecrc` | `#pragma forcecrc 12345` |
| `framerate` | Задаёт частоту кадров, используемую при расчёте `$frame`-макросов | `#pragma framerate 20` |
| `sourcefile` | Явно регистрирует исходные файлы в отладочных метаданных | `#pragma sourcefile foo.qc` |
| `file` / `line` | Подменяют отображаемое имя файла/номер строки в диагностике (для генераторов кода) | `#pragma line(120)` |
| `COPYRIGHT` | То же, что директива `#copyright` | `#pragma COPYRIGHT("My Mod")` |
| `DONT_COMPILE_THIS_FILE` | Пропускает остаток файла без компиляции | `#pragma DONT_COMPILE_THIS_FILE` |
| `wrasm` | Включает/выключает запись дампа ассемблера в `qc.asm` | `#pragma wrasm 1` |

Неизвестная директива `#pragma` не останавливает сборку — компилятор лишь выводит предупреждение о том, что она не распознана.

## Примеры

- Автор мода добавляет новую функцию в файл `weapons.qc`, набирает в игровой консоли [`compile`](../44-cli-commands-reference/04-server-multiplayer-commands.md#compile), затем [`applycompile`](../44-cli-commands-reference/04-server-multiplayer-commands.md#applycompile) — и тут же проверяет новое оружие в текущей тестовой игре, не выходя и не переподключаясь.
- Крупный командный проект держит два варианта `progs.src` — один с `#define MONSTERS` для одиночной игры с монстрами, другой без него для чисто многопользовательского режима, — и оба собираются из одного и того же набора файлов исходного кода.
- CI-скрипт собирает мод отдельной программой-компилятором: `fteqcc -src ./src -Tfte -O2 -Werror`, чтобы сборка падала при любом новом предупреждении.
- Мод подключает `#include "fteextensions.qc"` в начале `defs.qc` и сразу получает доступ к расширенным функциям FTEQW без переписывания объявлений вручную.
- При подозрительном поведении ИИ монстра ставится точка останова на функцию его принятия решений, и через строку инспекции проверяются текущие значения его внутренних переменных в момент остановки.
- При падении сервера с сообщением об ошибке в коде мода разработчик открывает автоматически созданный файл дампа в папке мода и по именам локальных переменных в нём понимает, какая именно функция и с какими данными привела к сбою.
