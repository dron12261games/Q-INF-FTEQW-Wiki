# Отладка и «горячая» пересборка логики

> [⬅ Вернуться к оглавлению вики](../README.md)

> Раздел: [Игровая логика: язык QuakeC](./README.md)

## Что это даёт геймдизайнеру

Движок содержит встроенные инструменты для разработки и отладки игровой логики (QuakeC) прямо во время игры, без необходимости в отдельной внешней среде разработки. Это значительно ускоряет процесс создания мода: можно вносить правки в код и почти сразу проверять результат, а если что-то пошло не так — пошагово пройти по коду и увидеть, что именно происходит внутри, вплоть до значений отдельных переменных в момент ошибки.

## Интерфейс настройки

- **Встроенный компилятор.** Команда `compile [имя_файла.src]` собирает исходный код мода (по умолчанию `progs.src`, либо `csprogs.src` для клиентской логики) прямо внутри запущенного движка; движок сам ищет исходники в подпапках `qc`, `progs` или прямо в папке мода, если явный путь не найден. Обратная операция — команда **`decompile [имя.dat]`** — превращает уже скомпилированный `.dat`-файл обратно в примерный QuakeC-исходник, что полезно для изучения устройства чужих модов, если их исходный код недоступен.
- **Применение изменений без перезапуска.** Команда `applycompile` подхватывает только что пересобранный код «на лету» — по сути это быстрое сохранение и мгновенная загрузка игры, — позволяя проверить исправление одной функции, не отключая игроков от сервера и не перезапуская карту. Важно понимать: этот способ не может сам по себе изменить структуру данных (добавить новые игровые поля) — только логику существующего кода.
- **Точки останова.** Команда `breakpoint <имя_файла> <номер_строки>` устанавливает (или снимает, если уже была установлена в этом же месте) точку останова по конкретному файлу исходного кода и номеру строки в нём — повторный вызов с теми же аргументами переключает её обратно. Для клиентской и MenuQC логики существуют отдельные команды **`breakpoint_csqc`** и **`breakpoint_menuqc`** с тем же синтаксисом, работающие с соответствующей вирту­альной машиной. Дополнительно доступна команда **`watchpoint <имя_переменной>`** (и её клиентский аналог `watchpoint_ssqc`), которая останавливает выполнение не по конкретной строке, а в момент, когда изменится значение указанной глобальной переменной — независимо от того, в какой функции это произошло. Условие для включения полноценной пошаговой отладки — включённая переменная `developer 1` и наличие рядом с прогс-файлом отладочного файла соответствий (создаётся автоматически любым современным QuakeC-компилятором вместе с самим прогс-файлом).
- **Программная точка останова прямо из кода мода.** Встроенная функция QuakeC **`breakpoint()`** (без аргументов) может быть вызвана прямо в исходном коде — при её достижении движок немедленно останавливает выполнение точно так же, как если бы здесь стояла точка останова, поставленная командой из консоли; на движках, не реализующих отладчик, аналогичный вызов может вместо этого привести к аварийному завершению с отладочным исключением.
- **Управление в момент остановки** (когда доступен графический интерфейс — то есть не на выделенном сервере без экрана):
  - `F11` — выполнить следующую строку кода (шаг внутрь вызовов);
  - `F9` — включить/выключить точку останова;
  - `F5` — продолжить выполнение до следующей точки останова;
  - строка ввода для проверки значений переменных прямо в момент остановки (можно даже присвоить переменной новое значение для проверки, но нельзя вызывать функции);
  - `Escape` — закрыть отладчик и продолжить выполнение как обычно.
  - На выделенном сервере без графического интерфейса вместо интерактивного отладчика движок просто построчно печатает в консоль код исполняемых строк.
- **Принудительное включение трассировки из самого кода мода** — специальная функция, которую можно вызвать прямо в исходниках, чтобы включить пошаговый режим программно, а не только вручную командой.
- **Аварийные дампы состояния.** Если движок обнаруживает, что причиной сбоя стал именно код мода, он автоматически создаёт файл-дамп в текущей игровой папке с информацией о состоянии переменных функций, всё ещё «стоявших в очереди» на момент сбоя — это можно изучить позже, чтобы понять причину падения. Дамп можно также создать вручную командой на серверной стороне.

## Примеры

- Разработчик правит функцию расчёта урона, выполняет `compile`, затем `applycompile` — и сразу же в текущем бою видит, что урон рассчитывается правильно, без выхода из игры.
- При подозрительном поведении ИИ монстра ставится точка останова на функцию его принятия решений, и через строку инспекции проверяются текущие значения его внутренних переменных в момент остановки.
- После падения сервера, вызванного ошибкой в моде, разработчик изучает автоматически созданный аварийный дамп, чтобы понять, какая функция и с какими значениями переменных привела к сбою.
