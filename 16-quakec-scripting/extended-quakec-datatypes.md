# Расширенные типы данных и встроенные функции в QuakeC

> [⬅ Вернуться к оглавлению вики](../README.md)

> Раздел: [Игровая логика: язык QuakeC](./README.md)

## Что это даёт геймдизайнеру

Классический язык QuakeC изначально был довольно ограниченным — он умел работать только с числами, строками, векторами (точками в пространстве), игровыми объектами (`entity`) и функциями, и предоставлял лишь около восьмидесяти встроенных команд. Движок значительно расширяет возможности этого языка, добавляя ему множество дополнительных встроенных функций («билтинов»), привычных по современным языкам программирования и играм. Это не меняет ничего в файлах игрока — это возможности, которыми пользуется **разработчик мода при написании кода** — но напрямую влияет на то, насколько сложную и надёжную логику можно реализовать без искусственных обходных путей и как быстро мод будет работать.

Ниже — подробный, сгруппированный по темам список всех таких расширений с описанием каждой функции.

## Интерфейс настройки

Все перечисленные ниже возможности доступны разработчику мода в виде обычных вызовов функций прямо в исходном коде QuakeC, если в проекте подключены соответствующие объявления (обычно они уже включены в стандартный заголовочный файл расширений, поставляемый вместе с компилятором). Игроку/пользователю файлов игры настраивать здесь нечего — это часть программного интерфейса, которым пользуется автор мода.

### Битовые операции

- **`bitshift(число, количество)`** — сдвигает биты числа: при положительном количестве — влево, при отрицательном — вправо. Позволяет компактно хранить наборы флагов в одном числовом поле вместо десятка отдельных полей.

### Система «измерений» (раздельная видимость и столкновения)

- **`dimension_see`** / **`dimension_seen`** (поля игрока/объекта) — объект виден игроку, только если их битовые маски совпадают (`player.dimension_see & other.dimension_seen`). Позволяет делать объекты, видимые только части игроков — например, отдельно для каждой команды.
- **`dimension_send`** — аналогичная маска, но применяется к широковещательным сетевым сообщениям, а не к отдельным объектам.
- **`dimension_ghost`** / **`dimension_ghost_alpha`** — если у объекта установлен бит измерения, не входящий в `dimension_seen` наблюдателя, объект всё равно останется виден, но его прозрачность будет умножена на `dimension_ghost_alpha` (по умолчанию — половина непрозрачности). Удобно для полупрозрачных «духов» или подсказок, видимых только части игроков в приглушённом виде.
- **`dimension_solid`** / **`dimension_hit`** — раздельные битовые маски для физических столкновений между объектами: объект А касается объекта Б, только если `A.dimension_hit & B.dimension_solid`. Позволяет одному объекту сталкиваться с миром, но проходить сквозь определённые другие объекты (и наоборот).

### Получение текущего времени суток

- **`calltimeofday()`** — запрашивает у движка текущее реальное время (не игровое, а системные часы) и передаёт его в сопутствующую функцию, которая раскладывает результат по глобальным переменным: `tod_sec`, `tod_min`, `tod_hour`, `tod_day`, `tod_mon`, `tod_year`, а также готовую строку `tod_string`. Полезно для механик, завязанных на реальное время суток (например, разное освещение днём и ночью на сервере, работающем круглосуточно).

### Скелетная анимация напрямую из кода («скелетные объекты»)

Эта группа функций позволяет программно управлять «скелетом» персонажа — костями и их поворотами — а не просто проигрывать готовые заранее анимации:

- **`skel_create(индекс_модели)`** — создаёт новый скелет для указанной модели, возвращает его номер (или 0, если модель не скелетная); результат нужно сохранить в поле `skeletonindex` объекта.
- **`skel_build(скелет, объект, индекс_модели, доля_сохранения, первая_кость, последняя_кость)`** — подмешивает в скелет стандартную проигрываемую анимацию объекта (поля `frame`/`frame2`/`lerpfrac`/`frame1time`/`frame2time`) в указанном диапазоне костей: `0` — заменить полностью, `1` — не менять вообще, `0.5` — смешать пополам. Диапазон костей позволяет анимировать, например, только ноги или только голову.
- **`skel_get_numbones(скелет)`** — возвращает количество костей в скелете.
- **`skel_get_bonename(скелет, номер_кости)`** — возвращает имя кости.
- **`skel_get_boneparent(скелет, номер_кости)`** — возвращает номер родительской кости (или -1, если кость корневая).
- **`skel_find_bone(скелет, "имя")`** — находит номер кости по её имени.
- **`skel_get_bonerel(скелет, номер_кости)`** / **`skel_get_boneabs(скелет, номер_кости)`** — получают положение и ориентацию кости относительно родителя или относительно всей модели соответственно (записывают ориентацию в `v_forward`/`v_right`/`v_up`, возвращают позицию).
- **`skel_set_bone(скелет, номер_кости, позиция)`** — задаёт положение и ориентацию кости относительно родительской (читает `v_forward`/`v_right`/`v_up` перед вызовом).
- **`skel_mul_bone(скелет, номер_кости, позиция)`** / **`skel_mul_bones(скелет, первая, последняя, позиция)`** — домножают текущую матрицу одной кости или диапазона костей на заданное преобразование — удобно для «довесочных» поворотов (например, довернуть голову к цели поверх обычной анимации ходьбы).
- **`skel_copybones(скелет_куда, скелет_откуда, первая, последняя)`** — копирует позы костей из одного скелета в другой, например, чтобы «заморозить» позу персонажа на трупе в момент смерти.
- **`skel_delete(скелет)`** — освобождает скелет (можно вызывать в конце текущего кадра, до этого он ещё будет корректно отрисован).
- **`frameforname(индекс_модели, "имя")`** — находит номер анимации по её имени.
- **`frameduration(индекс_модели, номер_анимации)`** — возвращает длительность анимации в секундах.

Типичные применения: смешивание нескольких анимаций одновременно, независимая анимация разных частей тела (ноги/торс/голова), собственные «контроллеры костей» (например, слежение взглядом за целью), использование анимаций из одной модели на скелете другой совместимой модели.

### Работа с шейдерами Quake III прямо из кода

- **`skinforname(индекс_модели, "имя_скина")`** — получает числовое значение скина для указанной модели по имени файла `.skin`.
- **`shaderforname("имя_шейдера")`** — получает числовой идентификатор шейдера по имени, который затем можно передать обратно движку.
- **`forceshader`** (поле объекта) — если задано, заставляет все поверхности объекта использовать указанный шейдер независимо от того, что прописано в самой модели.

### Проверка видимости и переполнения канала

- **`checkpvs(точка_обзора, объект)`** — возвращает истину, если объект потенциально виден из указанной точки согласно предрасчитанным данным видимости карты (PVS). Для повышения производительности рекомендуется не менять точку обзора слишком часто между вызовами подряд.
- **`isbackbuffered(игрок)`** — сообщает, не «захлёбывается» ли исходящий канал данных конкретного игрока (данные ставятся в очередь, а не отправляются немедленно). Полезно перед тем, как разом отправить игроку много данных, чтобы не вызвать переполнение и отключение по таймауту.

### Поиск игроков по имени

- **`matchclients("шаблон", номер_совпадения)`** — ищет среди подключённых игроков тех, чьё имя соответствует шаблону (поддерживается `*` как маска); номер совпадения выбирает, какого по счёту из нескольких найденных вернуть (0 — первого).
- **`matchclient("шаблон")`** — то же самое, но рассчитан ровно на одно совпадение — завершится ошибкой, если совпадений оказалось больше одного.

### Кооперативная многопоточность

Движок предоставляет псевдо-многопоточность прямо внутри игровой логики — код может «засыпать» и продолжать выполнение позже, без необходимости вручную хранить, на каком шаге он остановился:

- **`sleep(секунды)`** — приостанавливает выполнение текущего потока кода на заданное время. Если движок в этот момент ожидал от кода возвращаемое значение, оно временно станет нулевым/пустым.
- **`fork()`** — «расщепляет» выполнение на два продолжения: функция как бы возвращает управление дважды, с двумя разными результатами вызова — это основа для построения независимо «спящих» процессов внутри одной функции.
- **`abort(значение)`** — завершает текущий поток исполнения, возвращая управление движку (и, если нужно, конкретное значение как результат вызова).

Единственные переменные, которые остаются у каждого потока «свои» — это `self` и `other`; все остальные глобальные переменные общие для всех потоков и могут быть изменены другим потоком между переключениями. Поскольку объекты могут быть удалены, пока поток «спит», для проверки этого стоит использовать поле `uniquespawnid` (см. ниже) или встроенную проверку на «объект уже уничтожен».

### Уникальный идентификатор объекта при создании

- **`uniquespawnid`** (поле объекта) — увеличивается на единицу при каждом создании нового объекта, гарантируя, что даже если два разных объекта используют одну и ту же ячейку памяти движка друг за другом, их можно отличить — полезно при работе с «уснувшими» потоками (см. выше), которые могут проснуться уже после того, как объект, который они помнят, был удалён и заменён другим.

### Расширенная работа со строками

- **`strstrofs(строка, подстрока, начальная_позиция)`** — находит позицию вхождения подстроки (или -1, если не найдена), с учётом регистра.
- **`str2chr(строка, позиция)`** — возвращает код символа по указанной позиции (с поддержкой многобайтных символов UTF-8, если движок их поддерживает).
- **`chr2str(код, ...)`** — обратное преобразование: код символа обратно в строку (может быть несколько байт для символов старше 127 при поддержке UTF-8).
- **`strconv(регистр, цвет_букв, цвет_цифр, строка, ...)`** — перекодирует строку под специальные цветные символы шрифта консоли (актуально только для не-UTF8 движков — на современных движках вместо этого стоит использовать обычные цветовые коды вида `^4`).
- **`strpad(количество_символов, строка, ...)`** — дополняет строку пробелами до нужной длины (отрицательное число — выравнивание слева, положительное — справа).
- **`infoadd("infostring", "ключ", "значение", ...)`** — добавляет или заменяет пару ключ/значение в инфостроке (запрещённые символы — `\` и `"`).
- **`infoget("infostring", "ключ")`** — читает значение по ключу из инфостроки.
- **`strncmp(строка1, строка2, длина)`** / **`strcasecmp(строка1, строка2)`** / **`strncasecmp(строка1, строка2, длина)`** — сравнение строк с ограничением по длине и/или без учёта регистра.
- **`substring(строка, начало, длина)`** — вырезает часть строки; при этом отрицательные значения начала/длины отсчитываются от конца строки (например, `substring("blah", -3, 3)` вернёт `"lah"`).

### Готовые функции для классических визуальных эффектов

Набор готовых функций для проигрывания знакомых по классическому Quake визуальных эффектов «во временных объектах» без необходимости вручную формировать сетевое сообщение: `te_gunshot`, `te_spike`, `te_superspike`, `te_explosion`, `te_tarexplosion`, `te_wizspike`, `te_knightspike`, `te_lavasplash`, `te_teleport`, `te_lightning1`/`te_lightning2`/`te_lightning3` (молния между двумя точками, с привязкой к объекту-владельцу), `te_lightningblood`, `te_bloodqw` (с указанием количества частиц крови).

### Прочие расширения

- **Ладдер как отдельный тип твёрдости (`SOLID_LADDER`)** — ведёт себя как обычный триггер, но дополнительно отключает игроку гравитацию и позволяет двигаться как по лестнице, пока он находится внутри объёма.
- **Расширенные флаги трассировки** — `FL_FINDABLE_NONSOLID` (влияет на `findradius`, позволяя находить нетвёрдые объекты), `MOVE_TRIGGERS`/`MOVE_EVERYTHING` (дополнительные режимы для `traceline`, заставляющие луч также реагировать на триггеры и нетвёрдые объекты с соответствующим флагом).
- **Модульные прогс-файлы (addon/multiprogs)** — набор функций для общения между несколькими одновременно загруженными скомпилированными файлами логики: `externcall`/`externvalue` (вызвать функцию или прочитать переменную в другом прогс-файле по имени), `externset` (записать значение), `addprogs` (подключить ещё один прогс-файл), `thisprogs` (номер текущего прогс-файла). Подробнее — см. [«Множественные аддон-скрипты и модульные прогс-файлы»](./addon-modular-progs.md).
- Разработчики также могут пользоваться значительно расширенным набором стандартных возможностей самого языка компилятора (необязательные параметры функций, более широкий набор системных функций для работы со строками и файлами — см. [«Чтение и запись файлов из скриптов»](../18-data-access-from-scripts/file-read-write-from-scripts.md) и [«Встроенная база данных и SQL»](../18-data-access-from-scripts/embedded-database-sql.md)), что напрямую не является частью самого движка, но становится доступным именно благодаря используемому вместе с движком компилятору.

## Примеры

- Мод использует битовые флаги (`bitshift`), чтобы компактно хранить в одном числовом поле сразу десяток независимых булевых состояний персонажа, вместо создания десяти отдельных полей.
- Скелетная анимация используется для того, чтобы голова NPC плавно поворачивалась вслед за игроком поверх обычной проигрываемой анимации ходьбы — через `skel_build` с последующим `skel_mul_bone` только на кости головы.
- Система измерений используется, чтобы игроки одной команды не видели заранее расставленные ловушки другой команды на одной и той же карте.
- Кооперативная многопоточность используется, чтобы описать длинную сюжетную сценку («подожди 2 секунды, скажи фразу, подожди ещё 3 секунды, открой дверь») одной линейной функцией вместо цепочки из полудюжины `think`-функций.
