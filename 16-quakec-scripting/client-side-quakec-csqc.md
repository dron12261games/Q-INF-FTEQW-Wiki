# Клиентская логика и интерфейс (CSQC)

> [⬅ Вернуться к оглавлению вики](../README.md)

> Раздел: [Игровая логика: язык QuakeC](./README.md)

## Что это даёт геймдизайнеру

CSQC (Client-Side QuakeC) — это второй, отдельный скрипт на том же языке, что и SSQC, но выполняющийся **на компьютере каждого игрока**, а не на сервере. Он отвечает за всё, что видит и слышит именно этот игрок: отрисовку экрана и HUD (интерфейса поверх игры), реакцию на нажатия клавиш и движения мыши до того, как они уйдут на сервер, локальные визуальные эффекты (искры, частицы, кастомную анимацию), а также может полностью заменить стандартный игровой экран собственным. Это открывает возможность делать полностью кастомные интерфейсы, HUD-элементы, зрительские режимы и локальные эффекты без нагрузки на сервер и без необходимости пересылать по сети лишние данные.

Ниже — не только общая идея, но и подробный справочник по тому, какие именно функции ожидает от CSQC-скрипта движок, и какой полный набор инструментов рисования/чтения сети/управления доступен разработчику.

## Интерфейс настройки

CSQC компилируется в отдельный бинарный файл, по умолчанию называемый **`csprogs.dat`** — его имя определяется серверной переменной `sv_csqc_progname` (по умолчанию `csprogs.dat`). Сервер должен явно разрешить использование клиентской логики и указать, каким игрокам её загружать — если сервер не подключает CSQC, движок показывает игроку встроенный интерфейс по умолчанию.

Как и SSQC, клиентский скрипт можно собрать заранее и просто положить `csprogs.dat` в папку мода, либо прямо в движке командой `compile csprogs.src`.

### Точки входа, которые вызывает движок

| Функция | Когда вызывается |
|---|---|
| `CSQC_Init()` | один раз при загрузке клиентской логики — стартовая точка для инициализации |
| `CSQC_WorldLoaded()` | когда клиент загрузил новую карту — здесь удобно через `getentitytoken` вручную прочитать список объектов карты и создать чисто клиентские объекты (например, декоративные телепорты, не существующие на сервере) |
| `CSQC_UpdateView(ширина, высота, меню_открыто)` | каждый кадр — здесь описывается, что и как рисовать на экране целиком (мир, HUD, текст, картинки); если параметр «меню открыто» ложен, скрипт обязан также нарисовать HUD и таблицу результатов сам |
| `CSQC_InputEvent(тип_события, параметр_a, параметр_b)` | при нажатии клавиш, кнопок мыши или движении — позволяет перехватывать и переопределять управление ещё до того, как оно уйдёт в стандартную обработку; события: `0` — клавиша нажата, `1` — клавиша отпущена, `2` — движение мыши (тогда параметры — это смещение по X и Y); возвращаемое значение «истина» говорит движку полностью проигнорировать это нажатие |
| `CSQC_ConsoleCommand("команда")` | когда игрок вводит команду, заранее зарегистрированную через `registercommand` |
| `CSQC_Parse_StuffCmd("текст")` | когда сервер присылает команду на выполнение в консоли клиента — вместо автоматического исполнения решение об этом отдаётся на откуп скрипту |
| `CSQC_Parse_CenterPrint("текст")` | при получении от сервера текста для центрального сообщения на экране |
| `CSQC_Parse_Print("текст", тип_сообщения)` | при получении обычного текста в консоль/чат от сервера |
| `CSQC_Ent_Update(новый_ли)` | при получении обновления сетевого объекта, отправленного специально для CSQC (см. ниже про `SendEntity`) |
| `CSQC_Event_Sound(...)` | при получении события звука с сервера |
| `CSQC_Remove()` | когда объект удалён/скрыт на сервере |
| `CSQC_Shutdown()` | при штатной выгрузке CSQC |

Все перечисленные функции необязательны — если какая-то из них не описана в коде мода, движок просто её не вызывает.

### Управление 3D-сценой

- **`clearscene()`** — очищает список объектов для отрисовки и сбрасывает параметры вида к значениям по умолчанию; вызывается в начале каждого кадра.
- **`addentities(маска)`** — добавляет в сцену все «известные» объекты, отфильтрованные по битовой маске: `MASK_ENGINE` (обычные объекты, присланные не через CSQC-канал, включая классические временные эффекты), `MASK_ENGINEVIEWMODEL` (стандартная модель оружия от первого лица). Перед добавлением каждого объекта для него вызывается функция `predraw`.
- **`addentity(объект)`** — добавляет в сцену ровно один конкретный объект немедленно (без вызова его `predraw`) — удобно для добавления «дополнительных копий» объекта (например, эффект щита вокруг игрока).
- **`setviewprop(свойство, значение)`** / **`getviewpropf(свойство)`** / **`getviewpropv(свойство)`** — читают и меняют параметры текущего вида камеры. Основные свойства: `VF_MIN`/`VF_MIN_X`/`VF_MIN_Y` (верхний левый угол области вывода), `VF_SIZE`/`VF_SIZE_X`/`VF_SIZE_Y` (размер области вывода), `VF_VIEWPORT` (полный прямоугольник вьюпорта), `VF_FOV`/`VF_FOVX`/`VF_FOVY` (угол обзора), `VF_ORIGIN`/`VF_ORIGIN_X/Y/Z` (позиция камеры), `VF_ANGLES`/`VF_ANGLES_X/Y/Z` (углы обзора камеры), `VF_DRAWWORLD` (рисовать ли вообще мир и частицы), `VF_DRAWENGINESBAR` (рисовать ли стандартный статус-бар движка), `VF_DRAWCROSSHAIR` (рисовать ли стандартный прицел).
- **`adddynamiclight(позиция, радиус, цвет)`** — добавляет в сцену динамический источник света на этот кадр.
- **`renderscene()`** — фактически выполняет отрисовку всего, что было добавлено с момента `clearscene`, согласно текущим параметрам вида; список объектов при этом не очищается автоматически.
- **`project(вектор)`** / **`unproject(вектор)`** — переводят координаты между трёхмерным игровым пространством и двумерным пространством экрана (с глубиной в диапазоне 0…1) с учётом текущих параметров вида.

### Двумерная отрисовка интерфейса

- **`drawpic(позиция, "имя картинки", размер, цвет, прозрачность)`** — отрисовывает изображение.
- **`drawsubpic(...)`** (расширение) — отрисовывает часть изображения (фрагмент текстуры) — полезно для атласов иконок.
- **`drawfillrgb(позиция, размер, цвет, прозрачность)`** — закрашивает прямоугольник сплошным цветом (могут не поддерживать простые программные рендеры).
- **`drawfillpal(позиция, размер, индекс_палитры)`** — закрашивает прямоугольник цветом из палитры Quake.
- **`drawcharacter(позиция, код_символа, размер, цвет, прозрачность)`** — рисует один символ стандартным шрифтом консоли.
- **`drawrawstring(позиция, "текст", размер, цвет, прозрачность)`** — рисует строку текста стандартным шрифтом консоли без разметки цвета и без переноса строк.
- **`drawcolorcodedstring(позиция, "текст", масштаб, прозрачность)`** — рисует текст с поддержкой цветовой разметки консоли (включая цветовые коды вида `^4`), с возможностью переменной ширины шрифта.
- **`drawstring(...)`** — упрощённый аналог для быстрой печати строки на экране, широко используемый для HUD.
- **`precache_pic("имя")`** / **`is_cached_pic("имя")`** / **`free_pic("имя")`** — предзагружает изображение, проверяет, что оно уже загружено, и выгружает его из памяти соответственно.
- **`drawgetimagesize("имя")`** — возвращает размеры изображения (или «0 0 0», если оно не загрузилось).

### Модели, частицы и звук

- **`setmodelindex(объект, индекс_модели)`** — присваивает объекту модель по числовому индексу.
- **`modelnameforindex(индекс_модели)`** — возвращает имя файла модели по её индексу.
- **`particleeffectnum("имя_эффекта")`** — получает номер именованного эффекта частиц (в т.ч. стандартных: `te_explosion`, `te_tarexplosion`, `te_gunshot`, `te_wizspike`, `te_knightspike`, `te_spike`, `te_superspike`, `te_teleport`, `te_lavasplash`) для дальнейшей передачи в функции ниже.
- **`pointparticles(номер_эффекта, позиция, скорость, множитель_количества)`** — проигрывает частицы точечного эффекта (без звука и без динамического света).
- **`trailparticles(номер_эффекта, объект, начало, конец)`** — проигрывает частицы эффекта-«шлейфа» вдоль отрезка (объект используется, чтобы шлейф оставался связным между кадрами при высоком fps; можно передать `world` для независимого одноразового луча).
- **`setlistener(позиция, вперёд, вправо, вверх)`** — задаёт положение и ориентацию «слушателя» для объёмного звука; рекомендуется обновлять каждый кадр, особенно при использовании предсказания движения.

### Управление вводом, вид и предсказание движения

- **`setsensitivityscaler(множитель)`** — временно масштабирует чувствительность мыши игрока (удобно для реализации приближения оптического прицела); сбрасывается только при перезагрузке CSQC.
- **`getinputstate(номер_кадра)`** — считывает угол обзора и другие параметры ввода конкретного кадра предсказания в глобальные переменные `input_*`; возвращает ложь, если кадр устарел. Работает совместно с глобальными переменными `servercommandframe` (последний подтверждённый сервером кадр) и `clientcommandframe` (последний сгенерированный клиентом кадр) — кадры между ними нужно «доиграть» самостоятельно для правильного предсказания.
- **`runplayerphysics(объект)`** — прогоняет через объект встроенный алгоритм предсказания движения движка (читает `input_*`, меняет `origin`/`velocity`/`pmove_flags`, вызывает функции столкновений).
- **`keynumtostring(код_клавиши)`** / **`stringtokeynum("имя")`** — преобразуют код клавиши в её текстовое имя (как в команде `bind`) и обратно.
- **`getkeybind(код_клавиши)`** — возвращает полную команду, привязанную к клавише.
- **`deltalisten("имя модели", функция_обновления, флаги)`** — регистрирует функцию, вызываемую при получении любого сетевого объекта с указанной моделью — способ выборочно «подписаться» на серверные объекты определённого типа. Флаги: `RSES_NOLERP` (отключить интерполяцию положения — критично для собственного игрока при предсказании), `RSES_NOROTATE` (не применять автоповорот по эффектам), `RSES_NOTRAILS` (не добавлять автоматический шлейф), `RSES_NOLIGHTS` (не добавлять автоматический динамический свет).

### Чтение сетевых сообщений

Когда движок передаёт CSQC на разбор специально адресованное сетевое сообщение, доступны builtin-функции последовательного чтения (действительны только в момент разбора): **`readbyte`**, **`readchar`**, **`readshort`**, **`readlong`**, **`readcoord`**, **`readangle`**, **`readstring`**, **`readfloat`**, **`readentitynum`** (последняя — читает номер объекта, который нужно сопоставить с полем `entnum`).

### Статистика игрока (stat'ы) и данные других игроков

- **`getstatf(номер)`** / **`getstati(номер)`** / **`getstati_bits(номер, начальный_бит, количество_бит)`** / **`getstats(номер)`** — читают числовое (с плавающей точкой, целое, отдельные биты) или строковое значение стата игрока, посланное сервером.
- **`getplayerkey(номер_игрока, "ключ")`** — получает данные другого игрока для табло результатов: имя, число фрагов, цвета команды (отрицательные номера означают выборку по месту в таблице лидеров: `-1` — первое место и т.д.).
- **`serverkey("ключ")`** — получает информацию о самом сервере (например, `ip` — адрес, использованный для подключения).
- **`getentitytoken()`** — доступна только внутри `CSQC_WorldLoaded`; последовательно возвращает пары «ключ/значение» из текстового описания объектов карты (аналогично тому, как сам движок читает объекты при загрузке), что позволяет создать собственные чисто клиентские версии таких объектов.

### Разное

- **`registercommand("имя")`** — регистрирует консольную команду с наивысшим приоритетом (даже выше алиасов); при вводе вызывается `CSQC_ConsoleCommand`.
- **`wasfreed(объект)`** — сообщает, был ли объект недавно удалён и ещё не был переиспользован повторно (полезно после того, как код «поспал» — см. кооперативную многопоточность — и не уверен, жив ли ещё объект, который он помнит).
- **`sendevent("имя", "типы_аргументов", ...)`** — отправляет на сервер именованное событие, которое там обрабатывается функцией `Cmd_имя_типы` (поддерживаемые типы аргументов: `f`-число, `e`-объект, `v`-вектор, `s`-строка; максимум 6 дополнительных аргументов).
- **`cprint("текст", ...)`** — быстрый способ показать центральное сообщение на экране, тем же способом, что и стандартный ответ сервера (в отличие от прихода настоящего сетевого сообщения, не вызывает `CSQC_Parse_CenterPrint`).
- **`print("текст", ...)`** — выводит текст в консоль и в область уведомлений (аналог `dprint`, но без необходимости включённого режима разработчика).
- **`isdemo()`** — сообщает, идёт ли сейчас проигрывание демозаписи.
- **`isserver()`** — сообщает, может ли мод напрямую взаимодействовать с сервером через переменные и консольные команды (актуально в одиночной игре/при администрировании, но не должно использоваться, если на сервере есть настоящее голосование/античит).

### Как устроена отправка объектов именно на CSQC (для тех, кто хочет разобраться глубже)

На стороне SSQC для полностью кастомных сетевых объектов используется отдельная пара полей:

- **`.SendEntity(зритель, флаги_отправки)`** — функция, которую сервер вызывает для каждого потенциального зрителя объекта: она сама решает, отправлять ли объект (вернув ложь — не отправлять, что удалит уже известную зрителю копию), и сама формирует содержимое сообщения через стандартные функции записи данных.
- **`.SendFlags`** — битовая маска «что изменилось с прошлой отправки»; логика должна лишь добавлять биты (через `|`), а не затирать их — движок сам периодически сбрасывает это поле после копирования.
- **`.pvsflags`** — управляет тем, как строго учитывается видимость объекта: обычная видимость, видимость с учётом «зоны слышимости», без учёта видимости вовсе, либо (`PVSF_NOREMOVE`) не удалять объект у клиента даже после того, как он скрылся из видимости.
- **`clientstat(индекс, тип, поле)`** / **`globalstat(индекс, тип, "имя")`** — регистрируют автоматическую отправку каждому игроку значения указанного поля (индивидуально для каждого) либо глобальной переменной (одинаково для всех) в виде стандартного «стата», без необходимости вручную писать сетевой код.

## Примеры

- Полностью кастомный HUD мода рисует свою полосу здоровья и счётчик патронов через `drawpic`/`drawstring`, читая нужные значения через `getstatf`, вместо использования стандартного интерфейса движка.
- Мод перехватывает нажатие определённой клавиши в `CSQC_InputEvent`, чтобы локально, без задержки на отправку данных серверу, открыть кастомное меню инвентаря.
- Оружие со снайперским прицелом вызывает `setsensitivityscaler(0.3)` при удержании кнопки прицеливания, возвращая обычную чувствительность при отпускании.
- Зрительский (наблюдательский) режим полностью реализован в CSQC, используя `getplayerkey` для построения табло результатов без лишней нагрузки на сервер.
- Полностью кастомный сетевой объект (например, индикатор здоровья союзника у него над головой) реализован через `.SendEntity`/`.SendFlags`, минуя стандартный протокол видимых объектов.
