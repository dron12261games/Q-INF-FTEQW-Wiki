## Объяснение на пальцах

Движок полностью поддерживает исходный формат моделей из классического Quake — **MDL**. Это простые «покадровые» модели: у них нет скелета и костей, а анимация — это заранее просчитанный набор полностью готовых кадров (положений всех вершин модели), которые проигрываются подряд, как флипбук. Такой формат прост в создании, отлично работает на любом железе, и с ним по-прежнему совместим весь классический контент и инструментарий, созданный ещё для оригинальной игры.

Дополнительно поддерживается формат **SPR** — плоские спрайты (двумерные картинки, которые движок разворачивает в пространстве по одному из нескольких доступных правил ориентации — не только строго «лицом к камере», как принято думать), которые использовались, например, для взрывов, огня и подобных эффектов, не требующих настоящего трёхмерного объёма.

---

## Базовая логика

Файл `.mdl` при загрузке превращается в набор именованных кадров: игровая логика ссылается на конкретный кадр по его порядковому номеру (или, что удобнее для чтения кода, по имени, зашитому в модели ещё на этапе её создания), а движок сам отвечает за интерполяцию между соседними кадрами при проигрывании анимации, чтобы движение выглядело плавным, даже если исходных кадров было немного (классический приём экономии памяти в играх середины 90-х). Спрайты `.spr`, в отличие от моделей, всегда состоят из плоских прямоугольных кадров, но при этом сам файл хранит не одну-единственную схему ориентации в пространстве, а одну из пяти возможных — от классического разворота исключительно вокруг вертикальной оси (полезно для дыма и огня, которые всегда должны стоять «столбом») до полного разворота лицом к камере во всех направлениях (типично для вспышек выстрелов и мелких частиц).

## Пошаговый туториал: подключение первой классической модели

**Шаг 1.** Подготовьте файл модели в формате `.mdl` (или спрайта `.spr`) любым специализированным редактором, поддерживающим этот формат.

**Шаг 2.** Положите файл в подпапку `progs/` внутри папки мода, например `mymod/progs/mymonster.mdl`.

**Шаг 3.** В игровой логике (QuakeC) заранее «прекэшируйте» модель функцией [`precache_model("progs/mymonster.mdl")`](../37-quakec-builtins-reference/07-precache-resources-builtins.md#precache_model), чтобы движок загрузил её в память до первого фактического появления объекта в игре.

**Шаг 4.** Свяжите модель с игровым объектом функцией [`setmodel(self, "progs/mymonster.mdl")`](../37-quakec-builtins-reference/03-entity-world-builtins.md#setmodel).

**Шаг 5.** Задайте текущий кадр анимации через поле `self.frame = 0` (или другое число, соответствующее нужной позе) — при необходимости меняйте это значение по игровому таймеру, чтобы проиграть последовательность кадров как анимацию.

## Интерфейс настройки

Файлы моделей и спрайтов просто кладутся в игровую папку (обычно в подпапку `progs/`) с расширениями **`.mdl`** и **`.spr`** соответственно. Дальше на них ссылается игровая логика (см. [«Серверная игровая логика (SSQC)»](../16-quakec-scripting/server-side-quakec-ssqc.md)) — указывая путь к файлу модели при создании игрового объекта, а также номер и скорость проигрывания анимационных кадров.

Никаких дополнительных текстовых описаний не требуется — вся геометрия, текстура и кадры анимации целиком «зашиты» внутри самого `.mdl`/`.spr`-файла; создаются такие модели специализированными редакторами моделей для классического Quake.

## Инженерный справочник: типы ориентации спрайтов (поле `type` внутри `.spr`)

| Значение | Название | Дотошное описание поведения |
| :--- | :--- | :--- |
| `0` | `SPR_VP_PARALLEL_UPRIGHT` | Спрайт всегда развёрнут по горизонтали лицом к камере, но его вертикальная ось всегда направлена строго вверх — классическое поведение для столбов дыма и огня, которые не должны «заваливаться» при взгляде сверху или снизу |
| `1` | `SPR_FACING_UPRIGHT` | Спрайт развёрнут точно на игрока (а не просто на плоскость камеры) по горизонтали, вертикальная ось также всегда направлена вверх — вариант с более точным разворотом на позицию наблюдателя |
| `2` | `SPR_VP_PARALLEL` | Классическое поведение обычного спрайта — плоскость спрайта всегда параллельна плоскости экрана камеры, разворот происходит по всем осям одновременно |
| `3` | `SPR_ORIENTED` | Спрайт вообще не разворачивается к камере — вместо этого он жёстко ориентирован в мировом пространстве по осям, заданным при создании модели, как обычная плоская декаль на стене |
| `4` | `SPR_VP_PARALLEL_ORIENTED` | Спрайт сперва разворачивается лицом к камере, а затем дополнительно поворачивается вокруг своей нормали на угол, заданный игровой логикой — используется для эффектов, которым нужно и смотреть на игрока, и при этом иметь собственное вращение (например, вращающиеся вспышки) |
| `8` | `SPR_ORIENTED` с двусторонней отрисовкой (`SPR_ORIENTED_BACKFACE`) | То же самое жёсткое мировое ориентирование, что и у типа `3`, но с дополнительной отрисовкой обратной стороны спрайта — полезно, когда декаль-спрайт может быть виден с обеих сторон поверхности |

## Практический пример 1: монстр с покадровой анимацией атаки

```
precache_model("progs/ogre.mdl");
...
setmodel(self, "progs/ogre.mdl");
self.frame = 0;      // кадр стойки/ожидания
...
// в момент начала атаки:
self.frame = 12;     // конкретный кадр, соответствующий замаху оружием
```

Разбор: модель предзагружается один раз до появления первого монстра этого типа на уровне, что предотвращает задержку/подгрузку прямо во время боя. Присвоение `self.frame` конкретного номера мгновенно переключает видимую позу объекта на соответствующий кадр анимации, заранее нарисованный автором модели.

---

## Практический пример 2: дымовой эффект-столб на спрайте

```
precache_model("progs/smoke.spr");
...
newent = spawn();
setmodel(newent, "progs/smoke.spr");
newent.movetype = MOVETYPE_NONE;
newent.frame = 0;
```

Разбор: спрайт дыма, сохранённый с типом ориентации `SPR_VP_PARALLEL_UPRIGHT`, при взгляде с любой стороны всегда выглядит развёрнутым к игроку по горизонтали, но не «заваливается» при взгляде сверху вниз — визуально это выглядит так, будто дым всегда стоит вертикальным столбом, что и требуется для правдоподобия эффекта.

---

## Примеры

- Полностью оригинальный набор монстров и оружия классического Quake работает «из коробки» без каких-либо изменений — движок читает их `.mdl`-файлы напрямую.
- Мод добавляет собственный спрайтовый эффект дыма через `.spr`-файл, используемый как декоративный объект, всегда развёрнутый к игроку.
