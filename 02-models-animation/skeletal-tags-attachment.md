# Скелетные теги и присоединение объектов (tag attachment)

> [⬅ Вернуться к оглавлению вики](../README.md)

> Раздел: [Трёхмерные модели и анимация](./README.md)

## Что это даёт геймдизайнеру

**Тег** — это именованная точка привязки на модели (например, «рука», «дуло оружия», «голова»), координаты и ориентация которой автоматически следуют за анимацией модели. Система тегов позволяет «прикрепить» одну модель к другой — например, оружие к руке персонажа, или шляпу к его голове — так, чтобы прикреплённый объект автоматически двигался вместе с анимацией родительской модели, без необходимости вручную пересчитывать его положение в каждом кадре.

Это решает частую задачу геймдизайна: составные персонажи (тело + отдельно надеваемая экипировка), эффекты, привязанные к конкретной части тела (искры из дула оружия при выстреле), и модульная сборка персонажа из независимо анимируемых частей.

## Интерфейс настройки

Теги задаются не в отдельном текстовом файле, а являются частью самой модели — они экспортируются вместе с геометрией и скелетом из 3D-редактора (поддерживается как в классических составных форматах вроде MD3, так и в современных скелетных форматах вроде IQM). Из игровой логики (QuakeC) тег используется через две встроенные функции:

- **`gettagindex(ent, tagname)`** — находит номер точки привязки (тега или кости) на модели указанного объекта по её текстовому названию (например, `"tag_weapon"`); возвращает 0, если тег с таким именем на модели не найден.
- **`gettaginfo(ent, tagindex)`** — вычисляет текущее положение указанного тега в мировых координатах с учётом всей применённой к модели анимации на этот момент; одновременно с координатой заполняются глобальные переменные направления `v_forward`/`v_right`/`v_up`, отражающие ориентацию тега в пространстве — то есть куда «смотрит» эта точка привязки прямо сейчас.

Само «прикрепление» одного объекта к тегу другого в игровой логике реализуется стандартным для модов Quake способом — присвоением полей `.tag_entity` (ссылка на объект-родителя) и `.tag_index` (номер тега, полученный через [`gettagindex`](../37-quakec-builtins-reference/10-skeletal-model-builtins.md#gettagindex)) присоединяемому объекту; после этого при каждом обновлении сцены движок пересчитывает координаты присоединённого объекта через [`gettaginfo`](../37-quakec-builtins-reference/10-skeletal-model-builtins.md#gettaginfo), синхронизируя его с текущей анимацией родителя. Всё, что нужно геймдизайнеру — знать (или согласовать с художником) точные названия тегов, встроенных в конкретную модель, и указывать эти имена при написании логики присоединения объектов. Если нужно получить позицию тега вручную (например, для вспышки выстрела или дополнительного локального смещения), используйте возвращаемый вектор `gettaginfo`, а не глобальные `v_forward`/`v_right`/`v_up`, которые содержат только ориентацию.

## Примеры

- Оружие в руках персонажа присоединяется к тегу `tag_weapon` на модели руки — и автоматически покачивается в такт анимации бега или перезарядки, без ручной синхронизации.
- Частицы огня из дула оружия появляются именно в точке тега `tag_flash`, точно совпадающей с положением ствола, независимо от того, в какую сторону сейчас повёрнут персонаж.

## Практический пример: полный код присоединения оружия к руке персонажа

```
void() Weapon_AttachToHand =
{
    local entity weapon;
    local float tagidx;

    tagidx = gettagindex(self, "tag_weapon");
    if (!tagidx)
    {
        dprint("Внимание: на модели персонажа нет тега tag_weapon!\n");
        return;
    }

    weapon = spawn();
    setmodel(weapon, "models/weapons/v_shotgun.iqm");
    weapon.movetype = MOVETYPE_NONE;
    weapon.solid = SOLID_NOT;
    weapon.tag_entity = self;
    weapon.tag_index = tagidx;

    self.weaponentity = weapon;
};

void() Weapon_UpdateMuzzleHint =
{
    local vector tagorg;

    if (!self.weaponentity)
        return;

    tagorg = gettaginfo(self, self.weaponentity.tag_index);
    setorigin(self.weaponentity, tagorg);
    self.weaponentity.angles = vectoangles(v_forward);
};
```

Построчный разбор: `Weapon_AttachToHand` сначала через `gettagindex` пытается найти на модели персонажа тег с именем `tag_weapon`; если тег не найден, функция выводит диагностическое сообщение и прерывается. Далее создаётся сущность `weapon`, ей назначается модель оружия, и она делается физически неощутимой (`MOVETYPE_NONE`/`SOLID_NOT`), поскольку её позиция будет управляться присоединением. Поля `.tag_entity` и `.tag_index` — это и есть механизм присоединения. Вторая функция показывает именно ручной запрос тега: `gettaginfo` возвращает мировую позицию в `tagorg`, а `v_forward`/`v_right`/`v_up` после этого содержат ориентацию тега, которую можно использовать для поворота или дополнительных смещений.
