## Объяснение на пальцах

Чтобы не заставлять художников экспортировать модели строго в специфичные для этого движка форматы, движок умеет напрямую читать несколько распространённых обменных форматов. По фактическому коду стандартной сборки здесь подтверждена не только загрузка простых **OBJ**, но и поддержка **PSK** и **glTF/GLB**; при этом более экзотические расширения вроде `.lwo` и `.ase` движок действительно узнаёт в интерфейсе, но это ещё не равнозначно отдельному подтверждённому core-loader'у именно для этих форматов.

---

## Список форматов и статус поддержки

- **OBJ** (Wavefront, `.obj`) — прямой импорт статичной геометрии; без скелета и без собственных встроенных анимаций.
- **PSK** (`.psk`) — skeletal mesh-формат из Unreal-экосистемы; при наличии соседнего файла **`.psa`** движок умеет подцеплять и анимации. На вершину сохраняются четыре сильнейших костных веса.
- **glTF/GLB** (`.gltf`/`.glb`) — прямой загрузчик через встроенный model-plugin стандартной конфигурации; поддерживаются меши, материалы, скелеты и анимации, но с оговорками по возможностям (см. ниже).
- **LWO** (`.lwo`) — распознаётся браузером файлов/просмотрщиком моделей как «что-то модельное», но в этой ветке вики на него не стоит ссылаться как на столь же подтверждённый прямой loader, как для OBJ/PSK/glTF.
- **ASE** (`.ase`) — аналогично: расширение узнаётся интерфейсом, но это не тот же уровень подтверждённой поддержки, что у OBJ/PSK/glTF.

### Практические ограничения glTF/PSK

- В обычной сборке общий практический потолок skeletal-подсистемы — **256 костей/узлов** на модель.
- У glTF поддерживается только **один набор UV-координат**.
- У glTF и PSK фактически используются только **до 4 костей на вершину**.
- Для glTF не стоит рассчитывать на `KHR_draco_mesh_compression`; также `GLTF-1 techniques` по умолчанию игнорируются как проблемная часть старого формата.

## Пошаговый туториал: подключение OBJ-модели

**Шаг 1.** Экспортируйте геометрию из любого 3D-редактора в формат Wavefront OBJ.

**Шаг 2.** Положите получившийся файл `.obj` в игровую папку, например `mymod/models/prop.obj`. Если рядом есть `.mtl`, импорт использует его для имён материалов.

**Шаг 3.** Подключите модель в игровой логике или конфигурации ровно так же, как любую другую модель — по имени файла, например через [`precache_model("models/prop.obj")`](../37-quakec-builtins-reference/07-precache-resources-builtins.md#precache_model) и [`setmodel(self, "models/prop.obj")`](../37-quakec-builtins-reference/03-entity-world-builtins.md#setmodel).

**Шаг 4.** При необходимости настройте ориентацию импортированной модели соответствующим cvar'ом (см. таблицу ниже), если исходный редактор использует другую схему осей.

---

## Практический пример: статичный объект окружения из OBJ

```
precache_model("models/props/crate_wood.obj");
...
newent = spawn();
setmodel(newent, "models/props/crate_wood.obj");
newent.movetype = MOVETYPE_NONE;
newent.solid = SOLID_BSP;
```

Разбор: художник экспортирует ящик в OBJ и кладёт рядом `.mtl`; движок загружает геометрию напрямую, без промежуточной конвертации в внутренний формат.

---

## Интерфейс настройки

Для **OBJ**, **PSK** и **glTF/GLB** достаточно положить файл в игровую папку и сослаться на него по имени. OBJ регистрируется как текстовый mesh-loader, PSK — по магической сигнатуре `ACTR`, glTF — встроенным plugin-loader'ом (`.gltf` как текстовый JSON-вариант и `.glb` по бинарной сигнатуре). Для PSK анимации обычно лежат отдельным соседним `.psa`-файлом.

## Инженерный справочник

#### Cvar

| Cvar | Сигнатура | Описание | По умолчанию |
| :--- | :--- | :--- | :--- |
| [`mod_obj_orientation`](../38-cvars-reference/07-system-misc-cvars.md#mod_obj_orientation) | `mod_obj_orientation(int, "1")` | Переориентация импортируемой OBJ-геометрии при загрузке | `1` |
| `mod_gltf_scale` | `mod_gltf_scale(float, "30")` | Сколько игровых единиц считать одним метром при загрузке glTF | `30` |
| `mod_gltf_standardorientation` | `mod_gltf_standardorientation(int, "1")` | Преобразовывать стандартный glTF `y-up` в Quake-совместимый `z-up` | `1` |
| `mod_gltf_ignoretechniques` | `mod_gltf_ignoretechniques(int, "1")` | Игнорировать проблемные `techniques` из glTF 1.x | `1` |

#### Другое

| Элемент | Синтаксис/тип | Описание |
| :--- | :--- | :--- |
| `.obj` | Формат файла | Прямой импорт статичной геометрии |
| `.psk` + optional `.psa` | Формат mesh + animation | Скелетная модель Unreal-стиля с отдельными анимациями |
| `.gltf` / `.glb` | Формат файла | Современный обменный формат, загружаемый встроенным plugin-loader'ом |
